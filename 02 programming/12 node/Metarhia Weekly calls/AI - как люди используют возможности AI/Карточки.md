# Карточки — AI: как люди используют возможности AI

По результатам опроса (85 из ~2500 просмотревших), какой процент респондентов работает только в чат-режиме без агентского режима?
::
80%.

Какой процент опрошенных переключает модель прямо в процессе выполнения одной задачи, и как Тимур относится к этой практике?
::
17%; Тимур считает это нормальной и даже необходимой практикой, а не аномалией.

Для какого сценария, по практическому правилу Тимура, годится чисто чат-режим работы с AI?
::
Только для рефакторинга уже хорошего, нравящегося кода — постепенных правок «туда-обратно». Плохой код нужно не патчить в чате, а переписывать исходную постановку задачи.

Какой двухшаговый процесс Тимур рекомендует для написания нового кода вместо прямого чата?
::
Сначала режим планирования (агент пишет markdown-план, человек его правит, можно пробовать несколько моделей), и только когда план готов — запуск агента на автономное кодирование.

В чём главный недостаток антипаттерна «подкладывать модели папку примеров кода как контекст» (практика самого Тимура до знакомства со skills)?
::
Медленно (модель долго переваривает материал) и вытесняет контекст, оставляя мало места под саму доменную модель задачи.

Чем skills отличаются от больших `AGENTS.md`/rules-файлов на десятки страниц с точки зрения использования контекста?
::
Skills не загружаются в контекст целиком постоянно, а подгружаются по необходимости; огромные rules-файлы засоряют контекст полностью и постоянно.

Какую практику применяет Тимур после составления ТЗ для агента, чтобы улучшить результат?
::
Отдельным промптом просит сократить ТЗ примерно на 30%, иногда пробует альтернативные модели на той же задаче.

Какие две области, по мнению Тимура и коллег, AI пока не может полноценно заменить у разработчика?
::
Системное программирование (нужна экспертиза, интуиция и большой личный контекст человека) и доменную экспертизу/коммуникацию с пользователями и бизнесом.

Какие два фактора предположительно объясняют, почему решение сложных системных задач у человека происходит через «интуитивный щелчок», а не пошагово?
::
Больший личный контекст (фоново «крутится» опыт из разных языков и проектов) и работающая интуиция — решение может прийти без видимого процесса рассуждения.

Что такое «мамкин архитектор» в терминологии этого звонка?
::
Человек без архитектурного бэкграунда (иногда даже не умеющий писать `for`-цикл на чистом JS), который с помощью AI выдаёт архитектуру с Kafka, Docker, Kubernetes «по фичам», не понимая последствий.

Какой личный пример архитектурного опыта привёл Тимур про сложные корпоративные базы данных?
::
Опыт архитектора отраслевой информационной системы МВД Украины — около 300 основных баз данных плюс сотни мелких; типичная проблема — несколько логических баз, «спрятанных» внутри одной физической через префиксы таблиц.

Какую ошибку архитектора, ставящего задачу AI, назвал Тимур «эмоциональной привязанностью»?
::
Влюблённость в конкретный язык/рантайм — из-за неё архитектор заставляет модель решать несвойственные задачи «на любимом языке» вместо органичного выбора инструмента под задачу.

Какая доля классических паттернов «Банды четырёх» уже переведена Тимуром на функциональную и процедурную парадигмы (помимо ООП)?
::
80-90%.

Почему правильное называние паттерна (терминология) напрямую влияет на качество результата AI-агента?
::
Структурно похожий код (Decorator/Adapter/Facade, разные виды Factory) различается именно целью применения, а не структурой — точное название по цели помогает и человеку, и модели рассуждать осмысленно.

Какую распространённую терминологическую ошибку с паттернами приводит Тимур как пример?
::
Путают Abstract Factory с обычным Factory Method — 90% случаев «абстрактной фабрики» на практике оказываются фабричным методом.

В каком формате планируется перевести классические паттерны и Node.js-специфику асинхронного программирования для использования с AI?
::
В формат skills с иерархией примеров под разные фреймворки/языки, чтобы AI подгружал только релевантный пример вместо всего каталога.

Что имел в виду участник, говоря, что GitHub Copilot Business/M365 Copilot Chat «не теряет контекст» по сравнению с Cursor?
::
По его ощущениям, эта модель глубже анализирует контекст и дольше держит длинные многошаговые задачи без явной потери деталей задачи.

На каком базовом механическом уровне Тимур объяснил, почему любой AI-агент неизбежно теряет часть контекста в длинной сессии?
::
LLM в основе своей stateless; контекст держится самим чатом/сессией, и при достижении лимита неизбежно происходит сжатие (compaction) с потерей части истории — во всех средах без исключения.

В каком формате будет подаваться анонсированный модуль по архитектуре в курсе (а не как разовая видеозапись)?
::
В формате живых семинаров (с записью для отсутствующих), потому что архитектурное знание быстро меняется и не является «книжным».

Какая архитектурная аналогия (из личного опыта Тимура — сына архитекторов зданий) была приведена для объяснения роли паттернов и архитектурного надзора?
::
Паттерны создают структуру кода так же, как несущие конструкции — структуру здания; без паттернов код превращается в антипаттерн Big Ball of Mud. Архитектура ПО, как и здания, требует периодического «архитектурного надзора» после первоначального проектирования.
