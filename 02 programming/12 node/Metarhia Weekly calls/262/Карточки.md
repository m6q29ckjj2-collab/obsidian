# Карточки — Weekly call #262

Какую единственную внешнюю production-зависимость заменила собственная реализация WebSocket в Metacom?
::
Библиотеку `ws`.

Почему MetaSQL не считается частью ядра Metarhia?
::
Это необязательная утилитная надстройка с зависимостью на Postgres (`pg`); ядро (Impress, Metacom) принципиально не имеет внешних runtime-зависимостей.

Почему из Metacom дропнута поддержка Node.js 18/20/21?
::
В них нет нативного WebSocket-клиента, а архитектура Metacom требует одновременно и клиента, и сервера; минимальная версия теперь — Node.js 22.

Почему одиночные строковые константы выносят in place, а не в отдельный файл-константы?
::
Если строка используется один раз, вынос в константу не экономит память (литерал не дублируется при многократном использовании) и только усложняет код.

Почему в WebSocket-модуле `Set`/`Map` заменили на `Array`/plain objects для кодов закрытия соединения?
::
Коллекция маленькая (~20 элементов) и почти не меняется — накладные расходы на хэш-функцию не окупаются, линейный поиск не медленнее.

Сколько параллельных реализаций ping/pong-механизма было в кодовой базе до рефакторинга, и сколько осталось?
::
Было три (в Metacom, в WebSocket-модуле, и забытый недописанный код), осталась одна.

Куда перенесён `Result`-контейнер (ok/fail обёртка), ранее находившийся внутри Metacom?
::
В metautil — как общая утилита, не специфичная для конкретного протокола.

Почему поля `head`/`tail` в базовом классе `LinkedList` сделаны не приватными?
::
LinkedList — низкоуровневый класс, который никогда не используется напрямую пользователем («не торчит наружу») — на его основе строятся другие структуры (List и т.д.).

Чем `List` отличается от `LinkedList` по архитектуре?
::
LinkedList — низкоуровневая база (простые циклы, мономорфный код). List — userland-обёртка поверх LinkedList с богатым семантическим API (filter/reduce/map/split/group by и т.д.).

Зачем в List сделаны отдельные методы `rotateLeft`/`rotateRight`, если оба вызывают одну и ту же внутреннюю `rotate`?
::
Ради семантики API — читаемости кода, а не ради разной реализации.

Что такое `PersistentList` и в чём его главное свойство?
::
Неизменяемая структура в духе Lisp-списков (аналог car/cdr): каждое добавление создаёт новый экземпляр, ссылающийся на предыдущий через next; старые ссылки остаются валидны навсегда, список может «ветвиться».

Как реализован `Struct` (persistent object) в metautil на низком уровне?
::
Через цепочку прототипов (Object.create): каждая модификация создаёт новый объект-потомок, новые поля хранятся в самом объекте, старые доступны через прототипную цепочку.

В чём разница между `mutable` и `immutable` вариантами Struct с точки зрения используемого API JS?
::
immutable — Object.freeze (запрет и структуры, и значений); mutable — Object.seal (можно менять значения существующих полей, нельзя добавлять/удалять поля).

Чем отличаются методы `fork` и `branch` у Struct?
::
fork — отсоединяет полную независимую копию от цепочки наследования; branch — добавляет новые поля через Object.defineProperty, не трогая уже определённые в цепочке.

Какую задачу поставили AI-агенту в live coding эксперименте про класс с динамическим именем?
::
Сделать так, чтобы constructor.name динамически создаваемого класса Entity соответствовал переданному пользователем имени, нативными средствами JS, без eval/new Function/патчинга .name как отдельного свойства.

Почему первое решение агента через `Object.defineProperty(cls, 'name', ...)` было отклонено?
::
Это добавляет новое свойство поверх класса («брендинг»), а не по-настоящему переименовывает исходный конструктор.

Какое нативное решение для динамического имени класса использует спецификацию ECMAScript?
::
Обернуть создание класса в объектный литерал с вычисляемым именем ключа — анонимный класс внутри такого литерала наследует имя от ключа, в который присвоен (`{[name]: class {...}}[name]`).

На каких версиях Node.js падали (зависали) тесты Collector после рефакторинга на AbortController, и с какой версии заработали?
::
Падали на 18–23, заработали начиная с Node.js 24.

Какой была итоговая гипотеза причины бага с AbortController в тестах Collector?
::
Нестабильная/забагованная ранняя реализация API AbortController/AbortSignal в более старых версиях Node.js (появился API в районе версии 14-17) — платформенный баг, а не ошибка в бизнес-логике коллектора.

Какое итоговое решение приняли по багу с AbortController в Collector?
::
Откатить AbortController-версию, оставить рабочую реализацию на setTimeout для этого файла, применить оптимизацию приватных полей ко всем остальным классам, кроме файлов с AbortController/сигналами/таймаутами.

Какой вывод сделал Тимур о применимости AI-агентов для диагностики низкоуровневых платформенных багов?
::
У модели нет интуиции о таких багах — код «выглядит правильно», но для их поиска нужен человеческий опыт и целенаправленный поиск по changelog'ам конкретных версий платформы, а не общая генерация кода.

Какая дорожная карта развития технологического стека Metarhia озвучена в конце звонка?
::
Стабилизировать metautil → пересадить на него metacom → перенести наработки local-first/CRDT в GlobalStorage → выпустить новый metacom → выпустить обновлённый GlobalStorage поверх него.

Какие два параллельных формата live-стримов анонсированы — по системному и по прикладному коду?
::
Metarhia (по четвергам) — системное программирование; гильдия NextTick (совместно с Ильёй) — прикладной код.
