# Карточки — Weekly call #267

Какой процент опрошенных в группе не пользуется иммутабельными структурами данных, по опросу перед звонком #267?
::
57%

Какое общее правило сформулировал Тимур: когда использовать мутабельные, а когда иммутабельные структуры данных?
::
Мутабельные — для системного программирования (стримы, буферы, сеть — где важна производительность). Иммутабельные (`struct`, `record`, `result`, `cons`) — для бизнес-логики, где важнее дисциплина, надёжность и developer experience, а не сырая скорость.

Почему для системного кода вместо классического связного списка используют Unrolled list?
::
Unrolled list хранит данные в нескольких массивах (или circular array), и по массиву дешевле двигать указатель, чем ресайзить сам массив — это быстрее классического списка из отдельных узлов.

Как `struct` из metautil реализует копирование объекта без полного дублирования полей?
::
Через наследование (prototype-chain copy-on-write): копия хранит только диф от родителя, а не все поля; при необходимости копию можно материализовать (`materialize`) в плоскую коллекцию.

Какую побочную возможность даёт цепочка наследования у `struct` из metautil, помимо экономии памяти?
::
Доступ к истории изменений — на этой основе можно реализовать undo и транзакционные откаты (паттерн вроде Saga).

Что такое `fixed queue` в контексте Node.js и почему её оптимизация важна?
::
Внутренняя структура данных, лежащая в основе `process.nextTick`; её оптимизация ускоряет всю асинхронность Node.js.

Как Тимур оценил синтаксис и концепцию библиотеки Effect (effect-ts)?
::
Концепция хорошая (контейнер эффекта с явными зависимостями на вход/выход, runtime-проверка схемами, лени и композируемость), но синтаксис (`function*`/`yield*`) смущает, а использование файберов для JS избыточно — у языка уже есть event loop и очередь микротасков.

Какие два варианта беспарольной криптографической авторизации на клиенте есть у Тимура?
::
Один — на основе стандарта Passkeys (WebAuthn), уже поддерживаемого браузерами; второй — самописный аналог без использования этого стандарта.

Где Passkeys хранят приватный/публичный ключ в браузере, и чем это лучше localStorage/OPFS/cookies?
::
В специальном защищённом хранилище браузера с шифрованием на диске — обычные localStorage/OPFS/cookies такой встроенной защиты не дают.

Почему в PR по рефакторингу Impress убирают деструктуризацию массивов из возвращаемых значений функций?
::
Функции должны возвращать структуру (объект) вместо массива — деструктуризация структуры быстрее деструктуризации массива, а это системный код, где важна производительность.

Какая проблема найдена в PR по компрессии статических файлов в Impress?
::
Нет проверки заголовков клиента (какой тип компрессии он поддерживает) и нет fallback на некомпрессированную отдачу — неподдерживаемый клиент получает ошибку без понятной причины.

Почему наследование класса Certificate от Static признано архитектурно неудачным?
::
Certificate (отдающий TLS-сертификаты) наследует слишком много специфичного для раздачи статики функционала; предложено ввести промежуточный класс (Place/Resource) для общей логики «поднятия бинарных данных в память».

В чём разница между нодовской реализацией SharedArrayBuffer-based VFS для статики и самописной, которую сделал один из участников?
::
Нодовская реализация не переиспользует буфер между тредами, самописная — переиспользует.

В чём идея байткод-шаринга модулей между тредами и какой у неё главный открытый риск?
::
Загружать исходники с диска один раз, компилировать через `vm.compileFunction` в байткод и рассылать во все worker-треды вместо повторной загрузки/парсинга в каждом. Риск — байткод от compileFunction, скорее всего, неоптимизированный (сырой), неясно как это повлияет на дальнейшие оптимизации V8.

Что такое ADR и зачем его предложили завести для архитектурных решений вроде байткод-шаринга?
::
Architectural Design Record — запись о том, почему принято конкретное архитектурное решение, чтобы это знание не терялось для будущих контрибьюторов, которые будут читать и исправлять этот код.

Какой большой PR в metautil обсуждался как сложный, но оправданно плотный код (+751 строка)?
::
Priority Queue на основе Heap.

Какая проблема с таймерами в тестах Node.js обсуждалась, и почему предложенный фикс через `setTimeout` не устроил до конца?
::
После обновления Node.js (22/24) тесты стали падать из-за отсутствия `ref()` на указатели на ресурсы, из-за чего процесс завершался раньше времени. `setTimeout`-патч решает проблему только в тестах (в реальном коде ресурс и так удерживается бизнес-логикой), а более «чистый» вариант через `AbortSignal.timeout` потребовал бы runtime-патча под конкретную версию Node — задачу оставили как RnD / work in progress.

Почему нельзя эффективно добавить метод `add(index)` в Unroll list, и что предложили использовать вместо него?
::
У Unroll list нет произвольного индексного доступа без полного обхода — реализация add() убила бы весь смысл оптимизации (эффективность только для операций с концов). Предложили использовать обычный List (двусвязный список), где add(index) уже есть.

Какую документацию привели в пример хорошего developer experience, и что в итоге предложили в качестве единого источника истины для доков?
::
Документацию Tokio (Rust) — сигнатура + развёрнутое текстовое описание + snippet кода. В качестве единого источника истины предложили формат вроде JSON Schema с дополнительными человекочитаемыми полями, из которого компилируются TS-тайпинги, HTML/Markdown-доки и AI-skills.

В чём разница между предложенными usage skill и optimization skill для документации библиотек под AI-агентов?
::
Usage skill описывает обычное использование модуля и подгружается всегда. Optimization skill содержит инструкции по оптимизации производительности и должен подгружаться только когда пользователь явно просит оптимизацию — иначе агент на каждый запрос будет тратить лишние токены на сравнение структур данных и генерацию бенчмарков вместо разработки.

Почему нельзя решить проблему платежей одним универсальным провайдером вроде Stripe?
::
Stripe и аналоги недоступны/забанены для бизнесов из ряда стран (например, Украина, Турция упомянуты явно); такие бизнесы либо регистрируют юрлицо в другой юрисдикции, либо вынуждены работать с локальными провайдерами (Приватбанк, Монобанк и т.п.), которые хуже задокументированы.

Что произошло с проектом Nextic и провайдером SendPulse, обсуждавшееся как пример реальной проблемы с рекуррентными платежами?
::
Около 80 подписчиков не получили продление подписки, потому что провайдер SendPulse не уведомил ни пользователей, ни систему о неудачном рекуррентном списании — проблема обнаружилась только когда её начали целенаправленно копать.

Какая итоговая идея модуля платежей для Meta Qube прозвучала в конце обсуждения?
::
Небольшая постоянная команда (3-4 человека) внутри Metarhia/Meta Qube, которая знает нюансы всех поддерживаемых платёжных систем и поддерживает готовые протестированные интеграции-плагины, чтобы каждый новый проект не решал проблему платежей с нуля.

Какой план действий по модулю платежей озвучил Тимур в конце звонка?
::
Сначала собрать реальные требования/проблемы от участников → сформировать общий пул задач → принять архитектурные и организационные решения (скоуп, поддерживаемые провайдеры, точки расширения) → написать техническое задание → отдать LLM на генерацию реализации → ревью и тестирование людьми.
