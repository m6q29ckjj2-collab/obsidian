# Карточки — Q&A and code review #7: Algebraic Data Types

От какого TC39-пропозала (не принятого) отталкивается идея звонка про алгебраические типы данных на чистом JS?
::
Record & Tuple — предложение нативных иммутабельных структур данных, от которого в итоге отказались.

Как называется язык, придуманный Аланом Кеем, в котором впервые реализована оригинальная концепция ООП, обсуждённая на звонке?
::
Smalltalk.

Какие два принципа лежат в основе ООП по Алану Кею, исключающие race condition по конструкции?
::
(1) У каждого объекта — очередь сообщений на вход, обрабатываемая строго по одному (не может быть двух одновременных вызовов методов). (2) Никакой объект не имеет прямого доступа к состоянию другого — только через сообщения (геттеры/сеттеры).

Какая современная аналогия из JS помогает понять концепцию «очереди сообщений» Алана Кея?
::
Как если бы каждый объект нативно был EventEmitter/Observable, обрабатывающим входящие события строго по одному, без параллельных вызовов методов.

Какая историческая связь Smalltalk с современными фронтенд state-менеджерами была отмечена участником со ссылкой на статью Мартина Фаулера?
::
Smalltalk — первый язык с архитектурой MVC; оттуда через presentation model → view model (в одном из Microsoft-фреймворков) выросли современные state-менеджеры фронтенда.

Через что создаются экземпляры Record в реализации Тимура, и почему не через `{}`?
::
Через `Object.create(null)` — цепочка прототипов заканчивается на null, а не на Object.prototype, что чище и быстрее (поиск отсутствующего поля не тратит лишний шаг на Object.prototype).

Чем отличаются финализация mutable и immutable вариантов Record?
::
mutable — Object.seal (можно менять значения полей, нельзя добавлять/удалять); immutable — Object.freeze (нельзя менять вообще ничего).

Чем отличаются методы `update` и `fork` у Record?
::
update меняет поля существующего экземпляра (бросает исключение, если объект frozen); fork создаёт новую структуру-потомка, не трогая исходный экземпляр — основа immutable-обновления.

Приведи пример из звонка, где иммутабельность Record через агрегацию защищает от логической ошибки.
::
User (mutable) агрегирует City (immutable) по ссылке — благодаря иммутабельности City никто не может незаметно «переименовать» город и тем самым сломать данные всех пользователей, ссылающихся на него.

Почему TypeScript-типизация для динамически создаваемого Record оказалась малополезной?
::
Реальные поля структуры создаются динамически в рантайме, поэтому TypeScript вынужден оперировать unknown/generics без содержательной информации — статическая система типов не может знать заранее форму объекта, порождённого во время выполнения.

Почему алгебраические типы данных называются именно «алгебраическими»?
::
Новый тип конструируется алгебраическими операциями (сложение/объединение) над существующими типами — идея от математиков, реализованная в языках вроде Haskell.

В чём неоднозначность сокращения ADT, отмеченная на звонке?
::
Многие программисты по умолчанию читают ADT как «Abstract Data Type» (абстрактный тип данных), а не «Algebraic Data Type» (алгебраический).

Чем Tuple в реализации Тимура отличается от Record?
::
Tuple — иммутабельный Array фиксированной длины с проверкой arity при создании и Object.freeze на сам массив; поля не именованы (в отличие от именованных полей Record).

Какая ключевая проблема возникла в реализации типа Option (Some/None) на звонке?
::
Разделение на варианты строится на грубой проверке `value === undefined`, из-за чего невозможно корректно расширить на третий вариант; классы Some и None получились взаимно зацеплены по именам друг на друга.

Какой итоговый вывод сделал Тимур про практическую пользу Sum/Option в текущей реализации?
::
С трудом можно придумать полезное применение — конструкция не доведена до продакшн-состояния, в отличие от Record и Tuple.

Почему паттерн Result плохо ложится на парадигму JavaScript, по мнению Тимура?
::
В языке уже есть Promise, который решает ту же задачу (доставка значения-или-ошибки) более естественным для JS способом — поэтому Result не прижился так широко, как в Go/Rust, где нет Promise-подобного примитива.

Чем библиотека Effect (effect-ts) отличается от того, что пытались реализовать на звонке?
::
Effect реализует Result/Either в похожем духе, но с готовым фиксированным набором контейнеров — без возможности динамически конструировать новые типы в рантайме через алгебру типов.

Почему TypeScript union types (`type Option<T> = Some<T> | None`) не считаются полноценной заменой рантайм-ADT?
::
Union type — чисто compile-time декларация, полностью пропадающая в рантайме и не дающая никакой пользы после компиляции.

Какие встроенные TypeScript-утилиты назвали «зачатками» алгебраических операций над типами?
::
Omit и Pick.

Что обнаружил Тимур в архивном коде Metarhia (модуль libFP в metacom), и что случилось с этими наработками?
::
Реализации Maybe и Either как монад через классы (редкость — обычно монады в JS делают через замыкания), плюс enum-подобный тип; эти конструкции не прижились и не использовались после первоначальной реализации.

Какую конструкцию из показанных на звонке точно решили перенести в metautil?
::
Record — единственная с однозначно доказанной пользой (иммутабельность, быстрый прототип на null, удобный fork/update API).

Какую идею для будущей библиотеки типов данных предложил Тимур в конце звонка (физические единицы измерения)?
::
Библиотеку типов данных для системы СИ, где типы выводят не только значение, но и единицу измерения при операциях (пример — закон Ома: из значений с единицами на входе выводится значение с правильной единицей на выходе).

Когда, по мнению Тимура, оправдан переход от обычных объектов-литералов к алгебраическим структурам данных, несмотря на рост когнитивной нагрузки?
::
Там, где нужна дополнительная гарантия целостности типа — например, тип Money с обязательной валидацией точности до копейки и предотвращением накопления «плавающих» ошибок округления.
