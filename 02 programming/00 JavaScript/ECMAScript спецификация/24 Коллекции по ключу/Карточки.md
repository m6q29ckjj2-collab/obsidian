## Map — равенство и ключи

Какой алгоритм равенства использует `Map` для сравнения ключей::==SameValueZero== — как `===`, но `NaN` равен самому себе

Найдёт ли `new Map().set(NaN, 'x').get(NaN)` значение::==Да== — SameValueZero считает NaN равным себе

Считаются ли `+0` и `-0` разными ключами в `Map`::==Нет==, одним и тем же ключом (SameValueZero не различает знак нуля)

Может ли ключом `Map` быть объект без приведения к строке::==Да==, любое значение любого типа может быть ключом без приведения

Как сравниваются ключи-объекты в `Map`::==По ссылке==, а не по структуре — два разных объекта с одинаковым содержимым это разные ключи

Чем обычный объект отличается от `Map` в вопросе ключей::У обычного объекта нестроковые/несимвольные ключи ==приводятся к строке== при обращении

## Map — порядок и API

В каком порядке `Map` перечисляет свои записи::Строго в ==порядке вставки==, без особого случая для числовых ключей (в отличие от обычного объекта)

Является ли `Map.prototype.size` методом::==Нет==, это ==геттер-свойство== — обращаться нужно как `m.size`, не `m.size()`

В каком порядке `Map.prototype.forEach` передаёт аргументы колбэку::`(value, key, map)` — тот же порядок, что у ==Array.prototype.forEach==

Что выведет код
?
```js
new Set(['x']).forEach((value, key) => console.log(value === key));
```
`true` — у Set значение передаётся дважды, потому что значение и есть «ключ»

## Set — новые методы

Какие теоретико-множественные операции добавлены к `Set` в качестве методов::`union`, `intersection`, `difference`, `symmetricDifference`, `isSubsetOf`, `isSupersetOf`, `isDisjointFrom`

Что вернёт `new Set([1,2,3]).difference(new Set([2,3,4]))`::==`Set {1}`== — элементы, которые есть в первом множестве, но нет во втором

## WeakMap / WeakSet

В чём принципиальное отличие `WeakMap` от `Map`::`WeakMap` держит ==слабую ссылку== на ключ-объект — не мешает сборщику мусора удалить его, если других ссылок не осталось

Что произойдёт при попытке использовать примитив (число, строку) как ключ `WeakMap`::Выбросится ==`TypeError`== — ключом может быть объект или обычный (не зарегистрированный) символ

Может ли обычный (не через `Symbol.for`) символ быть ключом `WeakMap`::==Да== — а вот зарегистрированный символ (`Symbol.for(...)`) не подходит, он живёт в глобальном реестре вечно и не может быть собран сборщиком мусора

Есть ли у `WeakMap`/`WeakSet` свойство `size`::==Нет==

Можно ли перебрать записи `WeakMap` через `forEach` или `for...of`::==Нет==, WeakMap не итерируем и не имеет forEach

Почему у `WeakMap`/`WeakSet` намеренно нет способа посчитать или перечислить записи::Момент сборки мусора ==не специфицирован==; наблюдаемый счётчик сделал бы работу сборщика мусора видимой снаружи, что спецификация не допускает

Для какой типичной задачи используется `WeakMap`::Привязка ==приватных/вычисляемых данных к объекту== без риска утечки памяти — запись исчезает автоматически вместе с объектом-ключом
