> [!question] Какой алгоритм равенства использует `Map` для сравнения ключей?
> a) `===` (Strict Equality)
> b) `Object.is` (SameValue)
> c) SameValueZero
> d) сравнение по структуре (deep equality)
>> [!success]- Answer
>> c) SameValueZero
>> Тот же алгоритм, что у `Array.prototype.includes` и `Set` — ведёт себя как `===`, кроме одного отличия: `NaN` считается равным самому себе

> [!question] Что выведет код?
> ```js
> const m = new Map();
> m.set(0, 'a');
> m.set(-0, 'b');
> console.log(m.size, m.get(0));
> ```
> a) `2 'a'`
> b) `1 'b'`
> c) `2 'b'`
> d) `1 'a'`
>> [!success]- Answer
>> b) `1 'b'`
>> SameValueZero не различает `+0` и `-0` — это один и тот же ключ, второй `set` перезаписал значение первого

> [!question] Может ли объект (не примитив) быть ключом обычного `Map` без приведения к строке?
>> [!success]- Answer
>> True
>> В отличие от обычного объекта (где нестроковые ключи приводятся к строке), `Map` принимает любое значение как ключ без приведения, включая объекты, функции, массивы

> [!question] Что выведет код?
> ```js
> const m = new Map();
> m.set({}, 'значение');
> console.log(m.get({}));
> ```
> a) `'значение'`
> b) `undefined`
> c) выбросит `TypeError`
> d) `null`
>> [!success]- Answer
>> b) `undefined`
>> Ключи-объекты сравниваются по ссылке, а не по структуре. `{}` во втором вызове — это другой объект, даже если структурно идентичен первому

> [!question] В каком порядке `Map` перечисляет свои записи при итерации?
> a) в алфавитном порядке ключей
> b) числовые ключи сначала, потом остальные в порядке добавления
> c) строго в порядке вставки, без исключений
> d) порядок не специфицирован
>> [!success]- Answer
>> c) строго в порядке вставки, без исключений
>> В отличие от обычного объекта, где числовые (integer-like) ключи специально выносятся вперёд по возрастанию, `Map` сохраняет ровно тот порядок, в котором записи были добавлены

> [!question] `Map.prototype.size` — это метод, который нужно вызывать как `m.size()`
>> [!success]- Answer
>> False
>> Это геттер-свойство — обращаться нужно как `m.size`, без скобок. Функции вызова нет, значение вычисляется автоматически при каждом обращении к свойству

> [!question] В каком порядке `Map.prototype.forEach` передаёт аргументы колбэку?
> a) `(key, value, map)`
> b) `(value, key, map)`
> c) `(map, key, value)`
> d) `(key, map)`
>> [!success]- Answer
>> b) `(value, key, map)`
>> Намеренно тот же порядок, что у `Array.prototype.forEach` (`value, index, array`) — ради единообразного, переносимого API

> [!question] Что выведет код?
> ```js
> new Set(['x']).forEach((value, key) => console.log(value === key));
> ```
> a) `false`
> b) `true`
> c) выбросит ошибку
> d) `undefined`
>> [!success]- Answer
>> b) `true`
>> У `Set.prototype.forEach` значение передаётся дважды — как «value» и как «key» — потому что в множестве значение и есть его собственный ключ. Это сохраняет единый API с `Map.prototype.forEach`

> [!question] Что вернёт `new Set([1,2,3]).intersection(new Set([2,3,4]))`?
> a) `Set {1,2,3,4}`
> b) `Set {2,3}`
> c) `Set {1}`
> d) `Set {4}`
>> [!success]- Answer
>> b) `Set {2,3}`
>> `intersection` возвращает элементы, присутствующие в обоих множествах

> [!question] Какие из перечисленных методов недавно добавлены к `Set.prototype` для теоретико-множественных операций?
> a) `push`, `pop`, `shift`
> b) `union`, `intersection`, `difference`, `symmetricDifference`
> c) `map`, `filter`, `reduce`
> d) `concat`, `slice`, `splice`
>> [!success]- Answer
>> b) `union`, `intersection`, `difference`, `symmetricDifference`
>> Вместе с предикатами `isSubsetOf`, `isSupersetOf`, `isDisjointFrom` они реализуют стандартные операции теории множеств без ручного кода через `filter`/spread

> [!question] В чём принципиальное отличие `WeakMap` от обычного `Map`?
> a) `WeakMap` работает быстрее
> b) `WeakMap` держит слабую ссылку на объект-ключ, не мешая сборщику мусора его удалить
> c) `WeakMap` может хранить только строки как значения
> d) разницы нет, это синонимы
>> [!success]- Answer
>> b) `WeakMap` держит слабую ссылку на объект-ключ, не мешая сборщику мусора его удалить
>> Обычная `Map` держит сильную ссылку — ключ-объект никогда не будет собран, пока запись в `Map` жива, даже если больше нигде на него нет ссылок

> [!question] Что произойдёт при вызове `new WeakMap().set(1, 'x')` — числовой примитив как ключ?
> a) сработает как обычно
> b) выбросит `TypeError`
> c) число автоматически обернётся в объект-обёртку
> d) вернёт `undefined`
>> [!success]- Answer
>> b) выбросит `TypeError`
>> Ключом `WeakMap`/`WeakSet` может быть объект или обычный, не зарегистрированный символ — остальные примитивы никогда не собираются сборщиком мусора, «слабость» ссылки для них не имеет смысла (а зарегистрированный через `Symbol.for` символ не подходит по той же причине — он живёт в глобальном реестре вечно)

> [!question] Есть ли у `WeakMap` свойство `size`?
>> [!success]- Answer
>> False
>> Намеренно отсутствует, как и `forEach`, `keys`, `entries`, `clear` и сама итерируемость

> [!question] Почему у `WeakMap`/`WeakSet` намеренно нет способа перечислить или посчитать записи?
> a) это было бы слишком медленно
> b) момент сборки мусора не специфицирован — наблюдаемый счётчик сделал бы её видимой снаружи
> c) движки физически не могут это реализовать
> d) это ограничение исторически устарело, но никто не убрал
>> [!success]- Answer
>> b) момент сборки мусора не специфицирован — наблюдаемый счётчик сделал бы её видимой снаружи
>> Если бы количество записей можно было посчитать, оно могло бы «само по себе» измениться между двумя обращениями к программе без единой явной операции — то есть работа сборщика мусора стала бы наблюдаемым эффектом языка, чего спецификация принципиально избегает

> [!question] Можно ли перебрать `WeakSet` через `for...of`?
>> [!success]- Answer
>> False
>> `WeakSet`, как и `WeakMap`, не реализует `Symbol.iterator` — перебор в принципе недоступен

> [!question] Для какой типичной задачи лучше всего подходит `WeakMap`?
> a) хранение конфигурации приложения
> b) привязка приватных/вычисляемых данных к объекту без риска утечки памяти
> c) сортировка большого набора данных
> d) замена обычного массива
>> [!success]- Answer
>> b) привязка приватных/вычисляемых данных к объекту без риска утечки памяти
>> Запись в `WeakMap` исчезает автоматически вместе с объектом-ключом, когда на него больше нет других ссылок — идеально для кешей, привязанных к объектам с непредсказуемым временем жизни
