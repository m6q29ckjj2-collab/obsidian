# Глава 18 · Встроенные объекты: общие положения — отчёт

> [!info] Раздел спецификации
> [18 ECMAScript Standard Built-in Objects](https://262.ecma-international.org/#sec-ecmascript-standard-built-in-objects)
> Карточки → [[Карточки]] · квиз → [[Квиз]] · карта → [[00 Карта]]

Короткая, но важная глава: она задаёт конвенции, которым подчиняются **все** встроенные объекты из глав 19–28. Не зная её, легко удивляться поведению, которое на самом деле системно и предсказуемо.

---

## Атрибуты свойств по умолчанию

Ключевое общее правило: у большинства встроенных свойств `[[Writable]]: true`, `[[Enumerable]]: false`, `[[Configurable]]: true`. Неперечисляемость — то, что отличает встроенные методы от свойств, которые вы сами добавляете обычным присваиванием.

```js
console.log(Object.keys(Array.prototype));            // []
console.log(Array.prototype.propertyIsEnumerable('map')); // false
for (const k in []) console.log(k);                    // ничего не выведется для встроенных методов
```

Это же объясняет, почему добавление метода в `Array.prototype` через присваивание **не** ломает `for...in` по массивам — а вот через `Array.prototype.x = 1` без `defineProperty` как раз сломало бы, потому что обычное присваивание делает свойство перечисляемым.

## Длина и имя функции

Каждая встроенная функция имеет свойства `length` и `name`, и оба ведут себя не совсем так, как ожидается интуитивно.

`length` — число **обязательных** параметров до первого со значением по умолчанию или остаточного параметра, а не общее количество параметров.

```js
console.log(Math.max.length);              // 2 — не 0 и не Infinity
console.log(((a, b = 1, ...c) => {}).length); // 1 — считает только a
console.log(Array.prototype.slice.length);  // 2
```

`name` заполняется автоматически из контекста присваивания даже для анонимных функций — [NamedEvaluation](https://262.ecma-international.org/#sec-runtime-semantics-namedevaluation) выводит имя из места объявления.

```js
const f = () => {};
console.log(f.name); // 'f' — выведено из имени переменной
const obj = { method: function () {} };
console.log(obj.method.name); // 'method'
console.log((() => {}).bind(null).name); // 'bound '
```

## Хорошо известные символы

[6.1.5.1 Well-Known Symbols](https://262.ecma-international.org/#sec-well-known-symbols) — фиксированный набор символов, встроенных в язык и переопределяющих поведение стандартных операций. Три из них уже разбирались раньше: `Symbol.iterator`, `Symbol.hasInstance`, `Symbol.toStringTag`.

```js
class Range {
  constructor(a, b) { this.a = a; this.b = b; }
  *[Symbol.iterator]() { for (let i = this.a; i <= this.b; i++) yield i; }
  get [Symbol.toStringTag]() { return 'Range'; }
}
const r = new Range(1, 3);
console.log([...r], Object.prototype.toString.call(r));
// [1, 2, 3] '[object Range]'
```

Менее известные, но не менее реальные: `Symbol.toPrimitive` (уже разбирался в главе 7), `Symbol.species` (какой конструктор использовать для производных объектов вроде результата `Array.prototype.map`), `Symbol.isConcatSpreadable`, `Symbol.asyncIterator`, `Symbol.unscopables` (список имён, которые `with` обязан игнорировать — единственное официальное практическое применение `with` во всём стандарте).

```js
console.log(Array.prototype[Symbol.unscopables]);
// { at: true, copyWithin: true, entries: true, ... } — новые методы Array,
// добавленные после появления with, чтобы не сломать старый код внутри with-блоков
```

## Инварианты внутренних методов

[6.1.7.3 Invariants of the Essential Internal Methods](https://262.ecma-international.org/#sec-invariants-of-the-essential-internal-methods) — те самые правила, которые не даёт нарушить ни один объект языка, включая прокси (уже разбирались в главе 10 применительно конкретно к прокси). Здесь они описаны как общие требования ко **всем** объектам, а не специфика одной экзотической формы.

```js
const frozen = Object.freeze({ x: 1 });
console.log(Object.getOwnPropertyDescriptor(frozen, 'x').configurable); // false
// повторный вызов GetOwnProperty обязан вернуть тот же дескриптор — это инвариант,
// а не случайность реализации
```

## Well-Known Intrinsic Objects

[6.1.7.4 Well-Known Intrinsic Objects](https://262.ecma-international.org/#sec-well-known-intrinsic-objects) — таблица встроенных объектов с обозначениями вида `%Array.prototype%`, `%IteratorPrototype%`. Эта нотация используется всюду в главах 19–28 для ссылки на объект безотносительно того, как к нему добраться из пользовательского кода.

`%IteratorPrototype%` заслуживает отдельного внимания: это общий прототип **всех** встроенных итераторов, недоступный напрямую по имени, но легко достижимый через цепочку прототипов.

```js
const arrayIterProto = Object.getPrototypeOf([][Symbol.iterator]());
const mapIterProto = Object.getPrototypeOf(new Map()[Symbol.iterator]());
console.log(Object.getPrototypeOf(arrayIterProto) === Object.getPrototypeOf(mapIterProto));
// true — оба ссылаются на один и тот же %IteratorPrototype%
```

## Итог

> [!success] Что забирать
> - Большинство встроенных свойств неперечисляемы — поэтому методы прототипов не засоряют `for...in` и `Object.keys`
> - `length` функции считает обязательные параметры до первого со значением по умолчанию, а не общее число параметров
> - `name` автоматически выводится из контекста присваивания даже для анонимных функций
> - Хорошо известных символов больше, чем обычно вспоминают: species, isConcatSpreadable, asyncIterator, unscopables
> - `Symbol.unscopables` — единственное официальное практическое применение `with` во всём стандарте
> - Инварианты внутренних методов — общее требование ко всем объектам, не специфика одних лишь прокси
> - `%IteratorPrototype%` — общий прототип всех встроенных итераторов, недоступный по прямому имени
