> [!question] Что выведет код?
> ```js
> console.log(Object.keys(Array.prototype).length, Array.prototype.propertyIsEnumerable('map'));
> ```
> a) `0 false`
> b) `больше 0 true`
> c) `0 true`
> d) `больше 0 false`
>> [!success]- Answer
>> a) `0 false`
>> Встроенные методы прототипов неперечисляемы по умолчанию, поэтому не попадают в Object.keys

> [!question] Что вернёт `Math.max.length`?
> a) `0`
> b) `2`
> c) `Infinity`
> d) `NaN`
>> [!success]- Answer
>> b) `2`
>> length определён спецификацией явно и не зависит от того, что функция реально принимает произвольное число аргументов

> [!question] Что вернёт код?
> ```js
> console.log(((a, b = 1, ...c) => {}).length);
> ```
> a) `3`
> b) `2`
> c) `1`
> d) `0`
>> [!success]- Answer
>> c) `1`
>> length считает только параметры до первого со значением по умолчанию — b и остаточный параметр c не учитываются

> [!question] Что выведет код?
> ```js
> const f = () => {};
> console.log(f.name);
> ```
> a) пустую строку
> b) `'f'`
> c) `'anonymous'`
> d) выбросит `TypeError`
>> [!success]- Answer
>> b) `'f'`
>> Имя автоматически выводится из контекста присваивания даже для анонимных функциональных выражений

> [!question] Что выведет код?
> ```js
> console.log((() => {}).bind(null).name);
> ```
> a) пустую строку
> b) `'bound '`
> c) `'null'`
> d) выбросит `TypeError`
>> [!success]- Answer
>> b) `'bound '`
>> Связанная функция получает имя с префиксом bound и пробелом перед исходным именем

> [!question] Что определяет хорошо известный символ Symbol.unscopables?
> a) какие символы объект поддерживает
> b) список имён свойств, которые with обязан игнорировать
> c) порядок перечисления ключей
> d) видимость свойства для JSON.stringify
>> [!success]- Answer
>> b) список имён свойств, которые with обязан игнорировать
>> Введён, чтобы новые методы Array не ломали старый код внутри блоков with

> [!question] Зачем понадобился Symbol.unscopables?
> a) для оптимизации доступа к свойствам
> b) чтобы новые методы массива, добавленные позже, не конфликтовали со старым кодом внутри with
> c) для поддержки приватных полей
> d) для сериализации в JSON
>> [!success]- Answer
>> b) чтобы новые методы массива, добавленные позже, не конфликтовали со старым кодом внутри with
>> Единственное официальное практическое применение конструкции with во всём стандарте

> [!question] Что выведет код?
> ```js
> class R {
>   *[Symbol.iterator]() { yield 1; yield 2; }
>   get [Symbol.toStringTag]() { return 'R'; }
> }
> const r = new R();
> console.log([...r], Object.prototype.toString.call(r));
> ```
> a) `[1, 2] '[object Object]'`
> b) `[1, 2] '[object R]'`
> c) `[] '[object R]'`
> d) выбросит `TypeError`
>> [!success]- Answer
>> b) `[1, 2] '[object R]'`
>> Symbol.iterator даёт объекту протокол перебора, Symbol.toStringTag меняет результат стандартного метода строкового представления

> [!question] Распространяются ли инварианты внутренних методов только на объекты прокси?
>> [!success]- Answer
>> False
>> Это общее требование ко всем объектам языка, прокси лишь наиболее заметное место, где их можно нарушить намеренно

> [!question] Что гарантирует инвариант о неконфигурируемых свойствах?
> a) свойство нельзя прочитать дважды
> b) повторное получение дескриптора обязано вернуть тот же результат
> c) свойство автоматически становится перечисляемым
> d) значение свойства нельзя вывести в консоль
>> [!success]- Answer
>> b) повторное получение дескриптора обязано вернуть тот же результат
>> Это защищает от ситуации, когда объект выглядит замороженным, но фактически меняется

> [!question] Что представляет собой нотация вида `%Array.prototype%`?
> a) синтаксис регулярных выражений
> b) обозначение встроенного объекта безотносительно способа доступа из кода
> c) устаревшую запись для директив препроцессора
> d) формат именования приватных полей
>> [!success]- Answer
>> b) обозначение встроенного объекта безотносительно способа доступа из кода
>> Используется во всех главах, описывающих встроенные объекты, для точных перекрёстных ссылок

> [!question] Что выведет код?
> ```js
> const arrayIterProto = Object.getPrototypeOf([][Symbol.iterator]());
> const mapIterProto = Object.getPrototypeOf(new Map()[Symbol.iterator]());
> console.log(Object.getPrototypeOf(arrayIterProto) === Object.getPrototypeOf(mapIterProto));
> ```
> a) `true`
> b) `false`
> c) выбросит `TypeError`
> d) `undefined`
>> [!success]- Answer
>> a) `true`
>> Оба итератора в конечном счёте наследуют от одного и того же общего %IteratorPrototype%, недоступного напрямую по имени
