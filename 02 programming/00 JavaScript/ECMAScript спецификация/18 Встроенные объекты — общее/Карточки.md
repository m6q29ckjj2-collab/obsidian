## Атрибуты по умолчанию

Каковы атрибуты большинства встроенных свойств::`writable: true`, `enumerable: ==false==`, `configurable: true`

Что вернёт `Object.keys(Array.prototype)`::==Пустой массив==, потому что встроенные методы неперечисляемы

Почему методы прототипа не засоряют `for...in` по массиву::Они ==неперечисляемы== по умолчанию

---

## length и name

Что считает свойство `length` функции::Число ==обязательных параметров== до первого со значением по умолчанию или остаточного

Что вернёт `((a, b = 1, ...c) => {}).length`::`1` — считается только `a`

Откуда берётся `name` анонимной функции::Выводится ==из контекста присваивания== операцией NamedEvaluation

Что вернёт `(() => {}).bind(null).name`::`'bound '` — с префиксом от связывания

## Хорошо известные символы

Перечислите менее очевидные хорошо известные символы, помимо iterator/hasInstance/toStringTag::`toPrimitive`, `species`, `isConcatSpreadable`, `asyncIterator`, `unscopables`

Что определяет `Symbol.unscopables`::Список имён свойств, которые конструкция `with` обязана ==игнорировать== при разрешении

Зачем понадобился `Symbol.unscopables`::Чтобы новые методы Array, добавленные после появления with, не ==ломали старый код== внутри with-блоков

## Инварианты и интринсики

Распространяются ли инварианты внутренних методов только на прокси::==Нет==, это общее требование ко всем объектам языка

Что гарантирует инвариант для замороженного объекта::Повторный вызов получения дескриптора собственного свойства ==обязан вернуть тот же результат==

Что такое нотация вида `%Array.prototype%`::Обозначение для ссылки на ==встроенный объект== безотносительно способа доступа из пользовательского кода

Что такое `%IteratorPrototype%`::Общий ==прототип всех встроенных итераторов==, недоступный напрямую по имени, но достижимый через цепочку прототипов
