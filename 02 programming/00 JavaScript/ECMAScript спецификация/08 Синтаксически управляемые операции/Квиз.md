> [!question] Что такое синтаксически управляемая операция?
> a) операция, которая выполняется только во время синтаксического анализа
> b) алгоритм, определение которого прикреплено к конкретному правилу грамматики, а не к единой универсальной функции
> c) операция, доступная только внутри регулярных выражений
> d) устаревший механизм, заменённый в последних редакциях спецификации
>> [!success]- Answer
>> b) алгоритм, определение которого прикреплено к конкретному правилу грамматики, а не к единой универсальной функции
>> Например, `Evaluation` не имеет одного большого определения — оно раскидано по всей спецификации, отдельно для каждой грамматической конструкции

> [!question] Что делает синтаксически управляемая операция `VarDeclaredNames`?
> a) собирает только имена, объявленные через let/const
> b) собирает имена var и объявлений функций, «прорастая» сквозь границы вложенных блоков
> c) удаляет все var-объявления из дерева разбора
> d) работает только на верхнем уровне модуля
>> [!success]- Answer
>> b) собирает имена var и объявлений функций, «прорастая» сквозь границы вложенных блоков
>> Это формальная причина, почему `var`, объявленный внутри `if`/`for`, доступен на уровне всей функции — hoisting

> [!question] Что выведет код?
> ```js
> function f() {
>   if (true) { var x = 1; let y = 2; }
>   console.log(x);
>   try { console.log(y); } catch (e) { console.log(e.constructor.name); }
> }
> f();
> ```
> a) `1` затем `2`
> b) `1` затем `ReferenceError`
> c) `undefined` затем `ReferenceError`
> d) выбросит ошибку сразу на первой строке
>> [!success]- Answer
>> b) `1` затем `ReferenceError`
>> `x` (var) зарегистрирован через `VarDeclaredNames` на уровне всей функции и доступен снаружи блока `if`; `y` (let) через `LexicallyDeclaredNames` остался только внутри блока

> [!question] Что произойдёт при выполнении следующего кода?
> ```js
> function f() {
>   if (false) { break этогоНеСуществует; }
> }
> ```
> a) функция выполнится без ошибок, потому что код внутри if (false) никогда не выполняется
> b) сама программа не запустится — SyntaxError обнаруживается на этапе разбора
> c) выбросится ReferenceError при вызове f()
> d) выбросится ReferenceError, но только если f() действительно вызвана
>> [!success]- Answer
>> б) сама программа не запустится — SyntaxError обнаруживается на этапе разбора
>> `ContainsUndefinedBreakTarget` — проверка статической семантики, срабатывающая во время разбора независимо от того, выполнится ли когда-нибудь эта ветка кода

> [!question] Является ли повторное использование одной и той же метки в одной области видимости (`outer: outer: for(;;) {}`) ошибкой?
>> [!success]- Answer
>> True
>> `ContainsDuplicateLabels` — тоже проверка статической семантики, обнаруживающая эту ошибку при разборе, как SyntaxError

> [!question] Какой общий принцип иллюстрируют неопределённые метки break/continue и дублирующиеся метки?
> a) статическая семантика проверяется во время разбора, независимо от того, выполнится ли код фактически
> b) JavaScript никогда не проверяет метки заранее
> c) это особенность только строгого режима
> d) это ошибки времени выполнения, а не разбора
>> [!success]- Answer
>> a) статическая семантика проверяется во время разбора, независимо от того, выполнится ли код фактически
>> Именно поэтому программа с такой ошибкой не запускается вообще, даже если проблемный код лежит в никогда не достижимой ветке

> [!question] Что выведет код?
> ```js
> const obj = { b: function() {} };
> const arr = [function() {}];
> console.log(obj.b.name, arr[0].name);
> ```
> a) `'b' ''`
> b) `'' ''`
> c) `'b' '0'`
> d) `'anonymous' 'anonymous'`
>> [!success]- Answer
>> a) `'b' ''`
>> `NamedEvaluation` вызывается для свойства объектного литерала (даёт имя `'b'`), но не для позиции элемента массива — там имя остаётся пустым

> [!question] Для каких грамматических позиций формально определена операция `NamedEvaluation`?
> a) для любого места, где функция становится значением
> b) для ограниченного списка конкретных позиций — присваивание переменной, свойство объектного литерала и подобные
> c) только для function-объявлений верхнего уровня
> d) только внутри классов
>> [!success]- Answer
>> b) для ограниченного списка конкретных позиций — присваивание переменной, свойство объектного литерала и подобные
>> Литерал массива в этот список не входит — поэтому у функции внутри `[fn]` `.name` остаётся пустой строкой

> [!question] Что выведет код?
> ```js
> let c;
> c = function() {};
> console.log(c.name);
> ```
> a) `''`
> b) `'c'`
> c) `undefined`
> d) выбросит ошибку
>> [!success]- Answer
>> b) `'c'`
>> Обычное присваивание уже существующей переменной тоже входит в список позиций, где срабатывает `NamedEvaluation`, не только объявление с инициализацией

> [!question] Что делает `PropName`, помимо статического анализа объектного литерала в общем случае?
>> [!success]- Answer
>> Помогает находить дублирующиеся `__proto__` в одном объектном литерале
>> Это единственный ключ объектного литерала, повторное использование которого запрещено в современном JS — остальные дублирующиеся ключи разрешены и просто перезаписывают друг друга

> [!question] Занимают ли объявления функций (`function foo() {}`) внутри блока (`if { function foo() {} }`) формально пограничное положение между var-подобным и let-подобным поведением?
>> [!success]- Answer
>> True
>> На верхнем уровне функции/скрипта они входят в VarDeclaredNames; внутри блока возникает нюанс легаси-совместимости из Annex B — разные движки исторически трактовали это по-разному

> [!question] Определена ли операция `Evaluation` одним большим алгоритмом в одном месте спецификации?
>> [!success]- Answer
>> False
>> Она раскидана по всей спецификации — отдельное определение для каждой грамматической конструкции рядом с описанием этой конструкции, а не единый switch на все случаи
