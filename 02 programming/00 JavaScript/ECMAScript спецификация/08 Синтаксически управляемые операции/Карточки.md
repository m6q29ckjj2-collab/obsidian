Что такое синтаксически управляемая операция::Алгоритм, определение которого прикреплено к ==конкретному правилу грамматики==, а не к единой универсальной функции

## VarDeclaredNames vs LexicallyDeclaredNames

Что делает операция `VarDeclaredNames`::Собирает имена `var` и объявлений функций, ==«прорастая» сквозь границы блоков== — на уровне всей функции

Что делает операция `LexicallyDeclaredNames`::Собирает имена `let`/`const`/`class`, ==останавливаясь на границе каждого блока==

Какая из двух операций — формальная причина hoisting `var` за пределы `if`/`for`::`VarDeclaredNames`

Какая из двух операций — формальная причина, почему `let` не покидает свой блок::`LexicallyDeclaredNames`

## Метки и статическая семантика

Является ли `break несуществующаяМетка;` внутри никогда не выполняемой ветки (`if (false) {...}`) ошибкой::==Да==, `SyntaxError` — обнаруживается при разборе, программа не запустится вообще

Является ли повторное использование одной и той же метки (`outer: outer: for(;;){}`) ошибкой::==Да==, `SyntaxError`, обнаруживается статически

Какой принцип иллюстрируют эти два случая::Статическая семантика проверяется ==во время разбора==, независимо от того, выполнится ли конкретный код фактически

## NamedEvaluation — вывод имени функции

Что выведет код
?
```js
const obj = { b: function() {} };
const arr = [function() {}];
console.log(obj.b.name, arr[0].name);
```
`'b' ''` — свойство объектного литерала попадает в позиции NamedEvaluation, а элемент массива — нет

Для каких грамматических позиций определена операция `NamedEvaluation`::Присваивание переменной, свойство объектного литерала — ==конкретный ограниченный список==, а не «любое место, где функция становится значением»
