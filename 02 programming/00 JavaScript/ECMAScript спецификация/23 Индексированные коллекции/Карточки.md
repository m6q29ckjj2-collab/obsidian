## Array — сортировка и поиск

Что выведет код
?
```js
console.log([10, 1, 2].sort());
```
`[1, 10, 2]` — без компаратора sort сравнивает элементы как строки, а не как числа

Как правильно отсортировать массив чисел::Передать явный ==компаратор== `(a, b) => a - b`

Гарантирует ли спецификация стабильность `Array.prototype.sort`::==Да, начиная с ES2019== — равные по компаратору элементы сохраняют исходный порядок

Найдёт ли `[NaN].indexOf(NaN)` элемент::==Нет==, вернёт -1 — `indexOf` использует строгое равенство, а `NaN === NaN` всегда false

Найдёт ли `[NaN].includes(NaN)` элемент::==Да==, вернёт true — `includes` использует SameValueZero, где NaN равен самому себе

## Array — дыры и создание

Что такое дыра в разреженном массиве `[1, , 3]`::Индекс, для которого у массива ==вообще нет собственного свойства== — это не то же самое, что значение `undefined`

Пропускает ли `forEach`/`map`/`filter` дыры в массиве, не вызывая колбэк::==Да==

Как `for...of` и spread-оператор обращаются с дырами::Читают их как обычный ==`undefined`==, не различая дыру и настоящее значение undefined

Во что превращает дыры `JSON.stringify`::В ==`null`==

Что создаёт `Array(3)`::Разреженный массив ==длины 3 без элементов== (одно числовое значение — особый случай конструктора)

Чем `Array.of(3)` отличается от `Array(3)`::`Array.of(3)` создаёт массив ==из одного элемента `[3]`==, всегда трактуя аргументы как элементы, без особого случая для одного числа

Что принимает `Array.from` в качестве первого аргумента::Любой ==итерируемый объект== (строка, Map, Set) или ==массивоподобный== объект с `.length`

## Array — новые неизменяющие методы

Что общего у имён методов `toSorted`, `toReversed`, `toSpliced`::Префикс `to` сигнализирует, что метод ==возвращает новый массив==, не мутируя исходный

Изменяет ли `arr.with(1, 99)` исходный массив::==Нет==, возвращает новый массив с заменённым элементом

## TypedArray — базовое устройство

Чем принципиально отличается `TypedArray` от обычного `Array`::Это ==вид (view) на сырую память `ArrayBuffer`==, а не независимая динамическая структура

Что произойдёт при записи по индексу за пределами длины типизированного массива::Операция ==молча игнорируется==, без исключения и без изменения длины

Может ли несколько разных типизированных представлений указывать на одну и ту же память::==Да==, запись через одно немедленно видна через другое

## TypedArray — переполнение и сортировка

Что произойдёт при записи значения 300 в `Uint8Array`::Значение =="обернётся"== по модулю: `300 % 256 = 44`

Чем `Uint8ClampedArray` отличается от остальных целочисленных типизированных массивов при переполнении::Вместо оборачивания оно ==обрезает== значение до границ диапазона (0 или 255) — создан для работы с пикселями

Что выведет код
?
```js
const ta = new Int32Array([10, 1, 2]);
ta.sort();
console.log(Array.from(ta));
```
`[1, 2, 10]` — у `%TypedArray%.prototype.sort` сортировка по умолчанию числовая, в отличие от обычного Array
