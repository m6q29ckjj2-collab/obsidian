> [!question] Что выведет код?
> ```js
> console.log([10, 1, 2].sort());
> ```
> a) `[1, 2, 10]`
> b) `[1, 10, 2]`
> c) `[10, 1, 2]`
> d) `[2, 1, 10]`
>> [!success]- Answer
>> b) `[1, 10, 2]`
>> Без явного компаратора `sort` сравнивает элементы как строки: `'10'` начинается с `'1'`, но короче, чем ждёт числовое сравнение — строковый порядок и числовой не совпадают

> [!question] Как правильно отсортировать массив чисел по возрастанию?
> a) `arr.sort()`
> b) `arr.sort((a, b) => a - b)`
> c) `arr.reverse().sort()`
> d) `Array.sort(arr)`
>> [!success]- Answer
>> b) `arr.sort((a, b) => a - b)`
>> Явный компаратор — единственный надёжный способ; без него используется строковое сравнение даже для чисел

> [!question] Гарантирует ли спецификация стабильность `Array.prototype.sort` (сохранение порядка равных элементов)?
>> [!success]- Answer
>> True
>> Начиная с ES2019 стабильность обязательна. До этого она не была гарантирована спецификацией

> [!question] Что выведет код?
> ```js
> console.log([NaN].indexOf(NaN), [NaN].includes(NaN));
> ```
> a) `-1 -1`
> b) `true true`
> c) `-1 true`
> d) `0 true`
>> [!success]- Answer
>> c) `-1 true`
>> `indexOf` сравнивает через строгое равенство (`NaN === NaN` всегда `false`), `includes` использует SameValueZero, где `NaN` считается равным самому себе

> [!question] Что такое «дыра» в разреженном массиве `[1, , 3]`?
> a) элемент со значением `undefined`
> b) элемент со значением `null`
> c) индекс, для которого у массива вообще нет собственного свойства
> d) элемент, помеченный как неперечисляемый
>> [!success]- Answer
>> c) индекс, для которого у массива вообще нет собственного свойства
>> Это отличается от настоящего `undefined`-значения — `1 in [1, , 3]` даёт `false`, а `1 in [1, undefined, 3]` дало бы `true`

> [!question] Что выведет код?
> ```js
> let count = 0;
> [1, , 3].forEach(() => count++);
> console.log(count);
> ```
> a) `3`
> b) `2`
> c) `1`
> d) `0`
>> [!success]- Answer
>> b) `2`
>> `forEach` пропускает дыры — колбэк не вызывается для отсутствующих индексов

> [!question] Что выведет код?
> ```js
> console.log([...[1, , 3]]);
> ```
> a) `[1, <1 empty item>, 3]`
> b) `[1, undefined, 3]`
> c) `[1, null, 3]`
> d) `[1, 3]`
>> [!success]- Answer
>> b) `[1, undefined, 3]`
>> Spread-оператор основан на итерации (`for...of`), которая читает значение по индексу через обычный доступ — для дыры это даёт `undefined`, в отличие от `forEach`/`map`, которые дыры пропускают

> [!question] Во что `JSON.stringify` превращает дыры разреженного массива?
> a) в `undefined`
> b) в `null`
> c) выбрасывает ошибку
> d) пропускает индекс полностью, сдвигая нумерацию
>> [!success]- Answer
>> б) в `null`
>> `JSON.stringify([1, , 3])` даёт `'[1,null,3]'` — формат JSON не умеет представлять дыры

> [!question] Что создаёт вызов `Array(3)` (с одним числовым аргументом)?
> a) массив `[3]`
> b) разреженный массив длины 3 без элементов
> c) выбросит `TypeError`
> d) массив `[0, 0, 0]`
>> [!success]- Answer
>> b) разреженный массив длины 3 без элементов
>> Это специальный случай конструктора `Array`: единственный числовой аргумент трактуется как длина, а не как элемент

> [!question] Чем `Array.of(3)` отличается от `Array(3)`?
> a) ничем, это синонимы
> b) `Array.of(3)` всегда создаёт массив из элементов-аргументов, то есть `[3]`, без особого случая для одного числа
> c) `Array.of(3)` создаёт массив длины 3
> d) `Array.of` работает только со строками
>> [!success]- Answer
>> b) `Array.of(3)` всегда создаёт массив из элементов-аргументов, то есть `[3]`, без особого случая для одного числа
>> `Array.of` придумали специально, чтобы обойти особый случай конструктора `Array` с одним числовым аргументом

> [!question] Может ли `Array.from` принять на вход объект без `Symbol.iterator`, но с числовым свойством `.length`?
>> [!success]- Answer
>> True
>> `Array.from` принимает и итерируемые объекты, и просто массивоподобные объекты (с `.length`, без итератора) — например, `{0: 'a', 1: 'b', length: 2}` или `arguments`

> [!question] Изменяет ли `arr.toSorted()` исходный массив `arr`?
>> [!success]- Answer
>> False
>> Методы с префиксом `to` (`toSorted`, `toReversed`, `toSpliced`, а также `with`) всегда возвращают новый массив и не трогают исходный — в отличие от `sort`/`reverse`/`splice`

> [!question] Что произойдёт при записи значения по индексу за пределами длины типизированного массива (`ta[100] = 5` при `ta.length === 3`)?
> a) выбросится `RangeError`
> b) массив автоматически расширится
> c) запись молча игнорируется, длина и содержимое не меняются
> d) выбросится `TypeError`
>> [!success]- Answer
>> c) запись молча игнорируется, длина и содержимое не меняются
>> Длина типизированного массива жёстко привязана к размеру буфера — специфицированное поведение внутреннего метода [[Set]] для integer-indexed экзотических объектов

> [!question] Что выведет код?
> ```js
> const ta = new Uint8Array(1);
> ta[0] = 300;
> console.log(ta[0]);
> ```
> a) `300`
> b) `255`
> c) `44`
> d) выбросит ошибку
>> [!success]- Answer
>> c) `44`
>> Обычные целочисленные типизированные массивы применяют модульную арифметику при переполнении: `300 % 256 = 44`

> [!question] Что выведет код?
> ```js
> const ta = new Uint8ClampedArray(1);
> ta[0] = 300;
> console.log(ta[0]);
> ```
> a) `44`
> b) `255`
> c) `300`
> d) `0`
>> [!success]- Answer
>> b) `255`
>> `Uint8ClampedArray` — единственный тип, который обрезает значение до границ диапазона вместо оборачивания. Создан специально для работы с цветовыми каналами пикселей

> [!question] Что выведет код?
> ```js
> const ta = new Int32Array([10, 1, 2]);
> ta.sort();
> console.log(Array.from(ta));
> ```
> a) `[1, 10, 2]` (строковый порядок, как у Array)
> b) `[1, 2, 10]` (числовой порядок)
> c) `[10, 1, 2]` (без изменений)
> d) выбросит ошибку
>> [!success]- Answer
>> b) `[1, 2, 10]` (числовой порядок)
>> У `%TypedArray%.prototype.sort` сортировка по умолчанию числовая — прямая противоположность поведению обычного `Array.prototype.sort` по умолчанию

> [!question] Могут ли несколько разных типизированных представлений (например, `Uint8Array` и `Uint32Array`) указывать на один и тот же `ArrayBuffer`, так что запись через одно видна через другое?
>> [!success]- Answer
>> True
>> Типизированный массив — это лишь способ интерпретировать байты буфера, а не независимая копия данных; несколько представлений могут разделять одну и ту же память
