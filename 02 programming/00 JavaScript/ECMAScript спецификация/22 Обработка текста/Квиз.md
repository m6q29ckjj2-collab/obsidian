> [!question] Что выведет код?
> ```js
> const s = 'abc';
> s.foo = 1;
> console.log(s.foo);
> ```
> a) `1`
> b) `undefined`
> c) выбросит `TypeError` всегда
> d) `'abc'`
>> [!success]- Answer
>> b) `undefined`
>> Строковый примитив временно оборачивается в объект-обёртку для вызова методов и присваивания свойств, но эта обёртка сразу отбрасывается — присвоенное свойство не сохраняется (в строгом режиме та же попытка выбросит `TypeError`)

> [!question] В каких единицах измеряется `String.prototype.length`?
> a) в символах Unicode (кодовых точках)
> b) в байтах UTF-8
> c) в 16-битных кодовых единицах UTF-16
> d) в графемных кластерах
>> [!success]- Answer
>> c) в 16-битных кодовых единицах UTF-16
>> Символы вне Basic Multilingual Plane (многие эмодзи, редкие иероглифы) кодируются суррогатной парой — двумя единицами на один настоящий символ

> [!question] Что выведет код?
> ```js
> console.log('😀'.length, [...'😀'].length);
> ```
> a) `1 1`
> b) `2 2`
> c) `2 1`
> d) `1 2`
>> [!success]- Answer
>> c) `2 1`
>> `.length` считает кодовые единицы UTF-16 (эмодзи — суррогатная пара, две единицы), а spread-оператор итерирует по кодовым точкам (один настоящий символ)

> [!question] Зачем нужен метод `String.prototype.normalize()`?
> a) чтобы удалить пробелы по краям строки
> b) чтобы привести разные последовательности кодовых точек, кодирующие один видимый символ, к единому виду
> c) чтобы преобразовать строку в нижний регистр
> d) чтобы проверить корректность UTF-16
>> [!success]- Answer
>> b) чтобы привести разные последовательности кодовых точек, кодирующие один видимый символ, к единому виду
>> Например, буква «é» может быть закодирована одной составной кодовой точкой или разложенной последовательностью «e + диакритический знак» — визуально одинаково, но `===` без нормализации даст `false`

> [!question] Что проверяет `String.prototype.isWellFormed()`?
>> [!success]- Answer
>> Что в строке нет одиночных суррогатов без пары
>> Такие «битые» строки не соответствуют ни одному настоящему символу Unicode и ломают конвертацию в UTF-8; `toWellFormed()` чинит их, заменяя на символ замены U+FFFD

> [!question] Оператор `<` при сравнении строк учитывает языковые правила (например, порядок букв конкретного алфавита)
>> [!success]- Answer
>> False
>> `<`/`>` сравнивают строки побайтово по числовому коду UTF-16. Для сравнения с учётом языка нужен `String.prototype.localeCompare`

> [!question] Что выведет код?
> ```js
> console.log('a' < 'A');
> ```
> a) `true`
> b) `false`
> c) `0`
> d) выбросит ошибку
>> [!success]- Answer
>> b) `false`
>> Строчная 'a' имеет код 97, заглавная 'A' — 65 в UTF-16. Сравнение чисто позиционное, без учёта алфавитного порядка на человеческом языке

> [!question] Объект `RegExp` с флагом `g` — это неизменяемое значение без внутреннего состояния
>> [!success]- Answer
>> False
>> У него есть изменяемое свойство `lastIndex`, которое запоминает позицию после последнего найденного совпадения — повторные вызовы `exec`/`test` на этом же объекте продолжают поиск оттуда, а не с начала строки

> [!question] Что выведет код?
> ```js
> const re = /x/g;
> console.log(re.test('xx'));
> console.log(re.test('xx'));
> console.log(re.test('xx'));
> ```
> a) `true true true`
> b) `true true false`
> c) `false false false`
> d) `true false true`
>> [!success]- Answer
>> b) `true true false`
>> Каждый вызов `test` с флагом `g` продолжает поиск с сохранённого `lastIndex`. После двух совпадений (`lastIndex` дошёл до конца строки) третий вызов не находит ничего и сбрасывает `lastIndex` в 0

> [!question] Чем флаг `y` (sticky) отличается от флага `g` (global)?
> a) ничем, это синонимы
> b) `y` требует, чтобы совпадение начиналось ровно с позиции `lastIndex`, и не ищет дальше при неудаче
> c) `y` работает только с одной группой захвата
> d) `y` игнорирует регистр символов
>> [!success]- Answer
>> b) `y` требует, чтобы совпадение начиналось ровно с позиции `lastIndex`, и не ищет дальше при неудаче
>> `g` при неудаче на текущей позиции продолжает искать дальше по строке; `y` сразу возвращает `null`, если совпадения нет точно в этой точке

> [!question] Как безопаснее всего избежать бага с переиспользованием одного и того же `RegExp` с флагом `g` между независимыми вызовами функции?
> a) никогда не использовать флаг `g`
> b) создавать новый объект регулярного выражения на каждый вызов (литералом внутри функции) или сбрасывать `lastIndex` вручную
> c) использовать `try/catch` вокруг каждого вызова
> d) это невозможно предотвратить
>> [!success]- Answer
>> b) создавать новый объект регулярного выражения на каждый вызов (литералом внутри функции) или сбрасывать `lastIndex` вручную
>> Литерал `/re/` внутри тела функции создаёт новый объект при каждом входе в функцию — состояние не переживает между вызовами

> [!question] Что произойдёт при вызове `'aaa'.matchAll(/a/)` — регулярное выражение без флага `g`?
> a) вернёт только первое совпадение
> b) выбросит `TypeError`
> c) вернёт пустой итератор
> d) автоматически добавит флаг `g`
>> [!success]- Answer
>> b) выбросит `TypeError`
>> Спецификация явно требует флаг `g` для `matchAll` и не пытается его домыслить

> [!question] Мутирует ли вызов `str.matchAll(regexp)` свойство `lastIndex` переданного объекта `regexp`?
>> [!success]- Answer
>> False
>> Возвращаемый итератор ведёт собственное состояние позиции поиска — в отличие от ручного цикла с `exec`, `matchAll` не изменяет `lastIndex` исходного объекта

> [!question] Что произойдёт при вызове `'aaa'.replaceAll(/a/, 'b')` — регулярное выражение без флага `g`?
> a) заменит только первое вхождение
> b) заменит все вхождения, как и ожидалось
> c) выбросит `TypeError`
> d) вернёт исходную строку без изменений
>> [!success]- Answer
>> c) выбросит `TypeError`
>> Осознанная защита от частой ошибки: без явного флага `g` в самом регулярном выражении спецификация не позволяет `replaceAll` работать — намерение «заменить всё» должно быть видно в коде

> [!question] Требуется ли флаг `g` для `'aaa'.replaceAll('a', 'b')`, где первый аргумент — обычная строка, а не regexp?
>> [!success]- Answer
>> False
>> Ограничение по флагу `g` касается только regexp-аргумента. Строковый первый аргумент ищется буквально и заменяет все вхождения без всяких флагов

> [!question] Что выведет код?
> ```js
> console.log('2024-01-15'.replace(/(\d+)-(\d+)-(\d+)/, '$3/$2/$1'));
> ```
> a) `'2024-01-15'`
> b) `'15/01/2024'`
> c) `'$3/$2/$1'`
> d) выбросит `SyntaxError`
>> [!success]- Answer
>> b) `'15/01/2024'`
>> `$N` в строке замены подставляет содержимое N-й группы захвата — так можно переставлять части найденного совпадения местами

> [!question] Как правильно вставить произвольный текст пользователя в замену `replace`, не рискуя, что он будет интерпретирован как спецподстановка `$`?
> a) экранировать все символы `$` в пользовательском тексте вручную
> b) передать вторым аргументом функцию вместо строки
> c) это невозможно, спецподстановки нельзя отключить
> d) использовать `replaceAll` вместо `replace`
>> [!success]- Answer
>> b) передать вторым аргументом функцию вместо строки
>> То, что возвращает функция-замена, вставляется буквально, без повторной обработки `$`-последовательностей — строковый аргумент, наоборот, всегда проходит через интерпретацию `$`

> [!question] Что выведет код?
> ```js
> console.log('a1b2c3'.split(/(\d)/));
> ```
> a) `['a', 'b', 'c', '']`
> b) `['a', '1', 'b', '2', 'c', '3', '']`
> c) `['a1', 'b2', 'c3']`
> d) выбросит `TypeError`
>> [!success]- Answer
>> b) `['a', '1', 'b', '2', 'c', '3', '']`
>> Группа захвата в регулярном выражении-разделителе попадает в итоговый массив вместе с фрагментами строки — без круглых скобок (`/\d/`) разделители в результат не включаются

> [!question] Через какие well-known symbols методы вроде `String.prototype.replace` или `.split` делегируют логику поиска объекту-аргументу?
> a) `Symbol.iterator`
> b) `Symbol.toPrimitive`
> c) `Symbol.replace`, `Symbol.split`, `Symbol.match` и другие символы того же семейства
> d) никак, логика всегда встроена напрямую в String.prototype
>> [!success]- Answer
>> c) `Symbol.replace`, `Symbol.split`, `Symbol.match` и другие символы того же семейства
>> Это открытый протокол: любой объект с нужным символьным методом может подставляться вместо настоящего `RegExp` в строковые методы поиска и замены
