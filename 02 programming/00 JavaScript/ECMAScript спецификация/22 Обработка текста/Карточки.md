## String — общее

Что происходит при вызове метода на строковом примитиве (`'abc'.toUpperCase()`)::Примитив временно ==оборачивается в объект-обёртку== (ToObject), метод вызывается на ней, обёртка тут же исчезает

Сохранится ли присваивание `'abc'.foo = 1`::==Нет==. Записывается свойство во временный объект-обёртку, которая сразу отбрасывается

В каких единицах измеряется `.length` у строки::В ==16-битных кодовых единицах UTF-16==, а не в «символах» в бытовом смысле

Что выведет код
?
```js
console.log('😀'.length, [...'😀'].length);
```
`2 1` — эмодзи занимает две кодовые единицы (суррогатную пару), но одну кодовую точку; spread итерирует по кодовым точкам

Чем отличаются `charCodeAt` и `codePointAt` на суррогатной паре::`charCodeAt` даёт код ==только одной половины== пары, `codePointAt` — код ==настоящего символа целиком==

## normalize / isWellFormed

Зачем нужен `String.prototype.normalize()`::Один видимый символ может быть закодирован ==разными последовательностями== кодовых точек (составная/разложенная форма); normalize приводит к единому виду для сравнения

Равны ли `'é'` (составная é) и `'e' + '́'` (разложенная) без нормализации::==Нет==, хотя выглядят одинаково при отображении

Что проверяет `String.prototype.isWellFormed()`::Что в строке ==нет одиночных суррогатов== без пары (не соответствуют ни одному настоящему символу Unicode)

Что делает `toWellFormed()` с одиночным суррогатом::Заменяет его на ==символ замены U+FFFD== («�»)

## localeCompare

Чем `localeCompare` отличается от операторов `<`/`>`::`<`/`>` сравнивают ==побайтово по коду UTF-16==, `localeCompare` — ==по правилам конкретного языка==

Что вернёт `'a' < 'A'`::==`false`== — код строчной 'a' (97) больше кода заглавной 'A' (65) в UTF-16

## RegExp — состояние lastIndex

Является ли объект `RegExp` с флагом `g` чистым (без состояния)::==Нет==. У него есть изменяемое свойство `lastIndex`, которое запоминает позицию после последнего совпадения

Что произойдёт при повторном вызове `exec`/`test` на одном и том же объекте `RegExp` с флагом `g`::Поиск продолжится ==с позиции `lastIndex`==, а не с начала строки

Что случится с `lastIndex`, когда `exec` с флагом `g` не находит совпадение::Он ==сбрасывается в 0==, а сам вызов возвращает `null`

Чем флаг `y` (sticky) отличается от `g`::`y` требует, чтобы совпадение начиналось ==ровно с позиции `lastIndex`==; при неудаче не ищет дальше по строке, сразу даёт `null`

Как избежать бага с переиспользованием `RegExp` с флагом `g` между независимыми вызовами::Создавать новый объект литералом на каждый вызов, либо явно сбрасывать `re.lastIndex = 0` перед использованием

## matchAll / replaceAll

Что произойдёт при вызове `'aaa'.matchAll(/a/)` без флага `g`::Выбросится ==`TypeError`== — matchAll требует глобальный флаг

Мутирует ли `matchAll` свойство `lastIndex` переданного регэкспа::==Нет==, у его внутреннего итератора собственное состояние поиска

Что произойдёт при вызове `'aaa'.replaceAll(/a/, 'b')` без флага `g`::Выбросится ==`TypeError`== — защита от типичной ошибки ожидания, что replaceAll заменит всё само по себе

Нужен ли флаг `g` для `replaceAll` со строковым (не regexp) первым аргументом::==Нет==, требование флага касается только regexp-аргумента

## Спецподстановки и split

Что делает `$1` в строке замены `replace`::Подставляет содержимое ==первой группы захвата==

Как вставить в замену произвольный текст пользователя, не боясь спецсимволов `$`::Передать вторым аргументом ==функцию== вместо строки — её возвращаемое значение вставляется буквально

Что выведет код
?
```js
console.log('a1b2'.split(/(\d)/));
```
`['a', '1', 'b', '2', '']` — группа захвата в регулярном выражении попадает в результат split вместе с фрагментами строки

## Символьные методы и делегирование

Через какие well-known symbols `String.prototype.replace`/`match`/`split` и другие делегируют логику поиска::`Symbol.match`, `Symbol.matchAll`, `Symbol.replace`, `Symbol.search`, `Symbol.split`

Может ли произвольный (не встроенный `RegExp`) объект подставляться в `String.prototype.replace` вместо регулярного выражения::==Да==, если он реализует соответствующий символьный метод (`[Symbol.replace]`)
