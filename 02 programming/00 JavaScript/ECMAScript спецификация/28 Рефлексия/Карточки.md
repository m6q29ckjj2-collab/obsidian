## Reflect — назначение

Чему соответствует каждая функция `Reflect`::Одному ==внутреннему методу== объекта из главы 10 (`[[Get]]`, `[[Set]]`, `[[Delete]]` и т.д.)

Чем `Reflect.deleteProperty(obj, key)` практически удобнее, чем `delete obj[key]`::Это ==обычная функция==, её можно передать в `.map()`/`.forEach()` или сохранить в переменную — синтаксическую конструкцию `delete` так использовать нельзя

Как `Reflect.set` сообщает о неудаче записи (например, в замороженный объект), в отличие от обычного присваивания в строгом режиме::Возвращает ==`false`==, вместо того чтобы бросить исключение

Что позволяет сделать `Reflect.construct(Ctor, args, newTarget)`, недостижимое через обычный `new`::Вызвать конструктор с ==произвольным `new.target`==, определяющим, чей `.prototype` получит созданный объект

Что выведет код
?
```js
class A {} class B {}
const obj = Reflect.construct(A, [], B);
console.log(obj instanceof A, obj instanceof B);
```
`false true` — прототип объекта взят от newTarget (B), а не от исходного конструктора (A)

## Proxy — базовый механизм

Что перехватывают ловушки (traps) объекта `handler` в `new Proxy(target, handler)`::Соответствующие ==внутренние методы== цели

Что происходит, если ловушка не определена в `handler`::Операция автоматически ==делегируется реальному внутреннему методу== цели

Чем обычно заканчивается реализация типичной ловушки Proxy::Вызовом соответствующей функции ==`Reflect`== для цели, чтобы сохранить стандартное поведение везде, кроме нужного изменения

## Инварианты Proxy

Может ли ловушка `get` вернуть любое значение для неконфигурируемого, доступного только для чтения свойства цели::==Нет== — движок проверяет инвариант и бросает `TypeError`, если возвращённое значение не совпадает с реальным

Может ли ловушка `has` скрыть неконфигурируемое свойство цели, вернув `false`::==Нет==, это тоже нарушение инварианта, приводящее к `TypeError`

Зачем нужны инварианты Proxy для неконфигурируемых свойств::Чтобы гарантия неконфигурируемости, данная через `Object.defineProperty`, ==не теряла смысл== в присутствии Proxy

## Proxy.revocable и применение

Что делает функция `revoke`, полученная от `Proxy.revocable`::==Навсегда деактивирует прокси== — любая последующая операция с ним выбрасывает `TypeError`

Для какой типичной задачи полезен `Proxy.revocable`::Передать объект недоверенному стороннему коду с возможностью ==полностью отрезать доступ== позже одним вызовом

Назовите три типичных практических применения Proxy::Логирование обращений, ==валидация при записи==, вычисляемые/виртуальные свойства, значения по умолчанию, неизменяемые представления
