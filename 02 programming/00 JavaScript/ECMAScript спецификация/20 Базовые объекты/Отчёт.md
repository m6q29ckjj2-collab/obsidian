# Глава 20 · Базовые объекты — отчёт

Пять объектов: [Object](https://262.ecma-international.org/#sec-object-objects), [Function](https://262.ecma-international.org/#sec-function-objects), [Boolean](https://262.ecma-international.org/#sec-boolean-objects), [Symbol](https://262.ecma-international.org/#sec-symbol-objects), [Error](https://262.ecma-international.org/#sec-error-objects). ## 20.1 Object — статические методы, которые часто путают

| Метод | Раздел | Отличие от похожего |
|---|---|---|
| [Object.freeze](https://262.ecma-international.org/#sec-object.freeze) | 20.1.2.6 | только верхний уровень, уже разбиралось в главе 7 |
| [Object.fromEntries](https://262.ecma-international.org/#sec-object.fromentries) | 20.1.2.7 | принимает любой перебираемый объект пар, не только массив |
| [Object.groupBy](https://262.ecma-international.org/#sec-object.groupby) | 20.1.2.13 | группирует в объект без прототипа, а не в обычный |
| [Object.hasOwn](https://262.ecma-international.org/#sec-object.hasown) | 20.1.2.14 | статический метод, работает с объектами без прототипа |
| [Object.is](https://262.ecma-international.org/#sec-object.is) | 20.1.2.15 | использует SameValue, а не SameValueZero |

```js
console.log(Object.groupBy([1, 2, 3, 4], n => n % 2 === 0 ? 'чёт' : 'нечёт'));
// [Object: null prototype] { нечёт: [1, 3], чёт: [2, 4] }
```

Незаметная деталь: `Object.fromEntries` работает с любым перебираемым источником пар, включая генератор — не обязательно с массивом или Map.

```js
function* pairs() { yield ['a', 1]; yield ['b', 2]; }
console.log(Object.fromEntries(pairs())); // { a: 1, b: 2 }
```

### __proto__ как аксессор, а не встроенное поведение объекта

[20.1.3.8 Object.prototype.__proto__](https://262.ecma-international.org/#sec-object.prototype.__proto__) описан как **аксессорное свойство** прототипа, а не встроенная особенность каждого объекта. Это значит: объект без `Object.prototype` в цепочке `__proto__` не имеет вовсе.

```js
const dict = Object.create(null);
console.log(dict.__proto__); // undefined — это обычное отсутствующее свойство, не null-прототип напрямую
console.log(Object.getPrototypeOf(dict)); // null — а вот это надёжный способ узнать прототип
```

`Object.prototype.toString` уже разбирался при обсуждении `Symbol.toStringTag` — стоит напомнить: это самый надёжный способ определить встроенный тип значения через границу realm, надёжнее `instanceof`.

```js
console.log(Object.prototype.toString.call([]), Object.prototype.toString.call(null), Object.prototype.toString.call(async () => {}));
// '[object Array]' '[object Null]' '[object AsyncFunction]'
```

## 20.2 Function

`Function.prototype.bind`, `call`, `apply` уже подробно разбирались в контексте связывания `this`. Менее очевидное: [Function.prototype.toString](https://262.ecma-international.org/#sec-function.prototype.tostring) обязан вернуть исходный текст функции **если он доступен**, а для встроенных функций — специальную заглушку.

```js
function real() { return 1; }
console.log(real.toString());        // 'function real() { return 1; }'
console.log(Math.max.toString());    // 'function max() { [native code] }'
console.log((() => {}).toString());  // '() => {}'
```

[The Function Constructor](https://262.ecma-international.org/#sec-function-constructor) — `new Function('a', 'b', 'return a + b')` — создаёт функцию, которая выполняется **в глобальной области**, а не в области вызова, ровно как косвенный `eval`.

## 20.3–20.4 Boolean и Symbol

Boolean — самый скромный из пяти: конструктор, `toString`, `valueOf`. Единственная тонкость уже разбиралась в главе 6: `new Boolean(false)` — объект, и он истинен в логическом контексте, несмотря на обёрнутое ложное значение.

Symbol содержит две функции, о которых легко забыть: [Symbol.for](https://262.ecma-international.org/#sec-symbol.for) и [Symbol.keyFor](https://262.ecma-international.org/#sec-symbol.keyfor) работают с глобальным реестром символов, отдельным от обычного создания через `Symbol()`.

```js
const a = Symbol.for('shared');
const b = Symbol.for('shared');
console.log(a === b, Symbol.keyFor(a), Symbol.keyFor(Symbol('local')));
// true 'shared' undefined
```

Реестр общий даже между разными реалмами (главa 9) — это одно из немногих мест, где границу изоляции реалмов можно пересечь намеренно.

## 20.5 Error

### Иерархия типов ошибок

[20.5.5 Native Error Types Used in This Standard](https://262.ecma-international.org/#sec-native-error-types-used-in-this-standard) перечисляет типы, которые сам движок бросает в определённых ситуациях: `TypeError`, `RangeError`, `ReferenceError`, `SyntaxError`, `EvalError` (практически не используется современными движками), `URIError`.

```js
console.log(new TypeError('x') instanceof Error); // true — вся иерархия под общим Error
```

### AggregateError

[20.5.7.1 The AggregateError Constructor](https://262.ecma-international.org/#sec-aggregate-error-constructor) — единственный тип ошибки, оборачивающий **несколько** причин одновременно, а не одну. Появился вместе с `Promise.any`.

```js
try { await Promise.any([Promise.reject(1), Promise.reject(2)]); }
catch (e) { console.log(e instanceof AggregateError, e.errors); } // true [1, 2]
```

### cause — не часть иерархии типов, а свойство экземпляра

Опция `cause` в конструкторе `Error` не образует новый тип, а лишь заполняет [20.5.4 Properties of Error Instances](https://262.ecma-international.org/#sec-properties-of-error-instances) дополнительным полем. Уже разбиралась ранее — стоит подчеркнуть, что это стандартный способ сохранить исходную причину при перевыбрасывании, появившийся сравнительно недавно.

```js
try { JSON.parse('{битый'); }
catch (e) { const wrapped = new Error('конфиг повреждён', { cause: e }); console.log(wrapped.cause.constructor.name); }
// SyntaxError
```

### stack — не в стандарте

`Error.prototype.stack` **не описано** в этой главе и вообще нигде в ECMA-262. Это де-факто конвенция, реализованная всеми движками по-своему.

## Итог

> [!success] Что забирать
> - `Object.groupBy` создаёт результат без прототипа, `Object.fromEntries` принимает любой перебираемый источник пар
> - `__proto__` — аксессорное свойство Object.prototype, а не встроенная особенность каждого объекта; у объекта без прототипа его нет
> - `Object.prototype.toString.call` — самый надёжный способ определить встроенный тип значения через границу realm
> - `Function.prototype.toString` возвращает исходный текст, если он доступен, и специальную заглушку для встроенных функций
> - Function Constructor выполняет код в глобальной области, как косвенный eval
> - `Symbol.for`/`Symbol.keyFor` работают с глобальным реестром, отдельным от обычного `Symbol()`, и пересекают границу realm
> - AggregateError — единственный тип, оборачивающий несколько причин одновременно
> - `cause` — свойство экземпляра, а не отдельный тип ошибки
> - `error.stack` не описано стандартом вовсе, это конвенция движков
