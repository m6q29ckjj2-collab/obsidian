> [!question] Что выведет код?
> ```js
> const grouped = Object.groupBy([1, 2, 3, 4], n => n % 2 === 0 ? 'a' : 'b');
> console.log(Object.getPrototypeOf(grouped), typeof grouped.hasOwnProperty);
> ```
> a) `Object.prototype 'function'`
> b) `null 'undefined'`
> c) `null 'function'`
> d) `Object.prototype 'undefined'`
>> [!success]- Answer
>> b) `null 'undefined'`
>> Результат groupBy создаётся без прототипа, поэтому у него нет унаследованных методов — это защищает объект-словарь от коллизий с именами данных

> [!question] Что выведет код?
> ```js
> function* pairs() { yield ['a', 1]; yield ['b', 2]; }
> console.log(Object.fromEntries(pairs()));
> ```
> a) выбросит `TypeError`, нужен именно массив
> b) `{ a: 1, b: 2 }`
> c) `{}`
> d) `[['a',1],['b',2]]`
>> [!success]- Answer
>> b) `{ a: 1, b: 2 }`
>> Object.fromEntries принимает любой перебираемый источник пар, включая генератор, а не только массив

> [!question] Что произойдёт?
> ```js
> const dict = Object.create(null);
> dict.key = 1;
> dict.hasOwnProperty('key');
> ```
> a) вернёт `true`
> b) вернёт `false`
> c) выбросит `TypeError`, метода не существует
> d) вернёт `undefined`
>> [!success]- Answer
>> c) выбросит `TypeError`, метода не существует
>> hasOwnProperty унаследован от Object.prototype, а объект создан без прототипа. Object.hasOwn(dict, 'key') сработал бы без проблем

> [!question] Что выведет код?
> ```js
> console.log(Object.is(NaN, NaN), NaN === NaN, Object.is(0, -0), 0 === -0);
> ```
> a) `false false true true`
> b) `true false false true`
> c) `true true false false`
> d) `false true true false`
>> [!success]- Answer
>> b) `true false false true`
>> Object.is использует SameValue: считает NaN равным себе (в отличие от строгого равенства) и различает знак нуля (тоже в отличие от строгого равенства)

> [!question] Что выведет код?
> ```js
> const dict = Object.create(null);
> console.log(dict.__proto__, Object.getPrototypeOf(dict));
> ```
> a) `null null`
> b) `undefined null`
> c) `undefined undefined`
> d) `null undefined`
>> [!success]- Answer
>> b) `undefined null`
>> __proto__ — унаследованный аксессор с Object.prototype, у объекта без прототипа его попросту нет. Object.getPrototypeOf работает надёжно всегда

> [!question] Является ли `__proto__` встроенной особенностью каждого объекта JavaScript?
>> [!success]- Answer
>> False
>> Это обычное свойство-аксессор, унаследованное от Object.prototype. У объекта без этого прототипа в цепочке свойства __proto__ не существует

> [!question] Что выведет код?
> ```js
> console.log(Object.prototype.toString.call(null), Object.prototype.toString.call(async () => {}));
> ```
> a) `'[object Object]' '[object Function]'`
> b) `'[object Null]' '[object AsyncFunction]'`
> c) выбросит `TypeError` на null
> d) `'null' 'function'`
>> [!success]- Answer
>> b) `'[object Null]' '[object AsyncFunction]'`
>> Этот метод — самый надёжный способ определить встроенный тип значения, работает даже для null и через границу realm, где instanceof может ошибаться

> [!question] Что выведет код?
> ```js
> function real() { return 1; }
> console.log(real.toString(), Math.max.toString());
> ```
> a) одинаковый текст для обеих функций
> b) исходный код для real, заглушку [native code] для Math.max
> c) заглушку для обеих
> d) выбросит TypeError на Math.max
>> [!success]- Answer
>> b) исходный код для real, заглушку [native code] для Math.max
>> toString возвращает точный исходный текст, если он доступен движку; у встроенных функций исходного текста просто нет

> [!question] В какой области видимости выполняется тело функции, созданной через `new Function(...)`?
> a) в области того места, где написан new Function
> b) в глобальной области, как косвенный eval
> c) в изолированной области без доступа к глобальным объектам
> d) зависит от режима строгости
>> [!success]- Answer
>> b) в глобальной области, как косвенный eval
>> Функция не видит окружающее замыкание, даже если создана прямо внутри другой функции

> [!question] Что выведет код?
> ```js
> function outer() {
>   const secret = 'локальная';
>   const fn = new Function('return typeof secret');
>   return fn();
> }
> console.log(outer());
> ```
> a) `'string'`
> b) `'undefined'`
> c) выбросит `ReferenceError`
> d) `'локальная'`
>> [!success]- Answer
>> b) `'undefined'`
>> Функция, созданная через конструктор Function, выполняется в глобальной области и не имеет доступа к замыканию места создания

> [!question] Что произойдёт?
> ```js
> const wrapped = new Boolean(false);
> if (wrapped) { console.log('выполнится'); } else { console.log('не выполнится'); }
> ```
> a) выведет `'выполнится'`
> b) выведет `'не выполнится'`
> c) выбросит `TypeError`
> d) зависит от режима строгости
>> [!success]- Answer
>> a) выведет `'выполнится'`
>> new Boolean(false) — объект, а любой объект истинен в условном контексте, независимо от обёрнутого значения

> [!question] Что выведет код?
> ```js
> console.log(Symbol('id') === Symbol('id'), Symbol.for('key') === Symbol.for('key'));
> ```
> a) `true true`
> b) `false false`
> c) `false true`
> d) `true false`
>> [!success]- Answer
>> c) `false true`
>> Обычный Symbol() всегда создаёт уникальное значение. Symbol.for берёт символ из глобального реестра по ключу и переиспользует его при повторных вызовах

> [!question] Общий ли глобальный реестр символов между разными realm (например, разными iframe одной страницы)?
>> [!success]- Answer
>> True
>> Это единственный штатный способ пересечь границу изоляции realm — обычный Symbol(), созданный в одном realm, никогда не будет строго равен символу из другого

> [!question] Наследуются ли `TypeError`, `RangeError` и `ReferenceError` от общего `Error`?
>> [!success]- Answer
>> True
>> Поэтому catch без уточнения типа перехватывает любую из них; для различения нужна явная проверка через instanceof

> [!question] Для решения какой задачи специально придуман `AggregateError`?
> a) для группировки логов по уровню важности
> b) чтобы сообщить сразу о нескольких причинах отказа, используется в Promise.any
> c) для замены обычного Error во всех случаях
> d) для сериализации ошибок в JSON
>> [!success]- Answer
>> b) чтобы сообщить сразу о нескольких причинах отказа, используется в Promise.any
>> Если все переданные промисы отклонились, нужен способ передать все причины разом, а не только первую

> [!question] Что делает опция `cause` в конструкторе Error?
> ```js
> try { JSON.parse('{битый'); }
> catch (e) { throw new Error('конфиг повреждён', { cause: e }); }
> ```
> a) заменяет сообщение об ошибке
> b) создаёт новый тип ошибки
> c) сохраняет исходную ошибку как свойство нового объекта
> d) отменяет исходное исключение
>> [!success]- Answer
>> c) сохраняет исходную ошибку как свойство нового объекта
>> Это не отдельный тип ошибки, а обычное свойство cause на экземпляре — стандартный способ не терять техническую причину при перевыбрасывании

> [!question] Описано ли свойство `error.stack` в тексте ECMA-262?
>> [!success]- Answer
>> False
>> Это соглашение, реализованное всеми движками по-своему: разный формат строк, разное число кадров, разное поведение с асинхронным кодом
