## Языковые типы

Сколько языковых типов определяет спецификация::==Восемь==: Undefined, Null, Boolean, String, Symbol, Number, BigInt, Object

Совпадает ли список языковых типов с результатами оператора проверки типа
?
==Нет==. Для пустой ссылки возвращается название объектного типа, а для функций — отдельное значение, которого в списке типов нет.

Как спецификация определяет строку::Конечная упорядоченная последовательность ==16-битных беззнаковых целых==, не обязательно корректный UTF-16

Почему обычные числа и числа произвольной точности нельзя смешивать в арифметике::Это ==разные типы с разными наборами операций==, определённых в спецификации отдельно, а не разные представления одного типа

Разрешено ли сравнение чисел разных числовых типов::Да, сравнение и нестрогое равенство работают. Запрещена именно арифметика

Через что спецификация определяет объект::Через набор ==внутренних методов==, а не через структуру «ключ-значение»

Сколько внутренних методов обязательны для любого объекта::==Одиннадцать==. У вызываемых добавляется двенадцатый, у конструкторов тринадцатый

Какой объект называется обычным::Тот, у которого ==все== внутренние методы имеют поведение по умолчанию

Что делает объект экзотическим::Переопределение хотя бы одного внутреннего метода

Приведите пример экзотического поведения массива
?
Определение свойства длины связано с индексами: уменьшение длины удаляет элементы.
```js
const a = [1,2,3];
Object.defineProperty(a, 'length', { value: 1 }); // [1]
```

Сколько видов свойств существует::==Два==: с данными и с аксессорами. Совместить их нельзя

## Служебные типы

Чем служебные типы отличаются от языковых::Они существуют ==только в тексте стандарта==; значение такого типа нельзя положить в переменную

Назовите служебные типы::Enum, List и Record, Set и Relation, Completion Record, Reference Record, Property Descriptor, Environment Record, Abstract Closure, Data Block, PrivateElement, Private Name

Что даёт вычисление выражения обращения к свойству::Не функцию и не значение, а ==Reference Record== с полями базы, имени свойства и значения для получателя

Из-за чего «теряется получатель» при вызове::Любая операция, ==извлекающая из ссылки значение==, стирает базу: запятая, присваивание, логические и тернарный операторы

Почему скобки вокруг обращения к свойству базу НЕ теряют::Они сохраняют структуру ссылки целиком, значение из неё не извлекается

Какие умолчания атрибутов при обычном присваивании::Все ==истинны==

Какие умолчания при определении свойства без явных флагов::Все ==ложны==. Свойство читается, но невидимо для перечисления, сериализации и копирования

Для чего нужен тип абстрактного замыкания::Чтобы описать функцию ==внутри алгоритма==, не создавая объект языка. Так описаны внутренние обработчики промисов

Определено ли в спецификации понятие «замыкание»::==Нет==. Оно получается из того, что функция хранит ссылку на окружение, а окружение — ссылку на внешнее

## Порядок ключей

Гарантирован ли порядок собственных ключей объекта::==Да==

Каков этот порядок::Целочисленные индексы по ==возрастанию==, затем остальные строки в порядке добавления, затем символы в порядке добавления

Почему ключ с ведущим нулём не попадает в первую группу::Он ==не является каноническим индексом==: строка не совпадает со своим числовым представлением
