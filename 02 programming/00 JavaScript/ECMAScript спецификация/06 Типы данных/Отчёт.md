# Глава 6 · Типы данных и значения — отчёт

> [!info] Раздел спецификации
> [6 ECMAScript Data Types and Values](https://262.ecma-international.org/#sec-ecmascript-data-types-and-values)
> Карточки → [[Карточки]] · квиз → [[Квиз]] · карта → [[00 Карта]]

Глава отвечает на вопрос «над чем работают алгоритмы». Ключевое здесь — разделение на два мира: типы, которые видит программист, и типы, существующие только в тексте стандарта.

---

## 6.1 Типы языка

[Языковых типов](https://262.ecma-international.org/#sec-ecmascript-language-types) ровно восемь. Их значения может хранить переменная.

| Тип | Раздел | Особенность |
|---|---|---|
| Undefined | [6.1.1](https://262.ecma-international.org/#sec-ecmascript-language-types-undefined-type) | ровно одно значение |
| Null | [6.1.2](https://262.ecma-international.org/#sec-ecmascript-language-types-null-type) | ровно одно значение |
| Boolean | [6.1.3](https://262.ecma-international.org/#sec-ecmascript-language-types-boolean-type) | два значения |
| String | [6.1.4](https://262.ecma-international.org/#sec-ecmascript-language-types-string-type) | последовательность 16-битных единиц |
| Symbol | [6.1.5](https://262.ecma-international.org/#sec-ecmascript-language-types-symbol-type) | уникальные неперечисляемые ключи |
| Number | [6.1.6.1](https://262.ecma-international.org/#sec-ecmascript-language-types-number-type) | двойная точность по стандарту чисел |
| BigInt | [6.1.6.2](https://262.ecma-international.org/#sec-ecmascript-language-types-bigint-type) | целые произвольной точности |
| Object | [6.1.7](https://262.ecma-international.org/#sec-object-type) | набор свойств и внутренних методов |

> [!warning] Восемь типов, но семь результатов проверки типа
> Оператор проверки типа не является отражением этой таблицы. Для пустой ссылки он возвращает название объектного типа, а для функций — отдельное значение, которого в таблице нет вовсе.
> ```js
> console.log(typeof null, typeof function () {});
> // object function
> ```

### Строка

[6.1.4](https://262.ecma-international.org/#sec-ecmascript-language-types-string-type) определяет строку как конечную упорядоченную последовательность 16-битных беззнаковых целых. Не символов и **не обязательно корректный UTF-16**.

```js
const lone = '\uD800';
console.log(lone.length, lone.isWellFormed()); // 1 false
```

### Числовые типы

[6.1.6](https://262.ecma-international.org/#sec-numeric-types) объединяет два типа под общим понятием. У каждого свой набор операций, определённых в спецификации явно: сложение, сравнение, побитовые операции описаны отдельно для обычных чисел и отдельно для произвольной точности.

Смешивать их в арифметике нельзя именно потому, что это разные наборы операций, а не разные представления одного типа.

```js
console.log(1n + 1n, 1n < 2, 1n == 1);
try { eval('1n + 1'); } catch (e) { console.log(e.constructor.name); }
// 2n true true
// TypeError
```

### Объект

[6.1.7](https://262.ecma-international.org/#sec-object-type) — самый важный подраздел главы. Объект определяется не как «набор пар ключ-значение», а через **внутренние методы**.

Обязательных методов одиннадцать: получение и смена прототипа, проверка и запрет расширяемости, получение дескриптора, определение свойства, проверка наличия, чтение, запись, удаление и перечисление собственных ключей. У вызываемых объектов добавляется вызов, у конструкторов — конструирование.

Объект называется **обычным**, если все методы реализованы поведением по умолчанию, и **экзотическим**, если хотя бы один переопределён.

```js
const arr = [1, 2, 3];
Object.defineProperty(arr, 'length', { value: 1 });
console.log(arr); // [1] — экзотическое поведение: длина связана с индексами
```

Здесь же вводится различие двух видов свойств: с данными и с аксессорами. Совместить их нельзя.

```js
const o = { get computed() { return 42; } };
const d = Object.getOwnPropertyDescriptor(o, 'computed');
console.log('value' in d, 'get' in d); // false true
```

## 6.2 Служебные типы

[Служебные типы](https://262.ecma-international.org/#sec-ecmascript-specification-types) не существуют во время выполнения — это инструменты описания. Значение такого типа нельзя положить в переменную.

| Тип | Раздел | Зачем нужен |
|---|---|---|
| Enum | [6.2.1](https://262.ecma-international.org/#sec-enum-specification-type) | именованные константы вроде видов завершения |
| List и Record | [6.2.2](https://262.ecma-international.org/#sec-list-and-record-specification-type) | упорядоченные наборы и структуры с полями |
| Set и Relation | [6.2.3](https://262.ecma-international.org/#sec-set-and-relation-specification-type) | нужны модели памяти |
| Completion Record | [6.2.4](https://262.ecma-international.org/#sec-completion-record-specification-type) | результат любого шага алгоритма |
| Reference Record | [6.2.5](https://262.ecma-international.org/#sec-reference-record-specification-type) | незавершённое обращение к свойству или имени |
| Property Descriptor | [6.2.6](https://262.ecma-international.org/#sec-property-descriptor-specification-type) | атрибуты свойства |
| Environment Record | [6.2.7](https://262.ecma-international.org/#sec-lexical-environment-and-environment-record-specification-types) | области видимости |
| Abstract Closure | [6.2.8](https://262.ecma-international.org/#sec-abstract-closure) | функция, определённая внутри алгоритма |
| Data Block | [6.2.9](https://262.ecma-international.org/#sec-data-blocks) | последовательность байтов для буферов |
| PrivateElement | [6.2.10](https://262.ecma-international.org/#sec-privateelement-specification-type) | приватные поля и методы |
| Private Name | [6.2.12](https://262.ecma-international.org/#sec-private-names) | идентичность приватного имени |

### Reference Record — объяснение «потерь получателя»

[6.2.5](https://262.ecma-international.org/#sec-reference-record-specification-type) — структура с полями «база», «имя свойства» и «значение для получателя». Вычисление выражения `obj.method` даёт **не функцию**, а такую запись.

Отсюда единое объяснение всех случаев, где получатель «теряется»: любая операция, извлекающая из ссылки значение, стирает базу.

```js
const obj = { f() { return this; } };
console.log(obj.f() === obj);        // true  — база сохранена
console.log((obj.f)() === obj);      // true  — скобки ссылку не разрушают
console.log((0, obj.f)() === obj);   // false — запятая вернула значение
console.log((obj.f || obj.f)() === obj); // false — то же самое
```

Приём с запятой не курьёз: так намеренно сбрасывают базу вызова минификаторы.

### Property Descriptor

[6.2.6](https://262.ecma-international.org/#sec-property-descriptor-specification-type) описывает атрибуты. Умолчания зависят от способа создания свойства, и это регулярный источник багов.

```js
const a = {}; a.x = 1;                                   // все атрибуты истинны
const b = {}; Object.defineProperty(b, 'x', { value: 1 }); // все ложны

console.log(Object.keys(a), Object.keys(b));       // ['x'] []
console.log(JSON.stringify(b), { ...b });          // '{}' {}
```

### Environment Record

[6.2.7](https://262.ecma-international.org/#sec-lexical-environment-and-environment-record-specification-types) вводит записи окружения — механизм областей видимости. Подробности разбираются в главе 9, здесь только объявляется сам тип и указатель на внешнюю запись.

Замыкание в спецификации не определено как отдельное понятие: оно получается из того, что функция хранит ссылку на окружение, а у окружения есть ссылка на внешнее.

### Abstract Closure

[6.2.8](https://262.ecma-international.org/#sec-abstract-closure) — способ описать функцию внутри алгоритма, не создавая объект языка. Так описаны, например, внутренние обработчики промисов: они существуют, но из кода их не достать.

## Порядок ключей объекта

Формально это часть поведения обычных объектов из главы 10, но вопрос возникает именно здесь. Порядок **гарантирован**:

1. Целочисленные индексы по возрастанию числового значения
2. Остальные строковые ключи в порядке добавления
3. Символы в порядке добавления

```js
const sym = Symbol('s');
console.log(Reflect.ownKeys({ b: 1, 2: 2, a: 3, 1: 4, [sym]: 5, '01': 6 }).map(String));
// ['1','2','b','a','01','Symbol(s)']
```

Ключ с ведущим нулём каноническим индексом не считается и попадает во вторую группу.

## Итог

> [!success] Что забирать
> - Языковых типов восемь, но проверка типа не отражает эту таблицу: пустая ссылка даёт название объектного типа, функции — отдельное значение
> - Строка определена как последовательность 16-битных единиц и не обязана быть корректным UTF-16
> - Обычные числа и числа произвольной точности — разные типы с разными наборами операций, потому арифметика их и не смешивает
> - Объект определяется через одиннадцать внутренних методов; переопределение хотя бы одного делает его экзотическим
> - Свойство бывает ровно двух видов: с данными или с аксессорами
> - Служебные типы существуют только в тексте стандарта; значение такого типа нельзя положить в переменную
> - Reference Record даёт единое объяснение всех «потерь получателя»: базу стирает извлечение значения из ссылки
> - Умолчания атрибутов при определении свойства противоположны умолчаниям при обычном присваивании
> - Порядок собственных ключей объекта зафиксирован стандартом
