> [!question] Сколько языковых типов определяет спецификация?
> a) шесть
> b) семь
> c) восемь
> d) девять
>> [!success]- Answer
>> c) восемь
>> Неопределённое значение, пустая ссылка, логический, строка, символ, обычное число, число произвольной точности и объект

> [!question] Что выведет код?
> ```js
> console.log(typeof null, typeof function () {});
> ```
> a) `null function`
> b) `object function`
> c) `object object`
> d) `null object`
>> [!success]- Answer
>> b) `object function`
>> Результаты оператора проверки типа не отражают таблицу языковых типов: для пустой ссылки возвращается название объектного типа, а для функций — отдельное значение

> [!question] Как спецификация определяет тип строки?
> a) последовательность символов Unicode
> b) последовательность 16-битных беззнаковых целых
> c) массив байтов в кодировке UTF-8
> d) последовательность code point
>> [!success]- Answer
>> b) последовательность 16-битных беззнаковых целых
>> Требования корректности UTF-16 в определении нет, поэтому непарный суррогат — легальная строка

> [!question] Что выведет код?
> ```js
> const lone = '\uD800';
> console.log(lone.length, lone.isWellFormed());
> ```
> a) `1 true`
> b) `1 false`
> c) `2 false`
> d) `0 false`
>> [!success]- Answer
>> b) `1 false`
>> Одна 16-битная единица, но корректным UTF-16 такая строка не является

> [!question] Почему числа разных числовых типов нельзя складывать?
> a) это разные представления одного типа
> b) это разные типы с раздельно определёнными наборами операций
> c) сложение для них не определено вовсе
> d) мешает потеря точности
>> [!success]- Answer
>> b) это разные типы с раздельно определёнными наборами операций
>> Сравнение и нестрогое равенство при этом разрешены — запрещена именно арифметика

> [!question] Через что спецификация определяет объект?
> a) через набор пар ключ-значение
> b) через набор внутренних методов
> c) через прототипную цепочку
> d) через дескрипторы свойств
>> [!success]- Answer
>> b) через набор внутренних методов
>> Обязательных одиннадцать, у вызываемых объектов добавляется двенадцатый, у конструкторов тринадцатый

> [!question] Что делает объект экзотическим?
> a) наличие символьных ключей
> b) переопределение хотя бы одного внутреннего метода
> c) отсутствие прототипа
> d) заморозка
>> [!success]- Answer
>> b) переопределение хотя бы одного внутреннего метода
>> Массивы, прокси, объект аргументов в нестрогом режиме, обёртки строк, пространства имён модулей

> [!question] Что выведет код?
> ```js
> const arr = [1, 2, 3];
> Object.defineProperty(arr, 'length', { value: 1 });
> console.log(arr);
> ```
> a) `[1, 2, 3]`
> b) `[1]`
> c) выбросит `TypeError`
> d) `[]`
>> [!success]- Answer
>> b) `[1]`
>> Экзотическое поведение массива: определение длины связано с индексами и удаляет лишние элементы

> [!question] Что выведет код?
> ```js
> const o = { get computed() { return 42; } };
> const d = Object.getOwnPropertyDescriptor(o, 'computed');
> console.log('value' in d, 'get' in d);
> ```
> a) `true true`
> b) `false true`
> c) `true false`
> d) `false false`
>> [!success]- Answer
>> b) `false true`
>> Свойство бывает ровно двух видов, и совместить их нельзя: у аксессорного нет поля значения

> [!question] Чем служебные типы отличаются от языковых?
> a) они медленнее
> b) они существуют только в тексте стандарта
> c) они доступны только в строгом режиме
> d) различий нет
>> [!success]- Answer
>> b) они существуют только в тексте стандарта
>> Значение служебного типа нельзя положить в переменную — это инструмент описания

> [!question] Что даёт вычисление выражения обращения к свойству?
> a) сразу значение свойства
> b) структуру с базой, именем свойства и значением для получателя
> c) функцию-обёртку
> d) дескриптор свойства
>> [!success]- Answer
>> b) структуру с базой, именем свойства и значением для получателя
>> Из этой структуры операция вызова и берёт получателя

> [!question] Что выведет код?
> ```js
> const obj = { f() { return this; } };
> console.log(obj.f() === obj, (obj.f)() === obj, (0, obj.f)() === obj);
> ```
> a) `true true true`
> b) `true true false`
> c) `true false false`
> d) `false false false`
>> [!success]- Answer
>> b) `true true false`
>> Скобки сохраняют структуру ссылки, а оператор запятая извлекает из неё значение и стирает базу

> [!question] Что выведет код?
> ```js
> const a = {}; a.x = 1;
> const b = {}; Object.defineProperty(b, 'x', { value: 1 });
> console.log(Object.keys(a), Object.keys(b), JSON.stringify(b));
> ```
> a) `['x'] ['x'] '{"x":1}'`
> b) `['x'] [] '{}'`
> c) `[] [] '{}'`
> d) `['x'] ['x'] '{}'`
>> [!success]- Answer
>> b) `['x'] [] '{}'`
>> Умолчания атрибутов при определении свойства противоположны умолчаниям при обычном присваивании

> [!question] Зачем нужен служебный тип абстрактного замыкания?
> a) для оптимизации вызовов
> b) чтобы описать функцию внутри алгоритма без создания объекта языка
> c) для реализации стрелочных функций
> d) для описания замыканий в пользовательском коде
>> [!success]- Answer
>> b) чтобы описать функцию внутри алгоритма без создания объекта языка
>> Так описаны, например, внутренние обработчики промисов: они существуют, но из кода их не достать

> [!question] Что вернёт вызов?
> ```js
> const sym = Symbol('s');
> console.log(Reflect.ownKeys({ b: 1, 2: 2, a: 3, 1: 4, [sym]: 5, '01': 6 }).map(String).join(','));
> ```
> a) `b,2,a,1,01,Symbol(s)`
> b) `1,2,b,a,01,Symbol(s)`
> c) `1,2,01,b,a,Symbol(s)`
> d) порядок не определён
>> [!success]- Answer
>> b) `1,2,b,a,01,Symbol(s)`
>> Целые индексы по возрастанию, затем строки в порядке добавления, затем символы. Ключ с ведущим нулём каноническим индексом не считается

> [!question] Определено ли в спецификации понятие «замыкание»?
>> [!success]- Answer
>> False
>> Есть запись окружения со ссылкой на внешнюю и слот функции, хранящий окружение. Замыкание получается как следствие этих двух механизмов
