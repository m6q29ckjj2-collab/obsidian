## Опциональная цепочка

Обрывает ли `?.` только следующий шаг цепочки или всю оставшуюся::==Всю оставшуюся цепочку==. Продукция единая, не набор независимых проверок

Что выведет код
?
```js
const obj = { a: { b: null } };
obj?.a?.b?.c.d.e;
```
`undefined`, а не `TypeError`. Часть `.c.d.e` идёт без вопросов, но вся цепочка помечена опциональной с первого `?.`

Вычисляется ли правая часть опциональной цепочки, если левая оборвала выполнение::==Нет==, физически не вычисляется — это не просто игнорирование результата

## Обновляющие операторы

Что фиксируется первым при `arr[i++] = arr[i++] + 1` — ссылка для записи или правая часть::==Ссылка для записи== (левая часть), затем вычисляется правая

Что выведет код
?
```js
let i = 0;
const arr = [10, 20, 30];
arr[i++] = arr[i++] + 1;
```
`[21, 20, 30]`, `i` равно `2`. Левый `i++` фиксирует индекс 0, правый берёт индекс 1, результат 21 записывается в индекс 0.

## Унарные операторы

Что вернёт `delete` для значения, не являющегося ссылкой::==`true`==. Удалять нечего, поэтому всегда успех

От чего зависит результат `delete` для неконфигурируемого свойства::От ==режима==: `false` в нестрогом, `TypeError` в строгом

Единственный оператор, безопасный на необъявленном идентификаторе::==`typeof`==. Даёт `'undefined'` вместо исключения

Единственное исключение из этой безопасности `typeof`::Переменная в ==TDZ== — там `typeof` тоже бросает `ReferenceError`

## Приоритет и ассоциативность

Право- или левоассоциативно возведение в степень::==Правоассоциативно==, в отличие от вычитания и деления

Что выведет `2 ** 3 ** 2`::`512` — вычисляется как `2 ** (3 ** 2)`, а не `(2 ** 3) ** 2`

Почему `-2 ** 2` — синтаксическая ошибка::Из-за ==неоднозначности приоритета== унарного минуса перед возведением в степень. Нужны скобки

## instanceof и логические операторы

Что первым проверяет оператор `instanceof`::Хорошо известный символ ==`Symbol.hasInstance`==, и только при его отсутствии — цепочку прототипов

Является ли короткое замыкание `&&` и `||` оптимизацией реализации::==Нет==, это гарантия рантайм-семантики: правая часть физически не вычисляется

Чем `??` отличается от `||` по условию срабатывания::`??` реагирует только на `null`/`undefined`, `||` — на ==любое ложное значение==

Что выведет `0 ?? 'дефолт'` и `0 || 'дефолт'`::`0` и `'дефолт'`

## Присваивание и запятая

Наследуют ли логические операторы присваивания короткое замыкание::==Да==. Присваивание может не произойти вовсе, если левая часть уже определяет результат

Что выведет код
?
```js
const obj = { count: 3 };
let ran = false;
obj.count ||= (ran = true, 5);
```
`obj.count` остаётся `3`, `ran` остаётся `false` — count истинно, правая часть не вычисляется

Является ли деструктурирующее присваивание той же грамматикой, что деструктуризация при объявлении::==Нет==, это отдельная продукция. Присваивание работает с любым местом для записи, включая свойства и элементы

Что делает оператор запятая::Вычисляет ==оба операнда==, но значением выражения становится только правый

На каком приёме основан сброс базы вызова через `(0, obj.f)()`::Запятая возвращает ==значение==, а не ссылку на свойство — база теряется
