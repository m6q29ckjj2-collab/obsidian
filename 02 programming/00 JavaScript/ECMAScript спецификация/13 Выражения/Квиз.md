> [!question] Что выведет код?
> ```js
> const obj = { a: { b: null } };
> console.log(obj?.a?.b?.c.d.e);
> ```
> a) `null`
> b) `undefined`
> c) выбросит `TypeError`
> d) `NaN`
>> [!success]- Answer
>> b) `undefined`
>> Опциональная цепочка обрывается целиком при первом пустом значении. Часть `.c.d.e` синтаксически без вопросов, но помечена опциональной с первого `?.`

> [!question] Что выведет код?
> ```js
> let calls = 0;
> const w = { get x() { calls++; return null; } };
> w.x?.y.z(calls++);
> console.log(calls);
> ```
> a) `0`
> b) `1`
> c) `2`
> d) выбросит `TypeError`
>> [!success]- Answer
>> b) `1`
>> Геттер x вызывается один раз, дальнейшая часть цепочки не вычисляется вовсе, поэтому второй calls++ не выполнится

> [!question] Что выведет код?
> ```js
> let i = 0;
> const arr = [10, 20, 30];
> arr[i++] = arr[i++] + 1;
> console.log(arr, i);
> ```
> a) `[21, 20, 30] 2`
> b) `[10, 21, 30] 2`
> c) `[10, 20, 31] 2`
> d) `[21, 21, 30] 1`
>> [!success]- Answer
>> a) `[21, 20, 30] 2`
>> Ссылка для записи (индекс 0) вычисляется первой, до правой части. Правая часть берёт индекс 1: 20 + 1 = 21, и это значение записывается в уже зафиксированный индекс 0

> [!question] Что вернёт `delete 1`?
> a) `false`
> b) `true`
> c) `undefined`
> d) выбросит `SyntaxError`
>> [!success]- Answer
>> b) `true`
>> Операнд не является ссылкой на свойство, удалять нечего — оператор всегда успешен в этом случае

> [!question] Что произойдёт при удалении неконфигурируемого свойства в строгом режиме?
> ```js
> 'use strict';
> const o = {};
> Object.defineProperty(o, 'y', { value: 1, configurable: false });
> delete o.y;
> ```
> a) вернёт `false`
> b) выбросит `TypeError`
> c) вернёт `true`
> d) молча ничего не сделает
>> [!success]- Answer
>> b) выбросит `TypeError`
>> В нестрогом режиме та же операция дала бы false. Режим меняет не только поведение, но и сам факт исключения

> [!question] Что выведет код?
> ```js
> console.log(typeof neverDeclared);
> ```
> a) выбросит `ReferenceError`
> b) `'undefined'`
> c) выбросит `TypeError`
> d) `'null'`
>> [!success]- Answer
>> b) `'undefined'`
>> typeof — единственный оператор, безопасный на необъявленном идентификаторе

> [!question] Есть ли исключение из этой безопасности typeof?
> ```js
> typeof inTDZ; let inTDZ;
> ```
> a) нет, всегда безопасно
> b) да, переменная в TDZ даёт ReferenceError
> c) да, но только для констант
> d) да, но только в модулях
>> [!success]- Answer
>> b) да, переменная в TDZ даёт ReferenceError
>> Единственная ситуация, где typeof всё же бросает исключение

> [!question] Что выведет код?
> ```js
> console.log(2 ** 3 ** 2);
> ```
> a) `64`
> b) `512`
> c) `1024`
> d) `36`
>> [!success]- Answer
>> b) `512`
>> Возведение в степень правоассоциативно: вычисляется как 2 ** (3 ** 2), а не (2 ** 3) ** 2

> [!question] Почему `-2 ** 2` без скобок — синтаксическая ошибка?
> a) унарный минус запрещён перед числами
> b) неоднозначность приоритета унарного минуса перед возведением в степень
> c) степень не может быть отрицательной
> d) это устаревший синтаксис
>> [!success]- Answer
>> b) неоднозначность приоритета унарного минуса перед возведением в степень
>> Нужны явные скобки: (-2) ** 2 даёт 4

> [!question] Что первым проверяет оператор `instanceof`?
> a) цепочку прототипов
> b) хорошо известный символ Symbol.hasInstance
> c) свойство constructor
> d) внутренний слот класса
>> [!success]- Answer
>> b) хорошо известный символ Symbol.hasInstance
>> Только при его отсутствии оператор падает на обычное сравнение по цепочке прототипов

> [!question] Что выведет код?
> ```js
> class Even { static [Symbol.hasInstance](x) { return Number.isInteger(x) && x % 2 === 0; } }
> console.log(4 instanceof Even, 5 instanceof Even);
> ```
> a) `false false`
> b) `true true`
> c) `true false`
> d) выбросит `TypeError`
>> [!success]- Answer
>> c) `true false`
>> instanceof полностью делегирован переопределённому символу, сравнение прототипов не участвует

> [!question] Является ли короткое замыкание логических операторов оптимизацией реализации?
>> [!success]- Answer
>> False
>> Это гарантия рантайм-семантики: правая часть физически не вычисляется, а не просто игнорируется

> [!question] Что выведет код?
> ```js
> console.log(0 ?? 'дефолт', 0 || 'дефолт');
> ```
> a) `0 0`
> b) `дефолт дефолт`
> c) `0 дефолт`
> d) `дефолт 0`
>> [!success]- Answer
>> c) `0 дефолт`
>> Нулевое слияние реагирует только на null/undefined, логическое ИЛИ — на любое ложное значение, включая 0

> [!question] Наследуют ли логические операторы присваивания короткое замыкание?
>> [!success]- Answer
>> True
>> Присваивание может не произойти вовсе, если левая часть уже определяет результат операции

> [!question] Что выведет код?
> ```js
> const obj = { count: 3 };
> let ran = false;
> obj.count ||= (ran = true, 5);
> console.log(obj.count, ran);
> ```
> a) `5 true`
> b) `3 false`
> c) `5 false`
> d) `3 true`
>> [!success]- Answer
>> b) `3 false`
>> count истинно (3), поэтому правая часть логического ИЛИ не вычисляется и присваивания не происходит

> [!question] Что выведет код?
> ```js
> const obj = { count: 0 };
> let ran = false;
> obj.count ||= (ran = true, 5);
> console.log(obj.count, ran);
> ```
> a) `0 false`
> b) `5 true`
> c) `5 false`
> d) `0 true`
>> [!success]- Answer
>> b) `5 true`
>> count равно 0 — ложное значение, правая часть вычисляется, присваивание происходит

> [!question] Является ли деструктурирующее присваивание той же грамматикой, что деструктуризация при объявлении переменной?
>> [!success]- Answer
>> False
>> Это отдельная продукция. Присваивание работает с любым местом для записи, включая свойства объекта и элементы массива, а не только с новыми биндингами

> [!question] Что делает оператор запятая?
> a) вычисляет только левый операнд
> b) вычисляет оба операнда, значением становится левый
> c) вычисляет оба операнда, значением становится правый
> d) вычисляет операнды в произвольном порядке
>> [!success]- Answer
>> c) вычисляет оба операнда, значением становится правый
>> На этом основан приём (0, obj.f)() для намеренного сброса базы вызова

> [!question] Что выведет код?
> ```js
> const obj = { f() { return this; } };
> console.log((0, obj.f)() === obj);
> ```
> a) `true`
> b) `false`
> c) `undefined`
> d) выбросит `TypeError`
>> [!success]- Answer
>> b) `false`
>> Оператор запятая возвращает значение функции, а не ссылку на свойство obj.f — база вызова теряется
