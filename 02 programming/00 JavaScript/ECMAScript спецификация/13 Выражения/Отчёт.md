# Глава 13 · Выражения — отчёт

> [!info] Раздел спецификации
> [13 ECMAScript Language: Expressions](https://262.ecma-international.org/#sec-ecmascript-language-expressions)
> Карточки → [[Карточки]] · квиз → [[Квиз]] · карта → [[00 Карта]]

Самая длинная глава синтаксической части. Многие операторы уже разбирались с прикладной стороны в других материалах — здесь фокус на том, что даёт именно грамматика: порядок вычисления, короткое замыкание, разница между похожими конструкциями.

---

## 13.2–13.3 Первичные выражения и выражения левой части

[13.2 Primary Expression](https://262.ecma-international.org/#sec-primary-expression) — самый нижний уровень: `this`, идентификаторы, литералы, инициализаторы массива и объекта, выражения-функции, круглые скобки.

[13.3 Left-Hand-Side Expressions](https://262.ecma-international.org/#sec-left-hand-side-expressions) добавляет доступ к свойству, вызов, `new`, `super`, теговые шаблоны. Название условное — это не «то, что может стоять слева от `=`», а отдельная грамматическая категория с собственным приоритетом.

### Опциональная последовательность — короткое замыкание всей цепочки

[13.3.9 Optional Chains](https://262.ecma-international.org/#sec-optional-chains) — не набор независимых проверок `?.`, а единая продукция. [13.3.9.1 Runtime Semantics: Evaluation](https://262.ecma-international.org/#sec-optional-chaining-evaluation) обрывает **всю оставшуюся цепочку** при первом пустом значении, а не только следующий шаг.

```js
const obj = { a: { b: null } };
console.log(obj?.a?.b?.c.d.e); // undefined, а не TypeError на .d
```

Хотя `.c.d.e` идёт без вопросов, вся цепочка помечена как опциональная с момента первого `?.`, и оборвётся целиком, если `b` окажется пустым.

```js
let calls = 0;
const withSideEffect = { get x() { calls++; return null; } };
withSideEffect.x?.y.z(calls++);
console.log(calls); // 1, а не 2 — правая часть цепочки не вычисляется вовсе
```

### Обновляющие операторы — момент, когда фиксируется исходное значение

[13.4 Update Expressions](https://262.ecma-international.org/#sec-update-expressions). [13.4.2 Postfix Increment](https://262.ecma-international.org/#sec-postfix-increment-operator) и [13.4.4 Prefix Increment](https://262.ecma-international.org/#sec-prefix-increment-operator) — разница не только в возвращаемом значении, но и в том, что постфиксная форма обязана привести операнд к числу **до** вычисления новой ссылки для записи, если операнд сложный.

```js
let i = 0;
const arr = [10, 20, 30];
arr[i++] = arr[i++] + 1;
console.log(arr, i); // [21, 20, 30] 2
```

Ссылка на место записи (`arr[0]`, `i` становится `1`) вычисляется первой, **до** правой части. Затем вычисляется правая часть: `arr[1] + 1`, где второй `i++` берёт индекс `1` и переводит `i` в `2`. Итог — `20 + 1 = 21` записывается в уже зафиксированный `arr[0]`, а `arr[1]` остаётся нетронутым.

## 13.5–13.13 Унарные и бинарные операторы

[13.5 Unary Operators](https://262.ecma-international.org/#sec-unary-operators) объединяет `delete`, `typeof`, унарные `+`/`-`, `~`, `!`.

### delete — не всегда то, что ожидают

[13.5.1](https://262.ecma-international.org/#sec-delete-operator) работает только со ссылками на свойства. На простом идентификаторе результат зависит от режима, а на неконфигурируемом свойстве — от режима зависит сам факт исключения.

```js
console.log(delete 1);       // true — не ссылка, удалять нечего, всегда успех
var x = 1;
console.log(delete x);       // false в модуле/строгом коде из-за неконфигурируемости
                              // sloppy script: SyntaxError на этапе разбора для delete идентификатора
const o = {}; Object.defineProperty(o, 'y', { value: 1, configurable: false });
console.log(delete o.y);     // false в sloppy, TypeError в strict
```

### typeof — единственный оператор, не бросающий на необъявленном имени

[13.5.3](https://262.ecma-international.org/#sec-typeof-operator) особо оговаривает: если операнд — идентификатор, не связанный ни в одном окружении, результат `'undefined'` вместо исключения. Единственное исключение из этого исключения — переменная в TDZ.

```js
console.log(typeof neverDeclared);        // 'undefined' — не ошибка
try { typeof inTDZ; let inTDZ; } catch (e) { console.log(e.constructor.name); } // ReferenceError
```

### Приоритет и порядок вычисления

Разделы 13.6–13.13 задают жёсткую иерархию приоритета операций — от возведения в степень (наивысший из бинарных) до логических операторов (низший перед присваиванием). Показательный случай — [13.6 Exponentiation Operator](https://262.ecma-international.org/#sec-exp-operator): он **правоассоциативен**, в отличие от всех остальных бинарных арифметических.

```js
console.log(2 ** 3 ** 2);  // 512, не 64 — вычисляется как 2 ** (3 ** 2)
console.log(10 - 5 - 2);   // 3 — левоассоциативно: (10 - 5) - 2
```

```js
// унарный минус перед ** запрещён синтаксически без скобок
// -2 ** 2; // SyntaxError — неоднозначность приоритета
console.log((-2) ** 2); // 4
```

### Реляционные операторы и оператор instanceof

[13.10 Relational Operators](https://262.ecma-international.org/#sec-relational-operators). [13.10.1 Runtime Semantics: Evaluation](https://262.ecma-international.org/#sec-relational-operators-runtime-semantics-evaluation) использует уже знакомую по главе 7 операцию `IsLessThan`, а `instanceof` реализован через отдельную [InstanceofOperator](https://262.ecma-international.org/#sec-instanceofoperator) — 13.10.2, которая сначала проверяет хорошо известный символ `Symbol.hasInstance`, и только при его отсутствии падает на обычную проверку по цепочке прототипов.

```js
class Even { static [Symbol.hasInstance](x) { return Number.isInteger(x) && x % 2 === 0; } }
console.log(4 instanceof Even, 5 instanceof Even); // true false — сравнение прототипов не участвует
```

### Логические операторы — короткое замыкание как часть грамматики, а не оптимизация

[13.13 Binary Logical Operators](https://262.ecma-international.org/#sec-binary-logical-operators). Правая часть `&&`, `||` и `??` **не вычисляется**, если левая уже определяет результат — это гарантия рантайм-семантики, [13.13.1](https://262.ecma-international.org/#sec-binary-logical-operators-runtime-semantics-evaluation), а не побочный эффект реализации.

```js
let called = false;
const sideEffect = () => (called = true, 1);
false && sideEffect();
console.log(called); // false — правая часть не вычислена
```

```js
console.log(0 ?? 'дефолт', 0 || 'дефолт'); // 0 дефолт
// ?? реагирует только на null/undefined, || на любое ложное значение
```

## 13.14–13.16 Условный, оператор присваивания и запятая

### Логические операторы присваивания

[13.15 Assignment Operators](https://262.ecma-international.org/#sec-assignment-operators) включает `&&=`, `||=`, `??=` — они наследуют короткое замыкание своих логических операндов, поэтому правая часть может не вычисляться и **присваивание может не произойти вовсе**.

```js
const obj = { count: 0 };
let sideEffectRan = false;
obj.count ||= (sideEffectRan = true, 5);
console.log(obj.count, sideEffectRan); // 0 false — count истинно? нет, 0 ложно
```

```js
const obj2 = { count: 3 };
let ran = false;
obj2.count ||= (ran = true, 5);
console.log(obj2.count, ran); // 3 false — count истинно (3), правая часть не вычислена
```

### Деструктурирующее присваивание — отдельная грамматика

[13.15.5 Destructuring Assignment](https://262.ecma-international.org/#sec-destructuring-assignment) — не то же самое, что деструктуризация при объявлении из главы 14. Присваивание работает с любым `AssignmentTarget`, включая свойства и элементы, тогда как объявление создаёт только новые биндинги.

### Оператор запятая

[13.16 Comma Operator](https://262.ecma-international.org/#sec-comma-operator) вычисляет оба операнда, но значением выражения становится только правый. На этом основан классический приём сброса базы вызова.

```js
const obj3 = { f() { return this; } };
console.log((0, obj3.f)() === obj3); // false — запятая вернула значение функции, ссылка потеряна
```

## Итог

> [!success] Что забирать
> - Опциональная последовательность обрывает всю оставшуюся цепочку при первом пустом значении, а не только следующий шаг; правая часть цепочки при этом не вычисляется вовсе
> - Постфиксный инкремент фиксирует ссылку для записи до вычисления правой части выражения
> - `delete` результат зависит от типа операнда: не-ссылка всегда даёт успех, режим и конфигурируемость определяют остальное
> - `typeof` — единственный оператор, безопасный на необъявленном идентификаторе; TDZ остаётся исключением
> - Возведение в степень правоассоциативно, в отличие от вычитания и деления; унарный минус перед ним без скобок запрещён синтаксически
> - `instanceof` сначала проверяет `Symbol.hasInstance` и только затем падает на сравнение прототипов
> - Короткое замыкание логических операторов — гарантия рантайм-семантики: правая часть физически не вычисляется
> - Логические операторы присваивания наследуют короткое замыкание: присваивания может не произойти вовсе
> - Деструктурирующее присваивание — отдельная грамматика от деструктуризации при объявлении
> - Оператор запятая вычисляет оба операнда, но значением становится только правый — на этом стоит приём сброса базы вызова
