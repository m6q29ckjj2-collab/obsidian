> [!question] Сколько видов записи окружения определяет спецификация?
> a) три
> b) четыре
> c) пять
> d) семь
>> [!success]- Answer
>> c) пять
>> Declarative, Object, Function, Global, Module — все реализуют общий набор операций

> [!question] Что выведет код?
> ```js
> const arrow = () => this;
> console.log(arrow.call({ x: 1 }) === globalThis || arrow.call({ x: 1 }) === undefined);
> ```
> a) `true`
> b) `false`
> c) `TypeError`
> d) зависит от режима
>> [!success]- Answer
>> a) `true`
>> У стрелки статус связывания получателя lexical — своего связывания нет, переданный аргумент игнорируется, получатель берётся из внешней области

> [!question] Что произойдёт при обращении к `this` до вызова родительского конструктора?
> ```js
> class Base {}
> class Derived extends Base {
>   constructor() { console.log(this); super(); }
> }
> new Derived();
> ```
> a) выведет `undefined`
> b) выбросит `ReferenceError`
> c) выведет пустой объект
> d) выбросит `TypeError`
>> [!success]- Answer
>> b) выбросит `ReferenceError`
>> Статус связывания получателя ещё uninitialized. Его переводит в initialized вызов родительского конструктора

> [!question] Какая операция переводит статус связывания получателя в `initialized` в производном конструкторе?
>> [!success]- Answer
>> BindThisValue
>> Вызывается из super() и делает получатель доступным для остального кода конструктора

> [!question] Что выведет код на верхнем уровне обычного скрипта?
> ```js
> var a = 1;
> let b = 2;
> console.log(globalThis.a, globalThis.b);
> ```
> a) `1 2`
> b) `1 undefined`
> c) `undefined undefined`
> d) `undefined 2`
>> [!success]- Answer
>> b) `1 undefined`
>> Global Environment Record — гибрид: var идёт в объектную часть поверх глобального объекта, лексические объявления — в декларативную

> [!question] Что вернёт код?
> ```js
> var x = 1;
> console.log(delete globalThis.x);
> ```
> a) `true`
> b) `false`
> c) `undefined`
> d) выбросит `TypeError`
>> [!success]- Answer
>> b) `false`
>> Объявление через var создаёт неконфигурируемое свойство глобального объекта

> [!question] Почему конструкция `with` запрещена в строгом режиме?
> a) она устарела и заменена другим синтаксисом
> b) она делает разрешение имён динамическим через Object Environment Record
> c) она конфликтует с директивой use strict синтаксически
> d) она работает только с массивами
>> [!success]- Answer
>> b) она делает разрешение имён динамическим через Object Environment Record
>> Поиск имени превращается в проверку свойства объекта во время выполнения, что ломает статический анализ

> [!question] Что выведет код?
> ```js
> const arr = runInNewContext('[1,2,3]');
> console.log(arr instanceof Array, Array.isArray(arr));
> ```
> a) `true true`
> b) `false true`
> c) `true false`
> d) `false false`
>> [!success]- Answer
>> b) `false true`
>> У другого реалма свой прототип Array. Проверка внутренней природы объекта работает через границу реалма, проверка по прототипу — нет

> [!question] Что такое реалм в терминах спецификации?
> a) отдельный поток выполнения
> b) изолированный набор встроенных объектов со своим глобальным объектом
> c) отдельная область памяти для строк
> d) синоним контекста исполнения
>> [!success]- Answer
>> b) изолированный набор встроенных объектов со своим глобальным объектом
>> У каждого окна, воркера, iframe и изолированного контекста выполнения свой реалм

> [!question] Сколько компонентов у контекста исполнения?
> a) три
> b) пять
> c) семь
> d) девять
>> [!success]- Answer
>> c) семь
>> Точка возобновления, функция, реалм, исходный модуль, два окружения и приватное окружение классов

> [!question] Зачем контексту исполнения два разных окружения?
> a) для оптимизации доступа к памяти
> b) одно для лексических объявлений, другое для переменных и функций
> c) одно для чтения, другое для записи
> d) второе используется только в модулях
>> [!success]- Answer
>> b) одно для лексических объявлений, другое для переменных и функций
>> Это разделение и есть механизм, который делает let ограниченным блоком, а var — функцией

> [!question] Какая операция ищет ближайшую запись окружения со связыванием получателя?
>> [!success]- Answer
>> GetThisEnvironment
>> Поднимается по цепочке внешних окружений, пока проверка наличия связывания не даст истину

> [!question] Описан ли предел глубины стека вызовов в спецификации?
>> [!success]- Answer
>> False
>> Ограничение целиком на стороне реализации, сама ошибка переполнения стека в тексте стандарта не упоминается

> [!question] Находятся ли продолжения промисов в стеке контекстов исполнения?
>> [!success]- Answer
>> False
>> Они ставятся в очередь микрозадач и выполняются только после полного опустошения стека

> [!question] Что из перечисленного НЕ описано в стандарте языка?
> a) очередь микрозадач
> b) семантика промисов
> c) таймеры и события
> d) момент опустошения очереди микрозадач
>> [!success]- Answer
>> c) таймеры и события
>> Это зона ответственности хоста — отсюда различия в поведении между браузером и серверной средой

> [!question] В каком порядке выведутся значения?
> ```js
> console.log('1');
> setTimeout(() => console.log('4'), 0);
> Promise.resolve().then(() => console.log('2')).then(() => console.log('3'));
> ```
> a) `1 2 3 4`
> b) `1 4 2 3`
> c) `1 2 4 3`
> d) `4 1 2 3`
>> [!success]- Answer
>> a) `1 2 3 4`
>> Сначала синхронный код, затем очередь микрозадач до полного опустошения, и только потом задача таймера

> [!question] Что такое агент в терминах спецификации?
> a) объект-посредник для сетевых запросов
> b) независимый поток выполнения со своим стеком контекстов
> c) синоним реалма
> d) внутренний метод объекта
>> [!success]- Answer
>> b) независимый поток выполнения со своим стеком контекстов
>> Agent Clusters описывают, какие агенты могут делить память через SharedArrayBuffer

> [!question] Что выведет код?
> ```js
> function demo() {
>   let obj = {};
>   const ref = new WeakRef(obj);
>   obj = null;
>   return ref.deref() !== undefined;
> }
> console.log(demo());
> ```
> a) `true`
> b) `false`
> c) зависит от сборщика мусора
> d) выбросит исключение
>> [!success]- Answer
>> a) `true`
>> Спецификация гарантирует, что объект под слабой ссылкой не будет собран в пределах текущего синхронного участка кода, даже без сильных ссылок на него
