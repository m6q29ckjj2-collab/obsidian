# Глава 9 · Исполняемый код и контексты исполнения — отчёт

> [!info] Раздел спецификации
> [9 Executable Code and Execution Contexts](https://262.ecma-international.org/#sec-executable-code-and-execution-contexts)
> Карточки → [[Карточки]] · квиз → [[Квиз]] · карта → [[00 Карта]]

Здесь живёт механика, на которой стоят области видимости, `this`, замыкания и стек вызовов. Пять записей окружения из [9.1](https://262.ecma-international.org/#sec-environment-records) — самая насыщенная часть главы.

---

## 9.1 Записи окружения

[9.1.1 The Environment Record Type Hierarchy](https://262.ecma-international.org/#sec-the-environment-record-type-hierarchy) задаёт пять видов, и все они — реализация одного общего интерфейса с набором операций из [9.1.2](https://262.ecma-international.org/#sec-environment-record-operations): проверить наличие связывания, создать его, инициализировать, записать значение, прочитать, удалить.

| Вид | Раздел | Хранит |
|---|---|---|
| Declarative | [9.1.1.1](https://262.ecma-international.org/#sec-declarative-environment-records) | `let`, `const`, `class`, параметры, привязка `catch` |
| Object | [9.1.1.2](https://262.ecma-international.org/#sec-object-environment-records) | биндинги как свойства объекта — `var` в глобальном коде, `with` |
| Function | [9.1.1.3](https://262.ecma-international.org/#sec-function-environment-records) | Declarative плюс `this`, `new.target`, ссылка на функцию |
| Global | [9.1.1.4](https://262.ecma-international.org/#sec-global-environment-records) | гибрид Declarative и Object |
| Module | [9.1.1.5](https://262.ecma-international.org/#sec-module-environment-records) | Declarative плюс индирект-биндинги на импорты |

У каждой записи есть указатель на внешнюю. Разрешение имени — проход по цепочке этих указателей до первого совпадения.

### Function Environment Record и this

[9.1.1.3](https://262.ecma-international.org/#sec-function-environment-records) добавляет к обычной декларативной записи слоты `[[ThisValue]]`, `[[ThisBindingStatus]]`, `[[FunctionObject]]`, `[[NewTarget]]`.

Статус связывания получателя принимает три значения: `lexical` у стрелочных функций, `uninitialized` у производного конструктора до вызова родительского, `initialized` в обычном случае. Именно проверка этого статуса объясняет всё поведение `this`.

```js
const arrow = () => this;
arrow.call({ x: 1 }); // явное указание игнорируется — статус lexical, менять нечего

class Base {}
class Derived extends Base {
  constructor() {
    try { this; } catch (e) { console.log(e.constructor.name); } // ReferenceError
    super(); // BindThisValue переводит статус в initialized
    console.log(typeof this); // object
  }
}
new Derived();
```

Здесь же — [BindThisValue](https://262.ecma-international.org/#sec-bindthisvalue), которая срабатывает из `super()`, и [GetSuperBase](https://262.ecma-international.org/#sec-getsuperbase), объясняющая, как `super.method()` находит нужный прототип.

### Global Environment Record — гибрид

[9.1.1.4](https://262.ecma-international.org/#sec-global-environment-records) объединяет декларативную часть с объектной, надстроенной над глобальным объектом.

```js
var viaVar = 1;
let viaLet = 2;
function viaFn() {}

console.log(globalThis.viaVar, globalThis.viaLet, typeof globalThis.viaFn);
// 1 undefined function

console.log(delete globalThis.viaVar); // false — свойство неконфигурируемое
```

`var` и функциональные декларации идут в объектную часть и становятся свойствами глобального объекта с `[[Configurable]]: false`. Лексические объявления живут в декларативной части и снаружи невидимы.

### Object Environment Record и with

[9.1.1.2](https://262.ecma-international.org/#sec-object-environment-records) — механизм, на котором держится конструкция `with`: поиск имени превращается в проверку свойства объекта, включая прототипную цепочку.

```js
'use strict';
// with(obj) {}   // SyntaxError — запрещена в строгом режиме,
                  // потому что делает разрешение имён динамическим
```

## 9.3 Реалмы

[9.3 Realms](https://262.ecma-international.org/#sec-code-realms) — изолированный набор встроенных объектов: свой `Array`, `Object.prototype`, `Error`, свой глобальный объект. У каждого окна, воркера, iframe и изолированного контекста выполнения свой реалм.

```js
import { runInNewContext } from 'node:vm';
const arr = runInNewContext('[1,2,3]');
console.log(arr instanceof Array, Array.isArray(arr));
// false true — прототип массива в другом реалме другой
```

Практический вывод: `instanceof` через границу реалма ненадёжен, нужна проверка по внутренней природе объекта.

## 9.4 Контексты исполнения

[9.4 Execution Contexts](https://262.ecma-international.org/#sec-execution-contexts) — структура состояния из семи компонентов: точка возобновления, функция, реалм, исходный модуль, лексическое окружение, окружение переменных, приватное окружение.

Контексты складываются в стек. Верхний называется текущим исполняемым.

Разделение на два разных окружения — `LexicalEnvironment` и `VariableEnvironment` — и есть механизм, который разводит `let` (ограничен блоком) и `var` (ограничен функцией).

### Готовые операции над контекстом

- [GetActiveScriptOrModule](https://262.ecma-international.org/#sec-getactivescriptormodule) — 9.4.1
- [GetThisEnvironment](https://262.ecma-international.org/#sec-getthisenvironment) — 9.4.3, поднимается по цепочке, пока проверка наличия связывания получателя не даст истину
- [ResolveThisBinding](https://262.ecma-international.org/#sec-resolvethisbinding) — 9.4.4, то, что фактически вычисляет ключевое слово `this`
- [GetNewTarget](https://262.ecma-international.org/#sec-getnewtarget) — 9.4.5
- [GetGlobalObject](https://262.ecma-international.org/#sec-getglobalobject) — 9.4.6

```js
function f() { return this; }
console.log(typeof f.call('текст')); // 'string' в строгом режиме кода
```

Здесь же ключевое наблюдение про предел глубины стека: он **нигде не определён**. Ограничение полностью на стороне реализации, и `RangeError: Maximum call stack size exceeded` в тексте стандарта не упоминается вовсе.

```js
function probe(n = 0) { try { return probe(n + 1); } catch { return n; } }
console.log(probe() > 0); // предел есть, но какой — не определено стандартом
```

## 9.5 Задания и хостовые операции

[9.5 Jobs and Host Operations to Enqueue Jobs](https://262.ecma-international.org/#sec-jobs) описывает микрозадачи. Продолжения промисов не находятся в стеке контекстов — они ставятся в очередь и выполняются, когда стек полностью опустел.

```js
console.log('1');
setTimeout(() => console.log('4'), 0);
Promise.resolve().then(() => console.log('2')).then(() => console.log('3'));
// 1 2 3 4 — микрозадачи выполняются раньше задачи таймера
```

Важно: сама очередь микрозадач описана стандартом языка, а вот таймеры и события — нет. Это зона ответственности хоста, отсюда различия в поведении между браузером и серверной средой.

## 9.6–9.10 Агенты и модель памяти

[9.6 Agents](https://262.ecma-international.org/#sec-agents) вводит единицу параллелизма — независимый поток выполнения со своим стеком контекстов. [9.7 Agent Clusters](https://262.ecma-international.org/#sec-agent-clusters) описывает, какие агенты могут делить память через `SharedArrayBuffer`. [9.8 Forward Progress](https://262.ecma-international.org/#sec-forward-progress) — требование не блокировать другие агенты бесконечно. Разделы [9.9](https://262.ecma-international.org/#sec-weakref-processing-model) и [9.10](https://262.ecma-international.org/#sec-clear-kept-objects) касаются модели слабых ссылок: движок обязан гарантировать, что объект, на который ссылается `WeakRef`, не будет собран **в середине** выполнения синхронного участка кода, даже если больше нигде не используется.

```js
function demo() {
  let obj = {};
  const ref = new WeakRef(obj);
  obj = null; // единственная сильная ссылка снята
  // в пределах этого синхронного участка ref.deref() гарантированно вернёт объект
  console.log(ref.deref() !== undefined); // true
}
demo();
```

## Итог

> [!success] Что забирать
> - Пять видов записи окружения реализуют общий интерфейс операций; разрешение имени — проход по цепочке внешних окружений
> - Function Environment Record хранит статус связывания получателя: `lexical`, `uninitialized`, `initialized` — это объясняет всё поведение `this`
> - `super()` переводит статус из `uninitialized` в `initialized` через `BindThisValue`
> - Global Environment Record — гибрид: `var` и функции в объектной части становятся неконфигурируемыми свойствами глобального объекта
> - `with` работает через Object Environment Record и запрещён в строгом режиме, потому что делает разрешение имён динамическим
> - Реалм — изолированный набор интринсиков; `instanceof` через его границу ненадёжен
> - Контекст исполнения — семь компонентов; разделение лексического окружения и окружения переменных разводит `let` и `var`
> - Предел глубины стека нигде не определён стандартом
> - Очередь микрозадач описана языком, таймеры и события — нет, это ответственность хоста
> - Слабая ссылка гарантированно жива в пределах синхронного участка кода, даже без сильных ссылок на объект
