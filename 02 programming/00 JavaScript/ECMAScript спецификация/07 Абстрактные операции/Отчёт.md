## 7.1 Преобразования типов

[7.1 Type Conversion](https://262.ecma-international.org/#sec-type-conversion). Здесь нет операции, которая **меняет тип существующего значения**. Каждая берёт значение и порождает **новое** другого типа. Модель «переменная превратилась в строку» неверна: переменная как хранила прежнее значение, так и хранит.

### ToPrimitive — вход во всё остальное

[7.1.1 ToPrimitive](https://262.ecma-international.org/#sec-toprimitive) принимает значение и необязательный хинт: строковый, числовой или по умолчанию.

Порядок такой: не объект — вернуть как есть; есть метод преобразования к примитиву — вызвать его; иначе [7.1.1.1 OrdinaryToPrimitive](https://262.ecma-international.org/#sec-ordinarytoprimitive), который пробует два метода в порядке, зависящем от хинта.

| Хинт | Порядок методов |
|---|---|
| строковый | текстовый, затем числовой |
| числовой и по умолчанию | числовой, затем текстовый |

```js
const dual = {
  [Symbol.toPrimitive](hint) {
    return hint === 'number' ? 42 : hint === 'string' ? 'строка' : 'умолчание';
  }
};
console.log(+dual, `${dual}`, dual + '');
// 42 строка умолчание
```

Хинт по умолчанию запрашивают ровно два места: бинарное сложение и нестрогое равенство. Единственный встроенный тип, трактующий его как строковый, — дата.

```js
const d = new Date(0);
console.log(typeof (d + 1), typeof (d - 1)); // string number
```

Если оба метода вернут объект, преобразование невозможно:

```js
const hostile = Object.create(null);
try { `${hostile}`; } catch (e) { console.log(e.constructor.name); } // TypeError
```

### Остальные преобразования

| Операция | Раздел | Заметка |
|---|---|---|
| ToBoolean | [7.1.2](https://262.ecma-international.org/#sec-toboolean) | не вызывает ToPrimitive: любой объект истинен |
| ToNumeric | [7.1.3](https://262.ecma-international.org/#sec-tonumeric) | выбирает между обычным числом и произвольной точностью |
| ToNumber | [7.1.4](https://262.ecma-international.org/#sec-tonumber) | на символе и произвольной точности бросает |
| ToIntegerOrInfinity | [7.1.5](https://262.ecma-international.org/#sec-tointegerorinfinity) | усечение к нулю |
| ToInt32 / ToUint32 | [7.1.6](https://262.ecma-international.org/#sec-toint32) / [7.1.7](https://262.ecma-international.org/#sec-touint32) | побитовые операторы |
| ToString | [7.1.17](https://262.ecma-international.org/#sec-tostring) | на символе бросает |
| ToObject | [7.1.18](https://262.ecma-international.org/#sec-toobject) | на пустых значениях бросает |
| ToPropertyKey | [7.1.19](https://262.ecma-international.org/#sec-topropertykey) | ключи объектов |
| ToLength | [7.1.20](https://262.ecma-international.org/#sec-tolength) | длина массивоподобных |
| ToIndex | [7.1.22](https://262.ecma-international.org/#sec-toindex) | индексы буферов |

```js
console.log(Number(''), Number('   '), Number('12px'), Number('0x1F'));
// 0 0 NaN 31 — требуется, чтобы вся строка была числом

console.log(2 ** 32 | 0, -1 >>> 0, 1.9 | 0, -1.9 | 0);
// 0 4294967295 1 -1 — усечение к нулю и переполнение 32 бит

const o = {}; o[1] = 'a'; o['1'] = 'b'; o[{}] = 'c';
console.log(Object.keys(o), o[1]);
// ['1','[object Object]'] 'b' — ключ приводится к строке

console.log(Array.prototype.slice.call({ length: -5 }).length);
// 0 — длина ограничивается диапазоном
```

Ложных значений ровно восемь, и приведение к логическому типу к содержимому объекта не обращается:

```js
console.log([false, 0, -0, 0n, '', null, undefined, NaN].filter(v => !v).length); // 8
console.log(Boolean([]), Boolean({}), Boolean(new Boolean(false)));               // true true true
```

## 7.2 Сравнения и проверки

[7.2 Testing and Comparison Operations](https://262.ecma-international.org/#sec-testing-and-comparison-operations).

Проверки-предикаты: [IsCallable](https://262.ecma-international.org/#sec-iscallable), [IsConstructor](https://262.ecma-international.org/#sec-isconstructor), [IsArray](https://262.ecma-international.org/#sec-isarray), [IsPropertyKey](https://262.ecma-international.org/#sec-ispropertykey), [IsIntegralNumber](https://262.ecma-international.org/#sec-isintegralnumber), [RequireObjectCoercible](https://262.ecma-international.org/#sec-requireobjectcoercible).

Последняя объясняет, почему методы строкового прототипа принимают что угодно, кроме двух значений:

```js
console.log(String.prototype.toUpperCase.call(123)); // '123'
try { String.prototype.trim.call(null); } catch (e) { console.log(e.constructor.name); } // TypeError
```

### Три алгоритма равенства

| Операция | Раздел | Где применяется | NaN ≡ NaN | 0 ≡ −0 |
|---|---|---|:---:|:---:|
| [IsStrictlyEqual](https://262.ecma-international.org/#sec-isstrictlyequal) | 7.2.15 | строгое равенство, поиск по индексу, выбор ветки | нет | да |
| [SameValue](https://262.ecma-international.org/#sec-samevalue) | 7.2.11 | сравнение значений, определение свойства | да | нет |
| [SameValueZero](https://262.ecma-international.org/#sec-samevaluezero) | 7.2.12 | коллекции, поиск по совпадению | да | да |

```js
console.log(NaN === NaN, Object.is(NaN, NaN), [NaN].includes(NaN), [NaN].indexOf(NaN));
// false true true -1
console.log(Object.is(0, -0), [0].includes(-0), 0 === -0);
// false true true
```

### Нестрогое равенство и сравнение — разные алгоритмы

[IsLooselyEqual](https://262.ecma-international.org/#sec-islooselyequal) и [IsLessThan](https://262.ecma-international.org/#sec-islessthan) устроены по-разному, и отсюда известный парадокс.

```js
console.log(null == 0, null >= 0, null > 0, null == undefined);
// false true false true
```

В алгоритме равенства шага «привести пустую ссылку к числу» нет вовсе, а равенство с неопределённым значением прописано отдельным правилом. В алгоритме сравнения приведение к числу обязательно.

Там же видно нарушение транзитивности: при совпадении типов приведения не происходит.

```js
console.log('' == 0, '0' == 0, '' == '0'); // true true false
```

Сравнение может вернуть неопределённый результат, если участвует нечисло — поэтому все четыре сравнения с ним ложны:

```js
console.log(NaN < 1, NaN > 1, NaN <= 1, NaN >= 1); // false false false false
```

## 7.3 Операции над объектами

[7.3 Operations on Objects](https://262.ecma-international.org/#sec-operations-on-objects) — обёртки над внутренними методами, которыми пользуются остальные алгоритмы: [Get](https://262.ecma-international.org/#sec-get-o-p), [GetV](https://262.ecma-international.org/#sec-getv), [Set](https://262.ecma-international.org/#sec-set-o-p-v-throw), [GetMethod](https://262.ecma-international.org/#sec-getmethod), [HasProperty](https://262.ecma-international.org/#sec-hasproperty), [Call](https://262.ecma-international.org/#sec-call), [Construct](https://262.ecma-international.org/#sec-construct).

Практически важные:

**[SetIntegrityLevel](https://262.ecma-international.org/#sec-setintegritylevel)** — за ним стоят запечатывание и заморозка. Уровни различаются правами:

```js
const p = Object.preventExtensions({ a: 1 }); delete p.a;   // удаление разрешено
const s = Object.seal({ a: 1 }); s.a = 99;                  // изменение разрешено
const f = Object.freeze({ a: 1, nested: { b: 2 } });
f.nested.b = 99;                                            // заморозка поверхностная
console.log(Object.hasOwn(p, 'a'), s.a, f.nested.b);        // false 99 99
```

**[CopyDataProperties](https://262.ecma-international.org/#sec-copydataproperties)** — за ним стоят раскрытие в литерал и остаточный элемент. Копируются только собственные перечисляемые свойства, аксессоры при этом вызываются:

```js
let calls = 0;
const src = { a: 1, get b() { calls++; return 2; } };
const { ...copy } = src;
console.log(calls, copy.b, Object.getOwnPropertyDescriptor(copy, 'b').get);
// 1 2 undefined — геттер вызван, в копии лежит обычное свойство
```

**[EnumerableOwnProperties](https://262.ecma-international.org/#sec-enumerableownproperties)** — за ним стоят перечисление ключей, значений и пар.

## 7.4 Операции над итераторами

[7.4 Operations on Iterator Objects](https://262.ecma-international.org/#sec-operations-on-iterator-objects). Здесь вводится [Iterator Record](https://262.ecma-international.org/#sec-iterator-records) — структура из самого итератора, его метода перехода и флага завершённости.

Ключевые операции: [GetIterator](https://262.ecma-international.org/#sec-getiterator), [IteratorNext](https://262.ecma-international.org/#sec-iteratornext), [IteratorStep](https://262.ecma-international.org/#sec-iteratorstep), [IteratorClose](https://262.ecma-international.org/#sec-iteratorclose), [IteratorToList](https://262.ecma-international.org/#sec-iteratortolist).

Самая недооценённая — закрытие итератора. Оно вызывается при досрочном выходе и делает перебор безопасным для ресурсов:

```js
function* resource() {
  try { yield 'первый'; yield 'второй'; }
  finally { console.log('освобождено'); }
}

for (const v of resource()) { console.log(v); break; }
// первый
// освобождено

const [only] = resource();
// освобождено — при деструктуризации короче последовательности тоже
```

Тот же механизм объясняет, почему деструктуризация массива работает с любым перебираемым значением и падает на массивоподобном объекте:

```js
const [a] = new Set(['x']);                 // работает
try { const [b] = { 0: 'x', length: 1 }; }  // не перебирается
catch (e) { console.log(e.constructor.name); } // TypeError
```

## Итог

> [!success] Что забирать
> - Операции, меняющей тип существующего значения, не существует — есть операции, порождающие новые значения
> - Преобразование объекта к примитиву — вход во все остальные; порядок методов зависит от хинта
> - Хинт по умолчанию запрашивают только бинарное сложение и нестрогое равенство; дата трактует его как строковый
> - Приведение к логическому типу не обращается к содержимому объекта: ложных значений ровно восемь
> - Преобразование строки в число строгое — требуется, чтобы вся строка была числом
> - Алгоритмов равенства три, и расходятся они на нечисле и знаковом нуле
> - Равенство и сравнение — разные алгоритмы, отсюда парадокс с пустой ссылкой
> - Нестрогое равенство не транзитивно
> - Операции над объектами — обёртки над внутренними методами; за раскрытием в литерал стоит копирование данных, вызывающее аксессоры
> - Закрытие итератора при досрочном выходе делает перебор безопасным для ресурсов
