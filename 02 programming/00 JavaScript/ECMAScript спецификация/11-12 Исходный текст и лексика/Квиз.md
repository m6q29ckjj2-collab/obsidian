> [!question] Какой тип кода строгий по умолчанию, без директивы?
> a) Script
> b) Module
> c) оба одинаково
> d) ни один
>> [!success]- Answer
>> b) Module
>> Script требует явную директиву 'use strict', функция наследует режим места объявления

> [!question] Что произойдёт при выполнении в модуле?
> ```js
> function check() { try { x = 1; return 'ok'; } catch (e) { return e.constructor.name; } }
> check();
> ```
> a) вернёт `'ok'`
> b) вернёт `'ReferenceError'`
> c) вернёт `undefined`
> d) выбросит `SyntaxError`
>> [!success]- Answer
>> b) вернёт `'ReferenceError'`
>> Модуль строгий по умолчанию, присваивание необъявленной переменной запрещено

> [!question] Чем терминатор строки отличается от обычного пробела в лексической грамматике?
> a) ничем, это синонимы
> b) терминатор строки участвует в автоматической расстановке точек с запятой
> c) пробел запрещён внутри строковых литералов
> d) терминатор строки нельзя использовать внутри комментариев
>> [!success]- Answer
>> b) терминатор строки участвует в автоматической расстановке точек с запятой
>> Обычный пробел в этом механизме не участвует вовсе

> [!question] Является ли `yield` зарезервированным словом везде?
>> [!success]- Answer
>> False
>> Вне генератора и вне строгого режима он работает как обычный идентификатор. Внутри генератора и в строгом режиме зарезервирован

> [!question] Что произойдёт?
> ```js
> function* g() {
>   var yield = 1;
> }
> ```
> a) выполнится без ошибок
> b) выбросит `SyntaxError`
> c) выбросит `ReferenceError`
> d) `yield` станет равен `1`
>> [!success]- Answer
>> b) выбросит `SyntaxError`
>> Внутри генератора имя yield зарезервировано и не может использоваться как идентификатор

> [!question] Используют ли числовые литералы в коде ту же грамматику, что и разбор числа из строки?
>> [!success]- Answer
>> False
>> Это разные грамматики. Разделители-подчёркивания работают в литералах кода, но не при разборе строки

> [!question] Что выведет код?
> ```js
> console.log(1_000_000, 0b1010, 0o17, 0x1F, 1e3, .5, 5.);
> ```
> a) `1000000 10 15 31 1000 0.5 5`
> b) `1000000 1010 17 1F 1000 0.5 5.0`
> c) выбросит `SyntaxError`
> d) `1000000 2 8 16 1000 0.5 5`
>> [!success]- Answer
>> a) `1000000 10 15 31 1000 0.5 5`
>> Грамматика числовых литералов кода поддерживает разделители-подчёркивания, двоичную, восьмеричную и шестнадцатеричную формы, экспоненциальную запись и опущенную целую или дробную часть — все они дают обычное число

> [!question] Зачем появилась форма записи символа `\u{...}` в фигурных скобках?
> a) для совместимости со старыми браузерами
> b) старая форма кодирует ровно одну 16-битную единицу и не покрывает символы вне базовой плоскости
> c) она быстрее в разборе
> d) она заменяет собой все остальные escape-последовательности
>> [!success]- Answer
>> b) старая форма кодирует ровно одну 16-битную единицу и не покрывает символы вне базовой плоскости
>> Новая форма принимает произвольное число цифр и сама разворачивается в суррогатную пару при необходимости

> [!question] Что выведет теговый шаблон?
> ```js
> const tag = s => [s[0].length, s.raw[0].length];
> console.log(tag`a\nb`);
> ```
> a) `[3, 4]`
> b) `[4, 3]`
> c) `[3, 3]`
> d) `[4, 4]`
>> [!success]- Answer
>> a) `[3, 4]`
>> Обработанное значение содержит настоящий перенос строки — три символа. Сырое значение хранит буквальный слэш и n — четыре символа

> [!question] На какой паре значений построен метод `String.raw`?
>> [!success]- Answer
>> TV и TRV
>> Обработанное значение (Template Value) и сырое значение (Template Raw Value) шаблонного литерала

> [!question] Сколько правил автоматической расстановки точек с запятой описывает спецификация?
> a) одно
> b) два
> c) три
> d) пять
>> [!success]- Answer
>> c) три
>> Неподходящий токен после терминатора строки, конец программы при незавершённом разборе, явный запрет переноса в отдельных продукциях

> [!question] Что выведет код?
> ```js
> function f() {
>   return
>     { value: 1 };
> }
> console.log(f());
> ```
> a) `{ value: 1 }`
> b) `undefined`
> c) `SyntaxError`
> d) `null`
>> [!success]- Answer
>> b) `undefined`
>> После return действует явный запрет переноса строки — точка с запятой вставляется сразу после ключевого слова

> [!question] Когда автоматическая расстановка точек с запятой фактически НЕ спасает от склейки строк?
> a) когда следующая строка начинается с буквы
> b) когда следующая строка начинается со скобки, обратной кавычки или оператора вроде плюса
> c) когда предыдущая строка заканчивается на точку с запятой
> d) никогда, ASI всегда безопасен
>> [!success]- Answer
>> b) когда следующая строка начинается со скобки, обратной кавычки или оператора вроде плюса
>> В этих случаях парсер способен продолжить предыдущее выражение, и вставки не происходит

> [!question] Что делает hashbang-комментарий?
> a) это обычный однострочный комментарий, начинающийся с решётки
> b) отдельная продукция грамматики, разрешённая только в самом начале файла
> c) директива для препроцессора
> d) устаревший синтаксис, удалённый из современного стандарта
>> [!success]- Answer
>> b) отдельная продукция грамматики, разрешённая только в самом начале файла
>> Формально это не «комментарий» в обычном смысле — она описана как отдельная синтаксическая конструкция
