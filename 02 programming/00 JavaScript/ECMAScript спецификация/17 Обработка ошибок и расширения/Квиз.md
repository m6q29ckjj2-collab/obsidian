> [!question] Как формально классифицировано приложение B в спецификации?
> a) полностью необязательное для всех сред
> b) нормативное, но опциональное для не-браузерных сред
> c) устаревшее и удалённое из актуальной редакции
> d) экспериментальное предложение
>> [!success]- Answer
>> b) нормативное, но опциональное для не-браузерных сред
>> На практике реализовано мейнстримными движками независимо от среды — слишком много существующего кода на него полагается

> [!question] Что выведет код?
> ```js
> console.log('a') <!-- комментарий
> console.log('b');
> console.log('c');
> ```
> a) только `a`
> b) `a`, `b`, `c`
> c) ничего, SyntaxError
> d) только `b` и `c`
>> [!success]- Answer
>> b) `a`, `b`, `c`
>> HTML-подобный комментарий действует только до конца текущей строки, как //, а не многострочно

> [!question] Когда распознаётся закрывающая форма HTML-подобного комментария `-->`?
> a) в любом месте строки
> b) только в самом начале строки, после пробелов или комментариев
> c) она не поддерживается вовсе
> d) только внутри функций
>> [!success]- Answer
>> b) только в самом начале строки, после пробелов или комментариев
>> В противном случае символ `>` читается как оператор сравнения

> [!question] Зачем исторически появились HTML-подобные комментарии в JavaScript?
> a) для совместимости с XML
> b) скрипты оборачивали в `<!-- -->`, чтобы старые браузеры без поддержки JS показывали код как HTML-комментарий
> c) это требование ECMA для документирования кода
> d) для отладки в консоли браузера
>> [!success]- Answer
>> b) скрипты оборачивали в `<!-- -->`, чтобы старые браузеры без поддержки JS показывали код как HTML-комментарий
>> Наследие девяностых годов, до широкого распространения поддержки JavaScript

> [!question] Что вернёт `'текст'.blink()`?
> a) `'текст'`
> b) `'<blink>текст</blink>'`
> c) выбросит `TypeError`, метод удалён
> d) `undefined`
>> [!success]- Answer
>> b) `'<blink>текст</blink>'`
>> Метод остаётся в стандарте ради обратной совместимости, хотя тег blink браузерами давно не поддерживается

> [!question] Что вернёт `new Date(2024, 0, 1).getYear()`?
> a) `2024`
> b) `24`
> c) `124`
> d) выбросит `TypeError`
>> [!success]- Answer
>> c) `124`
>> Метод возвращает год минус 1900 — наследие короткой записи года из более старых стандартов

> [!question] Чем toGMTString отличается от toUTCString?

> [!question] Что необычного в поведении функции, объявленной внутри блока, в приложении B.3.2?
> a) функция вообще не создаётся
> b) значение биндинга появляется в момент выполнения декларации, а не при инстанцировании
> c) функция становится доступна только асинхронно
> d) она автоматически становится методом объекта
>> [!success]- Answer
>> b) значение биндинга появляется в момент выполнения декларации, а не при инстанцировании
>> Единственный такой случай во всей спецификации — везде подобное поведение задаётся заранее

> [!question] Разрешена ли функциональная декларация прямо в ветке if без фигурных скобок в обычном (нестрогом) коде браузера?

> if (true) function f() {} else function f() {}

> [!question] Что выведет код?
> ```js
> try { throw 1; } catch (e) { var e = 2; }
> console.log(e);
> ```
> a) `1`
> b) `2`
> c) выбросит SyntaxError
> d) `undefined`
>> [!success]- Answer
>> b) `2`
>> Приложение B.3.4 разрешает var внутри catch с тем же именем, что у параметра исключения — легальная синтаксическая коллизия

> [!question] Разрешён ли инициализатор в заголовке for...in вида `for (var x = 1 in obj)`?
