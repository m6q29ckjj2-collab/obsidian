## Дополнительный синтаксис

Действует ли HTML-подобный комментарий `<!--` до конца строки или до `-->`::До ==конца строки==, как `//`, а не как многострочный `/* */`

Что выведет код
?
```js
console.log('a') <!-- комментарий
console.log('b');
```
`a`, затем `b` — комментарий обрывает только первую строку, вторая инструкция выполняется как обычно

Когда распознаётся закрывающая форма `-->`::Только в ==самом начале строки==, после пробелов или комментариев — иначе `>` читается как оператор сравнения

Зачем появились HTML-подобные комментарии::Скрипты в девяностых оборачивали в `<!-- -->`, чтобы браузеры без поддержки JS показывали код как HTML-комментарий

## Прочие особенности

Что необычного в способе появления значения у функции, объявленной в блоке (приложение B.3.2)::Значение появляется ==в момент выполнения== декларации, а не при инстанцировании — единственный такой случай в спецификации

Разрешена ли функциональная декларация прямо в ветке `if` без фигурных скобок в обычном коде::==Да==, приложение B.3.3 разрешает то, что обычная грамматика Statement не допускает

Что выведет код
?
```js
try { throw 1; } catch (e) { var e = 2; }
console.log(e);
```
`2` — приложение B.3.4 разрешает var внутри catch с тем же именем, что у параметра исключения

Разрешён ли инициализатор в заголовке `for...in`, например `for (var x = 1 in obj)`::==Да==, но только для var в нестрогом режиме — приложение B.3.5

Какой пункт приложения B не связан с исторической практикой девяностых::==B.3.8==, про совместимость приватных полей с браузерными прокси-объектами
