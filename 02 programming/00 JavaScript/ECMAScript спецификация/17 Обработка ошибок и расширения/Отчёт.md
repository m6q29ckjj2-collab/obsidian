# Глава 17 · Обработка ошибок и расширения языка — отчёт

> [!info] Раздел спецификации
> [17 Error Handling and Language Extensions](https://262.ecma-international.org/#sec-error-handling-and-language-extensions)
> Карточки → [[Карточки]] · квиз → [[Квиз]] · карта → [[00 Карта]]

Сама 17 глава короткая — [17.1 Forbidden Extensions](https://262.ecma-international.org/#sec-forbidden-extensions) запрещает реализациям добавлять свои несовместимые расширения синтаксиса. Но она отсылает к самому интересному месту всего документа — **Annex B**, приложению, легализующему поведение, которого формально не должно быть.

---

## Что такое Annex B и почему он не факультативен

[Annex B](https://262.ecma-international.org/#sec-additional-ecmascript-features-for-web-browsers) описан как **нормативный, но опциональный для не-браузерных сред**. На практике это разграничение почти не работает: все мейнстримные движки реализуют Annex B независимо от среды выполнения, потому что слишком много существующего кода на него полагается.

Здесь собрано поведение, которое браузеры добавили в девяностых до появления единого стандарта, а затем стандарт был вынужден задним числом его описать — иначе такой код перестал бы работать.

---

## B.1 Дополнительный синтаксис

### HTML-подобные комментарии

[B.1.1 HTML-like Comments](https://262.ecma-international.org/#sec-html-like-comments) — да, в JavaScript можно писать комментарии в HTML-стиле, и это не опечатка:

```js
console.log('a') <!-- это комментарий только до конца текущей строки
console.log('b');
console.log('c');
// a
// b
// c — комментарий не многострочный, действует как //, а не как /* */
```

Есть и закрывающая форма — `-->`, но она распознаётся как начало комментария только в самом начале строки (после пробелов или других комментариев), иначе `>` читается как оператор сравнения. Появилось это из-за практики девяностых, когда скрипт оборачивали в `<!-- -->`, чтобы браузеры без поддержки JS показывали его как комментарий HTML, а не как текст на странице.

### Устаревшие восьмеричные литералы

[B.1.2](https://262.ecma-international.org/#sec-regular-expressions-patterns) относится к регулярным выражениям, но рядом в лексике главы 12 разрешена старая восьмеричная запись без префикса — `\101` вместо `\x41` — запрещённая в строгом режиме, но легальная в обычном скрипте.

## B.2 Дополнительные встроенные свойства

### Строковые методы разметки

[B.2.2](https://262.ecma-international.org/#sec-additional-properties-of-the-string.prototype-object) добавляет строковому прототипу методы, оборачивающие текст в устаревшие HTML-теги: `big`, `blink`, `bold`, `fixed`, `italics`, `small`, `strike`, `sub`, `sup`.

```js
console.log('текст'.blink());  // '<blink>текст</blink>'
console.log('текст'.sub());    // '<sub>текст</sub>'
```

Тег `<blink>` не поддерживается браузерами уже давно, но метод остаётся в стандарте — удалить его означало бы сломать код, который на него ссылается, пусть и редко.

### Дата — устаревшие геттеры

[B.2.3](https://262.ecma-international.org/#sec-additional-properties-of-the-date.prototype-object) добавляет `getYear` (в отличие от `getFullYear`, возвращает год минус 1900 — наследие короткой записи года) и `toGMTString` (синоним `toUTCString`).

```js
const d = new Date(2024, 0, 1);
console.log(d.getYear(), d.getFullYear()); // 124 2024
```

## B.3 Прочие дополнительные особенности

Самая практически значимая часть приложения — синтаксические послабления, которые незаметно меняют поведение кода в обычном скрипте по сравнению со строгим режимом.

### Функции в блоках

[B.3.2 Block-Level Function Declarations Web Legacy Compatibility Semantics](https://262.ecma-international.org/#sec-block-level-function-declarations-web-legacy-compatibility-semantics) — уже разбиралось в главе 14, но именно здесь, в приложении, находится нормативное описание. Дополнительный `var`-биндинг с тем же именем создаётся в функциональной области, а значение копируется в него **в момент выполнения** декларации — единственный такой случай во всей спецификации.

```js
console.log(typeof g); // 'undefined' — sloppy mode
{ function g() {} }
console.log(typeof g); // 'function'
```

### Функции в ветках if без блока

[B.3.3 FunctionDeclarations in IfStatement Statement Clauses](https://262.ecma-international.org/#sec-functiondeclarations-in-ifstatement-statement-clauses) разрешает то, что формально грамматика Statement не допускает: функциональную декларацию прямо в ветке `if` без фигурных скобок.

```js
if (true) function f() {} else function f() {}
console.log(typeof f); // 'function' в sloppy mode браузера
```

### var в блоке catch

[B.3.4 VariableStatements in Catch Blocks](https://262.ecma-international.org/#sec-variablestatements-in-catch-blocks) разрешает `var` внутри `catch` с тем же именем, что и у параметра исключения, — синтаксическую конструкцию, которая иначе была бы ошибкой.

```js
try { throw 1; } catch (e) { var e = 2; }
console.log(e); // 2 — легальная синтаксическая коллизия
```

### Инициализатор в заголовке for-in

[B.3.5 Initializers in ForIn Statement Heads](https://262.ecma-international.org/#sec-initializers-in-forin-statement-heads) разрешает древний синтаксис `for (var x = 1 in obj)` — инициализатор в заголовке `for-in`, запрещённый везде, кроме `var` в нестрогом режиме.

### Приватные поля — неожиданный сосед в этом разделе

[B.3.8 Non-default behaviour in HostEnsureCanAddPrivateElement](https://262.ecma-international.org/#sec-web-compat-host-ensure-can-add-private-field) — единственный пункт Annex B, не связанный с историческим наследием девяностых. Он существует ради совместимости с прокси в браузерных API: разрешает добавлять приватные поля к экзотическим объектам, которые обычно этого не допускают.

## Итог

> [!success] Что забирать
> - Приложение B формально опционально для не-браузерных сред, но на практике реализовано везде — считать его частью языка безопаснее, чем считать необязательным
> - HTML-подобные комментарии — легальный синтаксис, наследие оборачивания скриптов девяностых в `<!-- -->`
> - Устаревшие методы форматирования строк и даты остаются в стандарте ради обратной совместимости, а не по эстетическим причинам
> - Дополнительный биндинг для функции в блоке — единственное место в спецификации, где значение биндинга появляется в момент выполнения, а не при инстанцировании
> - Функциональная декларация допустима прямо в ветке if без блока — вопреки обычной грамматике Statement
> - var внутри catch может законно совпадать по имени с параметром исключения
> - Один пункт приложения не связан с историей девяностых вовсе — совместимость приватных полей с браузерными прокси-объектами
