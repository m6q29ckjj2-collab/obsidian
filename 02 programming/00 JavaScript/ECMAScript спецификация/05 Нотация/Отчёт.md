# Глава 5 · Нотация — отчёт

> [!info] Раздел спецификации
> [5 Notational Conventions](https://262.ecma-international.org/#sec-notational-conventions)
> Карточки → [[Карточки]] · квиз → [[Квиз]] · карта → [[00 Карта]]

Это глава про **язык, которым написана спецификация**. Она не описывает JavaScript — она описывает, как читать всё остальное. Пропустить её и начать с шестой главы значит смотреть на алгоритмы как на шифр.

## 5.1 Грамматики

Спецификация использует **четыре разные грамматики**, и они намеренно не смешиваются.

| Грамматика | Что описывает | Раздел |
|---|---|---|
| Лексическая | как символы складываются в токены | [5.1.2](https://262.ecma-international.org/#sec-lexical-and-regexp-grammars) |
| Регулярных выражений | содержимое литерала между слэшами | [5.1.2](https://262.ecma-international.org/#sec-lexical-and-regexp-grammars) |
| Числовых строк | что считается числом при разборе строки | [5.1.3](https://262.ecma-international.org/#sec-numeric-string-grammar) |
| Синтаксическая | как токены складываются в программу | [5.1.4](https://262.ecma-international.org/#sec-syntactic-grammar) |

Разделение объясняет вещи, которые иначе кажутся произволом. Например, `Number('0x10')` даёт `16`, а `Number('010')` даёт `10`, потому что грамматика числовых строк — не то же самое, что грамматика числовых литералов в коде.

```js
console.log(Number('0x10'), Number('0b11'), Number('1_000'));
// 16 3 NaN — подчёркивания разрешены в литералах кода, но не в разбираемых строках
console.log(1_000);  // 1000 — здесь работает лексическая грамматика
```

### Нотация грамматики

Раздел [5.1.5](https://262.ecma-international.org/#sec-grammar-notation) вводит обозначения, которые встречаются на каждой странице:

- **нижний индекс `opt`** — необязательный элемент продукции
- **`[Yield]`, `[Await]`, `[In]`, `[Return]`** — параметры продукций. Одна и та же конструкция разбирается по-разному внутри генератора, внутри асинхронной функции и в заголовке цикла. Отсюда, например, то, что `yield` — идентификатор в обычной функции и ключевое слово в генераторе
- **`[lookahead ∉ ...]`** — ограничение на следующий токен. Именно так запрещается начинать инструкцию с фигурной скобки, если имелся в виду объектный литерал
- **`[no LineTerminator here]`** — запрет переноса строки в конкретном месте

Последний пункт объясняет самую известную ловушку с автоматической вставкой точки с запятой:

```js
function f() {
  return
    42;
}
console.log(f()); // undefined — после return перенос строки запрещён,
                  // поэтому вставляется точка с запятой
```

## 5.2 Соглашения об алгоритмах

### Порядок вычисления

[5.2.1](https://262.ecma-international.org/#sec-evaluation-order) фиксирует то, что легко принять за деталь реализации: шаги алгоритма выполняются строго по порядку, и подвыражения вычисляются слева направо.

```js
const log = [];
const a = () => (log.push('a'), 1);
const b = () => (log.push('b'), 2);
a() + b();
console.log(log.join('')); // 'ab' — всегда, это требование, а не совпадение
```

### Абстрактные операции

[5.2.2](https://262.ecma-international.org/#sec-algorithm-conventions-abstract-operations) — операции, существующие только в тексте стандарта. Из кода их не вызвать, но именно они описывают работу движка. Пишутся с заглавной буквы и списком параметров.

Практическое правило поиска: если непонятно поведение, ищите не фольклорный термин, а имя операции. Слов «hoisting» и «coercion» в документе нет вовсе.

### Синтаксически управляемые операции

[5.2.3](https://262.ecma-international.org/#sec-algorithm-conventions-syntax-directed-operations) — операции, определённые не для значений, а для **узлов грамматики**. Одно имя операции получает разные тела для разных продукций.

Дальше они делятся на два вида:

- **Runtime Semantics** ([5.2.4](https://262.ecma-international.org/#sec-runtime-semantics)) — то, что происходит при выполнении
- **Static Semantics** ([5.2.5](https://262.ecma-international.org/#sec-static-semantic-rules)) — то, что проверяется или вычисляется **до** выполнения

Второе объясняет целый класс ошибок, возникающих до запуска первой строки:

```js
// SyntaxError на этапе разбора: ни одна строка не выполнится
// console.log('старт');
// let x = 1;
// let x = 2;
```

Отдельная разновидность статической семантики — **Early Errors**, ранние ошибки. Это условия, при которых код обязан быть отвергнут до выполнения.

### Математические значения

[5.2.6](https://262.ecma-international.org/#sec-mathematical-operations) вводит различие, которое легко пропустить, но без него алгоритмы читаются неверно.

Спецификация оперирует **математическими значениями** — точными числами без ограничений разрядности. Это не то же самое, что значения типа Number.

- **ℝ(x)** — математическое значение, соответствующее числу
- **𝔽(x)** — число типа Number, ближайшее к математическому значению
- **ℤ(x)** — значение произвольной точности

Отсюда видно, где именно теряется точность: алгоритм считает точно, а результат укладывается в двоичное представление.

```js
console.log(0.1 + 0.2);              // 0.30000000000000004
console.log(2 ** 53 === 2 ** 53 + 1); // true — соседние значения слились
console.log(9007199254740993n);       // точное значение произвольной точности
```

### Нотация значений и тождественность

[5.2.7](https://262.ecma-international.org/#sec-value-notation) и [5.2.8](https://262.ecma-international.org/#sec-identity) описывают, как записываются конкретные значения и что означает «то же самое» применительно к служебным структурам вроде записей и списков.

## Записи о завершении — ключ ко всему остальному

Формально это [6.2.4](https://262.ecma-international.org/#sec-completion-record-specification-type), но без этого понятия алгоритмы пятой главы не читаются, поэтому разбираем здесь.

Результат **любого** шага алгоритма — запись о завершении с тремя полями: тип, значение и цель. Тип принимает одно из значений:

| Тип | Когда возникает |
|---|---|
| normal | обычное завершение шага |
| throw | выброшено исключение |
| return | выполнен возврат из функции |
| break | прерван цикл или блок |
| continue | продолжена итерация |

Все, кроме первого, называются **резкими** (abrupt).

Из этого растут два значка, встречающиеся в каждом алгоритме:

- **`? выражение`** — сокращение для [ReturnIfAbrupt](https://262.ecma-international.org/#sec-returnifabrupt): если внутри случилось резкое завершение, немедленно пробросить его наружу
- **`! выражение`** — утверждение, что резкое завершение здесь невозможно. Если оно всё же произойдёт, это ошибка в движке или в самом стандарте

> [!tip] Как этим пользоваться
> По расстановке значков видно, где алгоритм способен выбросить исключение, а где нет. Это быстрее, чем читать текст целиком, когда нужно понять условия отказа.

Единая структура объясняет, почему `break`, `continue`, `return` и `throw` описываются одним механизмом: все они — резкие завершения, различающиеся типом и целью.

```js
// метка в поле «цель» записи о завершении
outer: for (const i of [1, 2]) {
  for (const j of [1, 2]) {
    if (j === 2) continue outer;
    console.log(i, j);
  }
}
// 1 1
// 2 1
```

## Итог

> [!success] Что забирать
> - Грамматик четыре, и они не взаимозаменяемы: разбор строки в число идёт по своей грамматике, а не по правилам литералов кода
> - Параметры продукций объясняют контекстную зависимость: одно и то же слово может быть идентификатором или ключевым словом
> - Ограничение на перенос строки — источник классической ловушки с возвратом значения
> - Порядок вычисления слева направо гарантирован стандартом
> - Статическая семантика работает до выполнения: отсюда ошибки, при которых не выполняется ни одна строка
> - Математические значения точны, значения типа Number — приближения; различие показывает, где теряется точность
> - Запись о завершении — единый механизм для обычного результата, исключения, возврата и выхода из цикла
> - Значки `?` и `!` читаются как «пробросить, если резкое» и «здесь резкого быть не может»
