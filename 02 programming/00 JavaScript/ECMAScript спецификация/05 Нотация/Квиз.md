> [!question] Сколько грамматик использует спецификация?
> a) одну
> b) две
> c) четыре
> d) по одной на каждую главу
>> [!success]- Answer
>> c) четыре
>> Лексическая, регулярных выражений, числовых строк и синтаксическая. Они намеренно не смешиваются

> [!question] Что выведет код?
> ```js
> console.log(Number('1_000'), 1_000);
> ```
> a) `1000 1000`
> b) `NaN 1000`
> c) `1 1000`
> d) `NaN NaN`
>> [!success]- Answer
>> b) `NaN 1000`
>> Разделители разрешены в литералах кода лексической грамматикой, но не входят в грамматику числовых строк, по которой разбирается строка

> [!question] Что выведет код?
> ```js
> console.log(Number('0x10'), Number('010'));
> ```
> a) `16 8`
> b) `16 10`
> c) `10 10`
> d) `NaN NaN`
>> [!success]- Answer
>> b) `16 10`
>> Шестнадцатеричная запись грамматикой числовых строк поддерживается, а ведущий ноль восьмеричной записи в ней не имеет специального смысла

> [!question] Что выведет код?
> ```js
> function f() {
>   return
>     42;
> }
> console.log(f());
> ```
> a) `42`
> b) `undefined`
> c) `SyntaxError`
> d) `null`
>> [!success]- Answer
>> b) `undefined`
>> В продукции возврата стоит запрет переноса строки, поэтому автоматически вставляется точка с запятой

> [!question] Что означает ограничение вида «следующий токен не должен быть таким-то»?
> a) запрет на определённые символы в идентификаторах
> b) ограничение на следующий токен при разборе
> c) требование к порядку объявлений
> d) указание на устаревшую конструкцию
>> [!success]- Answer
>> b) ограничение на следующий токен при разборе
>> Так, например, запрещается начинать инструкцию с фигурной скобки, когда имелся в виду объектный литерал

> [!question] Зачем продукции параметризованы флагами вроде «внутри генератора»?
> a) для оптимизации разбора
> b) одна конструкция разбирается по-разному в зависимости от контекста
> c) для обратной совместимости со старыми версиями
> d) это пометки для реализаций
>> [!success]- Answer
>> b) одна конструкция разбирается по-разному в зависимости от контекста
>> Отсюда то, что одно и то же слово бывает идентификатором в обычной функции и ключевым словом в генераторе

> [!question] Порядок вычисления подвыражений гарантирован спецификацией
>> [!success]- Answer
>> True
>> Слева направо, и это требование, а не деталь реализации. Побочные эффекты в аргументах выполняются в предсказуемом порядке

> [!question] Что такое абстрактная операция?
> a) функция стандартной библиотеки
> b) функция, существующая только в тексте стандарта
> c) внутренний метод объекта
> d) синоним метода прототипа
>> [!success]- Answer
>> b) функция, существующая только в тексте стандарта
>> Вызвать её из кода нельзя, но именно она описывает поведение движка

> [!question] Чем синтаксически управляемая операция отличается от обычной абстрактной?
> a) она быстрее
> b) она определена для узлов грамматики и имеет разные тела для разных продукций
> c) она работает только с числами
> d) отличий нет
>> [!success]- Answer
>> b) она определена для узлов грамматики и имеет разные тела для разных продукций
>> Поэтому одно имя операции встречается в документе десятки раз с разными определениями

> [!question] Что из перечисленного проверяется до выполнения кода?
> a) значения переменных
> b) статическая семантика и ранние ошибки
> c) типы аргументов функций
> d) наличие свойств у объектов
>> [!success]- Answer
>> b) статическая семантика и ранние ошибки
>> Отсюда ошибки, при которых не выполняется ни одна строка модуля

> [!question] Что выведет код?
> ```js
> console.log('старт');
> let x = 1;
> let x = 2;
> ```
> a) `старт`, затем ошибка
> b) ошибку до выполнения, `старт` не выведется
> c) `старт` и ничего больше
> d) выполнится без ошибок
>> [!success]- Answer
>> b) ошибку до выполнения, `старт` не выведется
>> Повторное лексическое объявление — ранняя ошибка, то есть часть статической семантики

> [!question] Чем математическое значение отличается от значения типа Number?
> a) ничем, это синонимы
> b) математическое точное и без ограничений разрядности
> c) математическое используется только для целых
> d) математическое существует только в реализациях
>> [!success]- Answer
>> b) математическое точное и без ограничений разрядности
>> Различие показывает, где именно теряется точность: алгоритм считает точно, результат укладывается в двоичное представление

> [!question] Что выведет код?
> ```js
> console.log(2 ** 53 === 2 ** 53 + 1);
> ```
> a) `true`
> b) `false`
> c) `undefined`
> d) выбросит `RangeError`
>> [!success]- Answer
>> a) `true`
>> Соседние математические значения отображаются в одно и то же значение типа Number: шаг представления стал больше единицы

> [!question] Сколько значений может принимать тип записи о завершении?
> a) два
> b) три
> c) пять
> d) семь
>> [!success]- Answer
>> c) пять
>> Обычное завершение, выброс, возврат, прерывание и продолжение. Все, кроме первого, называются резкими

> [!question] Значок вопроса перед выражением в алгоритме — сокращение для операции `___`
>> [!success]- Answer
>> ReturnIfAbrupt
>> При резком завершении оно немедленно пробрасывается наружу без выполнения оставшихся шагов

> [!question] Что означает восклицательный знак перед выражением в алгоритме?
> a) операция обязательно выбросит исключение
> b) резкое завершение здесь невозможно
> c) шаг выполняется асинхронно
> d) результат следует отбросить
>> [!success]- Answer
>> b) резкое завершение здесь невозможно
>> Это утверждение автора стандарта. Его нарушение означало бы ошибку в движке или в самой спецификации
