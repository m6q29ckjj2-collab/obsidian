# Глава 19 · Глобальный объект — отчёт

> [!info] Раздел спецификации
> [19 The Global Object](https://262.ecma-international.org/#sec-global-object)
> Карточки → [[Карточки]] · квиз → [[Квиз]] · карта → [[00 Карта]]

Всё, что доступно без квалификатора в любом месте кода — значения, функции, конструкторы. У глобального объекта конкретно нет собственного имени в тексте стандарта: он описан через свойства, доступные из скрипта.

---

## 19.1 Значимые свойства

[19.1 Value Properties](https://262.ecma-international.org/#sec-value-properties-of-the-global-object) — `NaN`, `Infinity`, `undefined`. Все три неперечисляемы, неизменяемы и неконфигурируемы. Присвоить `NaN = 5` можно в старых нестрогих окружениях без эффекта, но переопределить его невозможно нигде.

```js
console.log(Object.getOwnPropertyDescriptor(globalThis, 'undefined'));
// { value: undefined, writable: false, enumerable: false, configurable: false }
```

[19.1.1 globalThis](https://262.ecma-international.org/#sec-globalthis) — единственная стандартизированная ссылка на глобальный объект, работающая одинаково в браузере, воркере и на сервере. До её появления в каждой среде был свой способ (`window`, `self`, `global`).

## 19.2 Функциональные свойства

### eval — прямой и косвенный

[19.2.1 eval](https://262.ecma-international.org/#sec-eval-x) уже разбирался в главе 14 через призму области видимости. Здесь стоит добавить: различие прямого и косвенного вызова определяется **синтаксически** — буквальный вызов идентификатора `eval(...)` считается прямым, любая форма, где `eval` сначала присвоен переменной или прошёл через выражение, — косвенным.

```js
function test() {
  const local = 'локальная';
  eval('console.log(local)');           // прямой — видит локальную область
  const indirectEval = eval;
  try { indirectEval('console.log(local)'); }
  catch (e) { console.log(e.constructor.name); } // ReferenceError — косвенный работает в глобальной области
}
test();
```

### parseInt и parseFloat — свободный разбор

[19.2.4](https://262.ecma-international.org/#sec-parsefloat-string) и [19.2.5](https://262.ecma-international.org/#sec-parseint-string-radix) уже упоминались в главе 7 как противоположность строгому `Number`. Здесь стоит отметить деталь про основание счисления: если оно не указано и строка начинается с `0x`/`0X`, `parseInt` автоматически распознаёт шестнадцатеричную запись — единственный случай автоматического определения основания.

```js
console.log(parseInt('0x1F'), parseInt('1F', 16), parseInt('08'));
// 31 31 8 — восьмеричная автоопределяемость убрана из современной спецификации
```

### isNaN и isFinite — глобальные версии всегда приводят тип

[19.2.2](https://262.ecma-international.org/#sec-isfinite-number) и [19.2.3](https://262.ecma-international.org/#sec-isnan-number) — уже разбирались в главе 7 в сравнении с методами `Number`. Напоминание: глобальные версии сначала приводят аргумент к числу, версии из `Number` — нет.

### URI-функции

[19.2.6 URI Handling Functions](https://262.ecma-international.org/#sec-uri-syntax-and-semantics) — четыре функции с разной степенью «агрессивности» кодирования. `encodeURI` предполагает, что аргумент — уже полный URI, и не трогает зарезервированные символы вроде `/` и `?`. `encodeURIComponent` кодирует всё, кроме буквенно-цифровых символов и небольшого набора безопасных.

```js
const url = 'https://example.com/search?q=привет мир';
console.log(encodeURI(url));
// https://example.com/search?q=%D0%BF%D1%80%D0%B8%D0%B2%D0%B5%D1%82%20%D0%BC%D0%B8%D1%80
console.log(encodeURIComponent('a/b?c'));
// a%2Fb%3Fc — здесь / и ? тоже закодированы, потому что это компонент, а не целый URI
```

Обе функции, как уже разбиралось в других главах, бросают на непарном суррогате: строка обязана быть корректно оформленным UTF-16 для кодирования в байты.

## 19.3–19.4 Конструкторы и прочие свойства

[19.3 Constructor Properties](https://262.ecma-international.org/#sec-constructor-properties-of-the-global-object) — просто перечень: `Object`, `Array`, `Function`, `Boolean`, `Symbol`, `Error` и его подклассы, `Number`, `BigInt`, `Date`, `String`, `RegExp`, `Map`, `Set`, `WeakMap`, `WeakSet`, `ArrayBuffer`, типизированные массивы, `DataView`, `Promise`, `Proxy` и другие — все они подробно разбираются в последующих главах.

[19.4 Other Properties](https://262.ecma-international.org/#sec-other-properties-of-the-global-object) добавляет объекты без своего конструктора: `Math`, `JSON`, `Reflect`, `Atomics`.

Незаметный, но практически значимый факт: не все эти свойства неконфигурируемы. Большинство конструкторов и объектов из 19.3–19.4 можно переопределить или удалить, в отличие от `NaN`, `Infinity`, `undefined` из 19.1.

```js
console.log(Object.getOwnPropertyDescriptor(globalThis, 'Array').configurable); // true
delete globalThis.Array;
console.log(typeof Array); // 'undefined' — да, действительно можно снести
```

## Итог

> [!success] Что забирать
> - `NaN`, `Infinity`, `undefined` неконфигурируемы и неперечисляемы — в отличие от большинства других глобальных свойств
> - `globalThis` — единственная стандартизированная ссылка на глобальный объект, работающая одинаково во всех средах
> - Прямой и косвенный вызов eval различаются синтаксически, а не по значению переменной
> - Автоматическое определение основания счисления в parseInt работает только для шестнадцатеричного префикса
> - Глобальные isNaN/isFinite приводят тип, версии из Number — нет
> - encodeURI и encodeURIComponent кодируют по-разному именно потому, что предполагают разный контекст: целый URI против отдельного компонента
> - Большинство глобальных конструкторов и объектов конфигурируемы и удаляемы, в отличие от базовых значимых свойств главы 19.1
