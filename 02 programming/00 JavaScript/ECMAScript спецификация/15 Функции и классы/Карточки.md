## Параметры и arguments

Единственное условие «простого» списка параметров::Без ==значений по умолчанию==, без остаточного параметра, без деструктуризации

Что создаёт связанный (mapped) объект аргументов::Простой список параметров ==и== нестрогий режим — оба условия одновременно

Что выведет код
?
```js
function f(a = 0, b) { a = 99; return arguments[0]; }
f(1, 2);
```
`1`. Наличие дефолта делает arguments несвязанным независимо от режима

## Стрелки и методы

Какое единственное значение `[[ThisMode]]` есть у стрелочных функций::==lexical==

Что из перечисленного отсутствует у стрелки: конструирование, arguments, HomeObject::==Всё три==. Стрелка физически не может использовать super

Что задаёт HomeObject метода::Ссылку на объект, в котором метод ==определён==, а не на получателя вызова

Какая запись метода получает HomeObject::Только ==сокращённая запись== (`{ method() {} }`), не обычное функциональное выражение

Что выведет код
?
```js
const base = { greet() { return 'база'; } };
const mid = { __proto__: base, greet() { return super.greet(); } };
const child = { __proto__: mid, greet: mid.greet };
child.greet();
```
`'база'`. super ищет от HomeObject метода (mid), а не от получателя вызова (child)

## Генераторы

Выполняется ли тело генератора при вызове генераторной функции::==Нет==. Создаётся приостановленный объект, тело начинает выполняться только с первого next()

## Классы

В каком порядке инициализируются поля и статические блоки класса::Строго в ==порядке объявления==, независимо от типа элемента

Что выведет код
?
```js
class D {
  static log = [];
  static { D.log.push('A'); }
  static f = (D.log.push('B'), 1);
}
D.log;
```
`['A', 'B']` — блок и поле выполняются по порядку текста, не сгруппированы по типу

Что делает `super()` в производном конструкторе, помимо вызова родительской логики::==Создаёт объект== через Construct базового класса, передавая new.target по цепочке

Когда инициализируются поля производного класса относительно `super()`::==Сразу после== вызова super(), в момент связывания this

Что выведет код
?
```js
class Base { constructor() { console.log(new.target.name); } }
class Sub extends Base {}
new Sub();
```
`'Sub'`, а не `'Base'` — new.target передаётся через цепочку вызовов super

Является ли приватное имя строковым соглашением или служебным типом::==Служебным типом== (Private Name), а не строкой с решёткой

Что произойдёт при вызове метода с приватным полем на объекте, не являющемся экземпляром класса::==TypeError==, а не undefined — доступ реализован через MakePrivateReference

Как проверить наличие приватного поля у произвольного объекта::Оператором `#field in obj` — синтаксис, специально для этого предусмотренный

С каким получателем выполняется статический блок класса::С самим ==классом==, и с доступом к его приватным полям

## Асинхронные функции и хвостовые вызовы

Возвращает ли асинхронная функция промис, если в теле нет await::==Да==, всегда, обёртка в промис происходит безусловно

Какая статическая семантика определяет, находится ли вызов в хвостовой позиции::==HasCallInTailPosition==

Требует ли спецификация переиспользовать фрейм стека для хвостового вызова::==Да==, через операцию PrepareForTailCall

Сколько мейнстримных движков реализовало это требование::Только ==один== — расхождение между требованием и практикой здесь предельно наглядное
