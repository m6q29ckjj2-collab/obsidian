# Глава 15 · Функции и классы — отчёт

> [!info] Раздел спецификации
> [15 ECMAScript Language: Functions and Classes](https://262.ecma-international.org/#sec-ecmascript-language-functions-and-classes)
> Карточки → [[Карточки]] · квиз → [[Квиз]] · карта → [[00 Карта]]

Десять форм определения функций и классов — и почти все различия между ними сводятся к трём параметрам: какое связывание получателя, есть ли собственный объект аргументов, можно ли использовать как конструктор.

---

## 15.1 Списки параметров

[15.1 Parameter Lists](https://262.ecma-international.org/#sec-parameter-lists) — грамматика параметров, от которой зависит поведение [FunctionDeclarationInstantiation](https://262.ecma-international.org/#sec-functiondeclarationinstantiation) (10.2.11), уже разбиравшейся в главе 10.

Ключевой параметр — «простой» список параметров: без значений по умолчанию, без остаточного параметра, без деструктуризации. Именно от него зависит, создаётся ли **связанный** (mapped) объект аргументов.

```js
function simple(a, b) { a = 99; return arguments[0]; }
console.log(simple(1, 2)); // 99 — связанный объект, изменение параметра видно в arguments

function withDefault(a = 0, b) { a = 99; return arguments[0]; }
console.log(withDefault(1, 2)); // 1 — несвязанный объект, несмотря на sloppy mode
```

Строгий режим или наличие сложного списка параметров — любое из двух условий даёт несвязанный `arguments`.

## 15.2–15.4 Функции, стрелки, методы

[15.2 Function Definitions](https://262.ecma-international.org/#sec-function-definitions) — обычные функции, `[[ThisMode]]` = `strict` или `global` в зависимости от режима кода.

[15.3 Arrow Function Definitions](https://262.ecma-international.org/#sec-arrow-function-definitions) — единственная форма с `[[ThisMode]]` = `lexical`. У стрелки нет ни `[[Construct]]`, ни `prototype`, ни собственного `arguments`, ни `[[HomeObject]]` — она физически не может использовать `super`.

```js
const obj = { arrow: () => typeof this, method() { return typeof this; } };
console.log(obj.arrow(), obj.method()); // 'undefined' (или 'object' в скрипте) 'object'
```

[15.4 Method Definitions](https://262.ecma-international.org/#sec-method-definitions) вводит слот `[[HomeObject]]` — ссылку на объект, в котором метод определён. Именно от него, а не от получателя вызова, `super` берёт точку отсчёта для поиска. Слот выставляется **только** сокращённой записи метода.

```js
const base = { greet() { return 'база'; } };
const mid = { __proto__: base, greet() { return super.greet() + '→сред'; } };
const child = { __proto__: mid, greet: mid.greet }; // тот же метод, тот же HomeObject

console.log(child.greet()); // 'база→сред' — super ищет от HomeObject (mid), не от child
```

Это объясняет, почему нельзя написать `super` в обычном функциональном выражении: `[[HomeObject]]` для него не определён синтаксически.

## 15.5–15.6 Генераторы

[15.5 Generator Function Definitions](https://262.ecma-international.org/#sec-generator-function-definitions), рантайм в [15.5.2](https://262.ecma-international.org/#sec-generator-function-definitions-runtime-semantics-evaluatebody). Тело генератора не выполняется при вызове функции — создаётся объект генератора, приостановленный **до первой строки**.

```js
function* g() { console.log('старт'); yield 1; }
const it = g();
console.log('создан');
it.next(); // 'создан' затем 'старт'
```

[15.6 Async Generator Function Definitions](https://262.ecma-international.org/#sec-async-generator-function-definitions) объединяет механизм приостановки генератора с очередью микрозадач `await`: `for await...of` вызывает асинхронный метод перехода, возвращающий промис с записью `{ value, done }`.

## 15.7 Классы

Самый насыщенный раздел. [15.7.14 Runtime Semantics: ClassDefinitionEvaluation](https://262.ecma-international.org/#sec-runtime-semantics-classdefinitionevaluation) описывает порядок, в котором происходит немало неочевидного.

### Порядок инициализации

1. Создаётся окружение класса (для приватного имени и для самого имени класса, если есть)
2. Вычисляется родительский класс, определяется прототип
3. Создаётся конструктор — экзотический объект, `[[HomeObject]]` которого указывает на прототип
4. Собственные и статические поля/методы **вычисляются в порядке объявления**, но обычные поля инициализируются лениво — при каждом создании экземпляра, а статические — сразу
5. Статические блоки выполняются в этом же проходе, вперемешку со статическими полями по порядку объявления

```js
class Demo {
  static log = [];
  static { Demo.log.push('блок 1'); }
  static field2 = (Demo.log.push('поле после блока'), 1);
  static { Demo.log.push('блок 2'); }
}
console.log(Demo.log); // ['блок 1', 'поле после блока', 'блок 2'] — порядок объявления, не тип элемента
```

### Производный конструктор

[GetSuperConstructor](https://262.ecma-international.org/#sec-getsuperconstructor) (13.3.7.2) и связывание `this` через `[[ThisBindingStatus]]` уже разбирались в главе 9. Здесь стоит добавить: `super()` — это не просто вызов родителя, а операция, которая **создаёт объект** через `[[Construct]]` базового класса с `new.target`, унаследованным от текущего вызова.

```js
class Base { constructor() { console.log(new.target.name); } }
class Sub extends Base {}
new Sub(); // 'Sub' — new.target передан через цепочку super()
```

### Поля класса и порядок относительно super()

Поля инициализируются операцией [ClassFieldDefinitionEvaluation](https://262.ecma-international.org/#sec-runtime-semantics-classfielddefinitionevaluation) сразу после того, как `this` становится доступен — то есть сразу после `super()` в производном классе, и в самом начале конструктора в базовом.

```js
class Base { field = 'база'; constructor() { console.log(this.field); } }
class Derived extends Base {
  extra = 'доп';
  constructor() { super(); console.log(this.extra); } // super() выполнил инициализацию Base.field первой
}
new Derived();
// база
// доп
```

### Приватные поля — не просто соглашение об именах

Приватное имя — служебный тип из [6.2.12](https://262.ecma-international.org/#sec-private-names), а не строка с решёткой. Доступ реализован через [MakePrivateReference](https://262.ecma-international.org/#sec-makeprivatereference) (6.2.5.9), и попытка обратиться к приватному полю на объекте, не являющемся экземпляром объявившего класса, даёт `TypeError`, а не `undefined`.

```js
class Box { #v = 1; static has(x) { return #v in x; } get() { return this.#v; } }
const b = new Box();
console.log(Box.has(b), Box.has({}));      // true false — #v in x, не обычная проверка свойства
try { Box.prototype.get.call({}); } catch (e) { console.log(e.constructor.name); } // TypeError
```

### Статические блоки

`static { }` выполняется с `this`, равным самому классу, и имеет доступ к приватным полям класса — единственное место снаружи методов, где это возможно без создания экземпляра.

## 15.8–15.9 Асинхронные функции

[15.8 Async Function Definitions](https://262.ecma-international.org/#sec-async-function-definitions) — `await` внутри приостанавливает выполнение и ставит продолжение в очередь микрозадач; функция всегда возвращает промис, даже если тело не содержит `await` вовсе.

```js
async function f() { return 1; }
console.log(f() instanceof Promise); // true — обёртка происходит всегда
```

[15.9 Async Arrow Function Definitions](https://262.ecma-international.org/#sec-async-arrow-function-definitions) сочетает оба режима: лексический получатель стрелки и приостановку `await`.

## 15.10 Хвостовые вызовы

[15.10 Tail Position Calls](https://262.ecma-international.org/#sec-tail-position-calls). Статическая семантика [HasCallInTailPosition](https://262.ecma-international.org/#sec-static-semantics-hascallintailposition) (15.10.2) определяет, какие вызовы синтаксически находятся в хвостовой позиции, а операция [PrepareForTailCall](https://262.ecma-international.org/#sec-preparefortailcall) (15.10.3) обязана переиспользовать текущий фрейм стека для такого вызова.

```js
'use strict';
const sum = (n, acc = 0) => n === 0 ? acc : sum(n - 1, acc + n); // хвостовая позиция
```

Стандарт требует эту оптимизацию, но реализовал её из мейнстримных движков только один — расхождение между требованием и практикой здесь предельно наглядное.

## Итог

> [!success] Что забирать
> - Простой список параметров — без дефолтов, остатка и деструктуризации — единственное условие связанного объекта аргументов; строгий режим и любая сложность параметров дают несвязанный
> - Стрелка — единственная форма с лексическим `[[ThisMode]]`; у неё нет конструирования, своего arguments и HomeObject
> - `[[HomeObject]]` задаётся только сокращённой записи метода и определяет точку отсчёта для super, а не получатель вызова
> - Тело генератора не выполняется при создании объекта — только с первого next()
> - Порядок инициализации полей и статических блоков класса — строго порядок объявления, тип элемента роли не играет
> - super() создаёт объект через Construct базового класса, передавая new.target по цепочке
> - Поля инициализируются сразу после того, как this становится доступен: после super() в производном классе, в начале конструктора в базовом
> - Приватное имя — служебный тип, а не строковое соглашение; доступ извне даёт TypeError, а не undefined
> - Асинхронная функция всегда возвращает промис, даже без await в теле
> - Требование переиспользовать фрейм для хвостового вызова реализовано только в одном движке из трёх мейнстримных
