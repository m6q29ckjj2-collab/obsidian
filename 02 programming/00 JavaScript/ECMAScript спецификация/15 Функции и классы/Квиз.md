> [!question] Что выведет код?
> ```js
> function simple(a, b) { a = 99; return arguments[0]; }
> console.log(simple(1, 2));
> ```
> a) `1`
> b) `99`
> c) `undefined`
> d) выбросит `TypeError`
>> [!success]- Answer
>> b) `99`
>> Простой список параметров в нестрогом режиме даёт связанный объект аргументов, изменение параметра видно через него

> [!question] Что выведет код?
> ```js
> function f(a = 0, b) { a = 99; return arguments[0]; }
> console.log(f(1, 2));
> ```
> a) `1`
> b) `99`
> c) `0`
> d) `undefined`
>> [!success]- Answer
>> a) `1`
>> Наличие значения по умолчанию делает объект аргументов несвязанным независимо от режима строгости

> [!question] Какое значение слота режима связывания получателя единственное у стрелочных функций?
> a) `strict`
> b) `global`
> c) `lexical`
> d) `bound`
>> [!success]- Answer
>> c) `lexical`
>> Отсюда следует всё остальное: отсутствие собственного связывания получателя, невозможность конструирования

> [!question] Есть ли у стрелочной функции слот HomeObject?
>> [!success]- Answer
>> False
>> Поэтому стрелка физически не может использовать оператор super — ему не от чего оттолкнуться

> [!question] Что задаёт слот HomeObject метода?
> a) объект, на котором метод был вызван
> b) объект, в котором метод определён
> c) прототип получателя вызова
> d) конструктор класса
>> [!success]- Answer
>> b) объект, в котором метод определён
>> Именно от него super ищет точку отсчёта для поиска метода, а не от получателя вызова

> [!question] Что выведет код?
> ```js
> const base = { greet() { return 'база'; } };
> const mid = { __proto__: base, greet() { return super.greet(); } };
> const child = { __proto__: mid, greet: mid.greet };
> console.log(child.greet());
> ```
> a) `'база'`
> b) выбросит `TypeError`
> c) бесконечная рекурсия
> d) `undefined`
>> [!success]- Answer
>> a) `'база'`
>> super в методе mid.greet ищет от HomeObject этого метода — mid, а не от получателя вызова child

> [!question] Выполняется ли тело генератора при вызове генераторной функции?
>> [!success]- Answer
>> False
>> Создаётся приостановленный объект генератора, тело начинает выполняться только при первом вызове next()

> [!question] Что выведет код?
> ```js
> const log = [];
> function* g() { log.push('старт'); yield 1; }
> const it = g();
> log.push('создан');
> it.next();
> console.log(log);
> ```
> a) `['старт', 'создан']`
> b) `['создан', 'старт']`
> c) `['старт']`
> d) `['создан']`
>> [!success]- Answer
>> b) `['создан', 'старт']`
>> Создание объекта генератора не запускает тело, оно выполняется только с первого next()

> [!question] В каком порядке инициализируются поля и статические блоки класса?
> a) сначала все поля, затем все блоки
> b) сначала все блоки, затем все поля
> c) строго в порядке объявления в тексте класса
> d) порядок не определён
>> [!success]- Answer
>> c) строго в порядке объявления в тексте класса
>> Тип элемента (поле или блок) на порядок не влияет

> [!question] Что выведет код?
> ```js
> class D {
>   static log = [];
>   static { D.log.push('A'); }
>   static f = (D.log.push('B'), 1);
> }
> console.log(D.log);
> ```
> a) `['A', 'B']`
> b) `['B', 'A']`
> c) `[]`
> d) выбросит `ReferenceError`
>> [!success]- Answer
>> a) `['A', 'B']`
>> Статический блок и статическое поле выполняются в порядке текста класса

> [!question] Что делает вызов `super()` в производном конструкторе, помимо запуска родительской логики?
> a) ничего особенного, просто вызывает функцию
> b) создаёт объект через Construct базового класса, передавая new.target
> c) копирует свойства родителя в this
> d) вызывает статический метод базового класса
>> [!success]- Answer
>> b) создаёт объект через Construct базового класса, передавая new.target
>> Именно поэтому this недоступен в производном конструкторе до вызова super

> [!question] Что выведет код?
> ```js
> class Base { constructor() { console.log(new.target.name); } }
> class Sub extends Base {}
> new Sub();
> ```
> a) `'Base'`
> b) `'Sub'`
> c) `undefined`
> d) выбросит `TypeError`
>> [!success]- Answer
>> b) `'Sub'`
>> new.target передаётся через цепочку вызовов super, а не привязан к классу, где написан код

> [!question] Когда инициализируются поля экземпляра производного класса относительно super()?
> a) до вызова super()
> b) сразу после вызова super()
> c) после выполнения всего конструктора
> d) при первом обращении к полю
>> [!success]- Answer
>> b) сразу после вызова super()
>> В этот момент this становится доступен, и поля инициализируются немедленно

> [!question] Является ли приватное имя поля класса строковым соглашением?
>> [!success]- Answer
>> False
>> Это отдельный служебный тип (Private Name), доступ к которому реализован через специальную операцию, а не просто строка с символом решётки

> [!question] Что произойдёт при вызове метода с приватным полем на постороннем объекте?
> ```js
> class Box { #v = 1; get() { return this.#v; } }
> Box.prototype.get.call({});
> ```
> a) вернёт `undefined`
> b) выбросит `TypeError`
> c) вернёт `1`
> d) выбросит `SyntaxError`
>> [!success]- Answer
>> b) выбросит `TypeError`
>> Приватное поле не найдено у объекта, не являющегося экземпляром класса — доступ падает с ошибкой, а не тихо возвращает пустое значение

> [!question] Какой синтаксис проверяет наличие приватного поля у произвольного объекта без выбрасывания исключения?
>> [!success]- Answer
>> #field in obj
>> Специально предусмотренная форма оператора in для приватных полей

> [!question] С каким получателем выполняется статический блок класса?
> a) с прототипом класса
> b) с undefined
> c) с самим классом
> d) с первым созданным экземпляром
>> [!success]- Answer
>> c) с самим классом
>> Статический блок также имеет доступ к приватным полям и методам класса

> [!question] Возвращает ли асинхронная функция промис, если в её теле нет await?
>> [!success]- Answer
>> True
>> Обёртка результата в промис происходит безусловно для любой асинхронной функции

> [!question] Что выведет код?
> ```js
> async function f() { return 1; }
> console.log(f() instanceof Promise);
> ```
> a) `true`
> b) `false`
> c) `undefined`
> d) выбросит `TypeError`
>> [!success]- Answer
>> a) `true`
>> Асинхронная функция всегда оборачивает результат в промис, независимо от наличия await

> [!question] Какая статическая семантика определяет, находится ли вызов в хвостовой позиции?
>> [!success]- Answer
>> HasCallInTailPosition
>> Синтаксический анализ, а не поведение во время выполнения

> [!question] Сколько мейнстримных движков реализовало требование переиспользовать фрейм стека для хвостового вызова?
> a) все три
> b) два
> c) только один
> d) ни одного
>> [!success]- Answer
>> c) только один
>> Требование есть в стандарте, но выполнено лишь в одном движке из трёх — расхождение между спецификацией и практикой

> [!question] Что произойдёт при попытке использовать `super` в обычном функциональном выражении внутри объектного литерала?
> ```js
> const obj = { m: function () { return super.toString; } };
> ```
> a) выполнится нормально
> b) выбросит SyntaxError на этапе разбора
> c) вернёт undefined
> d) выбросит TypeError во время выполнения
>> [!success]- Answer
>> b) выбросит SyntaxError на этапе разбора
>> Слот HomeObject выставляется только сокращённой записи метода — обычное функциональное выражение его не получает, и super синтаксически недопустим
