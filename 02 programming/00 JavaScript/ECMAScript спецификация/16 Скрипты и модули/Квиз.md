> [!question] Что проверяет GlobalDeclarationInstantiation до создания хотя бы одного глобального биндинга?
> a) синтаксическую корректность кода
> b) возможность создать все биндинги без конфликта с неконфигурируемыми свойствами
> c) наличие директивы use strict
> d) доступность сети для загрузки модулей
>> [!success]- Answer
>> b) возможность создать все биндинги без конфликта с неконфигурируемыми свойствами
>> Если хоть одно имя конфликтует, инстанцирование проваливается целиком, до выполнения первой строки

> [!question] Сколько раздельных фаз проходит обработка модуля?
> a) одна
> b) две
> c) три
> d) пять
>> [!success]- Answer
>> c) три
>> Разбор, связывание и выполнение — именно разделение фаз объясняет живые связывания и поведение циклов

> [!question] Почему `import` работает независимо от того, в каком месте файла он написан?
> a) движок переносит все импорты в начало файла
> b) связывание завершается до выполнения любого кода модуля
> c) импорт — не исполняемая инструкция вовсе
> d) это не так, порядок имеет значение
>> [!success]- Answer
>> b) связывание завершается до выполнения любого кода модуля
>> Фаза связывания предшествует фазе выполнения для всего графа зависимостей

> [!question] Что выведет код?
> ```js
> // counter.mjs
> export let count = 0;
> export const inc = () => count++;
>
> // main.mjs
> import { count, inc } from './counter.mjs';
> console.log(count);
> inc();
> console.log(count);
> ```
> a) `0 0`
> b) `0 1`
> c) `undefined undefined`
> d) выбросит `TypeError`
>> [!success]- Answer
>> b) `0 1`
>> Импортированное имя — индирект-биндинг на ту же ячейку, что и в экспортирующем модуле, а не копия значения

> [!question] Что произойдёт при попытке присвоить значение импортированному имени?
> ```js
> import { count } from './counter.mjs';
> count = 5;
> ```
> a) присвоится без ошибок
> b) выбросит `TypeError`
> c) создастся локальная переменная-тень
> d) выбросит `SyntaxError` на этапе разбора
>> [!success]- Answer
>> b) выбросит `TypeError`
>> Связывание доступно только на чтение со стороны импортёра

> [!question] Ломает ли циклическая зависимость двух модулей граф связывания?
>> [!success]- Answer
>> False
>> Связывание отделено от выполнения, поэтому оба модуля успешно связываются несмотря на цикл

> [!question] Что произойдёт при выполнении этой пары модулей?
> ```js
> // a.mjs
> import { b } from './b.mjs';
> export const a = 'A';
>
> // b.mjs
> import { a } from './a.mjs';
> export const b = 'B';
> console.log(a);
> ```
> a) выведет `undefined`
> b) выбросит `ReferenceError`
> c) выведет `'A'`
> d) зависнет
>> [!success]- Answer
>> b) выбросит `ReferenceError`
>> Модуль b выполняется первым в цепочке (его импортирует a), и биндинг a в этот момент ещё не инициализирован — TDZ

> [!question] Чем поведение циклических зависимостей ESM отличается от CommonJS?
> a) ESM не поддерживает циклы вовсе
> b) в CommonJS на этом месте была бы тихая undefined, в ESM — явная ошибка
> c) CommonJS выбрасывает ошибку, ESM даёт undefined
> d) различий нет
>> [!success]- Answer
>> b) в CommonJS на этом месте была бы тихая undefined, в ESM — явная ошибка
>> Явная ошибка предпочтительнее тихого распространения неопределённого значения по коду

> [!question] Является ли объект пространства имён модуля расширяемым?
>> [!success]- Answer
>> False
>> Object.isExtensible для него всегда false

> [!question] Что покажет дескриптор свойства пространства имён модуля для переменной, объявленной через `let`?
> a) `writable: false` всегда
> b) `writable: true`, отражая изменяемость исходной переменной
> c) дескриптор недоступен для чтения
> d) зависит от того, был ли модуль связан асинхронно
>> [!success]- Answer
>> b) `writable: true`, отражая изменяемость исходной переменной
>> Дескриптор честно показывает природу биндинга, хотя запись всё равно будет отклонена

> [!question] Что произойдёт при попытке записи в это свойство несмотря на writable: true в дескрипторе?
> ```js
> import * as ns from './counter.mjs';
> ns.count = 99;
> ```
> a) запишется успешно
> b) выбросит `TypeError`
> c) молча проигнорируется
> d) выбросит `SyntaxError`
>> [!success]- Answer
>> b) выбросит `TypeError`
>> Запрет реализован через переопределённый внутренний метод записи, а не через атрибут дескриптора

> [!question] Почему `Object.isFrozen()` на пространстве имён модуля с изменяемым экспортом возвращает `false`, хотя запись в него невозможна?
> a) это ошибка в реализации движков
> b) isFrozen проверяет атрибуты дескрипторов, а не фактическое поведение при записи
> c) пространство имён на самом деле не заморожено вовсе
> d) isFrozen работает только с обычными объектами
>> [!success]- Answer
>> b) isFrozen проверяет атрибуты дескрипторов, а не фактическое поведение при записи
>> Атрибут writable честно отражает изменяемость исходного биндинга, поэтому формальная проверка даёт false, хотя реальная запись отклоняется

> [!question] Может ли модуль содержать верхнеуровневый await?
>> [!success]- Answer
>> True
>> Выполнение графа зависимостей при этом упорядочивается с учётом асинхронного ожидания, не блокируя граф целиком

> [!question] Что происходит при экспорте через `export * from` из двух модулей с одинаковым именем экспорта?
> a) побеждает первый по порядку модуль
> b) побеждает последний по порядку модуль
> c) возникает неоднозначность, которую обрабатывает алгоритм разрешения экспорта
> d) это запрещено синтаксически
>> [!success]- Answer
>> c) возникает неоднозначность, которую обрабатывает алгоритм разрешения экспорта
>> Операция разрешения экспорта специально описывает обнаружение таких конфликтов

> [!question] Что представляет собой Module Record сразу после фазы разбора, но до связывания?
> a) уже полностью выполненный модуль
> b) структуру со списками импортов и экспортов, без выполненного кода
> c) обычный объект JavaScript
> d) массив строк исходного кода
>> [!success]- Answer
>> b) структуру со списками импортов и экспортов, без выполненного кода
>> Код модуля начинает выполняться только на третьей фазе, после завершения связывания
