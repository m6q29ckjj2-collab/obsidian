# Глава 14 · Инструкции и объявления — отчёт

> [!info] Раздел спецификации
> [14 ECMAScript Language: Statements and Declarations](https://262.ecma-international.org/#sec-ecmascript-language-statements-and-declarations)
> Карточки → [[Карточки]] · квиз → [[Квиз]] · карта → [[00 Карта]]

Инструкции выполняются ради побочного эффекта, а не ради значения — но у каждой всё равно есть Completion Record, и именно через него объясняется вся управляющая логика: `break`, `continue`, `return`, обработка исключений.

---

## 14.1–14.2 Семантика инструкций и блок

[14.1 Statement Semantics](https://262.ecma-international.org/#sec-statement-semantics) фиксирует общий принцип: каждая инструкция при выполнении порождает Completion Record. У большинства он обычный (normal), но управляющие конструкции дают резкие типы.

[14.2 Block](https://262.ecma-international.org/#sec-block), [14.2.2 Runtime Semantics: Evaluation](https://262.ecma-international.org/#sec-block-runtime-semantics-evaluation) — блок создаёт собственную запись окружения при наличии лексических объявлений и выполняет BlockDeclarationInstantiation перед первой инструкцией.

```js
{
  console.log(typeof blockFn); // 'function' — инстанцирована в этом же блоке
  function blockFn() {}
}
```

## 14.3 Объявления и инструкция var

[14.3.1 Let and Const Declarations](https://262.ecma-international.org/#sec-let-and-const-declarations) и его рантайм-часть [14.3.1.2](https://262.ecma-international.org/#sec-let-and-const-declarations-runtime-semantics-evaluation) описывают то, что фактически инициализирует биндинг в момент выполнения строки — до этого момента он существует, но находится в неинициализированном состоянии.

[14.3.2 Variable Statement](https://262.ecma-international.org/#sec-variable-statement) — `var`. Присваивание в объявлении `var` семантически описано как обычное присваивание существующей переменной, а не создание новой: сама переменная уже существует благодаря инстанцированию.

```js
console.log(v); // undefined, не ошибка — переменная уже существует
var v = 1;
console.log(v); // 1 — присваивание выполнилось как обычное
```

## 14.6–14.7 Условные инструкции и циклы

### if — completion пустой ветки

[14.6 The if Statement](https://262.ecma-international.org/#sec-if-statement). Незаметная деталь: если ветка `else` отсутствует и условие ложно, инструкция всё равно возвращает Completion Record — со значением `undefined`, а не «ничего».

```js
console.log(eval('if (false) 1;')); // undefined — completion пуст, но существует
```

### Циклы — единый механизм per-iteration окружения

[14.7 Iteration Statements](https://262.ecma-international.org/#sec-iteration-statements) объединяет `do-while` ([14.7.2](https://262.ecma-international.org/#sec-do-while-statement)), `while` ([14.7.3](https://262.ecma-international.org/#sec-while-statement)), `for` ([14.7.4](https://262.ecma-international.org/#sec-for-statement)), `for-in`/`for-of` ([14.7.5](https://262.ecma-international.org/#sec-for-in-and-for-of-statements)).

Механизм `CreatePerIterationEnvironment`, отвечающий за корректные замыкания с `let` в классическом `for`, определён именно здесь, для конкретной продукции цикла — это не общее свойство `let`, а специальное правило только для заголовка `for` с лексическим объявлением.

```js
const fns = [];
for (let i = 0; i < 3; i++) fns.push(() => i);
console.log(fns.map(f => f())); // [0, 1, 2] — новая запись на каждой итерации

const fns2 = [];
for (var j = 0; j < 3; j++) fns2.push(() => j);
console.log(fns2.map(f => f())); // [3, 3, 3] — одна запись на весь цикл
```

`for-in` перечисляет ключи по цепочке прототипов, `for-of` требует протокола итератора. Разница становится заметна на объектах-обёртках и на изменении коллекции во время обхода.

```js
for (const k in { a: 1, b: 2 }) console.log(k);          // 'a' 'b' — строки-ключи
for (const v of new Map([['x', 1]])) console.log(v);     // ['x', 1] — пары через протокол
```

## 14.8–14.10 break, continue, return

[14.8](https://262.ecma-international.org/#sec-continue-statement), [14.9](https://262.ecma-international.org/#sec-break-statement), [14.10](https://262.ecma-international.org/#sec-return-statement) — три инструкции, дающие резкие завершения с полем «цель», равным либо пустой строке, либо метке.

```js
outer: for (const i of [1, 2]) {
  for (const j of [1, 2]) {
    if (j === 2) continue outer; // цель = 'outer'
    console.log(i, j);
  }
}
// 1 1
// 2 1
```

`return` вне функции — синтаксическая ошибка на этапе разбора, а не ошибка времени выполнения: продукция `FunctionBody` — единственное место, где `ReturnStatement` синтаксически допустима.

## 14.11–14.12 with и switch

[14.11 The with Statement](https://262.ecma-international.org/#sec-with-statement) уже разбирался в главе 9 через призму Object Environment Record; здесь он описан как синтаксическая конструкция, запрещённая в строгом коде на уровне ранних ошибок.

[14.12 The switch Statement](https://262.ecma-international.org/#sec-switch-statement) сравнивает через строгое равенство и не делает автоматического `break`. Менее очевидно: весь блок `switch` — это **один** блок с одной записью окружения на все case-ветки, если внутри используются лексические объявления.

```js
switch (1) {
  case 0: let x = 'a'; break;
  case 1: console.log(typeof x); break;
}
// ReferenceError: Cannot access 'x' before initialization
```

Все ветки `switch` делят одну запись окружения, поэтому биндинг `x` существует и во второй ветке — но инициализирующая строка из первой ветки не выполнилась, и `x` остаётся в TDZ. Здесь `typeof` не спасает: он безопасен только для по-настоящему необъявленных имён, а для биндинга в TDZ бросает исключение так же, как и обычное обращение.

```js
// объявление одноимённой let в разных case — ошибка, это одна область
try { eval('switch(1){ case 0: let y=1; break; case 1: let y=2; }'); }
catch (e) { console.log(e.constructor.name); } // SyntaxError
```

## 14.13–14.16 Метки, throw, try, debugger

[14.13 Labelled Statements](https://262.ecma-international.org/#sec-labelled-statements) — метки работают не только с циклами, но с любым блоком, что даёт способ выйти из вложенного блока без цикла.

```js
label: {
  console.log('до');
  break label;
  console.log('не выполнится');
}
console.log('после');
```

[14.15 The try Statement](https://262.ecma-international.org/#sec-try-statement), рантайм в [14.15.3](https://262.ecma-international.org/#sec-try-statement-runtime-semantics-evaluation) — самая насыщенная часть главы. Ключевое правило: если `finally` завершается резко (например, содержит `return`), его завершение **полностью заменяет** завершение из `try`/`catch`, включая уже готовое исключение.

```js
function f() {
  try { throw new Error('из try'); }
  finally { return 'из finally'; } // подавляет исключение
}
console.log(f()); // 'из finally' — ошибка потеряна безвозвратно
```

```js
function g() {
  try { return 1; }
  finally { console.log('finally выполнился'); } // логирует, но не подавляет
}
console.log(g()); // 'finally выполнился', затем 1
```

[14.16 The debugger Statement](https://262.ecma-international.org/#sec-debugger-statement) формально не имеет заданного эффекта — стандарт разрешает реализации делать с ним что угодно, включая полное игнорирование.

## Итог

> [!success] Что забирать
> - Каждая инструкция порождает Completion Record; даже пустая ветка `if` даёт `undefined`, а не отсутствие результата
> - `var` в объявлении семантически описан как обычное присваивание уже существующей переменной
> - `CreatePerIterationEnvironment` — специальное правило конкретно для заголовка `for` с лексическим объявлением, а не общее свойство `let`
> - `for-in` обходит перечислимые ключи по цепочке прототипов, `for-of` требует протокола итератора
> - `return` вне тела функции — синтаксическая ошибка на этапе разбора
> - Весь `switch` — одна область видимости на все case-ветки при наличии лексических объявлений
> - Метка применима к любому блоку, не только к циклу
> - Резкое завершение блока `finally` полностью замещает завершение из `try`/`catch`, включая уже брошенное исключение
> - `debugger` не имеет заданного стандартом эффекта
