## Циклы

Какая операция обеспечивает корректные замыкания с `let` в цикле `for`::==CreatePerIterationEnvironment==

Является ли это общим свойством `let` или специальным правилом конкретно для цикла `for`::Специальным правилом ==конкретно для заголовка for== с лексическим объявлением

Что выведет код
?
```js
const a = [], b = [];
for (let i = 0; i < 3; i++) a.push(() => i);
for (var j = 0; j < 3; j++) b.push(() => j);
```
`a.map(f=>f())` даёт `[0,1,2]`, `b.map(f=>f())` даёт `[3,3,3]`

Чем `for-in` отличается от `for-of` по механизму обхода::`for-in` перечисляет ключи по ==цепочке прототипов==, `for-of` требует ==протокола итератора==

## break, continue, return

Что хранится в поле «цель» записи о завершении для `break` и `continue`::==Метка== либо пустая строка

Что выведет код
?
```js
outer: for (const i of [1, 2]) {
  for (const j of [1, 2]) {
    if (j === 2) continue outer;
    console.log(i, j);
  }
}
```
`1 1` затем `2 1` — переход по метке пропускает вторую итерацию внутреннего цикла

На каком этапе обнаруживается `return` вне тела функции::На этапе ==разбора== — это синтаксическая ошибка, а не ошибка выполнения

## with и switch

Как классифицирована конструкция `with` в строгом коде::Запрещена на уровне ==ранних ошибок==

Сколько записей окружения у блока `switch` с лексическими объявлениями в нескольких case::==Одна== на весь switch, общая для всех веток

Что выведет код
?
```js
switch (1) {
  case 0: let x = 'a'; break;
  case 1: console.log(typeof x); break;
}
```
`ReferenceError`. Ветки делят одну запись окружения, инициализация из case 0 не выполнилась, x остаётся в TDZ — и typeof на TDZ всё равно бросает

Можно ли объявить одноимённый `let` в разных case-ветках одного switch::==Нет==, это одна область — получится SyntaxError о повторном объявлении

## Метки, try/finally

Работает ли метка только с циклами::==Нет==, метка применима к любому блоку — способ выйти из вложенного блока без цикла

Что произойдёт, если блок `finally` завершается через `return`, а перед этим в `try` было выброшено исключение::Завершение `finally` ==полностью заменяет== завершение из try — исключение теряется безвозвратно

Что выведет код
?
```js
function f() {
  try { throw new Error('из try'); }
  finally { return 'из finally'; }
}
```
`'из finally'` — return в finally подавляет исключение

Подавляет ли обычное логирование в `finally` (без return) завершение из try::==Нет==, побочный эффект выполняется, но завершение из try сохраняется

Задан ли стандартом эффект инструкции `debugger`::==Нет==, реализация вправе делать с ней что угодно, включая полное игнорирование
