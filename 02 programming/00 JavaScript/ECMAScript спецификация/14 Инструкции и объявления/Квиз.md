> [!question] Что вернёт код?
> ```js
> console.log(eval('if (false) 1;'));
> ```
> a) `null`
> b) `undefined`
> c) `1`
> d) выбросит `SyntaxError`
>> [!success]- Answer
>> b) `undefined`
>> Пустая ветка if всё равно порождает запись о завершении со значением undefined, а не отсутствие результата

> [!question] Как семантически описано присваивание значения в объявлении `var x = 1`?
> a) как создание новой переменной с одновременной инициализацией
> b) как обычное присваивание уже существующей переменной
> c) как вызов конструктора
> d) отдельного описания нет
>> [!success]- Answer
>> b) как обычное присваивание уже существующей переменной
>> Переменная var уже существует благодаря инстанцированию деклараций до выполнения кода

> [!question] Что выведет код?
> ```js
> const a = [], b = [];
> for (let i = 0; i < 3; i++) a.push(() => i);
> for (var j = 0; j < 3; j++) b.push(() => j);
> console.log(a.map(f => f()), b.map(f => f()));
> ```
> a) `[0,1,2] [0,1,2]`
> b) `[3,3,3] [3,3,3]`
> c) `[0,1,2] [3,3,3]`
> d) `[3,3,3] [0,1,2]`
>> [!success]- Answer
>> c) `[0,1,2] [3,3,3]`
>> CreatePerIterationEnvironment — специальное правило для заголовка for с лексическим объявлением, не общее свойство let

> [!question] Является ли корректность замыканий с let в цикле for общим свойством let или специальным правилом для цикла?
>> [!success]- Answer
>> False
>> Это специальное правило конкретно для заголовка for с лексическим объявлением, реализованное операцией CreatePerIterationEnvironment

> [!question] Чем for-in отличается от for-of по механизму?
> a) ничем, это синонимы
> b) for-in перечисляет ключи по цепочке прототипов, for-of требует протокола итератора
> c) for-in работает только с массивами
> d) for-of работает только с числами
>> [!success]- Answer
>> b) for-in перечисляет ключи по цепочке прототипов, for-of требует протокола итератора
>> Поэтому for-of работает с Map и Set, а for-in — с перечислимыми свойствами объекта

> [!question] Что выведет код?
> ```js
> outer: for (const i of [1, 2]) {
>   for (const j of [1, 2]) {
>     if (j === 2) continue outer;
>     console.log(i, j);
>   }
> }
> ```
> a) `1 1`, `1 2`, `2 1`, `2 2`
> b) `1 1`, `2 1`
> c) `1 1`
> d) ничего не выведет
>> [!success]- Answer
>> b) `1 1`, `2 1`
>> continue с меткой переходит к следующей итерации внешнего цикла, минуя вторую итерацию внутреннего

> [!question] На каком этапе обнаруживается `return` вне тела функции?
> a) во время выполнения, как обычное исключение
> b) на этапе разбора, как синтаксическая ошибка
> c) не обнаруживается вовсе
> d) зависит от режима строгости
>> [!success]- Answer
>> b) на этапе разбора, как синтаксическая ошибка
>> Продукция ReturnStatement синтаксически допустима только внутри тела функции

> [!question] Разрешена ли конструкция with в строгом коде?
>> [!success]- Answer
>> False
>> Запрещена на уровне ранних ошибок — обнаруживается на этапе разбора, а не выполнения

> [!question] Сколько записей окружения у блока switch с лексическими объявлениями в разных case-ветках?
> a) одна на весь switch
> b) одна на каждую ветку
> c) ни одной, лексические объявления в switch запрещены
> d) зависит от количества веток
>> [!success]- Answer
>> a) одна на весь switch
>> Все case-ветки делят общую запись окружения

> [!question] Что выведет код?
> ```js
> switch (1) {
>   case 0: let x = 'a'; break;
>   case 1: console.log(typeof x); break;
> }
> ```
> a) `'undefined'`
> b) выбросит `ReferenceError`
> c) `'a'`
> d) выбросит `SyntaxError`
>> [!success]- Answer
>> b) выбросит `ReferenceError`
>> Ветки делят одну запись окружения. Case 0 не выполнился, инициализация x не произошла, биндинг остался в TDZ — typeof на TDZ бросает исключение

> [!question] Что произойдёт при попытке объявить одноимённый `let` в разных case одного switch?
> ```js
> switch (1) { case 0: let y = 1; break; case 1: let y = 2; }
> ```
> a) выполнится без ошибок, каждая ветка получит свою переменную
> b) выбросит SyntaxError о повторном объявлении
> c) вторая переменная перезапишет первую
> d) выбросит TypeError
>> [!success]- Answer
>> b) выбросит SyntaxError о повторном объявлении
>> Все case-ветки — одна область видимости, повторное лексическое объявление в ней запрещено

> [!question] Работает ли метка только с циклами?
>> [!success]- Answer
>> False
>> Метка применима к любому блоку — это способ выйти из вложенного блока без использования цикла

> [!question] Что выведет код?
> ```js
> const log = [];
> label: {
>   log.push('до');
>   break label;
>   log.push('не выполнится');
> }
> log.push('после');
> console.log(log);
> ```
> a) `['до', 'не выполнится', 'после']`
> b) `['до', 'после']`
> c) `['до']`
> d) выбросит `SyntaxError`
>> [!success]- Answer
>> b) `['до', 'после']`
>> break с меткой на блоке выходит из этого блока, минуя оставшийся код внутри него

> [!question] Что выведет код?
> ```js
> function f() {
>   try { throw new Error('из try'); }
>   finally { return 'из finally'; }
> }
> console.log(f());
> ```
> a) выбросит исключение 'из try'
> b) `'из finally'`
> c) `undefined`
> d) выбросит `TypeError`
>> [!success]- Answer
>> b) `'из finally'`
>> Резкое завершение блока finally полностью заменяет завершение из try, включая уже готовое исключение — оно теряется безвозвратно

> [!question] Что выведет код?
> ```js
> const log = [];
> function g() {
>   try { return 1; }
>   finally { log.push('finally'); }
> }
> const res = g();
> console.log(log, res);
> ```
> a) `['finally'] 1`
> b) `[] 1`
> c) `['finally'] undefined`
> d) выбросит исключение
>> [!success]- Answer
>> a) `['finally'] 1`
>> Обычное (не резкое) выполнение finally не подавляет завершение из try — побочный эффект выполняется, а результат сохраняется

> [!question] Что выведет код?
> ```js
> {
>   console.log(typeof blockFn);
>   function blockFn() {}
> }
> ```
> a) `'undefined'`
> b) `'function'`
> c) выбросит `ReferenceError`
> d) выбросит `SyntaxError`
>> [!success]- Answer
>> b) `'function'`
>> Функциональная декларация внутри блока инстанцируется в этом же блоке, до выполнения первой инструкции блока
