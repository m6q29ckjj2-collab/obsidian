> [!question] Что делает объект «обычным» в терминах спецификации?
> a) отсутствие прототипа
> b) ни один из внутренних методов не переопределён
> c) отсутствие символьных ключей
> d) неизменяемость
>> [!success]- Answer
>> b) ни один из внутренних методов не переопределён
>> Все одиннадцать реализованы поведением по умолчанию из главы 10.1

> [!question] Что выведет код?
> ```js
> let calls = 0;
> const base = { set value(v) { calls++; } };
> const child = Object.create(base);
> child.value = 1;
> Object.defineProperty(child, 'value', { value: 2 });
> console.log(calls, child.value, Object.hasOwn(child, 'value'));
> ```
> a) `1 2 true`
> b) `2 2 true`
> c) `1 1 false`
> d) `0 2 true`
>> [!success]- Answer
>> a) `1 2 true`
>> Присваивание идёт по цепочке прототипов и вызывает сеттер. Определение свойства работает только с собственным и аксессор игнорирует

> [!question] Что выведет код?
> ```js
> let calls = 0;
> const target = { set greeting(v) { calls++; } };
> Object.assign(target, { greeting: 'привет' });
> const spread = { ...target, greeting: 'привет' };
> console.log(calls);
> ```
> a) `0`
> b) `1`
> c) `2`
> d) `3`
>> [!success]- Answer
>> b) `1`
>> Копирование через assign вызывает сеттер, а раскрытие в новый литерал создаёт обычное свойство и аксессор не трогает

> [!question] Что вернёт вызов?
> ```js
> const sym = Symbol('s');
> const obj = { b: 1, 2: 2, a: 3, 1: 4, [sym]: 5, '01': 6 };
> console.log(Reflect.ownKeys(obj).map(String).join(','));
> ```
> a) `b,2,a,1,01,Symbol(s)`
> b) `1,2,b,a,01,Symbol(s)`
> c) `1,2,01,b,a,Symbol(s)`
> d) порядок не определён
>> [!success]- Answer
>> b) `1,2,b,a,01,Symbol(s)`
>> Целочисленные индексы по возрастанию, затем строки в порядке добавления, затем символы. Ключ с ведущим нулём каноническим индексом не считается

> [!question] Что выведет код?
> ```js
> const dict = Object.create(null);
> dict.key = 1;
> console.log(typeof dict.toString, 'key' in dict);
> ```
> a) `function true`
> b) `undefined true`
> c) `undefined false`
> d) выбросит `TypeError`
>> [!success]- Answer
>> b) `undefined true`
>> Объект без прототипа не наследует методы Object.prototype

> [!question] Когда определяется режим связывания получателя функции?
> a) при каждом вызове
> b) при создании функции
> c) при первом обращении к получателю
> d) при связывании через bind
>> [!success]- Answer
>> b) при создании функции
>> Поэтому режим задаётся местом объявления, а не местом вызова

> [!question] Что выведет код?
> ```js
> class Counter {
>   #n = 0;
>   inc() { this.#n++; }
> }
> const m = new Counter().inc;
> try { m(); } catch (e) { console.log(e.constructor.name); }
> ```
> a) `TypeError`
> b) `ReferenceError`
> c) `SyntaxError`
> d) ничего не выведет
>> [!success]- Answer
>> a) `TypeError`
>> Тело класса всегда строгое, поэтому оторванный метод получает пустое значение вместо глобального объекта, и обращение к приватному полю падает

> [!question] Что выведет код?
> ```js
> function RetObj() { this.a = 1; return { b: 2 }; }
> function RetPrim() { this.a = 1; return 42; }
> console.log(JSON.stringify(new RetObj()), JSON.stringify(new RetPrim()));
> ```
> a) `{"b":2} 42`
> b) `{"b":2} {"a":1}`
> c) `{"a":1} {"a":1}`
> d) `{"a":1} 42`
>> [!success]- Answer
>> b) `{"b":2} {"a":1}`
>> Конструирование возвращает объект тела, только если это действительно объект. Примитив отбрасывается в пользу созданного экземпляра

> [!question] Перечислите встроенные экзотические объекты
> a) Bound Function, Array, String, Arguments, TypedArray, Module Namespace, Immutable Prototype
> b) только Array и String
> c) все объекты являются экзотическими
> d) Proxy и WeakMap
>> [!success]- Answer
>> a) Bound Function, Array, String, Arguments, TypedArray, Module Namespace, Immutable Prototype
>> Каждый переопределяет свой набор внутренних методов

> [!question] Что выведет код?
> ```js
> const arr = [];
> arr[5] = 'x';
> console.log(arr.length, Object.keys(arr).length, 1 in arr);
> ```
> a) `6 1 false`
> b) `1 1 true`
> c) `6 6 true`
> d) `5 1 false`
>> [!success]- Answer
>> a) `6 1 false`
>> Экзотическое поведение массива работает и в обратную сторону: запись по индексу автоматически растягивает length. Между элементами остаются дырки — отсутствующие свойства, а не значения undefined

> [!question] Что выведет код?
> ```js
> function f() { return this.tag; }
> const once = f.bind({ tag: 'a' });
> console.log(once.bind({ tag: 'b' })());
> ```
> a) `a`
> b) `b`
> c) `undefined`
> d) выбросит `TypeError`
>> [!success]- Answer
>> a) `a`
>> Повторное связывание оборачивает уже связанную функцию, но внутренние слоты первой перезаписать не может

> [!question] Что произойдёт?
> ```js
> try { Object.setPrototypeOf(Object.prototype, {}); }
> catch (e) { console.log(e.constructor.name); }
> ```
> a) выведет `TypeError`
> b) прототип сменится без ошибок
> c) выведет `SyntaxError`
> d) ничего не произойдёт
>> [!success]- Answer
>> a) выведет `TypeError`
>> Object.prototype — экземпляр с неизменяемым прототипом, смена запрещена внутренним методом

> [!question] Делегированы ли ловушкам прокси все внутренние методы безусловно?
>> [!success]- Answer
>> False
>> Каждая ловушка обязана соблюдать инварианты, привязанные к целевому объекту — делегирование не безусловное

> [!question] Что произойдёт при чтении?
> ```js
> const target = Object.freeze({ x: 1 });
> const p = new Proxy(target, { get: () => 'подмена' });
> p.x;
> ```
> a) вернёт `'подмена'`
> b) вернёт `1`
> c) выбросит `TypeError`
> d) вернёт `undefined`
>> [!success]- Answer
>> c) выбросит `TypeError`
>> Для неконфигурируемого неперезаписываемого свойства ловушка обязана вернуть исходное значение

> [!question] Зачем нужны инварианты прокси?
> a) для повышения производительности
> b) чтобы прокси не мог сделать замороженный объект видимым как незамороженный
> c) чтобы прокси нельзя было использовать с массивами
> d) для совместимости со старыми версиями языка
>> [!success]- Answer
>> b) чтобы прокси не мог сделать замороженный объект видимым как незамороженный
>> Без этих проверок гарантии Object.freeze рухнули бы при первом же оборачивании в прокси

> [!question] Сколько из этих ловушек выбросят исключение?
> ```js
> const t1 = {}; Object.defineProperty(t1, 'f', { value: 1, configurable: false });
> 'f' in new Proxy(t1, { has: () => false });
> Object.keys(new Proxy({}, { ownKeys: () => ['a', 'a'] }));
> Object.isExtensible(new Proxy(Object.preventExtensions({}), { isExtensible: () => true }));
> ```
> a) ни одна
> b) одна
> c) две
> d) три
>> [!success]- Answer
>> d) три
>> Нельзя скрыть неконфигурируемое свойство, вернуть дубликаты ключей и объявить нерасширяемый объект расширяемым

> [!question] Какая операция стоит за `Object.create`?
>> [!success]- Answer
>> OrdinaryObjectCreate
>> Создаёт объект с заданным прототипом без дополнительных собственных свойств
