## Внутренние методы обычного объекта

Что делает объект «обычным»::Ни один из ==одиннадцати внутренних методов== не переопределён — все реализованы поведением по умолчанию из главы 10.1

Чем `Set` отличается от `DefineOwnProperty`
?
`Set` идёт по ==цепочке прототипов== и вызывает наследованные сеттеры.
`DefineOwnProperty` работает только с ==собственным свойством== и аксессоры игнорирует.

Вызовет ли `Object.assign` наследованный сеттер целевого объекта::==Да==, он использует Set

Вызовет ли раскрытие объекта в новый литерал наследованный сеттер::==Нет==, оно использует CopyDataProperties, а не Set

Что выведет код
?
```js
const base = { set value(v) { console.log('сеттер'); } };
const child = Object.create(base);
Object.defineProperty(child, 'value', { value: 2 });
```
Ничего не выведет — DefineOwnProperty работает с собственным свойством ребёнка и наследованный сеттер не вызывает.

Гарантирован ли порядок собственных ключей объекта::==Да==, операцией OrdinaryOwnPropertyKeys

Каков этот порядок::Целочисленные индексы по ==возрастанию==, затем строки в порядке добавления, затем символы в порядке добавления

Какая операция стоит за `Object.create`::==OrdinaryObjectCreate==

## Функциональные объекты

Когда определяется слот режима связывания получателя функции::При ==создании== функции, а не при вызове

Три значения этого слота::`lexical` (стрелки), `strict`, `global`

Почему оторванный метод класса даёт `TypeError`, а не тихо портит глобальный объект::Тело класса всегда строгое, значит режим связывания равен `strict`, и получатель не заменяется глобальным объектом

Чем встроенная функция отличается снаружи от функции на JavaScript::==Ничем== для `typeof` — оба дают `'function'`, хотя реализованы разными видами объектов

Что вернёт конструктор, если тело функции вернуло объект::==Возвращённый объект==, а не только что созданный экземпляр

Что вернёт конструктор, если тело функции вернуло примитив::Созданный экземпляр — ==примитив отбрасывается==

## Экзотические объекты

Перечислите встроенные экзотические объекты::Bound Function, Array, String, Arguments, TypedArray, Module Namespace, Immutable Prototype

Что переопределяет Array Exotic Object::`[[DefineOwnProperty]]` — держит ==длину в связи с индексами==

Что произойдёт при `Object.defineProperty(arr, 'length', { value: 1 })` на массиве `[1,2,3]`::Массив станет `[1]` — лишние элементы удаляются переопределённым методом

Что переопределяет Immutable Prototype Exotic Object::`[[SetPrototypeOf]]` ==всегда отказывает==

Где встречается неизменяемый прототип на практике::У `Object.prototype` — попытка сменить его прототип выбрасывает `TypeError`

Перезаписывает ли повторный `bind` связанного получателя::==Нет==. Первое связывание побеждает, повторный bind оборачивает уже связанную функцию

Что выведет код
?
```js
function f() { return this.tag; }
const once = f.bind({ tag: 'a' });
once.bind({ tag: 'b' })();
```
`'a'` — внутренние слоты связанной функции хранят первого получателя, и он побеждает при вызове.

## Прокси

Являются ли все внутренние методы прокси делегированными ловушкам::==Да==, но не безусловно — каждая ловушка обязана соблюдать инварианты целевого объекта

Что произойдёт при чтении, если ловушка `get` подменяет значение неконфигурируемого неперезаписываемого свойства::`TypeError` — ловушка обязана вернуть исходное значение

Зачем нужны инварианты прокси::Без них прокси мог бы притвориться, что замороженный объект не заморожен, и гарантии `Object.freeze` рухнули бы при оборачивании

Назовите три типовых инварианта, которые прокси не может нарушить::Нельзя скрыть неконфигурируемое свойство, вернуть дубликаты ключей, объявить нерасширяемый объект расширяемым
