# Глава 10 · Обычные и экзотические объекты — отчёт

> [!info] Раздел спецификации
> [10 Ordinary and Exotic Objects Behaviours](https://262.ecma-international.org/#sec-ordinary-and-exotic-objects-behaviours)
> Карточки → [[Карточки]] · квиз → [[Квиз]] · карта → [[00 Карта]]

Глава 6 объявила, что объект — это набор внутренних методов. Здесь описано, **как именно** они реализованы по умолчанию — и что переопределяют массивы, функции, строки, прокси и другие экзотические объекты.

---

## 10.1 Внутренние методы обычного объекта

[10.1 Ordinary Object Internal Methods and Internal Slots](https://262.ecma-international.org/#sec-ordinary-object-internal-methods-and-internal-slots) даёт эталонную реализацию всех одиннадцати методов из главы 6. «Обычный» объект — тот, у которого ни один из них не переопределён.

| Метод | Раздел | Что делает |
|---|---|---|
| GetPrototypeOf | [10.1.1.1](https://262.ecma-international.org/#sec-ordinarygetprototypeof) | вернуть значение слота прототипа |
| SetPrototypeOf | [10.1.2.1](https://262.ecma-international.org/#sec-ordinarysetprototypeof) | сменить прототип, запретить цикл |
| IsExtensible | [10.1.3.1](https://262.ecma-international.org/#sec-ordinaryisextensible) | проверить флаг расширяемости |
| PreventExtensions | [10.1.4.1](https://262.ecma-international.org/#sec-ordinarypreventextensions) | сбросить флаг расширяемости |
| GetOwnProperty | [10.1.5.1](https://262.ecma-international.org/#sec-ordinarygetownproperty) | вернуть дескриптор собственного свойства |
| DefineOwnProperty | [10.1.6.1](https://262.ecma-international.org/#sec-ordinarydefineownproperty) | создать или изменить свойство |
| HasProperty | [10.1.7.1](https://262.ecma-international.org/#sec-ordinaryhasproperty) | проверить наличие с обходом прототипов |
| Get | [10.1.8.1](https://262.ecma-international.org/#sec-ordinaryget) | прочитать значение |
| Set | [10.1.9.1](https://262.ecma-international.org/#sec-ordinaryset) | записать значение |
| Delete | [10.1.10.1](https://262.ecma-international.org/#sec-ordinarydelete) | удалить свойство |
| OwnPropertyKeys | [10.1.11.1](https://262.ecma-international.org/#sec-ordinaryownpropertykeys) | перечислить собственные ключи в заданном порядке |

### DefineOwnProperty против Set — источник всех «непонятных» багов

Разница между [10.1.6.1](https://262.ecma-international.org/#sec-ordinarydefineownproperty) и [10.1.9.1](https://262.ecma-international.org/#sec-ordinaryset) объясняет добрую половину вопросов про объекты на собеседованиях.

`Set` идёт по цепочке прототипов и уважает наследованные аксессоры. `DefineOwnProperty` работает только с собственным свойством и аксессоры игнорирует.

```js
let calls = 0;
const base = { set value(v) { calls++; } };
const child = Object.create(base);

child.value = 1;                                    // Set — вызывает сеттер
Object.defineProperty(child, 'value', { value: 2 }); // DefineOwnProperty — не вызывает

console.log(calls, child.value, Object.hasOwn(child, 'value'));
// 1 2 true
```

Отсюда же разница между `Object.assign` (использует `Set`, вызывает сеттеры) и раскрытием объекта в новый литерал (использует `CopyDataProperties`, сеттеры не трогает).

Внутри `DefineOwnProperty` работает [ValidateAndApplyPropertyDescriptor](https://262.ecma-international.org/#sec-validateandapplypropertydescriptor) — [10.1.6.3](https://262.ecma-international.org/#sec-validateandapplypropertydescriptor). Именно она не даёт прокси соврать про неконфигурируемое свойство: подробнее — в разделе про прокси ниже.

### OrdinaryOwnPropertyKeys — гарантированный порядок

[10.1.11.1](https://262.ecma-international.org/#sec-ordinaryownpropertykeys) закрепляет порядок, который часто ошибочно считают неопределённым: целочисленные индексы по возрастанию, затем остальные строки в порядке добавления, затем символы.

```js
const sym = Symbol('s');
console.log(Reflect.ownKeys({ b: 1, 2: 2, a: 3, 1: 4, [sym]: 5, '01': 6 }).map(String));
// ['1','2','b','a','01','Symbol(s)']
```

### Создание объекта

[10.1.12 OrdinaryObjectCreate](https://262.ecma-international.org/#sec-ordinaryobjectcreate) — операция за `Object.create`: создать объект с заданным прототипом, без дополнительных свойств.

```js
const dict = Object.create(null);
dict.key = 1;
console.log(typeof dict.toString); // undefined — прототипа Object.prototype нет
```

## 10.2 Функциональные объекты ECMAScript

[10.2 ECMAScript Function Objects](https://262.ecma-international.org/#sec-ecmascript-function-objects) — функции, определённые кодом на JavaScript. У них переопределены `[[Call]]` и, если применимо, `[[Construct]]`.

Здесь же — слот `[[ThisMode]]`, определяемый **при создании** функции, а не при вызове: `lexical` (стрелка), `strict`, `global`. Этим слотом объясняется, что `this` внутри метода класса не превращается в глобальный объект даже в вызове без базы: тело класса всегда строгое, значит `[[ThisMode]]` равен `strict`.

```js
class Counter {
  #n = 0;
  inc() { this.#n++; }
}
const m = new Counter().inc;
try { m(); } catch (e) { console.log(e.constructor.name); } // TypeError, не портит globalThis
```

Конструирование объекта возвращённым объектом описано здесь же: если тело функции вернуло объект, конструирование отдаёт его вместо только что созданного экземпляра.

```js
function RetObj() { this.a = 1; return { b: 2 }; }
function RetPrim() { this.a = 1; return 42; }
console.log(JSON.stringify(new RetObj()), JSON.stringify(new RetPrim()));
// {"b":2} {"a":1} — примитив отбрасывается, объект побеждает
```

## 10.3 Встроенные функциональные объекты

[10.3 Built-in Function Objects](https://262.ecma-international.org/#sec-built-in-function-objects) — функции, реализованные не кодом на JavaScript, а самим движком: `Array.prototype.map`, `Object.keys` и подобные. Формально это другой вид объекта, но снаружи неотличимый: `typeof` даёт `'function'` для обоих видов.

## 10.4 Встроенные экзотические объекты

[10.4 Built-in Exotic Object Internal Methods and Slots](https://262.ecma-international.org/#sec-built-in-exotic-object-internal-methods-and-slots) перечисляет объекты, переопределяющие поведение по умолчанию.

| Вид | Раздел | Что переопределено |
|---|---|---|
| Bound Function | [10.4.1](https://262.ecma-international.org/#sec-bound-function-exotic-objects) | `[[Call]]` подставляет связанного получателя |
| Array | [10.4.2](https://262.ecma-international.org/#sec-array-exotic-objects) | `[[DefineOwnProperty]]` держит длину в связи с индексами |
| String | [10.4.3](https://262.ecma-international.org/#sec-string-exotic-objects) | индексы ведут себя как собственные свойства |
| Arguments | [10.4.4](https://262.ecma-international.org/#sec-arguments-exotic-objects) | в нестрогом режиме связаны с параметрами |
| TypedArray | [10.4.5](https://262.ecma-international.org/#sec-typedarray-exotic-objects) | индексы читают буфер напрямую |
| Module Namespace | [10.4.6](https://262.ecma-international.org/#sec-module-namespace-exotic-objects) | `[[Get]]` читает живое связывание модуля |
| Immutable Prototype | [10.4.7](https://262.ecma-international.org/#sec-immutable-prototype-exotic-objects) | `[[SetPrototypeOf]]` всегда отказывает |

### Array — самый известный пример

```js
const arr = [1, 2, 3];
Object.defineProperty(arr, 'length', { value: 1 });
console.log(arr); // [1] — лишние элементы удалены переопределённым DefineOwnProperty
```

### Bound Function — почему повторный bind не перезаписывает

```js
function f() { return this.tag; }
const once = f.bind({ tag: 'a' });
console.log(once.bind({ tag: 'b' })()); // 'a'
```

Связанная функция хранит целевую функцию и связанного получателя в собственных слотах. Повторный `bind` создаёт **новую** связанную функцию, оборачивающую первую, но при вызове управление доходит до внутренней, и её слот побеждает.

### Immutable Prototype — единственный объект с этим поведением в браузере

```js
console.log(Object.getPrototypeOf(Object.prototype)); // null
try { Object.setPrototypeOf(Object.prototype, {}); } catch (e) { console.log(e.constructor.name); }
// TypeError — прототип Object.prototype неизменяем
```

## 10.5 Внутренние методы прокси

[10.5 Proxy Object Internal Methods and Internal Slots](https://262.ecma-international.org/#sec-proxy-object-internal-methods-and-internal-slots). Прокси — экзотический объект, у которого **все** внутренние методы делегированы ловушкам. Но делегирование не безусловное: каждая ловушка обязана соблюдать инварианты, привязанные к целевому объекту.

```js
const target = Object.freeze({ x: 1 });
const p = new Proxy(target, { get: () => 'подмена' });
try { p.x; } catch (e) { console.log(e.constructor.name); }
// TypeError — для неконфигурируемого неперезаписываемого свойства
// ловушка обязана вернуть исходное значение
```

Без этой проверки прокси мог бы притвориться, что объект не заморожен, хотя он заморожен, — и все гарантии `Object.freeze` рухнули бы при первом же оборачивании.

Три инварианта, которые встречаются на практике чаще всего:

```js
// нельзя скрыть неконфигурируемое свойство
const t1 = {}; Object.defineProperty(t1, 'f', { value: 1, configurable: false });
try { 'f' in new Proxy(t1, { has: () => false }); } catch (e) { console.log(1, e.constructor.name); }

// нельзя вернуть дубликаты ключей
try { Object.keys(new Proxy({}, { ownKeys: () => ['a', 'a'] })); } catch (e) { console.log(2, e.constructor.name); }

// нельзя объявить нерасширяемый объект расширяемым
const t2 = Object.preventExtensions({});
try { Object.isExtensible(new Proxy(t2, { isExtensible: () => true })); } catch (e) { console.log(3, e.constructor.name); }
// 1 TypeError
// 2 TypeError
// 3 TypeError
```

## Итог

> [!success] Что забирать
> - Одиннадцать внутренних методов обычного объекта реализованы в 10.1; переопределение хотя бы одного делает объект экзотическим
> - `Set` идёт по цепочке прототипов и уважает наследованные сеттеры, `DefineOwnProperty` работает только с собственным свойством
> - Отсюда разница между `Object.assign` (вызывает сеттеры) и раскрытием в литерал (не вызывает)
> - Порядок собственных ключей гарантирован: целые индексы по возрастанию, затем строки, затем символы, в порядке добавления
> - Слот `[[ThisMode]]` функции определяется при создании, а не при вызове; тело класса всегда строгое
> - Конструирование возвращает объект тела функции, если это объект, и отбрасывает примитив
> - Массивы, строки, объект аргументов, связанные функции, типизированные массивы, пространства имён модулей — все экзотические по-своему
> - Повторный `bind` не перезаписывает связанного получателя: первое связывание побеждает
> - Внутренние методы прокси делегированы ловушкам, но не безусловно: инварианты, привязанные к целевому объекту, ловушка нарушить не может
