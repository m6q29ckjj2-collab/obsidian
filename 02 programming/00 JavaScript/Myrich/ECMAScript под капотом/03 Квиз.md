> [!question] Что выведет код? Здесь работают инстанцирование деклараций и окружение параметров одновременно
> ```js
> const value = 'внешнее';
> function f(a = value) {
>   var value = 'внутреннее';
>   return a;
> }
> console.log(f());
> ```
> a) `'внешнее'`
> b) `'внутреннее'`
> c) `undefined`
> d) `ReferenceError`
>> [!success]- Answer
>> a) `'внешнее'`
>> Наличие дефолта создаёт отдельное окружение для списка параметров, дефолт вычисляется в нём. Объявление var в теле живёт в дочернем окружении и повлиять не может

> [!question] Сколько ключей окажется в объекте? Пересекаются ToPropertyKey и порядок ключей
> ```js
> const o = {};
> o[1] = 'a'; o['1'] = 'b'; o[{}] = 'c'; o[Symbol('s')] = 'd';
> console.log(Object.keys(o).length);
> ```
> a) 2
> b) 3
> c) 4
> d) 1
>> [!success]- Answer
>> a) 2
>> Числовой и строковый ключ схлопываются в один, объект превращается в строку с текстовым представлением, а символьный ключ в Object.keys не попадает

> [!question] Что выведет код? Нужны и протокол итератора, и приостановка контекста генератора
> ```js

>   finally { console.log('finally'); }
> }
> const [first] = g();
> console.log(first);
> ```
> a) `1`, затем `finally`
> b) `finally`, затем `1`
> c) только `1`
> d) только `finally`
>> [!success]- Answer
>> b) `finally`, затем `1`
>> Деструктуризация короче последовательности вызывает закрытие итератора, оно возобновляет приостановленный контекст в режиме возврата и запускает finally — всё до возврата управления

> [!question] Сколько записей окажется в коллекции? Сходятся нормализация строк и алгоритм SameValueZero

> [!question] Что попадёт в результат? Пересекаются дескрипторы свойств и семантика спреда

> [!question] Инвариант Proxy может выбросить исключение даже при простом чтении свойства
>> [!success]- Answer
>> True
>> Если у цели свойство неконфигурируемое и неперезаписываемое, ловушка обязана вернуть именно его значение. Иначе гарантии Object.freeze рухнули бы при оборачивании

> [!question] Что выведет код? Нужны и порядок микрозадач, и момент постановки продолжения
> ```js
> async function a() { await null; console.log('a'); }

> console.log('c');
> ```
> a) `c a b`
> b) `c b a`
> c) `a b c`
> d) `a c b`
>> [!success]- Answer

> [!question] Что вернёт последняя строка? Сходятся статические поля и прототипная цепочка конструкторов
> ```js
> class Base { static reg = new Map(); static add(k) { this.reg.set(k, 1); } }
> class Sub extends Base {}
> Sub.add('x');
> console.log(Base.reg.has('x'));
> ```
> a) `true`
> b) `false`
> c) `undefined`
> d) `TypeError`
>> [!success]- Answer
>> a) `true`
>> В статическом методе this равен Sub, но Sub.reg не собственное свойство — оно находится по цепочке и указывает на тот же объект Map

> [!question] Что выведет код в нестрогом режиме? Пересекаются mapped arguments и наличие дефолта

> [!question] Что выведет код? Работают Annex B и различие режимов

> [!question] Почему проверка типа даёт неверный результат? Сходятся Realm и семантика instanceof
> ```js
> const arr = runInNewContext('[1, 2, 3]');
> console.log(arr instanceof Array, Array.isArray(arr));
> ```
> a) `true true`
> b) `false true`
> c) `true false`
> d) `false false`
>> [!success]- Answer
>> b) `false true`
>> У другого realm свой Array.prototype, а instanceof сравнивает объекты прототипов. Array.isArray смотрит на внутреннюю природу объекта

> [!question] Что выведет код? Нужны и лексическое окружение цикла, и захват записи замыканием

> ```
> a) `[0, 1, 2]`
> b) `[3, 3, 3]`

> [!question] Как поведут себя три механизма с непарным суррогатом? Сходятся определение типа String и границы системы

> ```

> c) все три вернут строку без изменений

>> [!success]- Answer

> [!question] Почему хвостовая рекурсия внутри `try` не оптимизируется даже в JavaScriptCore?
