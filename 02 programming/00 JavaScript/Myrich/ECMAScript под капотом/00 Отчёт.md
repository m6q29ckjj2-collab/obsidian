## 0. Как вообще читать спецификацию

Без этого раздела остальные читаются как набор фактов. Спецификация — не учебник, а формальный алгоритм, и у неё своя нотация.

**Абстрактные операции** — функции, существующие только в тексте стандарта: `ToPrimitive`, `GetValue`, `OrdinaryGet`. Их нельзя вызвать из кода, но именно они описывают, что делает движок.

**Completion Record** — результат любого шага. Это запись `{ [[Type]], [[Value]], [[Target]] }`, где тип — `normal`, `throw`, `return`, `break` или `continue`. Отсюда два ключевых значка:

- `? expr` — сокращение для `ReturnIfAbrupt`: если внутри случился `throw`, немедленно пробросить наружу
- `! expr` — утверждение «здесь исключение невозможно»; если оно всё-таки произойдёт, это баг в движке или в самой спецификации

**Внутренние слоты** пишутся как `[[Environment]]`, `[[ThisValue]]`, `[[Prototype]]`. Это состояние объекта, недоступное из JS напрямую.

> [!tip] Практический приём
> Когда непонятно поведение — ищите не «hoisting» или «coercion» (таких терминов в стандарте нет), а имя абстрактной операции. `hoisting` → `FunctionDeclarationInstantiation`; «приведение типов» → `ToPrimitive` / `ToNumeric`; «замыкание» → `Environment Record`.

Отсюда же ответ на вопрос из видео `spec:05` — почему язык считается непонятым. Массовые материалы описывают фольклор («переменные всплывают наверх»), а стандарт описывает механику (движок создаёт биндинги до выполнения кода). Фольклор даёт верный прогноз в простых случаях и ломается на краевых — а именно они и попадаются на собеседованиях.

## 1. Execution Context и Call Stack

### Что такое контекст исполнения

Контекст исполнения — структура, которую движок создаёт перед выполнением любого кода. В ней:

- **code evaluation state** — точка, с которой продолжить (нужна для генераторов)
- **Function** — функциональный объект или `null` для скрипта/модуля
- **Realm** — набор интринсиков: свой `Array`, свой `Object.prototype` и так далее
- **LexicalEnvironment** — окружение для `let`/`const`/классов
- **VariableEnvironment** — окружение для `var` и функций
- **PrivateEnvironment** — приватные поля классов

Контексты складываются в стек, вершина — **running execution context**.

> [!warning] Чего в спецификации нет
> `RangeError: Maximum call stack size exceeded` стандартом **не описан**. Ограничение глубины отдано на откуп реализации, поэтому предел зависит от движка, от размера фреймов и даже от количества аргументов функции.

```js
// Глубина стека — величина непостоянная даже в рамках одного движка
function probe(n = 0) {
  try { return probe(n + 1); } catch { return n; }
}

function probeHeavy(n = 0, a = 1, b = 2, c = 3, d = 4) {
  try { return probeHeavy(n + 1, a, b, c, d); } catch { return n; }
}

console.log(probe());       // порядка 10⁴
console.log(probeHeavy());  // заметно меньше — фрейм толще
```

### Хвостовые вызовы

В стандарте есть **proper tail calls**: вызов в хвостовой позиции должен переиспользовать фрейм. Операция называется `PrepareForTailCall`.

> [!danger] Практика расходится со стандартом
> Из мейнстримных движков это реализовал только JavaScriptCore (Safari). В V8 и SpiderMonkey оптимизация не включена, и рекурсия на миллион вызовов упадёт. Полагаться на PTC в кроссбраузерном коде нельзя — переписывайте в цикл.

```js
'use strict';
const sum = (n, acc = 0) => n === 0 ? acc : sum(n - 1, acc + n); // хвостовой вызов
sum(1e6); // Safari: 500000500000 · V8: RangeError
```

### Микрозадачи живут вне стека

Промисы не попадают в стек контекстов. Их коллбэки ставятся в очередь задач через `HostEnqueuePromiseJob` и выполняются, **когда стек полностью опустел**.

```js
console.log('sync 1');

setTimeout(() => console.log('macro'), 0);

Promise.resolve()
  .then(() => console.log('micro 1'))
  .then(() => console.log('micro 2'));

queueMicrotask(() => console.log('micro 3'));

console.log('sync 2');

// sync 1 · sync 2 · micro 1 · micro 3 · micro 2 · macro
```

Порядок `micro 1 → micro 3 → micro 2` — не случайность. Второй `.then` регистрируется только после исполнения первого, поэтому в очередь он попадает уже после `queueMicrotask`.

## 2. Инстанцирование деклараций — то, что зовут hoisting

Термина «hoisting» в ECMA-262 нет. Есть операции, которые выполняются **до** первой строки кода: `GlobalDeclarationInstantiation`, `FunctionDeclarationInstantiation`, `BlockDeclarationInstantiation`, `EvalDeclarationInstantiation`.

Каждая проходит по телу и создаёт биндинги. Ничто никуда не «поднимается» — просто имена появляются в окружении раньше, чем начинает исполняться код.

### Четыре разных начальных состояния

| Объявление | Момент создания | Начальное значение |
|---|---|---|
| `function` | инстанцирование | **готовый функциональный объект** |
| `var` | инстанцирование | `undefined` |
| `let` | инстанцирование | *uninitialized* → TDZ |
| `const` | инстанцирование | *uninitialized* → TDZ |
| `class` | инстанцирование | *uninitialized* → TDZ |

```js
fn();   // работает — объект уже создан
function fn() { return 1; }

expr(); // TypeError: expr is not a function — биндинг есть, значение undefined
var expr = function () {};

lex();  // ReferenceError: Cannot access 'lex' before initialization
let lex = function () {};
```

Разница между `TypeError` и `ReferenceError` здесь диагностична: первая означает, что биндинг существует и хранит `undefined`, вторая — что биндинг существует, но не инициализирован.

### TDZ и единственный случай, когда `typeof` бросает

```js
console.log(typeof neverDeclared); // 'undefined' — безопасно
console.log(typeof inTDZ);         // ReferenceError
let inTDZ = 1;
```

Это единственная ситуация во всём языке, где `typeof` выбрасывает исключение. Приём «проверю через typeof, вдруг переменная не объявлена» с приходом `let` перестал быть безопасным.

### Функции в блоках и Annex B

```js
'use strict';
{ function blockFn() {} }
typeof blockFn; // 'undefined' — область видимости строго блочная
```

```js
// без strict mode — Annex B.3.3, легализованное историческое поведение
{ function blockFn() {} }
typeof blockFn; // 'function' — имя протекло в функциональную область
```

> [!warning] Annex B — не опциональщина
> Приложение B формально помечено как нормативно-опциональное для не-браузерных сред, но в браузерах реализовано везде. Именно оно отвечает за протекающие из блоков функции, за `escape`/`unescape` и за строковые методы вроде `String.prototype.blink`.

## 3. Environment Records и замыкания

Замыкание — это не отдельная сущность языка. Это следствие того, что у функционального объекта есть слот `[[Environment]]`, куда при создании записывается **текущее окружение**.

### Виды записей окружения

- **Declarative** — `let`, `const`, `class`, параметры, `catch`
- **Object** — привязана к объекту; так работает глобальный `var` и `with`
- **Function** — Declarative плюс `[[ThisValue]]`, `[[NewTarget]]`, `[[FunctionObject]]`
- **Global** — гибрид Declarative и Object
- **Module** — Declarative плюс индирект-биндинги на импорты

У каждой есть `[[OuterEnv]]`. Разрешение имени — проход по этой цепочке до первого совпадения.

### Ключевой момент: захватывается окружение, а не значение

```js
const byVar = [];
for (var i = 0; i < 3; i++) byVar.push(() => i);
console.log(byVar.map(f => f())); // [3, 3, 3]

const byLet = [];
for (let j = 0; j < 3; j++) byLet.push(() => j);
console.log(byLet.map(f => f())); // [0, 1, 2]
```

Разницу делает `CreatePerIterationEnvironment`. Для `let` спецификация предписывает на каждой итерации создавать **новую** запись окружения и копировать в неё текущие значения. Для `var` окружение одно на всю функцию.

Тонкость, которую редко замечают: копирование происходит до вычисления условия, поэтому изменение переменной внутри тела видно в инкременте, но каждая замкнутая функция держит свою копию.

### Утечка через общий контекст

Практически важный случай. V8 кладёт в контекст только те переменные, которые кем-то захвачены, — но контекст **один на область видимости**.

```js
function makeLeaky() {
  const huge = new Uint8Array(50 * 1024 * 1024); // 50 МБ
  const small = 42;

  const usesHuge = () => huge.length; // из-за этой функции huge попадает в Context
  const usesSmall = () => small;

  return usesSmall; // возвращаем «лёгкую», но Context общий → 50 МБ живы
}

const f = makeLeaky(); // память не освободится, пока жив f
```

```js
function makeClean() {
  const small = (() => {
    const huge = new Uint8Array(50 * 1024 * 1024);
    return huge.length;      // huge не переживает свою IIFE
  })();

  return () => small;
}
```

> [!tip] Как диагностировать
> В DevTools → Memory снимите heap snapshot и посмотрите Retainers у крупного объекта. Если в цепочке удержания стоит `system / Context`, значит объект держит именно замыкание, а не ссылка из структуры данных.

### `var` против `let` на верхнем уровне

```js
var withVar = 1;
let withLet = 2;

globalThis.withVar; // 1        — Object Environment Record поверх globalThis
globalThis.withLet; // undefined — Declarative Environment Record
```

Глобальное окружение — гибрид. `var` и функции идут в объектную часть и становятся свойствами `globalThis`; `let`, `const` и `class` — в декларативную и остаются невидимыми снаружи. Это же объясняет, почему `var` на верхнем уровне нельзя удалить через `delete`: свойство создаётся с `[[Configurable]]: false`.

## 4. Связывание `this`

`this` — не переменная и не параметр. Это результат абстрактной операции `ResolveThisBinding`, которая обращается к ближайшему **Function Environment Record** через `GetThisEnvironment`.

У Function Environment Record есть слот `[[ThisBindingStatus]]` с тремя значениями:

- `lexical` — у стрелочных функций; своего `this` нет, поиск идёт выше по `[[OuterEnv]]`
- `uninitialized` — в конструкторе производного класса до вызова `super()`
- `initialized` — обычное состояние

### Что происходит при вызове

Операция `OrdinaryCallBindThis` работает по-разному в зависимости от режима:

```js
'use strict';
function strictFn() { return this; }

strictFn();            // undefined — передаётся как есть
strictFn.call('text'); // 'text' — примитив остаётся примитивом
strictFn.call(null);   // null
```

```js
// sloppy mode
function sloppyFn() { return this; }

sloppyFn();            // globalThis — undefined заменяется на глобальный объект
sloppyFn.call('text'); // объект String — примитив проходит через ToObject
sloppyFn.call(null);   // globalThis
typeof sloppyFn.call(1); // 'object'
```

Именно поэтому в нестрогом режиме `this` внутри метода, вызванного «оторванно», оказывается глобальным объектом, а в строгом — `undefined` с понятным `TypeError` при первом же обращении к свойству.

### Тела классов всегда строгие

```js
class Counter {
  #value = 0;
  increment() { this.#value++; return this.#value; }
}

const c = new Counter();
const detached = c.increment;
detached(); // TypeError: Cannot read private member — this === undefined
```

Классы неявно переводятся в strict mode, поэтому оторванный метод получает `undefined`, а не глобальный объект.

### TDZ для `this` в производном конструкторе

```js
class Base {}

class Derived extends Base {
  constructor() {
    // console.log(this); // ReferenceError — [[ThisBindingStatus]] === uninitialized
    super();              // BindThisValue переводит слот в initialized
    console.log(this);    // теперь можно
  }
}
```

В производном классе `this` создаётся не в момент входа в конструктор, а в момент `super()`. Поэтому обращение до вызова родителя даёт `ReferenceError` — тот же механизм, что у `let`.

### Стрелки и поля класса

```js
class Button {
  label = 'ok';

  onClickMethod() { return this.label; }
  onClickArrow = () => this.label;
}

const btn = new Button();
const m = btn.onClickMethod;
const a = btn.onClickArrow;

m(); // TypeError — this потерян
a(); // 'ok' — стрелка замкнула this инстанса
```

Разница в том, **где живёт функция**. Метод лежит в прототипе и получает `this` из вызова. Поле-стрелка создаётся заново для каждого экземпляра при конструировании и лексически захватывает `this`.

> [!warning] Цена полей-стрелок
> Каждый экземпляр получает собственный функциональный объект — это память и отсутствие переиспользования. Для компонента, который создаётся тысячами, лучше метод плюс `bind` в конструкторе или обработчик, устойчивый к потере `this`.

## 5. Object согласно спецификации

Объект в ECMAScript определён через две вещи: набор свойств и набор **внутренних методов**.

### Обязательные внутренние методы

`[[GetPrototypeOf]]`, `[[SetPrototypeOf]]`, `[[IsExtensible]]`, `[[PreventExtensions]]`, `[[GetOwnProperty]]`, `[[DefineOwnProperty]]`, `[[HasProperty]]`, `[[Get]]`, `[[Set]]`, `[[Delete]]`, `[[OwnPropertyKeys]]`. У вызываемых объектов добавляется `[[Call]]`, у конструкторов — `[[Construct]]`.

Объект называется **ordinary**, если все внутренние методы реализованы поведением по умолчанию. Если хоть один переопределён — это **exotic object**: массивы (особое `[[DefineOwnProperty]]` для `length`), `arguments` в sloppy mode, Proxy, модульные namespace-объекты, строковые объекты-обёртки.

### Дескрипторы

Свойство — это либо data property (`[[Value]]`, `[[Writable]]`, `[[Enumerable]]`, `[[Configurable]]`), либо accessor property (`[[Get]]`, `[[Set]]`, `[[Enumerable]]`, `[[Configurable]]`). Третьего не дано.

```js
const o = {};

Object.defineProperty(o, 'hidden', {
  value: 1,
  // все три флага по умолчанию false — в отличие от присваивания
});

Object.keys(o);              // [] — не enumerable
o.hidden = 99;               // молча игнорируется в sloppy mode
delete o.hidden;             // false — не configurable

'use strict';
// o.hidden = 99;            // здесь уже TypeError
```

Ловушка, стоящая денег на код-ревью: `defineProperty` без явных флагов создаёт свойство, которое не видно в `Object.keys`, не переживает spread и не сериализуется в JSON.

### Порядок ключей строго определён

Вопреки распространённому «порядок свойств не гарантирован», операция `OrdinaryOwnPropertyKeys` задаёт его жёстко:

1. Целочисленные индексы — по возрастанию числового значения
2. Остальные строковые ключи — в порядке добавления
3. Символы — в порядке добавления

```js
const sym = Symbol('s');
const obj = { b: 1, 2: 2, a: 3, 1: 4, [sym]: 5, '01': 6 };

Reflect.ownKeys(obj);
// ['1', '2', 'b', 'a', '01', Symbol(s)]
```

`'01'` не является каноническим целочисленным индексом (строка не совпадает с `ToString(ToNumber('01'))`), поэтому попадает в строковую группу и сохраняет порядок вставки. `Object.keys` и `JSON.stringify` следуют тому же порядку, а вот `for...in` дополнительно обходит прототипы, и его порядок стандартом полностью не зафиксирован.

### Proxy и инварианты

Proxy — экзотический объект, у которого внутренние методы делегируются ловушкам. Но стандарт защищает инварианты: результат ловушки проверяется операцией `ValidateAndApplyPropertyDescriptor`.

```js
const target = Object.freeze({ x: 1 });

const p = new Proxy(target, {
  get() { return 'подменённое'; }
});

p.x; // TypeError: 'get' on proxy: property 'x' is a read-only and
     // non-configurable data property on the proxy target but the
     // proxy did not return its actual value
```

Соврать про неконфигурируемое неперезаписываемое свойство нельзя — иначе рухнули бы гарантии, на которые опираются `Object.freeze` и системы безопасности вроде SES.

```js
const p2 = new Proxy({}, {
  ownKeys: () => ['a', 'a'] // дубликаты запрещены
});
Object.keys(p2); // TypeError
```

## 6. Преобразования типов: приведения не существует

Название видео провокационное, но точное. В спецификации нет операции, которая **меняет тип существующего значения**. Значения в JavaScript иммутабельны по типу; есть абстрактные операции, которые по одному значению **порождают новое**: `ToPrimitive`, `ToNumber`, `ToString`, `ToNumeric`, `ToBoolean`, `ToObject`.

Разница не терминологическая. Из неё следует, что «переменная превратилась в строку» — неверная модель: переменная как хранила ссылку на прежнее значение, так и хранит, а результат операции — отдельное новое значение.

### ToPrimitive и хинты

```js
const dual = {
  [Symbol.toPrimitive](hint) {
    switch (hint) {
      case 'number': return 42;
      case 'string': return 'строка';
      default:       return 'по умолчанию';
    }
  }
};

+dual;          // 42            — хинт number
`${dual}`;      // 'строка'      — хинт string
dual + '';      // 'по умолчанию' — хинт default
dual == 'по умолчанию'; // true
```

Если `Symbol.toPrimitive` нет, работает `OrdinaryToPrimitive`: для хинта `string` порядок `toString` → `valueOf`, для остальных — `valueOf` → `toString`.

### Единственное исключение — Date

```js
const d = new Date();
d + 1; // строка — Date трактует хинт default как string
d - 1; // число  — хинт number
```

`Date.prototype[Symbol.toPrimitive]` переопределён так, что `default` ведёт себя как `string`. Это единственный встроенный тип с таким поведением, и именно поэтому конкатенация с датой даёт человекочитаемый вид, а вычитание — миллисекунды.

### Оператор `+`

```js
1 + '1';       // '11'  — один операнд строка → конкатенация
1 + 1;         // 2
[] + {};       // '[object Object]'
[] + [];       // ''
1 + null;      // 1     — ToNumber(null) === 0
1 + undefined; // NaN   — ToNumber(undefined) === NaN
```

Алгоритм `ApplyStringOrNumericBinaryOperator`: сначала **оба** операнда проходят `ToPrimitive` без хинта, затем — если хоть один оказался строкой, выполняется конкатенация, иначе `ToNumeric` и сложение.

Важно, что `ToPrimitive` применяется к обоим до принятия решения. Поэтому объект с `valueOf`, возвращающим число, складывается арифметически даже рядом со строкой-соседкой только в том случае, если та тоже дала не-строку.

### BigInt не смешивается

```js
1n + 1;   // TypeError: Cannot mix BigInt and other types
1n + '1'; // '11' — строковый путь разрешён
1n < 2;   // true — сравнение работает
1n == 1;  // true
1n === 1; // false — разные типы
```

Арифметика требует одинаковой «числовой природы» обоих операндов, а конкатенация и сравнение — нет.

### Нестрогое равенство

`IsLooselyEqual` — алгоритм из десятка шагов. Практически значимые следствия:

```js
null == undefined;  // true  — прописано явным шагом
null == 0;          // false — null не приводится к числу
undefined == 0;     // false

[] == ![];          // true
```

Разбор последнего по шагам: `![]` → `ToBoolean([])` это `true` → `false`. Дальше `[] == false` → правый операнд число `0` → левый через `ToPrimitive` даёт `''` → `ToNumber('')` это `0` → `0 == 0`.

```js
'' == 0;      // true
'0' == 0;     // true
'' == '0';    // false — обе строки, приведения нет
NaN == NaN;   // false
```

> [!note] Единственный «магический» случай
> `document.all == null` возвращает `true`, хотя `document.all` — объект. У него есть внутренний слот `[[IsHTMLDDA]]`, введённый в стандарт ради веб-совместимости. Также `typeof document.all === 'undefined'` и объект ложен в булевом контексте. Это официально закреплённая аномалия, а не баг браузера.

## 7. Тип String: последовательность 16-битных единиц

Стандарт определяет String как конечную упорядоченную последовательность **16-битных беззнаковых целых**. Не символов. Не UTF-8. И — принципиально — **не обязательно валидный UTF-16**.

### Проблема первая: длина и индексы считают code unit

```js
const math = '𝒳'; // U+1D4B3, вне BMP

math.length;        // 2  — суррогатная пара
[...math].length;   // 1  — итератор строки идёт по code point
math[0];            // одиночный суррогат, отдельно бессмысленный
math.charCodeAt(0); // 55349 (0xD835)
math.codePointAt(0);// 119987 (0x1D4B3)
math.split('').reverse().join(''); // строка разрушена
[...math].reverse().join('');      // корректно
```

Всё, что индексирует строку напрямую — `slice`, `substring`, `charAt`, обрезка «по N символов» — разрезает суррогатные пары и порождает битые строки. Обрезка пользовательского текста по `length` это классический баг с эмодзи.

### Проблема вторая: одинаковый текст — разные строки

```js
const composed   = 'é';        // U+00E9
const decomposed = 'é';  // 'e' + combining acute

composed === decomposed;       // false
composed.length;               // 1
decomposed.length;             // 2

composed.normalize('NFC') === decomposed.normalize('NFC'); // true
```

Юникод допускает несколько представлений одного текста. Сравнение строк в спецификации — побитовое по code unit, никакой нормализации нет. Отсюда правило: любой текст, пришедший извне и участвующий в сравнении или в ключах, нормализуйте на границе системы.

### Графемные кластеры — третий уровень

```js
const flag = '🇺🇦';
flag.length;      // 4 — два суррогатных пары
[...flag].length; // 2 — два regional indicator

const family = '👨‍👩‍👧';
family.length;      // 8
[...family].length; // 5 — символы + ZWJ

const seg = new Intl.Segmenter('ru', { granularity: 'grapheme' });
[...seg.segment(flag)].length;   // 1
[...seg.segment(family)].length; // 1
```

Итого три разных «длины»: code unit (`length`), code point (спред) и графемный кластер (`Intl.Segmenter`). Пользователь считает третью, код по умолчанию использует первую.

### Строки могут быть невалидным UTF-16

```js
const lone = '\uD800'; // одиночный старший суррогат — без пары

lone.length;          // 1
lone.isWellFormed();  // false  (ES2024)
lone.toWellFormed();  // '�' — заменяющий символ

JSON.stringify(lone); // '"\\ud800"' — well-formed JSON.stringify, ES2019
encodeURIComponent(lone); // URIError: URI malformed
new TextEncoder().encode(lone); // Uint8Array заменяющего символа
```

Это прямое следствие определения типа: раз строка — просто последовательность 16-битных чисел, ничто не мешает ей содержать непарный суррогат. Любая операция, выводящая строку наружу (URI, сеть, база), обязана с этим считаться. Перед отправкой во внешнюю систему — `isWellFormed()`, и либо `toWellFormed()`, либо отказ.

### Ключи объектов и сравнение

```js
const key = {};
key['1'] = 'строка';
key[1]   = 'число';
Object.keys(key); // ['1'] — ключ один, число прошло через ToString

'a' < 'b';    // true — сравнение по code unit
'Z' < 'a';    // true — 0x5A < 0x61
'ё' < 'я';    // false — code unit 'ё' (0x451) больше 'я' (0x44F)

['я', 'ё', 'а'].sort();                       // ['а', 'я', 'ё'] — по кодам
['я', 'ё', 'а'].sort(new Intl.Collator('ru').compare); // ['а', 'ё', 'я']
```

Стандартная сортировка строк лексикографична по числовым кодам и для естественного языка неверна. Для отображаемых пользователю списков — только `Intl.Collator`.

## 8. NaN: одно значение и девять квадриллионов представлений

### Откуда берётся число

Number в JavaScript — это IEEE 754 binary64: 1 бит знака, 11 бит экспоненты, 52 бита мантиссы. NaN кодируется так: **все биты экспоненты равны единице, мантисса не равна нулю**.

Значит, под NaN отведено `2 × (2⁵² − 1) = 9 007 199 254 740 990` различных битовых комбинаций — те самые «девять квадриллионов».

### Что говорит спецификация

Стандарт занимает жёсткую позицию: тип Number содержит **ровно одно** значение NaN. Различать битовые представления средствами языка нельзя, и спецификация прямо разрешает движку при записи NaN в буфер подставить любое из них.

```js
const buf = new ArrayBuffer(8);
const f64 = new Float64Array(buf);
const u8  = new Uint8Array(buf);

f64[0] = NaN;
console.log([...u8].map(b => b.toString(16).padStart(2, '0')).join(' '));
// типично: 00 00 00 00 00 00 f8 7f — канонический quiet NaN

// сконструируем другое представление вручную
u8.set([0x01, 0, 0, 0, 0, 0, 0xf8, 0x7f]);

console.log(f64[0]);              // NaN
console.log(Number.isNaN(f64[0]));// true
console.log([...u8].at(0));       // 1 — payload на месте, но из JS он недоступен
```

Старший бит мантиссы отличает quiet NaN от signaling NaN. Payload в младших битах движки используют под **NaN-boxing** — упаковку указателей и тегов типов в неиспользуемое пространство double. Так устроены JavaScriptCore и SpiderMonkey.

### Три разных равенства

```js
NaN === NaN;              // false — IsStrictlyEqual
Object.is(NaN, NaN);      // true  — SameValue
[NaN].includes(NaN);      // true  — SameValueZero
[NaN].indexOf(NaN);       // -1    — строгое равенство
new Set([NaN, NaN]).size; // 1     — SameValueZero
new Map([[NaN, 'a']]).get(NaN); // 'a'
```

В языке три алгоритма сравнения, и они расходятся именно на NaN и на нуле:

```js
Object.is(0, -0);   // false — SameValue различает знак нуля
[0].includes(-0);   // true  — SameValueZero не различает
0 === -0;           // true
```

`SameValueZero` — это `SameValue`, в котором нули объявлены равными. Он используется в коллекциях и в `includes` именно чтобы `NaN` можно было найти, а `-0` не создавал дублей.

### Практика

```js
Number.isNaN(x);  // проверка настоящего NaN
isNaN(x);         // глобальная — сначала ToNumber, поэтому isNaN('abc') === true
```

Глобальный `isNaN` отвечает на вопрос «не приводится к числу», а не «является NaN». В коде почти всегда нужен `Number.isNaN` или `Object.is(x, NaN)`.

## 9. Assignment Patterns

Деструктуризация в позиции присваивания и в позиции объявления — **разные грамматические конструкции**. При объявлении работает `BindingPattern`, при присваивании — `AssignmentPattern` с собственной операцией `DestructuringAssignmentEvaluation`. Отсюда отличия, которые выглядят как непоследовательность языка.

### Целью может быть любое место для записи

```js
const target = {};
[target.x, target.y] = [1, 2];       // свойства объекта
({ a: target.z } = { a: 3 });        // скобки обязательны

const arr = [];
[arr[0], arr[2]] = ['первый', 'третий']; // arr[1] — дырка

let a, b;
[a, b] = [b, a];                     // обмен без временной переменной
```

Скобки вокруг объектного паттерна нужны потому, что `{` в начале инструкции разбирается как начало блока. В объявлении `const {x} = o` этой проблемы нет — там уже контекст объявления.

### Значение по умолчанию срабатывает только на `undefined`

```js
const [x = 'по умолчанию'] = [undefined]; // 'по умолчанию'
const [y = 'по умолчанию'] = [null];      // null
const [z = 'по умолчанию'] = [0];         // 0
const [w = 'по умолчанию'] = [];          // 'по умолчанию'

const { p = 1 } = { p: null };            // null
```

Проверка идёт строго на `undefined`, не на falsy и не на `null`. Для данных из API, где «нет значения» приходит как `null`, дефолты деструктуризации **не сработают** — нужен `??`.

### Дефолты вычисляются лениво и слева направо

```js
const compute = () => { console.log('вычислено'); return 1; };

const [m = compute()] = [42]; // ничего не выведено — значение есть
const [n = compute()] = [];   // 'вычислено'
```

```js
function withTDZ(a = b, b = 2) { return [a, b]; }
withTDZ(); // ReferenceError: Cannot access 'b' before initialization

function ok(a = 1, b = a + 1) { return [a, b]; }
ok();      // [1, 2] — обращение к уже инициализированному параметру
```

Параметры инициализируются последовательно, каждый следующий видит предыдущие. Обратное направление упирается в TDZ.

### Массивы деструктурируются через протокол итератора

Это не индексный доступ. Спецификация вызывает `GetIterator`, затем `IteratorStep` нужное число раз, и — что важно — `IteratorClose` при досрочном выходе.

```js
function* gen() {
  try {
    yield 1; yield 2; yield 3;
  } finally {
    console.log('генератор закрыт');
  }
}

const [first] = gen();
// 'генератор закрыт' — IteratorClose вызывается сразу
console.log(first); // 1
```

```js
const set = new Set(['a', 'b']);
const [s1, s2] = set;   // работает — Set итерируем

const plain = { 0: 'a', 1: 'b', length: 2 };
// const [p1] = plain;  // TypeError: plain is not iterable
const [p1] = Array.from(plain); // так корректно
```

Объектная деструктуризация, наоборот, итератор не использует — она читает свойства по ключам, поэтому работает с любым объектом.

### Rest: два разных механизма

```js
const [head, ...tail] = [1, 2, 3];   // tail — всегда новый массив

const src = { a: 1, b: 2, get c() { return 3; } };
const { a, ...rest } = src;
// rest === { b: 2, c: 3 } — геттер ВЫЗВАН, в rest попало значение
```

Объектный rest копирует собственные перечисляемые свойства через `CopyDataProperties`, вызывая геттеры и **теряя** их «ленивость», а также прототип и неперечисляемые свойства. Для объекта с дорогим геттером spread превращается в неявный вызов.

```js
// rest должен быть последним — синтаксическая ошибка иначе
// const [...init, last] = [1, 2, 3]; // SyntaxError
```

### Вложенность и осечки

```js
const cfg = { server: { port: 8080 } };
const { server: { port } } = cfg;      // 8080, но `server` НЕ объявлен

const empty = {};
// const { server: { port: p } } = empty; // TypeError: Cannot destructure

const { server: { port: safe } = {} } = empty; // undefined — дефолт спасает
```

Вложенный паттерн — это не объявление промежуточного имени, а инструкция «зайти внутрь». Если внутри `undefined`, попытка чтения свойства даёт `TypeError`, и защищаться нужно дефолтом на каждом уровне.

```js
// боевой приём: деструктуризация параметра со сквозными дефолтами
function connect({
  host = 'localhost',
  port = 5432,
  auth: { user = 'guest', pass = '' } = {},
} = {}) {
  return `${user}:${pass}@${host}:${port}`;
}

connect();                                  // guest:@localhost:5432
connect({ auth: { user: 'admin' } });       // admin:@localhost:5432
```

Внешний `= {}` позволяет вызвать функцию вообще без аргумента, внутренний — без секции `auth`.

## 10. Чек-лист senior-уровня

> [!success] Что должно отскакивать от зубов
> - «Hoisting» — это `FunctionDeclarationInstantiation`, а не всплытие. Разные типы объявлений получают разные начальные состояния
> - `TypeError` при вызове `var`-функции и `ReferenceError` при `let` — диагностический признак стадии инициализации
> - `typeof` бросает исключение ровно в одном случае — на переменной в TDZ
> - Замыкание захватывает Environment Record целиком; общий контекст удерживает всё, что захвачено хотя бы одной функцией области
> - `let` в цикле работает за счёт `CreatePerIterationEnvironment`, а не за счёт особой природы `let`
> - `this` определяется `[[ThisBindingStatus]]`; стрелка имеет статус `lexical`, производный конструктор до `super()` — `uninitialized`
> - Порядок ключей объекта **гарантирован**: целые индексы, строки, символы
> - Приведения типов как мутации не существует — есть абстрактные операции, порождающие новые значения
> - `Date` — единственный встроенный тип, где хинт `default` эквивалентен `string`
> - Строка — последовательность 16-битных единиц, не обязательно валидный UTF-16; три уровня «длины»
> - NaN — одно значение языка и ~9 × 10¹⁵ битовых представлений; три алгоритма равенства расходятся на NaN и `-0`
> - Дефолты деструктуризации срабатывают только на `undefined`; массивная деструктуризация идёт через итератор и закрывает его
