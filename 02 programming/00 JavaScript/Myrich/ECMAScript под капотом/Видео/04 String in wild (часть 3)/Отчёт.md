## 1. Строка на границе системы

Первые две части показали, что строка в ECMAScript — последовательность 16-битных единиц, не обязательно валидный UTF-16. Пока значение живёт внутри программы, это почти не мешает. Проблемы начинаются на **границах**: URI, JSON, сеть, база, DOM, файловая система.

За каждой границей стоит своя модель текста, и почти нигде она не совпадает с моделью JavaScript.

| Граница | Ожидаемая модель | Что ломается |
|---|---|---|
| `encodeURIComponent` | валидный UTF-8 | непарные суррогаты → `URIError` |
| `TextEncoder` | валидный UTF-8 | молча заменяет на `U+FFFD` |
| `JSON.stringify` | JSON-текст | с ES2019 экранирует суррогаты |
| Файловая система | зависит от ОС | macOS хранит в NFD, Linux — как дали |
| База данных | обычно UTF-8 | ошибка вставки или обрезка |
| DOM / вывод | графемы | визуальный разъезд |

## 2. Валидность UTF-16 и `isWellFormed`

```js
const lone = '\uD800'; // старший суррогат без пары

console.log(lone.length);         // 1
console.log(lone.isWellFormed()); // false — ES2024

try { encodeURIComponent(lone); }
catch (e) { console.log(e.name); } // 'URIError'

console.log(new TextEncoder().encode(lone)); // Uint8Array(3) [239,191,189] — U+FFFD
console.log(JSON.stringify(lone));           // '"\\ud800"' — экранирован
```

Три разных реакции на одну и ту же строку: исключение, тихая подмена и экранирование. Именно поэтому проверку выносят на вход в систему.

```js
function ingest(text) {
  if (typeof text !== 'string') throw new TypeError('ожидалась строка');
  if (!text.isWellFormed()) {
    // либо отказ, либо починка — решение принимается осознанно
    return text.toWellFormed(); // непарные суррогаты → U+FFFD
  }
  return text;
}
```

Откуда вообще берутся непарные суррогаты: обрезка строки по `length`, склейка кусков из потока, `String.fromCharCode` с произвольным числом, данные из бинарного источника.

## 3. Нормализация — и где именно её ставить

```js
const composed   = 'é';        // é одним кодом
const decomposed = 'é';       // e + комбинирующий акут

console.log(composed === decomposed);         // false
console.log(composed.length, decomposed.length); // 1 2
console.log(composed.normalize('NFC') === decomposed.normalize('NFC')); // true
```

Четыре формы:

| Форма | Что делает |
|---|---|
| **NFC** | композиция — по возможности один код на символ |
| **NFD** | декомпозиция — база плюс комбинирующие знаки |
| **NFKC** | композиция с заменой совместимых форм |
| **NFKD** | декомпозиция с заменой совместимых форм |

```js
console.log('ﬁ'.normalize('NFKC'));   // 'fi' — лигатура разложена
console.log('①'.normalize('NFKC'));   // '1'
console.log('Ⅻ'.normalize('NFKC'));   // 'XII'
console.log('①'.normalize('NFC'));    // '①' — NFC не трогает
```

> [!warning] Порядок «нормализовать → проверить» критичен
> Нормализация **после** валидации открывает обход проверок:
> ```js
> const input = 'adımin'; // dotless i
> // проверка "равно ли admin" не сработает
> // а после NFKC-подобных преобразований в другой системе может сработать
> ```
> Правило: нормализовать на входе, до любых сравнений, проверок уникальности и записи в хранилище. NFC — разумный выбор по умолчанию для хранения, NFKC — для сравнения идентификаторов.

### macOS и файловые имена

```js
// файл создан в Finder с именем 'é'
// macOS (HFS+/APFS) хранит имя в форме, близкой к NFD
const fromFs = 'é';
const fromUser = 'é';
console.log(fromFs === fromUser); // false — файл «не найден»
console.log(fromFs.normalize('NFC') === fromUser.normalize('NFC')); // true
```

Классический баг кроссплатформенных инструментов: список файлов с диска не совпадает со списком из конфига.

## 4. Регулярные выражения: флаги `u` и `v`

Без флага `u` движок работает с code unit, и всё, что вне BMP, разъезжается.

```js
const emoji = '😀';

console.log(/^.$/.test(emoji));   // false — точка это один code unit
console.log(/^.$/u.test(emoji));  // true  — с флагом u точка это code point

console.log(emoji.replace(/./g, 'X'));  // 'XX'
console.log(emoji.replace(/./gu, 'X')); // 'X'
```

### Property escapes

```js
const text = 'Привет, world 123!';

console.log(text.match(/\p{Script=Cyrillic}+/gu)); // ['Привет']
console.log(text.match(/\p{Script=Latin}+/gu));    // ['world']
console.log(text.match(/\p{Letter}+/gu));          // ['Привет', 'world']
console.log(text.match(/\p{Number}+/gu));          // ['123']
```

`\w` и `\d` привязаны к ASCII и для нелатинского текста бесполезны — `\p{...}` решает это корректно.

### Флаг `v` — множества и строковые свойства

```js
// разность и пересечение множеств
console.log(/[\p{Letter}--[aeiou]]/v.test('a')); // false — буква, но исключена
console.log(/[\p{Letter}--[aeiou]]/v.test('b')); // true

// свойства, состоящие из последовательностей
console.log(/^\p{RGI_Emoji}$/v.test('👨‍👩‍👧')); // true — целое семейство как единица
```

Флаг `v` (ES2024) — надмножество `u`: добавляет операции над классами символов и свойства, значения которых представляют собой строки, а не одиночные code point. Для работы с составными эмодзи это единственный корректный инструмент внутри регулярных выражений.

## 5. Регистр — и почему `toLowerCase` небезопасен

```js
console.log('İ'.toLowerCase());          // 'i̇' — i с точкой сверху, длина 2
console.log('I'.toLocaleLowerCase('tr')); // 'ı' — турецкая i без точки
console.log('I'.toLowerCase());           // 'i'

console.log('ß'.toUpperCase());          // 'SS' — длина выросла
console.log('SS'.toLowerCase());         // 'ss' — обратно не вернуть
```

Отсюда два практических правила:

1. Регистровые преобразования **не сохраняют длину** и **не обратимы**
2. Для сравнения без учёта регистра используйте `Intl.Collator`, а не приведение регистра

```js
// ОПАСНО: локаль берётся из окружения. На турецкой локали 'I' даст 'ı',
// и сравнение с 'admin' провалится там, где должно было сработать
if (input.toLocaleLowerCase() === 'admin') { /* ... */ }

// приемлемо: toLowerCase локаль-независим по спецификации
if (input.toLowerCase() === 'admin') { /* ... */ }

// если локальные правила всё же нужны — указывайте локаль явно
if (input.toLocaleLowerCase('tr') === 'admin') { /* ... */ }

// лучше для сравнения естественного текста
const collator = new Intl.Collator('ru', { sensitivity: 'accent' });
console.log(collator.compare('Привет', 'привет') === 0); // true
```

Ключевое различие: методы **без** `Locale` в имени (`toLowerCase`, `toUpperCase`) спецификация определяет как локаль-независимые — они всегда работают по корневым правилам Unicode. Опасны именно `toLocaleLowerCase` и `toLocaleUpperCase` без явного аргумента: они берут локаль из окружения, и поведение кода начинает зависеть от настроек машины.

## 6. Сравнение и сортировка

```js
const words = ['ёлка', 'яблоко', 'арбуз', 'Ель'];

console.log([...words].sort());
// ['Ель', 'арбуз', 'яблоко', 'ёлка'] — по числовым кодам, заглавные впереди

const collator = new Intl.Collator('ru', { sensitivity: 'base' });
console.log([...words].sort(collator.compare));
// ['арбуз', 'Ель', 'ёлка', 'яблоко'] — по правилам языка
```

Опции `Intl.Collator`, которые стоит знать:

```js
// numeric — «естественная» сортировка чисел в строках
const natural = new Intl.Collator('ru', { numeric: true });
console.log(['файл10', 'файл2'].sort(natural.compare)); // ['файл2', 'файл10']
console.log(['файл10', 'файл2'].sort());                // ['файл10', 'файл2']

// sensitivity — что считать различием
// 'base'    — игнорирует регистр и диакритику
// 'accent'  — учитывает диакритику, игнорирует регистр
// 'variant' — учитывает всё (по умолчанию)
```

> [!tip] Производительность
> `Intl.Collator` дорог при создании и дёшев при вызове. Создавайте один экземпляр и переиспользуйте — не вызывайте `localeCompare` в компараторе для больших массивов.
> ```js
> const cmp = new Intl.Collator('ru').compare; // один раз
> bigArray.sort(cmp);                          // быстро
> ```

## 7. Обрезка текста по-человечески

```js
// неправильно — режет суррогатные пары и графемы
const badTruncate = (s, n) => s.slice(0, n) + '…';
console.log(badTruncate('Привет 👨‍👩‍👧 мир', 9)); // разъехавшийся вывод

// правильно — по графемным кластерам
function truncate(text, maxGraphemes) {
  const seg = new Intl.Segmenter(undefined, { granularity: 'grapheme' });
  const graphemes = [...seg.segment(text)];
  if (graphemes.length <= maxGraphemes) return text;
  return graphemes.slice(0, maxGraphemes).map(g => g.segment).join('') + '…';
}

console.log(truncate('Привет 👨‍👩‍👧 мир', 9)); // 'Привет 👨‍👩‍👧…'
```

`Intl.Segmenter` умеет три уровня:

```js
const text = 'Привет, мир! Как дела?';

const byWord = new Intl.Segmenter('ru', { granularity: 'word' });
console.log([...byWord.segment(text)].filter(s => s.isWordLike).map(s => s.segment));
// ['Привет', 'мир', 'Как', 'дела']

const bySentence = new Intl.Segmenter('ru', { granularity: 'sentence' });
console.log([...bySentence.segment(text)].length); // 2
```

Свойство `isWordLike` отделяет слова от пробелов и пунктуации — это корректный подсчёт слов вместо `split(/\s+/)`.

## 8. Безопасность: визуально неразличимые строки

```js
const latin    = 'apple';
const cyrillic = 'аpple'; // первая буква — кириллическая 'а' U+0430

console.log(latin === cyrillic);          // false
console.log(latin.length, cyrillic.length); // 5 5
console.log([...cyrillic].map(c => c.codePointAt(0).toString(16)));
// ['430', '70', '70', '6c', '65'] — видно подмену
```

Атака подмены символов (homograph / confusables) применима к доменам, никнеймам, названиям пакетов. Нормализация её **не решает** — NFKC не сводит кириллическую `а` к латинской `a`, потому что это разные буквы разных алфавитов.

```js
// практичная эвристика: запретить смешение письменностей в одном токене
function mixedScripts(s) {
  const scripts = ['Latin', 'Cyrillic', 'Greek'];
  const present = scripts.filter(sc =>
    new RegExp(`\\p{Script=${sc}}`, 'u').test(s)
  );
  return present.length > 1;
}

console.log(mixedScripts('apple'));  // false
console.log(mixedScripts('аpple'));  // true — сигнал к отказу
```

Дополнительно стоит проверять невидимые символы:

```js
// U+200B ZWSP, U+200C ZWNJ, U+200D ZWJ, U+2060 word joiner, U+FEFF BOM
const invisible = /[\u200B\u200C\u200D\u2060\uFEFF]/u;

console.log(invisible.test('\u0430\u0434\u200B\u043C\u0438\u043D')); // true — внутри «админ» спрятан ZWSP
console.log(invisible.test('админ'));                          // false
```

> [!danger] Не забыть про ZWJ
> `U+200D` нужен для составных эмодзи, поэтому слепой запрет сломает легитимный ввод. Проверку делают контекстно: в идентификаторах, логинах и именах пакетов — запрещать, в свободном тексте — нет.

## 9. Как строки устроены в движке

Знание, объясняющее странности производительности.

**Rope (cons string).** Конкатенация не копирует байты, а создаёт узел со ссылками на части. Материализация («флэттенинг») происходит при первом обращении, требующем линейного представления, — например при `charAt` или регулярном выражении.

```js
let s = '';
for (let i = 0; i < 1e5; i++) s += 'x'; // дёшево: строится дерево
s.length;                                // дёшево: длина известна
s[500];                                  // здесь произойдёт флэттенинг
```

**Sliced string.** `slice` и `substring` могут не копировать, а хранить ссылку на родителя со смещением. Следствие — маленькая подстрока способна удерживать в памяти огромный оригинал.

```js
const huge = 'x'.repeat(10_000_000);
const tiny = huge.slice(0, 10); // может удерживать все 10 МБ
const safe = (' ' + huge.slice(0, 10)).slice(1); // принудительная копия
```

**Интернирование.** Короткие литералы и ключи объектов хранятся в общей таблице, поэтому сравнение таких строк вырождается в сравнение указателей.

Все три механизма — детали реализации, не гарантированные спецификацией. Полагаться на них нельзя, но знать полезно: они объясняют, почему профиль памяти иногда выглядит неожиданно.

## 10. Итог

> [!success] Что забирать
> - Основные проблемы строк проявляются на **границах системы**, и каждая граница реагирует по-своему: `URIError`, тихая подмена на `U+FFFD` или экранирование
> - `isWellFormed()` / `toWellFormed()` — проверка и починка на входе
> - Нормализовать нужно **до** любых сравнений и записи; NFC для хранения, NFKC для идентификаторов
> - macOS хранит имена файлов в декомпозированной форме — источник кроссплатформенных багов
> - Флаг `u` переводит регулярное выражение на code point, `v` добавляет операции над множествами и `\p{RGI_Emoji}`
> - `\p{Script=...}` и `\p{Letter}` заменяют бесполезные для юникода `\w` и `\d`
> - Регистровые преобразования не сохраняют длину и не обратимы; `toLowerCase` локаль-независим, `toLocaleLowerCase` — нет
> - `Intl.Collator` создавать один раз и переиспользовать; `numeric: true` даёт естественную сортировку
> - Обрезка текста — только по графемам через `Intl.Segmenter`
> - Визуальную подмену символов нормализация не лечит — нужна проверка на смешение письменностей
> - Rope, sliced string и интернирование объясняют неожиданный профиль памяти и производительности
