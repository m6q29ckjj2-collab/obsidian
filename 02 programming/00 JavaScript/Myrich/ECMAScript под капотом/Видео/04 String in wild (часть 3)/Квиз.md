> [!question] Что произойдёт при вызове?
> ```js
> encodeURIComponent('\uD800');
> ```
> a) вернёт `'%ED%A0%80'`
> b) вернёт `'\uD800'`
> c) выбросит `URIError`
> d) вернёт `'%EF%BF%BD'`
>> [!success]- Answer
>> c) выбросит `URIError`
>> Непарный суррогат нельзя закодировать в UTF-8. Проверять валидность нужно на входе в систему, а не полагаться на поведение конкретного механизма

> [!question] `TextEncoder` на непарном суррогате тоже выбрасывает исключение
>> [!success]- Answer
>> False
>> Он молча подменяет символ на U+FFFD. Это худший для отладки вариант: данные повреждаются тихо и обнаруживается это далеко от места сбоя

> [!question] Каким методом проверяют, что строка является валидным UTF-16?
>> [!success]- Answer
>> isWellFormed
>> Появился в ES2024 вместе с toWellFormed, который заменяет непарные суррогаты на U+FFFD

> [!question] Что вернёт нормализация?
> ```js
> console.log('ﬁ'.normalize('NFKC'));
> ```
> a) `'ﬁ'`
> b) `'fi'`
> c) `'f'`
> d) пустую строку
>> [!success]- Answer
>> b) `'fi'`
>> NFKC сводит совместимые формы: лигатуры, кружковые цифры, римские числа. NFC такие замены не делает

> [!question] Преобразование NFKC обратимо — из результата можно восстановить исходную строку
>> [!success]- Answer
>> False
>> Совместимая эквивалентность теряет оформление навсегда. Обратима только каноническая: из NFD всегда получится NFC

> [!question] Где единственно правильное место для нормализации?
> a) перед записью в хранилище
> b) на границе входа, до любых проверок
> c) перед выводом пользователю
> d) при каждом сравнении строк
>> [!success]- Answer
>> b) на границе входа, до любых проверок
>> Нормализация после валидации открывает обход: строка проходит фильтр в одной форме, а в хранилище попадает в другой

> [!question] Почему список файлов, прочитанный с диска macOS, может не совпасть со строкой из конфига?
> a) macOS использует другую кодировку
> b) macOS хранит имена в декомпозированной форме
> c) в именах появляются непарные суррогаты
> d) файловая система приводит имена к нижнему регистру
>> [!success]- Answer
>> b) macOS хранит имена в декомпозированной форме
>> Форма близка к NFD, а строка из конфига обычно в NFC. Побайтово это разные строки, визуально — одинаковые

> [!question] Что выведет код?
> ```js
> console.log('😀'.replace(/./g, 'X'));
> ```
> a) `'X'`
> b) `'XX'`
> c) `'😀'`
> d) `'XXXX'`
>> [!success]- Answer
>> b) `'XX'`
>> Без флага u точка соответствует одному code unit, а эмодзи занимает суррогатную пару. С флагом u вернётся один X

> [!question] Чем заменить бесполезный для юникода `\w` при поиске букв?
> a) `[a-zA-Zа-яА-Я]`
> b) `\p{Letter}` с флагом `u`
> c) `\S`
> d) `[^\d\s]`
>> [!success]- Answer
>> b) `\p{Letter}` с флагом `u`
>> Property escapes покрывают весь юникод. Флаг u обязателен — без него это просто экранированная буква p

> [!question] Флаг `v` в регулярных выражениях является надмножеством флага `u`
>> [!success]- Answer
>> True
>> Добавляет операции над множествами символов и свойства со строковыми значениями вроде RGI_Emoji — единственный корректный способ матчить составные эмодзи

> [!question] Какой метод приведения регистра зависит от настроек окружения и потому опасен?
> a) `toLowerCase`
> b) `toLocaleLowerCase` без аргумента
> c) `normalize('NFKC')`
> d) оба метода приведения регистра
>> [!success]- Answer
>> b) `toLocaleLowerCase` без аргумента
>> Спецификация определяет toLowerCase как локаль-независимый. На турецкой локали toLocaleLowerCase превращает I в точку-без-i, и сравнения с ASCII ломаются

> [!question] Чем корректно обрезать текст, содержащий составные эмодзи?
> a) `slice` по количеству code unit
> b) спред и `slice` по code point
> c) `Intl.Segmenter` с гранулярностью grapheme
> d) `split('')` и обратная склейка
>> [!success]- Answer
>> c) `Intl.Segmenter` с гранулярностью grapheme
>> Графемный кластер — единственная единица, совпадающая с интуитивным «символом» пользователя. Спред разорвёт ZWJ-последовательность

> [!question] Нормализация решает проблему подмены латинской буквы на визуально идентичную кириллическую
>> [!success]- Answer
>> False
>> NFKC не сводит кириллическую «а» к латинской — это разные буквы разных алфавитов. Защита — запрет смешения письменностей в одном токене

> [!question] Оптимизация, при которой подстрока хранит ссылку на родителя со смещением и может удерживать его в памяти, называется `___`
>> [!success]- Answer
>> sliced string
>> Не гарантирована спецификацией, это деталь реализации. Принудительная материализация — операция, ломающая возможность оставить ссылку

> [!question] Сколько раз следует создавать `Intl.Collator` при сортировке большого массива?
> a) по одному на каждое сравнение
> b) один раз, затем переиспользовать
> c) по одному на каждый элемент
> d) не имеет значения
>> [!success]- Answer
>> b) один раз, затем переиспользовать
>> Конструктор дорогой, вызов compare дешёвый. Вызов localeCompare внутри компаратора создаёт коллатор на каждое сравнение
