## 1. `this` — не переменная

Ключевое отличие от большинства изложений: `this` не хранится в переменной и не передаётся скрытым параметром. Вычисление ключевого слова `ThisExpression` описано одной строкой алгоритма — вызвать `ResolveThisBinding`.

```
ResolveThisBinding():
  envRec = GetThisEnvironment()
  return envRec.GetThisBinding()
```

`GetThisEnvironment` поднимается по цепочке `[[OuterEnv]]`, пока не найдёт запись, у которой метод `HasThisBinding()` возвращает `true`.

| Запись окружения | `HasThisBinding()` |
|---|---|
| Function Environment Record | `true`, если `[[ThisBindingStatus]]` не `lexical` |
| Global Environment Record | `true` |
| Module Environment Record | `true` |
| Declarative Environment Record | `false` |
| Object Environment Record | `false` |

Из таблицы сразу следует всё поведение стрелок: их Function Environment Record имеет статус `lexical`, значит `HasThisBinding()` даёт `false`, и поиск идёт дальше вверх.

## 2. Function Environment Record

Создаётся при вызове обычной функции. Помимо обычных биндингов содержит четыре слота:

| Слот | Содержимое |
|---|---|
| `[[ThisValue]]` | само значение `this` |
| `[[ThisBindingStatus]]` | `lexical` / `uninitialized` / `initialized` |
| `[[FunctionObject]]` | функция, для которой создана запись |
| `[[NewTarget]]` | значение `new.target` |

```js
function regular() { return this; }
const arrow = () => this;

// у regular создаётся FER со статусом initialized
// у arrow создаётся FER со статусом lexical — поиск идёт выше
```

Метод `GetThisBinding()` у Function Environment Record проверяет статус:

```
if [[ThisBindingStatus]] is uninitialized → throw ReferenceError
return [[ThisValue]]
```

Это и есть источник ошибки «Must call super constructor before accessing 'this'».

## 3. Что происходит при вызове

Операция `[[Call]]` для обычной функции состоит из трёх шагов:

1. `PrepareForOrdinaryCall` — создать контекст, создать Function Environment Record, положить контекст на стек
2. **`OrdinaryCallBindThis`** — заполнить `[[ThisValue]]`
3. `OrdinaryCallEvaluateBody` — инстанцировать декларации и выполнить тело

### `OrdinaryCallBindThis` подробно

```
1. thisMode = F.[[ThisMode]]
2. если thisMode = lexical → ничего не делать, выйти
3. если thisMode = strict → thisValue = thisArgument
4. иначе (global):
     если thisArgument is undefined или null →
        thisValue = глобальный объект realm функции
     иначе →
        thisValue = ToObject(thisArgument)
5. envRec.BindThisValue(thisValue)
```

Слот `[[ThisMode]]` определяется при **создании** функции:

- `lexical` — стрелочная функция
- `strict` — функция в строгом коде
- `global` — функция в нестрогом коде

```js
'use strict';
function strict() { return this; }
console.log(strict.call(42));        // 42
console.log(typeof strict.call(42)); // 'number'
console.log(strict.call(null));      // null
console.log(strict());               // undefined
```

```js
// нестрогий режим — шаг 4
function sloppy() { return this; }
console.log(typeof sloppy.call(42)); // 'object' — ToObject
console.log(sloppy.call(null) === globalThis); // true
console.log(sloppy() === globalThis);          // true
```

> [!note] Realm имеет значение
> На шаге 4 подставляется глобальный объект **того realm, которому принадлежит функция**, а не текущего. Для функции из iframe это будет глобальный объект iframe.

## 4. Откуда берётся `thisArgument`

Значение приходит из вычисления вызова. Ключевое понятие — **Reference Record**, промежуточная структура с полями `[[Base]]`, `[[ReferencedName]]`, `[[ThisValue]]`.

```js
obj.method();
// вычисление obj.method даёт Reference Record с [[Base]] = obj
// операция EvaluateCall берёт [[Base]] как thisArgument
```

```js
method();
// вычисление method даёт Reference Record с [[Base]] = Environment Record
// значит thisArgument = undefined
```

Отсюда объясняются все «странности»:

```js
const obj = { f() { return this; } };

obj.f();          // Reference с базой obj
(obj.f)();        // скобки сохраняют Reference — база остаётся
(0, obj.f)();     // запятая возвращает ЗНАЧЕНИЕ, Reference потерян → undefined
const g = obj.f;  // присваивание берёт значение → Reference потерян
g();              // undefined

(obj.f || obj.f)(); // логический оператор тоже возвращает значение → undefined
(true ? obj.f : 0)(); // тернарный оператор — то же самое
```

Любая операция, превращающая ссылку в значение, стирает базу вызова. Это единое объяснение вместо списка частных случаев.

## 5. `new` и `[[Construct]]`

```js
function Ctor() { this.created = true; }
const inst = new Ctor();
```

Операция `[[Construct]]` для обычной функции:

1. Создать объект с прототипом из `Ctor.prototype` (операция `OrdinaryCreateFromConstructor`)
2. Вызвать `OrdinaryCallBindThis` с этим объектом
3. Выполнить тело
4. Если тело вернуло **объект** — вернуть его; иначе вернуть созданный

```js
function ReturnsObject() { this.a = 1; return { b: 2 }; }
console.log(new ReturnsObject()); // { b: 2 } — объект побеждает

function ReturnsPrimitive() { this.a = 1; return 42; }
console.log(new ReturnsPrimitive()); // { a: 1 } — примитив игнорируется
```

### `new.target`

```js
let seen;
function Detect() { seen = new.target; }

Detect();
console.log(seen);        // undefined — обычный вызов

new Detect();
console.log(seen.name);   // 'Detect' — конструирование
```

> [!warning] Почему значение нельзя вернуть из функции напрямую
> Соблазнительно написать `return new.target ? 'да' : 'нет'` и посмотреть на результат `new Detect()`. Но это не сработает: строка — **примитив**, а `[[Construct]]` примитивы отбрасывает и возвращает созданный объект. Вы увидите `{}` независимо от логики внутри.
>
> Наблюдать `new.target` нужно через побочный эффект — присваивание во внешнюю переменную или `console.log` внутри тела.

```js
// при наследовании new.target равен подклассу
class Base { constructor() { console.log(new.target.name); } }
class Sub extends Base {}
new Sub(); // 'Sub' — не 'Base'
```

`new.target` читается из слота `[[NewTarget]]` той же Function Environment Record — тем же механизмом, что и `this`. В стрелке он тоже берётся лексически.

## 6. Классы

### Всегда строгий режим

```js
class Counter {
  #count = 0;
  increment() { this.#count++; }
}
const m = new Counter().increment;
// m(); // TypeError — this равен undefined, а не globalThis
```

Тело класса выполняется в строгом режиме без директивы, поэтому у методов `[[ThisMode]]` равен `strict`.

### Производный конструктор

```js
class Base { constructor() { this.base = 1; } }

class Derived extends Base {
  constructor() {
    // this;         // ReferenceError — [[ThisBindingStatus]] = uninitialized
    super();         // вызывает BindThisValue
    console.log(this.base); // 1
  }
}
```

В производном классе `this` **не создаётся** при входе в конструктор. Объект создаёт базовый конструктор, а `super()` привязывает его к текущей записи окружения через `BindThisValue`. Повторный вызов даёт `ReferenceError`, потому что связывание уже инициализировано.

```js
// поля инициализируются в момент связывания this
class WithFields extends Base {
  field = 'значение';   // выполняется сразу после super()
  constructor() {
    super();
    console.log(this.field); // 'значение' — уже доступно
  }
}
```

### Статический контекст

```js
class Config {
  static registry = new Map();
  static register(key) { this.registry.set(key, true); return this; }
  static { console.log(this === Config); } // true — статический блок
}

console.log(Config.register('a') === Config); // true
```

В статических методах и блоках `this` — сам класс, а не экземпляр. Отсюда работает наследование статики:

```js
class Sub extends Config {}
Sub.register('b');            // this === Sub
console.log(Sub.registry);    // унаследованная Map — та же самая!
```

Тонкость: `registry` наследуется по прототипной цепочке конструкторов, поэтому подкласс делит **тот же объект** с родителем. Это регулярный источник неожиданного обмена состоянием.

## 7. Верхний уровень и особые случаи

```js
// модуль ESM — спецификация задаёт явно
console.log(this); // undefined

// обычный скрипт в нестрогом режиме
console.log(this); // globalThis

// CommonJS в Node
console.log(this === module.exports); // true
```

```js
// геттер получает объект, с которого читали
const base = { get self() { return this; } };
const derived = Object.create(base);
console.log(derived.self === derived); // true
```

```js
// связанная функция: слот [[BoundThis]]
function f() { return this.tag; }
const once = f.bind({ tag: 'первый' });
console.log(once.bind({ tag: 'второй' })()); // 'первый' — перезаписи нет
```

```js
// но new игнорирует связывание
function Ctor() { this.ok = true; }
console.log(new (Ctor.bind({ ignored: 1 }))().ok); // true
```

## 8. Итог

> [!success] Что забирать
> - `this` — не переменная, а результат `ResolveThisBinding` → `GetThisEnvironment` → `GetThisBinding`
> - `HasThisBinding()` возвращает `true` только у Function (кроме `lexical`), Global и Module Environment Record
> - Function Environment Record хранит `[[ThisValue]]`, `[[ThisBindingStatus]]`, `[[FunctionObject]]`, `[[NewTarget]]`
> - Слот `[[ThisMode]]` (`lexical` / `strict` / `global`) определяется при **создании** функции
> - `OrdinaryCallBindThis` в режиме `global` подменяет `undefined` и `null` глобальным объектом **realm функции** и оборачивает примитивы
> - `thisArgument` берётся из `[[Base]]` Reference Record; любая операция, превращающая ссылку в значение, стирает базу — это единое объяснение всех «потерь `this`»
> - При `new` тело возвращает объект — он побеждает; примитив игнорируется
> - `new.target` читается из того же Function Environment Record и в стрелке тоже лексический
> - Тела классов строгие по определению; в производном конструкторе `this` создаёт `super()` через `BindThisValue`
> - В статическом контексте `this` — сам класс; статические поля наследуются как **общий объект**
> - `[[BoundThis]]` не перезаписывается повторным `bind`, но игнорируется при `new`
