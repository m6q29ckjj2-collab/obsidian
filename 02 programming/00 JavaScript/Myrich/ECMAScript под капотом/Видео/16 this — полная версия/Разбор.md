### 1. Опишите алгоритм вычисления `this` в терминах спецификации

> [!success]- Ответ
> Ключевое слово `this` — это продукция `ThisExpression`, вычисление которой сводится к одной операции:
>
> ```
> ResolveThisBinding():
>   envRec = GetThisEnvironment()
>   return envRec.GetThisBinding()
> ```
>
> `GetThisEnvironment` поднимается по цепочке `[[OuterEnv]]`, пока не найдёт запись окружения, у которой `HasThisBinding()` возвращает `true`.
>
> `this` не является ни переменной, ни скрытым параметром — это результат поиска по цепочке окружений.

### 2. У каких записей окружения `HasThisBinding()` возвращает `true`

> [!success]- Ответ
> | Запись | `HasThisBinding()` |
> |---|---|
> | Function Environment Record | `true`, если `[[ThisBindingStatus]]` не `lexical` |
> | Global Environment Record | `true` |
> | Module Environment Record | `true` |
> | Declarative Environment Record | `false` |
> | Object Environment Record | `false` |
>
> Из первой строки напрямую следует всё поведение стрелок: их запись имеет статус `lexical`, значит `HasThisBinding()` даёт `false`, и поиск продолжается вверх. Никакого отдельного правила «стрелка берёт `this` снаружи» в спецификации нет — это следствие.

### 3. Назовите слоты Function Environment Record и объясните источник ошибки про `super`

> [!success]- Ответ
> Слоты: `[[ThisValue]]`, `[[ThisBindingStatus]]`, `[[FunctionObject]]`, `[[NewTarget]]`.
>
> Метод `GetThisBinding()` начинается с проверки:
> ```
> if [[ThisBindingStatus]] is uninitialized → throw ReferenceError
> return [[ThisValue]]
> ```
>
> Это и есть источник сообщения «Must call super constructor before accessing 'this'». В производном конструкторе слот находится в состоянии `uninitialized` до вызова `super()`.

### 4. Опишите `OrdinaryCallBindThis` и назовите три значения `[[ThisMode]]`

> [!success]- Ответ
> ```
> 1. thisMode = F.[[ThisMode]]
> 2. lexical → выйти, ничего не связывая
> 3. strict  → thisValue = thisArgument
> 4. global  → undefined или null → глобальный объект realm функции
>              иначе → ToObject(thisArgument)
> 5. envRec.BindThisValue(thisValue)
> ```
>
> Значения `[[ThisMode]]`: `lexical` (стрелка), `strict` (функция в строгом коде), `global` (функция в нестрогом коде).
>
> Важно: слот определяется при **создании** функции, а не при вызове. Поэтому режим задаётся местом объявления.

### 5. Что вернёт каждая строка в двух режимах

```js
function show() { return this; }
show();
show.call(42);
show.call(null);
```

> [!success]- Ответ
> **Строгий режим:** `undefined`, `42`, `null` — значения передаются как есть.
>
> **Нестрогий режим:** `globalThis`, объект-обёртка `Number`, `globalThis`.
>
> В режиме `global` операция подменяет `undefined` и `null` глобальным объектом, а примитивы пропускает через `ToObject`. Проверяется через `typeof show.call(42)`: `'number'` в strict, `'object'` в sloppy.
>
> Тонкость: подставляется глобальный объект **того realm, которому принадлежит функция**, а не текущего. Для функции из iframe это глобальный объект iframe.

### 6. Дайте единое объяснение всем этим случаям

```js
const obj = { f() { return this; } };
obj.f();
(obj.f)();
(0, obj.f)();
(obj.f || obj.f)();
const g = obj.f; g();
```

> [!success]- Ответ
> `obj`, `obj`, `undefined`, `undefined`, `undefined`.
>
> Единое объяснение — **Reference Record**. Вычисление `obj.f` даёт не функцию, а промежуточную структуру с полями `[[Base]]`, `[[ReferencedName]]`, `[[ThisValue]]`. Операция `EvaluateCall` берёт `[[Base]]` в качестве `thisArgument`.
>
> Скобки Reference Record сохраняют. А любая операция, которая **извлекает значение** из ссылки, базу стирает: оператор запятая, логические операторы, тернарный оператор, присваивание в переменную.
>
> Это одно правило вместо списка частных случаев «где теряется `this`».

### 7. Что вернут эти конструкторы

```js
function ReturnsObject()    { this.a = 1; return { b: 2 }; }
function ReturnsPrimitive() { this.a = 1; return 42; }
console.log(new ReturnsObject(), new ReturnsPrimitive());
```

> [!success]- Ответ
> `{ b: 2 }` и `{ a: 1 }`.
>
> Операция `[[Construct]]` на последнем шаге проверяет тип возвращённого значения: **объект побеждает** созданный через `new`, примитив игнорируется.
>
> На этом свойстве построены фабрики, притворяющиеся конструкторами, и паттерн «синглтон через конструктор».

### 8. Что выведет код и откуда берётся `new.target`

```js
function Detect() {
  return new.target === undefined ? 'обычный' : `new: ${new.target.name}`;
}
console.log(Detect(), new Detect());
```

> [!success]- Ответ
> `'обычный'` и **`{}`** — а вовсе не `'new: Detect'`.
>
> Здесь пересекаются два правила, и второе про него обычно забывают.
>
> `new.target` действительно читается из слота `[[NewTarget]]` **той же Function Environment Record**, что и `this`, и при конструировании содержит `Detect`. Ветка тернарного оператора отрабатывает верно.
>
> Но результат до вас не доходит: `[[Construct]]` на последнем шаге проверяет тип возвращённого значения, и **примитив отбрасывает**, возвращая созданный объект. Строка — примитив, поэтому вы видите `{}`.
>
> Наблюдать `new.target` нужно через побочный эффект:
> ```js
> let seen;
> function Detect() { seen = new.target; }
> Detect();     console.log(seen);      // undefined
> new Detect(); console.log(seen.name); // 'Detect'
> ```
>
> Два следствия про сам `new.target`: в стрелочной функции он лексический (берётся из внешней функции, как и `this`), а при наследовании равен **подклассу**, а не базовому классу.

### 9. Почему падает и кто создаёт объект

```js
class Base { constructor() { this.base = 1; } }
class Derived extends Base {
  constructor() { console.log(this); super(); }
}
new Derived();
```

> [!success]- Ответ
> `ReferenceError`.
>
> В производном классе `this` **не создаётся** при входе в конструктор — слот `[[ThisBindingStatus]]` равен `uninitialized`.
>
> Объект создаёт **базовый** конструктор, а `super()` привязывает его к текущей записи окружения операцией `BindThisValue`, переводя статус в `initialized`.
>
> Отсюда же два следствия: поля экземпляра инициализируются сразу после `super()`, а повторный вызов `super()` бросает `ReferenceError`, поскольку связывание уже инициализировано.

### 10. В чём подвох этого кода

```js
class Config {
  static registry = new Map();
  static register(k) { this.registry.set(k, true); }
}
class Sub extends Config {}

Sub.register('a');
console.log(Config.registry.has('a'));
```

> [!success]- Ответ
> `true` — и это чаще всего не то, чего ожидают.
>
> В статическом методе `this` — сам класс, через который произошёл вызов, то есть `Sub`. Но `Sub.registry` не собственное свойство: оно находится по **прототипной цепочке конструкторов** и указывает на тот же самый объект `Map`, что и `Config.registry`.
>
> В результате подкласс и родитель делят общее состояние. Чтобы этого избежать, статическое поле нужно переобъявить в подклассе либо создавать реестр в статическом блоке каждого класса.

### 11. Чему равен `this` на верхнем уровне и почему это важно

> [!success]- Ответ
> **Модуль ESM** — `undefined`, задано спецификацией явно.
> **Обычный скрипт (sloppy)** — `globalThis`.
> **Модуль CommonJS** — `module.exports`.
>
> Важно это для библиотек, собираемых сразу в несколько форматов: код, полагающийся на `this` верхнего уровня, будет вести себя по-разному в зависимости от сборки. Универсальная и единственная надёжная ссылка на глобальный объект — `globalThis`.

### 12. Объясните оба результата

```js
function f() { return this.tag; }
console.log(f.bind({ tag: 'a' }).bind({ tag: 'b' })());

function Ctor() { this.ok = true; }
console.log(new (Ctor.bind({ ignored: 1 }))().ok);
```

> [!success]- Ответ
> `'a'` и `true`.
>
> Связанная функция — экзотический объект со слотами `[[BoundTargetFunction]]` и `[[BoundThis]]`. Второй `bind` оборачивает первую обёртку, но при вызове управление доходит до внутренней связанной функции, которая подставляет своё значение. **Первый `bind` побеждает.**
>
> При этом внутренний метод `[[Construct]]` связанной функции слот `[[BoundThis]]` **игнорирует** и создаёт объект обычным образом. То есть `new` сильнее `bind` — что согласуется с общим порядком: `new` определяет `this` раньше, чем явное связывание.
