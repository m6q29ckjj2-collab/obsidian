> [!question] У какой записи окружения проверка наличия связывания `this` даёт ложь?
> a) Function со статусом `initialized`
> b) Global
> c) Module
> d) Declarative
>> [!success]- Answer
>> d) Declarative
>> Истину дают только Function, кроме лексического статуса, а также Global и Module. Из этой таблицы напрямую следует поведение стрелок

> [!question] Какого слота НЕТ у Function Environment Record?
> a) `ThisValue`
> b) `NewTarget`
> c) `Prototype`
> d) `FunctionObject`
>> [!success]- Answer
>> c) `Prototype`
>> Это слот объекта, а не записи окружения. У записи есть ещё и статус связывания, чья проверка на uninitialized даёт ошибку про super

> [!question] Когда определяется слот `ThisMode` функции?
> a) при каждом вызове
> b) при создании функции
> c) при первом обращении к `this`
> d) при связывании через `bind`
>> [!success]- Answer
>> b) при создании функции
>> Поэтому режим задаётся местом объявления, а не местом вызова. Значения: lexical, strict и global

> [!question] Что делает операция связывания `this` в режиме `global`?
> a) передаёт аргумент как есть
> b) всегда подставляет `globalThis`
> c) заменяет `undefined` и `null` глобальным объектом, остальное оборачивает
> d) выбрасывает исключение при примитиве
>> [!success]- Answer
>> c) заменяет `undefined` и `null` глобальным объектом, остальное оборачивает
>> Причём подставляется глобальный объект того realm, которому принадлежит функция, а не текущего

> [!question] Из какого поля структуры ссылки берётся значение для `this` при вызове?
> a) `ReferencedName`
> b) `Base`
> c) `Value`
> d) `Strict`
>> [!success]- Answer
>> b) `Base`
>> Это единое объяснение всех «потерь this»: любая операция, извлекающая из ссылки значение, стирает базу

> [!question] Что вернёт код?
> ```js
> function RetPrim() { this.a = 1; return 42; }
> console.log(new RetPrim());
> ```
> a) `42`
> b) `{ a: 1 }`
> c) `undefined`
> d) `TypeError`
>> [!success]- Answer
>> b) `{ a: 1 }`
>> Операция конструирования возвращает объект тела, только если это действительно объект. Примитив отбрасывается в пользу созданного экземпляра

> [!question] Откуда читается значение `new.target`?
> a) из аргументов вызова
> b) из свойства функции
> c) из слота той же записи окружения, что и `this`
> d) из глобального объекта
>> [!success]- Answer
>> c) из слота той же записи окружения, что и `this`
>> Механизм поиска общий. Следствие: в стрелочной функции new.target тоже лексический

> [!question] При наследовании `new.target` равен подклассу, а не базовому классу
>> [!success]- Answer
>> True
>> На этом строится определение того, что именно конструируется. При обычном вызове слот содержит undefined

> [!question] Кто создаёт объект при конструировании производного класса?
> a) производный конструктор до вызова `super()`
> b) базовый конструктор
> c) оператор `new` до входа в конструктор
> d) прототип производного класса
>> [!success]- Answer
>> b) базовый конструктор
>> Вызов super привязывает созданный объект к текущей записи окружения. До этого связывание находится в состоянии uninitialized

> [!question] Связывание `this` в производном конструкторе выполняет операция `___`
>> [!success]- Answer
>> BindThisValue
>> Повторный вызов super бросает ошибку, потому что связывание уже инициализировано

> [!question] Статическое поле класса — общий объект для базового класса и всех подклассов
>> [!success]- Answer
>> True
>> Оно находится по прототипной цепочке конструкторов. Изменение через подкласс видно в родителе — регулярный источник неожиданного обмена состоянием

> [!question] Чему равен `this` в статическом методе?
> a) экземпляру класса
> b) самому классу, через который произошёл вызов
> c) прототипу класса
> d) `undefined`
>> [!success]- Answer
>> b) самому классу, через который произошёл вызов
>> Поэтому при вызове через подкласс this равен подклассу, а не тому классу, где метод объявлен

> [!question] Когда инициализируются поля экземпляра в производном классе?
> a) до вызова `super()`
> b) сразу после вызова `super()`
> c) после выполнения всего конструктора
> d) при первом обращении к полю
>> [!success]- Answer
>> b) сразу после вызова `super()`
>> То есть в момент связывания this. До super обращение к полю невозможно по той же причине, что и обращение к this

> [!question] Какая из операций НЕ стирает базу вызова?
> a) оператор запятая
> b) присваивание в переменную
> c) обёртывание в скобки
> d) логический оператор `||`
>> [!success]- Answer
>> c) обёртывание в скобки
>> Скобки сохраняют структуру ссылки целиком. Остальные три извлекают из неё значение, и база теряется
