## Механизм разрешения

Как спецификация вычисляет `ThisExpression`
?
```
ResolveThisBinding():
  envRec = GetThisEnvironment()
  return envRec.GetThisBinding()
```

Что делает `GetThisEnvironment`::Поднимается по цепочке `[[OuterEnv]]`, пока не найдёт запись, у которой ==`HasThisBinding()`== возвращает `true`

У каких записей окружения `HasThisBinding()` даёт `true`::У ==Function== (кроме статуса `lexical`), ==Global== и ==Module== Environment Record

У каких записей `HasThisBinding()` даёт `false`::У Declarative и Object Environment Record

Как из этой таблицы следует поведение стрелок::Их FER имеет статус `lexical`, значит `HasThisBinding()` даёт `false` и поиск ==идёт дальше вверх==

## Function Environment Record

Четыре слота Function Environment Record::`[[ThisValue]]`, `[[ThisBindingStatus]]`, `[[FunctionObject]]`, `[[NewTarget]]`

Что делает `GetThisBinding()` при статусе `uninitialized`::Бросает ==`ReferenceError`== — это и есть источник ошибки «Must call super constructor before accessing 'this'»

## OrdinaryCallBindThis

Три шага операции `[[Call]]` для обычной функции::`PrepareForOrdinaryCall` → ==`OrdinaryCallBindThis`== → `OrdinaryCallEvaluateBody`

Три значения слота `[[ThisMode]]`::`lexical` (стрелки), `strict` (функция в строгом коде), `global` (функция в нестрогом коде)

Когда определяется `[[ThisMode]]`::При ==создании== функции, а не при вызове

Что делает `OrdinaryCallBindThis` при режиме `lexical`::Ничего — сразу выходит, связывание не создаётся

Что делает `OrdinaryCallBindThis` при режиме `strict`::Присваивает `thisArgument` ==как есть==, включая `undefined`, `null` и примитивы

Что делает `OrdinaryCallBindThis` при режиме `global`
?
`undefined` и `null` заменяет на ==глобальный объект realm функции==, остальные значения пропускает через ==`ToObject`==.

Глобальный объект какого realm подставляется::Того, ==которому принадлежит функция==, а не текущего. Для функции из iframe это глобальный объект iframe

## Reference Record

Откуда берётся `thisArgument` при вызове::Из поля ==`[[Base]]`== структуры Reference Record, полученной при вычислении выражения вызова

Три поля Reference Record::`[[Base]]`, `[[ReferencedName]]`, `[[ThisValue]]`

Почему `(0, obj.f)()` теряет `this`::Оператор запятая возвращает ==значение==, а не Reference Record — база стирается

Назовите операции, стирающие базу вызова::Запятая, присваивание в переменную, логические операторы `||` и `&&`, тернарный оператор — всё, что превращает ссылку в значение

Почему `(obj.f)()` базу НЕ теряет::Скобки сохраняют Reference Record, значение из него не извлекается

## new и Construct

Четыре шага операции `[[Construct]]`
?
1. Создать объект с прототипом из `Ctor.prototype`
2. `OrdinaryCallBindThis` с этим объектом
3. Выполнить тело
4. Если тело вернуло ==объект== — вернуть его, иначе созданный

Что вернёт конструктор, возвращающий объект::==Возвращённый объект==, а не созданный через `new`

Что вернёт конструктор, возвращающий примитив::Созданный объект — примитив ==игнорируется==

Откуда читается `new.target`::Из слота ==`[[NewTarget]]`== той же Function Environment Record — тем же механизмом, что и `this`

Чему равен `new.target` при обычном вызове::`undefined`

Является ли `new.target` в стрелке лексическим::==Да==, берётся из внешней функции, как и `this`

## Классы

Почему в классах не нужна директива `'use strict'`::Тело класса выполняется в строгом режиме ==по определению==, у методов `[[ThisMode]]` равен `strict`

Кто создаёт объект в производном классе::==Базовый конструктор==. `super()` привязывает его к текущей записи через `BindThisValue`

Когда инициализируются поля экземпляра в производном классе::==Сразу после `super()`==, в момент связывания `this`

Почему повторный `super()` бросает ошибку::Связывание уже находится в состоянии `initialized`

Чему равен `this` в статическом методе::==Самому классу==, а не экземпляру

В чём подвох наследования статических полей
?
Поле наследуется по прототипной цепочке конструкторов, поэтому подкласс делит с родителем ==тот же объект==:
```js
class Sub extends Config {}
Sub.registry === Config.registry; // true
```

## Верхний уровень и bind

Чему равен `this` на верхнем уровне в трёх системах::ESM — ==`undefined`==, скрипт — `globalThis`, CommonJS — `module.exports`

Какой объект получает `this` внутри геттера::Тот, ==с которого началось чтение==, а не тот, где геттер объявлен

Перезаписывается ли `[[BoundThis]]` повторным `bind`::==Нет==. Первый `bind` побеждает

Что происходит с `[[BoundThis]]` при вызове через `new`::==Игнорируется== — создаётся новый объект обычным образом
