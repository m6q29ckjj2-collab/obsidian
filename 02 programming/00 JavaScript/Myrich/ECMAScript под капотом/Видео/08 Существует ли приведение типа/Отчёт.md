# 08 · Существует ли приведение типа — отчёт

## 1. Ответ: нет, и это не игра словами

В ECMA-262 нет операции, которая **меняет тип существующего значения**. Значение в JavaScript иммутабельно вместе со своим типом: число не может стать строкой, как `5` не может стать `6`.

Есть набор **абстрактных операций**, которые по одному значению порождают **новое** значение другого типа:

`ToPrimitive` · `ToNumber` · `ToNumeric` · `ToString` · `ToBoolean` · `ToObject` · `ToPropertyKey` · `ToInt32` · `ToUint32` · `ToLength` · `ToIndex`

> [!abstract] Почему различие не терминологическое
> Модель «переменная превратилась в строку» предсказывает неверно. Переменная как хранила прежнее значение, так и хранит; результат операции — **отдельное новое значение**, которое куда-то передали.
> ```js
> const n = 5;
> const s = n + '';   // n по-прежнему число 5
> console.log(typeof n, typeof s); // 'number' 'string'
> ```
> Понимание этого сразу снимает вопросы вида «почему объект не изменился после сравнения».

## 2. `ToPrimitive` — вход во всё остальное

Любое преобразование объекта начинается здесь. Операция принимает значение и необязательный **хинт**: `'string'`, `'number'` или `'default'`.

Алгоритм:

1. Если значение не объект — вернуть как есть
2. Взять метод `[Symbol.toPrimitive]`. Если он есть — вызвать с хинтом и вернуть результат; если результат объект — `TypeError`
3. Иначе выполнить `OrdinaryToPrimitive` с тем же хинтом

`OrdinaryToPrimitive` перебирает методы в порядке, зависящем от хинта:

| Хинт | Порядок |
|---|---|
| `'string'` | `toString` → `valueOf` |
| `'number'` и `'default'` | `valueOf` → `toString` |

Первый вызов, вернувший примитив, побеждает. Если оба вернули объект — `TypeError: Cannot convert object to primitive value`.

```js
const dual = {
  [Symbol.toPrimitive](hint) {
    console.log('хинт:', hint);
    return { number: 42, string: 'строка' }[hint] ?? 'по умолчанию';
  }
};

console.log(+dual);        // хинт: number  → 42
console.log(`${dual}`);    // хинт: string  → 'строка'
console.log(dual + '');    // хинт: default → 'по умолчанию'
console.log(dual == 'по умолчанию'); // хинт: default → true
```

```js
// объект, который невозможно привести к примитиву
const hostile = Object.create(null); // нет ни toString, ни valueOf
try { `${hostile}`; } catch (e) { console.log(e.name); } // TypeError
```

### Кто какой хинт запрашивает

```js
const probe = { [Symbol.toPrimitive]: h => (console.log(h), 1) };

+probe;            // number
-probe;            // number
probe * 2;         // number
probe - 1;         // number
probe < 2;         // number  — реляционные операторы
`${probe}`;        // string
String(probe);     // string
probe + 1;         // default — оператор сложения
probe == 1;        // default — нестрогое равенство
({})[probe];       // string  — ToPropertyKey
```

Хинт `'default'` запрашивают ровно два места: бинарный `+` и нестрогое равенство. Всё остальное просит `'number'` или `'string'` явно.

### Date — единственное исключение

```js
const d = new Date(0);
console.log(typeof (d + 1)); // 'string'
console.log(typeof (d - 1)); // 'number'
```

`Date.prototype[Symbol.toPrimitive]` реализован так, что хинт `'default'` обрабатывается как `'string'`. Это единственный встроенный тип с таким поведением, и сделано оно ради исторической совместимости: конкатенация с датой должна давать человекочитаемый текст.

## 3. `ToNumber` по типам

| Вход | Результат |
|---|---|
| `undefined` | `NaN` |
| `null` | `0` |
| `true` / `false` | `1` / `0` |
| Number | само значение |
| String | по грамматике `StringNumericLiteral`, иначе `NaN` |
| Symbol | **TypeError** |
| BigInt | **TypeError** |
| Object | `ToPrimitive` с хинтом number, затем `ToNumber` |

```js
console.log(Number(''));         // 0    — пустая строка это ноль
console.log(Number('   '));      // 0    — только пробелы тоже
console.log(Number('\n\t 12 ')); // 12   — пробелы по краям отбрасываются
console.log(Number('12px'));     // NaN  — строгая грамматика, в отличие от parseInt
console.log(Number('0x1F'));     // 31   — шестнадцатеричная поддерживается
console.log(Number('0b101'));    // 5
console.log(Number('0o17'));     // 15
console.log(Number('1e3'));      // 1000
console.log(Number('Infinity')); // Infinity
console.log(Number('+ 1'));      // NaN  — пробел внутри недопустим
```

Разница со свободным разбором:

```js
console.log(parseInt('12px'));   // 12  — читает сколько может
console.log(parseFloat('1.5e2abc')); // 150
console.log(Number('12px'));     // NaN — либо всё число, либо NaN
```

```js
// массивы через ToPrimitive дают неожиданное
console.log(Number([]));      // 0   — '' → 0
console.log(Number([5]));     // 5   — '5' → 5
console.log(Number([1, 2]));  // NaN — '1,2' не число
console.log(Number({}));      // NaN — '[object Object]'
```

## 4. `ToBoolean` — единственная операция без исключений

Всего восемь ложных значений, остальное истинно:

```js
const falsy = [false, 0, -0, 0n, '', null, undefined, NaN];
console.log(falsy.every(v => !v)); // true
```

```js
console.log(Boolean([]));          // true — пустой массив истинен
console.log(Boolean({}));          // true
console.log(Boolean(new Boolean(false))); // true — объект всегда истинен
console.log(Boolean(' '));         // true — пробел это непустая строка
console.log(Boolean('0'));         // true — строка, а не число
```

`ToBoolean` **не вызывает** `ToPrimitive` — любой объект истинен без обращения к его методам. Единственное исключение — `document.all`.

## 5. Оператор `+`

Алгоритм `ApplyStringOrNumericBinaryOperator` для сложения:

1. `lprim = ToPrimitive(left)` без хинта
2. `rprim = ToPrimitive(right)` без хинта
3. Если **хотя бы один** из них строка → `ToString` обоих и конкатенация
4. Иначе `ToNumeric` обоих; при разной числовой природе (Number и BigInt) — `TypeError`
5. Сложить

Критично, что оба операнда приводятся к примитивам **до** принятия решения о ветке.

```js
console.log(1 + '1');        // '11'
console.log(1 + 1);          // 2
console.log([] + []);        // ''     — '' + ''
console.log([] + {});        // '[object Object]'
console.log({} + []);        // '[object Object]' — как выражение
console.log(1 + null);       // 1      — ToNumber(null) === 0
console.log(1 + undefined);  // NaN
console.log('' + null);      // 'null' — строковая ветка
console.log(true + true);    // 2
console.log([1,2] + [3]);    // '1,23'
```

> [!warning] `{} + []` в консоли даёт `0`
> Не из-за приведения типов, а из-за парсинга: в позиции инструкции `{}` читается как пустой **блок**, а дальше остаётся унарный `+[]`, то есть `ToNumber('')` — ноль. В позиции выражения (внутри `console.log` или после `const x =`) это конкатенация. Классическая подмена вопроса о преобразованиях вопросом о грамматике.

### Унарные операторы всегда числовые

```js
console.log(+'42');    // 42
console.log(+'');      // 0
console.log(+[]);      // 0
console.log(+{});      // NaN
console.log(-'5');     // -5
console.log(+true);    // 1

console.log(+1n);      // TypeError — унарный плюс запрещён для BigInt
console.log(-1n);      // -1n — унарный минус разрешён
```

Унарный `+` — единственный оператор, полностью запрещённый для BigInt: он обязан вернуть Number, а безопасно преобразовать BigInt нельзя.

## 6. Нестрогое равенство

Алгоритм `IsLooselyEqual` по шагам (упрощённо, но без потери сути):

1. Типы одинаковы → `IsStrictlyEqual`
2. `null == undefined` → **true** (отдельный явный шаг)
3. Number и String → `ToNumber` строки
4. BigInt и String → `StringToBigInt`
5. Boolean с любой стороны → `ToNumber` булева
6. Object и примитив (кроме `null`/`undefined`) → `ToPrimitive` объекта, повтор
7. BigInt и Number → математическое сравнение
8. Иначе **false**

```js
console.log(null == undefined); // true — шаг 2
console.log(null == 0);         // false — ToNumber(null) в алгоритме НЕТ
console.log(null == false);     // false
console.log(undefined == 0);    // false

console.log('1' == 1);          // true  — шаг 3
console.log(true == 1);         // true  — шаг 5
console.log(true == '1');       // true  — true→1, затем '1'→1
console.log(true == 2);         // false — 1 != 2
```

### Разбор классических загадок

```js
console.log([] == ![]); // true
```

1. `![]` → `ToBoolean([])` это `true` → `false`
2. `[] == false` → булев через `ToNumber` → `0`
3. `[] == 0` → объект через `ToPrimitive` → `''`
4. `'' == 0` → строка через `ToNumber` → `0`
5. `0 == 0` → **true**

```js
console.log([] == 0);        // true  — '' → 0
console.log([0] == false);   // true  — '0' → 0, false → 0
console.log([1] == true);    // true
console.log([[]] == 0);      // true  — вложенный join даёт ''
console.log('' == 0);        // true
console.log('0' == 0);       // true
console.log('' == '0');      // false — обе строки, приведения нет
console.log(NaN == NaN);     // false
```

Последние три строки показывают, что `==` **не транзитивен**: `'' == 0` и `'0' == 0`, но `'' != '0'`.

### Аномалия `document.all`

```js
// только в браузере
console.log(document.all == null);      // true
console.log(document.all === null);     // false
console.log(typeof document.all);       // 'undefined'
console.log(Boolean(document.all));      // false
```

У объекта есть внутренний слот `[[IsHTMLDDA]]`, введённый в стандарт ради веб-совместимости. Это единственный объект, который ложен в булевом контексте и равен `null` при нестрогом сравнении. Официально закреплённая аномалия, а не баг браузера.

## 7. Реляционные операторы — другой алгоритм

`<`, `>`, `<=`, `>=` используют `IsLessThan`, а не `IsLooselyEqual`. Различия принципиальны.

```js
console.log(null == 0);  // false — равенство
console.log(null >= 0);  // true  — сравнение
console.log(null > 0);   // false
```

Парадокс объясняется тем, что в алгоритме **равенства** приведение `null` к числу отсутствует, а в алгоритме **сравнения** обязателен `ToNumeric`, где `ToNumber(null)` даёт `0`. Отсюда `null >= 0` истинно, хотя `null == 0` ложно.

```js
// если оба операнда строки — сравнение лексикографическое
console.log('10' < '9');    // true  — посимвольно
console.log('10' < 9);      // false — одна строка → числовое сравнение

// NaN делает ложными все четыре
console.log(NaN < 1, NaN > 1, NaN <= 1, NaN >= 1); // false false false false
```

Последнее — причина, по которой `<=` не эквивалентен `!(a > b)`.

## 8. Менее известные операции преобразования

```js
// ToPropertyKey — ключи объектов
const obj = {};
obj[1] = 'число';
obj['1'] = 'строка';
console.log(Object.keys(obj)); // ['1'] — ключ один
obj[{}] = 'объект';
console.log(obj['[object Object]']); // 'объект'

// символ ключом остаётся символом
const s = Symbol('k');
obj[s] = 'символ';
```

```js
// ToInt32 / ToUint32 — побитовые операторы
console.log(1.9 | 0);            // 1  — усечение к нулю
console.log(-1.9 | 0);           // -1
console.log(2 ** 32 | 0);        // 0  — переполнение 32 бит
console.log(2 ** 31 | 0);        // -2147483648
console.log(-1 >>> 0);           // 4294967295 — ToUint32
console.log(NaN | 0);            // 0
```

```js
// ToLength — длина массивоподобных, ограничена 2⁵³−1
console.log(Array.prototype.slice.call({ length: -5 }));   // []
console.log(Array.prototype.slice.call({ length: 2.7, 0: 'a', 1: 'b' })); // ['a','b']
```

## 9. Итог

> [!success] Что забирать
> - Операции, меняющей тип значения, **не существует** — есть абстрактные операции, порождающие новые значения
> - `ToPrimitive` — вход во все преобразования объектов; хинты `string`, `number`, `default`
> - Хинт `default` запрашивают ровно два места: бинарный `+` и нестрогое равенство
> - Порядок в `OrdinaryToPrimitive`: для `string` — `toString` → `valueOf`, иначе наоборот
> - `Date` — единственный встроенный тип, где `default` эквивалентен `string`
> - `ToNumber` строки строг: `'12px'` даёт `NaN`, в отличие от `parseInt`
> - `ToBoolean` не вызывает `ToPrimitive` — любой объект истинен, кроме `document.all`
> - В операторе `+` **оба** операнда приводятся к примитивам до выбора ветки
> - `{} + []` в консоли даёт `0` из-за парсинга блока, а не из-за преобразований
> - Унарный `+` — единственный оператор, полностью запрещённый для BigInt
> - `==` не транзитивен; приведения `null` к числу в его алгоритме нет
> - Реляционные операторы используют другой алгоритм — отсюда `null >= 0` при `null != 0`
> - Все четыре сравнения с `NaN` ложны, поэтому `<=` не равен `!(a > b)`
