## Постановка

Существует ли в спецификации операция, меняющая тип значения::==Нет==. Значение иммутабельно вместе со своим типом; абстрактные операции порождают ==новые== значения

Почему различие не терминологическое
?
Модель «переменная превратилась в строку» предсказывает неверно. Переменная хранит прежнее значение, а результат операции — отдельное новое:
```js
const n = 5;
const s = n + '';
typeof n; // 'number' — не изменилось
```

Перечислите основные операции преобразования::`ToPrimitive`, `ToNumber`, `ToNumeric`, `ToString`, `ToBoolean`, `ToObject`, `ToPropertyKey`, `ToInt32`, `ToUint32`, `ToLength`

## ToPrimitive

Три хинта операции `ToPrimitive`::`'string'`, `'number'`, `'default'`

Алгоритм `ToPrimitive` в трёх шагах
?
1. Не объект — вернуть как есть
2. Есть `[Symbol.toPrimitive]` — вызвать с хинтом; объект в результате даёт `TypeError`
3. Иначе `OrdinaryToPrimitive` с тем же хинтом

Порядок методов в `OrdinaryToPrimitive` для хинта `'string'`::`toString` → `valueOf`

Порядок методов для хинтов `'number'` и `'default'`::`valueOf` → `toString`

Что произойдёт, если оба метода вернут объект::`TypeError: Cannot convert object to primitive value`

Какие ровно два места запрашивают хинт `'default'`::Бинарный оператор ==`+`== и нестрогое равенство ==`==`==

Какой хинт запрашивают реляционные операторы `<` и `>`::`'number'`

Какой встроенный тип трактует `'default'` как `'string'`::==`Date`==, ради исторической совместимости конкатенации

Почему `Object.create(null)` нельзя вставить в шаблонную строку::У него нет ни `toString`, ни `valueOf` — `OrdinaryToPrimitive` бросает `TypeError`

## ToNumber

Во что `ToNumber` превращает `undefined` и `null`::`NaN` и `0`

На каких типах `ToNumber` бросает `TypeError`::==Symbol== и ==BigInt==

Что вернёт `Number('')` и `Number('   ')`::Оба `0` — пустая строка и строка из пробелов дают ноль

Что вернёт `Number('12px')` и почему::`NaN`. Грамматика `StringNumericLiteral` требует, чтобы ==вся== строка была числом

Чем `Number` отличается от `parseInt`::`parseInt` читает столько, сколько может (`'12px'` → `12`), `Number` требует полного соответствия

Какие системы счисления понимает `Number`::Шестнадцатеричную `0x`, двоичную `0b`, восьмеричную `0o`, экспоненциальную запись

Что вернут `Number([])`, `Number([5])`, `Number([1,2])`::`0`, `5`, `NaN` — через `ToPrimitive` получаются `''`, `'5'`, `'1,2'`

## ToBoolean

Перечислите все ложные значения::`false`, `0`, `-0`, `0n`, `''`, `null`, `undefined`, `NaN` — ==восемь==

Вызывает ли `ToBoolean` операцию `ToPrimitive`::==Нет==. Любой объект истинен без обращения к его методам

Что вернёт `Boolean(new Boolean(false))`::`true` — это объект, а объекты всегда истинны

Единственное исключение из правила «объект истинен»::`document.all` со слотом `[[IsHTMLDDA]]`

## Оператор +

Алгоритм оператора `+` по шагам
?
1. `ToPrimitive` ==обоих== операндов без хинта
2. Если хотя бы один результат — строка, то `ToString` обоих и конкатенация
3. Иначе `ToNumeric` обоих; смешение Number и BigInt даёт `TypeError`
4. Сложить

Что важно в порядке шагов оператора `+`::Оба операнда приводятся к примитивам ==до== выбора между конкатенацией и сложением

Что вернут `[] + []`, `[] + {}`, `[1,2] + [3]`::`''`, `'[object Object]'`, `'1,23'`

Почему `{} + []` в консоли даёт `0`
?
Из-за ==парсинга==, а не преобразований: в позиции инструкции `{}` читается как пустой блок, остаётся унарный `+[]` → `ToNumber('')` → `0`. В позиции выражения это конкатенация.

Для какого типа полностью запрещён унарный `+`::==BigInt==. Он обязан вернуть Number, а безопасно преобразовать BigInt нельзя. Унарный минус при этом разрешён

## Нестрогое равенство

Почему `null == undefined` истинно, а `null == 0` ложно
?
Равенство `null` и `undefined` прописано ==отдельным явным шагом== алгоритма.
Приведения `null` к числу в `IsLooselyEqual` ==нет вовсе==.

Что происходит с булевым операндом в `==`::Проходит через `ToNumber`: `true` → `1`, `false` → `0`

Почему `true == 2` ложно::`true` превращается в `1`, а `1 != 2`

Разберите `[] == ![]` по шагам
?
1. `![]` → `ToBoolean([])` это `true` → `false`
2. `[] == false` → булев через `ToNumber` → `0`
3. `[] == 0` → объект через `ToPrimitive` → `''`
4. `'' == 0` → строка через `ToNumber` → `0`
5. `0 == 0` → `true`

Транзитивен ли оператор `==`::==Нет==. `'' == 0` и `'0' == 0` истинны, но `'' == '0'` ложно

Что особенного у `document.all`::Слот `[[IsHTMLDDA]]`: равен `null` при `==`, `typeof` даёт `'undefined'`, в булевом контексте ложен

## Реляционные операторы

Какой алгоритм используют `<`, `>`, `<=`, `>=`::`IsLessThan` — ==не== `IsLooselyEqual`

Почему `null >= 0` истинно, а `null == 0` ложно::В алгоритме сравнения обязателен `ToNumeric`, где `ToNumber(null)` даёт `0`. В алгоритме равенства такого шага нет

Когда сравнение строк лексикографическое::Когда ==оба== операнда после `ToPrimitive` оказались строками. Иначе оба идут через `ToNumeric`

Что вернут `'10' < '9'` и `'10' < 9`::`true` и `false` — в первом случае посимвольное сравнение, во втором числовое

Почему `<=` не эквивалентен `!(a > b)`::Все четыре сравнения с `NaN` ==ложны==, поэтому отрицание даёт другой результат

## Прочие операции

Что делает `ToPropertyKey`::Приводит ключ к строке или оставляет символом. Поэтому `obj[1]` и `obj['1']` — один ключ

Во что превращается объект в роли ключа::В `'[object Object]'` — все объекты дают один и тот же ключ

Какие операторы используют `ToInt32`::Побитовые: `|`, `&`, `^`, `<<`, `>>`. Оператор `>>>` использует `ToUint32`

Что вернёт `-1 >>> 0`::`4294967295` — `ToUint32` трактует биты как беззнаковое число

Что делает `ToLength`::Приводит значение к целому в диапазоне от `0` до `2⁵³−1`; отрицательные становятся `0`
