> [!question] В спецификации есть операция, меняющая тип существующего значения
>> [!success]- Answer
>> False
>> Значения иммутабельны вместе со своим типом. Абстрактные операции вроде ToNumber порождают новое значение, а не переделывают старое

> [!question] Какие ровно два места запрашивают хинт `default` у `ToPrimitive`?
> a) унарный плюс и шаблонные строки
> b) бинарный плюс и нестрогое равенство
> c) реляционные операторы и `ToPropertyKey`
> d) все арифметические операторы
>> [!success]- Answer
>> b) бинарный плюс и нестрогое равенство
>> Всё остальное запрашивает number или string явно. Реляционные операторы, например, всегда просят number

> [!question] Что вернёт вызов?
> ```js
> console.log(Number('12px'));
> ```
> a) 12
> b) `NaN`
> c) 0
> d) `TypeError`
>> [!success]- Answer
>> b) `NaN`
>> Грамматика требует, чтобы вся строка была числом. Это ключевое отличие от parseInt, который читает столько, сколько может

> [!question] Сколько всего ложных значений в языке?
>> [!success]- Answer
>> 8
>> Это false, ноль, минус ноль, нулевой BigInt, пустая строка, null, undefined и NaN

> [!question] Операция `ToBoolean` вызывает `ToPrimitive` для объектов
>> [!success]- Answer
>> False
>> Любой объект истинен без обращения к его методам. Единственное исключение — document.all со слотом IsHTMLDDA

> [!question] Что вернёт выражение?
> ```js
> console.log([] + {});
> ```
> a) `''`
> b) `'[object Object]'`
> c) `'0'`
> d) `NaN`
>> [!success]- Answer
>> b) `'[object Object]'`
>> Оба операнда сначала проходят ToPrimitive и дают пустую строку и текстовое представление объекта, затем выполняется конкатенация

> [!question] Почему в консоли `{} + []` даёт ноль?
> a) пустой объект приводится к нулю
> b) в позиции инструкции фигурные скобки читаются как блок
> c) массив приводится к нулю раньше объекта
> d) это ошибка реализации консоли
>> [!success]- Answer
>> b) в позиции инструкции фигурные скобки читаются как блок
>> Остаётся унарный плюс перед массивом, то есть ToNumber от пустой строки. Внутри вызова функции это уже конкатенация — вопрос про грамматику, а не про типы

> [!question] Чему равно `[] == ![]`?
> a) `true`
> b) `false`
> c) `undefined`
> d) выбросит `TypeError`
>> [!success]- Answer
>> a) `true`
>> Отрицание массива даёт false, тот превращается в ноль, массив через ToPrimitive даёт пустую строку, она тоже ноль. Ноль равен нулю

> [!question] Оператор нестрогого равенства транзитивен
>> [!success]- Answer
>> False
>> Пустая строка равна нулю и строка с нулём равна нулю, но между собой они не равны: при совпадении типов приведения не происходит

> [!question] Что вернут эти два сравнения?
> ```js
> console.log(null == 0, null >= 0);
> ```
> a) `true true`
> b) `false false`
> c) `false true`
> d) `true false`
>> [!success]- Answer
>> c) `false true`
>> Равенство и сравнение используют разные алгоритмы. В алгоритме равенства шага «привести null к числу» нет вовсе, а в сравнении ToNumeric обязателен

> [!question] Какой встроенный тип трактует хинт `default` как `string`?
>> [!success]- Answer
>> Date
>> Единственный. Поэтому конкатенация с датой даёт человекочитаемый текст, а вычитание — миллисекунды

> [!question] Что произойдёт при вычислении `1n + 1`?
> a) вернётся `2n`
> b) вернётся `2`
> c) вернётся `'11'`
> d) выбросит `TypeError`
>> [!success]- Answer
>> d) выбросит `TypeError`
>> Арифметика требует одинаковой числовой природы обоих операндов. Строковый путь при этом разрешён: сложение с строкой даёт конкатенацию

> [!question] Нестрогое равенство описано операцией `___`
>> [!success]- Answer
>> IsLooselyEqual
>> Реляционные операторы используют другую — IsLessThan, и именно расхождение между ними даёт парадокс с null

> [!question] Что вернёт `-1 >>> 0`?
> a) `-1`
> b) `0`
> c) `4294967295`
> d) `NaN`
>> [!success]- Answer
>> c) `4294967295`
>> Оператор беззнакового сдвига применяет ToUint32 и трактует биты как беззнаковое 32-битное число. Остальные побитовые используют ToInt32

> [!question] Что станет ключом объекта при `obj[{}] = 1`?
> a) сам объект как ключ
> b) строка `'[object Object]'`
> c) уникальный символ
> d) числовой индекс
>> [!success]- Answer
>> b) строка `'[object Object]'`
>> ToPropertyKey приводит любой не-символьный ключ через ToString, поэтому разные объекты в роли ключей перезаписывают друг друга
