> [!question] Какие хинты запросит каждая операция?
> ```js
> const probe = { [Symbol.toPrimitive]: h => (hints.push(h), 1) };
> +probe; probe < 2; `${probe}`; probe + 1; probe == 1;
> ```
> a) `number number string default default`
> b) `number number string number number`
> c) `default default string default default`
> d) `number string string default number`
>> [!success]- Answer
>> a) `number number string default default`
>> Хинт по умолчанию запрашивают ровно два места: бинарное сложение и нестрогое равенство. Остальное просит число или строку явно

> [!question] Что выведет код?
> ```js
> const d = new Date(0);
> console.log(typeof (d + 1), typeof (d - 1));
> ```
> a) `string number`
> b) `number number`
> c) `string string`
> d) `object number`
>> [!success]- Answer
>> a) `string number`
>> Единственный встроенный тип, трактующий хинт по умолчанию как строковый. Вычитание запрашивает числовой и получает миллисекунды

> [!question] Что выведет код?
> ```js
> console.log([] + [], [] + {}, [1, 2] + [3]);
> ```
> a) `'' '[object Object]' '1,23'`
> b) `'' '{}' '1,2,3'`
> c) `0 NaN NaN`
> d) `[] {} [1,2,3]`
>> [!success]- Answer
>> a) `'' '[object Object]' '1,23'`
>> Оба операнда сначала приводятся к примитивам, и раз хоть один оказался строкой, выполняется склейка

> [!question] Почему в консоли браузера `{} + []` даёт ноль, а `console.log({} + [])` — строку?
> a) консоль использует другой алгоритм
> b) в позиции инструкции фигурные скобки читаются как блок
> c) массив приводится раньше объекта
> d) это ошибка реализации
>> [!success]- Answer
>> b) в позиции инструкции фигурные скобки читаются как блок
>> Остаётся унарный плюс перед массивом. Вопрос о приведении типов на деле оказывается вопросом о грамматике

> [!question] Что выведет код?

> [!question] Что выведет код?
> ```js
> console.log(null == 0, null >= 0, null > 0, null == undefined);
> ```
> a) `false true false true`
> b) `true true true true`
> c) `false false false true`
> d) `false true true false`
>> [!success]- Answer
>> a) `false true false true`

> [!question] Что произойдёт при выполнении каждой строки?
> ```js
> -1n;
> +1n;
> ```
> a) обе вернут значение
> b) первая вернёт значение, вторая выбросит `TypeError`
> c) первая выбросит, вторая вернёт
> d) обе выбросят
>> [!success]- Answer
>> b) первая вернёт значение, вторая выбросит `TypeError`
>> Унарный плюс обязан вернуть число обычного типа, а безопасно преобразовать длинное целое нельзя. Это единственный полностью запрещённый для него оператор

> [!question] Сколько всего ложных значений в языке?
> a) `5`
> b) `6`
> c) `7`
> d) `8`
>> [!success]- Answer
>> d) `8`
>> Это ложь, ноль, минус ноль, нулевое длинное целое, пустая строка, а также неопределённое значение, пустая ссылка и нечисло

> [!question] Что выведет код?

> [!question] Что выведет код?

>> a) `0` и `['a','b']`

> [!question] Что выведет код?

> [!question] Существует ли в спецификации операция, меняющая тип существующего значения?
>> [!success]- Answer
>> False
>> Значения иммутабельны вместе со своим типом. Абстрактные операции порождают новое значение, а не переделывают старое

> [!question] Нестрогое равенство описано операцией `___`
>> [!success]- Answer
>> IsLooselyEqual
>> Реляционные операторы используют другую, и расхождение между ними даёт парадокс с пустой ссылкой
