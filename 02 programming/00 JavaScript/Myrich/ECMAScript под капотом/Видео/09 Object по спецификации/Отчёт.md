## 1. Определение через внутренние методы

Спецификация определяет объект не как «набор пар ключ-значение», а как сущность с набором **внутренних методов**. Именно они, а не структура данных, задают поведение.

Одиннадцать обязательных методов есть у каждого объекта:

| Метод | Отвечает за |
|---|---|
| `[[GetPrototypeOf]]` | чтение прототипа |
| `[[SetPrototypeOf]]` | смену прототипа |
| `[[IsExtensible]]` | проверку расширяемости |
| `[[PreventExtensions]]` | запрет добавления свойств |
| `[[GetOwnProperty]]` | получение дескриптора собственного свойства |
| `[[DefineOwnProperty]]` | создание или изменение свойства |
| `[[HasProperty]]` | проверку наличия с учётом прототипов |
| `[[Get]]` | чтение значения |
| `[[Set]]` | запись значения |
| `[[Delete]]` | удаление |
| `[[OwnPropertyKeys]]` | перечисление собственных ключей |

Дополнительно у вызываемых объектов есть `[[Call]]`, у конструкторов — `[[Construct]]`.

> [!abstract] Ordinary и exotic
> Объект называется **ordinary**, если все внутренние методы реализованы поведением по умолчанию (операции `OrdinaryGet`, `OrdinarySet` и так далее). Если хотя бы один переопределён — объект **exotic**.

Экзотические объекты в языке:

```js
Array.isArray([]);                    // особое [[DefineOwnProperty]] ради length
(function () { return arguments; })(); // в sloppy mode связан с параметрами
new Proxy({}, {});                     // все методы делегируются ловушкам
new String('abc');                     // индексы как собственные свойства
import('./mod.js');                    // namespace-объект модуля
```

## 2. Свойство бывает ровно двух видов

**Data property** — атрибуты `[[Value]]`, `[[Writable]]`, `[[Enumerable]]`, `[[Configurable]]`.
**Accessor property** — атрибуты `[[Get]]`, `[[Set]]`, `[[Enumerable]]`, `[[Configurable]]`.

Третьего не дано, и одно свойство не может быть одновременно тем и другим.

```js
const obj = { plain: 1, get computed() { return 2; } };

console.log(Object.getOwnPropertyDescriptor(obj, 'plain'));
// { value: 1, writable: true, enumerable: true, configurable: true }

console.log(Object.getOwnPropertyDescriptor(obj, 'computed'));
// { get: [Function], set: undefined, enumerable: true, configurable: true }
```

### Присваивание против `defineProperty`

Разница в умолчаниях — источник неприятных сюрпризов.

```js
const a = {};
a.x = 1;                              // все атрибуты true

const b = {};
Object.defineProperty(b, 'x', { value: 1 }); // все атрибуты FALSE

console.log(Object.keys(a), Object.keys(b));       // ['x'] []
console.log(JSON.stringify(a), JSON.stringify(b)); // '{"x":1}' '{}'
console.log({ ...b });                              // {}
b.x = 99;                                           // sloppy: молча игнорируется
console.log(delete b.x);                            // sloppy: false
```

Свойство, созданное через `defineProperty` без явных флагов, невидимо для перечисления, не сериализуется, не копируется спредом и не удаляется.

> [!warning] В строгом режиме те же строки бросают
> ```js
> 'use strict';
> b.x = 99;       // TypeError: Cannot assign to read only property
> delete b.x;     // TypeError: Cannot delete property
> ```
> Код модулей ESM и тела классов строгие по определению, поэтому в современной кодовой базе вы увидите именно исключения, а не тихий отказ. Значения `false` из `delete` дождётся только код в обычном скрипте.

### Семантика записи различается принципиально

```js
const base = {
  set value(v) { console.log('сеттер вызван:', v); }
};
const child = Object.create(base);

child.value = 1;
// 'сеттер вызван: 1' — [[Set]] идёт по цепочке прототипов

Object.defineProperty(child, 'value', { value: 2 });
// сеттер НЕ вызван — [[DefineOwnProperty]] работает только с собственным свойством
console.log(child.value); // 2
```

`[[Set]]` уважает наследованные аксессоры и `[[Writable]]` родителя; `[[DefineOwnProperty]]` их игнорирует. Отсюда правило: `Object.assign` использует присваивание и вызывает сеттеры, а `Object.defineProperties` и спред — определение, и не вызывает.

```js
const target = { set greeting(v) { console.log('через сеттер'); } };
Object.assign(target, { greeting: 'привет' }); // 'через сеттер'

const spread = { ...target, greeting: 'привет' }; // сеттер не вызван, обычное свойство
```

## 3. Порядок ключей строго определён

Распространённое «порядок свойств объекта не гарантирован» — устаревший миф. Операция `OrdinaryOwnPropertyKeys` задаёт его жёстко:

1. **Целочисленные индексы** — по возрастанию числового значения
2. **Остальные строковые ключи** — в порядке добавления
3. **Символы** — в порядке добавления

```js
const sym = Symbol('s');
const obj = { b: 1, 2: 2, a: 3, 1: 4, [sym]: 5, '01': 6, '-1': 7 };

console.log(Reflect.ownKeys(obj));
// ['1', '2', 'b', 'a', '01', '-1', Symbol(s)]
```

Каноническим целочисленным индексом считается строка, совпадающая с `ToString(ToNumber(строка))` и находящаяся в диапазоне от `0` до `2³²−2`. Поэтому `'01'` и `'-1'` в первую группу не попадают и сохраняют порядок вставки.

```js
// практическое следствие: числовые ключи всегда всплывают наверх
const scores = { 100: 'сто', 5: 'пять', 50: 'пятьдесят' };
console.log(Object.keys(scores)); // ['5', '50', '100'] — не порядок вставки
```

Тому же порядку следуют `Object.keys`, `Object.values`, `Object.entries`, `JSON.stringify` и спред. Исключение — `for...in`: он дополнительно обходит прототипы, и порядок для унаследованных свойств стандартом полностью не зафиксирован.

## 4. Уровни целостности

```js
const obj = { a: 1, nested: { b: 2 } };

Object.preventExtensions(obj); // нельзя добавлять новые
obj.c = 3;                     // игнорируется
delete obj.a;                  // но удалять можно
console.log(Object.isExtensible(obj)); // false
```

```js
const sealed = Object.seal({ a: 1 });
sealed.b = 2;      // нельзя добавить
delete sealed.a;   // нельзя удалить
sealed.a = 99;     // но изменить можно
console.log(Object.isSealed(sealed)); // true
```

```js
const frozen = Object.freeze({ a: 1, nested: { b: 2 } });
frozen.a = 99;            // игнорируется
frozen.nested.b = 99;     // РАБОТАЕТ — заморозка поверхностная
console.log(frozen.nested.b); // 99
```

| Операция | Добавление | Удаление | Изменение |
|---|:---:|:---:|:---:|
| `preventExtensions` | нет | да | да |
| `seal` | нет | нет | да |
| `freeze` | нет | нет | нет |

```js
// глубокая заморозка
const deepFreeze = obj => {
  for (const key of Reflect.ownKeys(obj)) {
    const v = obj[key];
    if (v && (typeof v === 'object' || typeof v === 'function')) deepFreeze(v);
  }
  return Object.freeze(obj);
};
```

## 5. Proxy и защита инвариантов

Proxy — экзотический объект, у которого все внутренние методы делегируются ловушкам. Но спецификация не даёт ловушкам лгать: результат проверяется операцией `ValidateAndApplyPropertyDescriptor`.

```js
const target = Object.freeze({ x: 1 });
const p = new Proxy(target, { get: () => 'подмена' });

p.x; // TypeError — для non-configurable non-writable свойства
     // ловушка обязана вернуть исходное значение
```

```js
// нельзя скрыть неконфигурируемое свойство
const t2 = {};
Object.defineProperty(t2, 'fixed', { value: 1, configurable: false });
const p2 = new Proxy(t2, { has: () => false });
'fixed' in p2; // TypeError

// нельзя вернуть дубликаты ключей
const p3 = new Proxy({}, { ownKeys: () => ['a', 'a'] });
Object.keys(p3); // TypeError

// нельзя объявить нерасширяемый объект расширяемым
const t4 = Object.preventExtensions({});
const p4 = new Proxy(t4, { isExtensible: () => true });
Object.isExtensible(p4); // TypeError
```

Без этих проверок рухнули бы гарантии `Object.freeze`, на которые опираются системы изоляции кода.

### `Reflect` как эталонная реализация

```js
const logged = new Proxy({ a: 1 }, {
  get(target, key, receiver) {
    console.log('чтение:', String(key));
    return Reflect.get(target, key, receiver); // поведение по умолчанию
  }
});
```

Методы `Reflect` соответствуют внутренним методам один к одному и принимают те же аргументы, что и ловушки. Третий параметр `receiver` важен: он передаёт объект, с которого началось чтение, — без него наследованные геттеры получат неверный `this`.

```js
const base = { get self() { return this; } };
const derived = Object.create(base);

console.log(Reflect.get(base, 'self', derived) === derived); // true — receiver учтён
console.log(base.self === base);                             // true
```

## 6. Прототипная цепочка и `[[Get]]`

```js
const grandparent = { level: 'дед' };
const parent = Object.create(grandparent);
const child = Object.create(parent);

console.log(child.level);            // 'дед' — обход цепочки
console.log(child.hasOwnProperty('level')); // false
console.log('level' in child);       // true — [[HasProperty]] учитывает прототипы
console.log(Object.hasOwn(child, 'level')); // false — современная замена
```

`Object.hasOwn` (ES2022) предпочтительнее `hasOwnProperty`: он работает и с объектами без прототипа.

```js
const dict = Object.create(null);
dict.key = 1;
// dict.hasOwnProperty('key'); // TypeError — метода нет
console.log(Object.hasOwn(dict, 'key')); // true
```

### Тень над сеттером

```js
const base = { _v: 0, set value(v) { this._v = v; } };
const child = Object.create(base);

child.value = 5;
console.log(child._v);                       // 5 — сеттер записал в child
console.log(Object.hasOwn(child, 'value'));  // false — своё свойство не создано
```

Наследованный сеттер перехватывает запись и собственное свойство не появляется. Если бы в прототипе лежало обычное data property, запись создала бы собственное свойство-тень.

## 7. Итог

> [!success] Что забирать
> - Объект определяется через **внутренние методы**, а не через структуру данных; их одиннадцать плюс `[[Call]]` и `[[Construct]]`
> - Ordinary — все методы по умолчанию; exotic — хотя бы один переопределён (массивы, Proxy, `arguments`, обёртки, namespace модулей)
> - Свойство бывает ровно двух видов: data и accessor
> - `defineProperty` без флагов создаёт свойство со **всеми атрибутами `false`** — невидимое для `Object.keys`, JSON и спреда
> - `[[Set]]` уважает наследованные сеттеры, `[[DefineOwnProperty]]` — нет; отсюда разница между `Object.assign` и спредом
> - Порядок ключей **гарантирован**: целые индексы по возрастанию, строки и символы в порядке добавления
> - Числовые ключи всегда всплывают наверх независимо от порядка вставки
> - Три уровня целостности различаются правами на добавление, удаление и изменение; `freeze` поверхностный
> - Proxy не может нарушить инварианты — их проверяет `ValidateAndApplyPropertyDescriptor`
> - `Reflect` повторяет внутренние методы один к одному; параметр `receiver` обеспечивает правильный `this` наследованным аксессорам
> - `Object.hasOwn` предпочтительнее `hasOwnProperty` и работает с объектами без прототипа
