> [!question] Что выведет код?
> ```js
> const a = {}; a.x = 1;
> const b = {}; Object.defineProperty(b, 'x', { value: 1 });
> console.log(Object.keys(a), Object.keys(b), JSON.stringify(b), { ...b });
> ```
> a) `['x'] ['x'] '{"x":1}' {x:1}`
> b) `['x'] [] '{}' {}`
> c) `[] [] '{}' {}`
> d) `['x'] ['x'] '{}' {}`
>> [!success]- Answer
>> b) `['x'] [] '{}' {}`
>> Определение свойства без явных флагов выставляет все атрибуты в ложь. Свойство читается, но невидимо для перечисления, сериализации и копирования

> [!question] Что выведет код?
> ```js
> const b = {};
> Object.defineProperty(b, 'x', { value: 1 });
> const d = Object.getOwnPropertyDescriptor(b, 'x');
> console.log(d.writable, d.enumerable, d.configurable);
> ```
> a) `true true true`
> b) `false false false`
> c) `true false false`
> d) `false true false`
>> [!success]- Answer
>> b) `false false false`
>> Умолчания прямо противоположны обычному присваиванию, где все три атрибута истинны

> [!question] Что выведет код?
> ```js
> let calls = 0;
> const base = { set value(v) { calls++; } };
> const child = Object.create(base);
> child.value = 1;
> Object.defineProperty(child, 'value', { value: 2 });
> console.log(calls, child.value, Object.hasOwn(child, 'value'));
> ```
> a) `1 2 true`
> b) `2 2 true`
> c) `1 1 false`
> d) `0 2 true`
>> [!success]- Answer
>> a) `1 2 true`
>> Присваивание идёт по цепочке прототипов и вызывает сеттер. Определение свойства работает только с собственным и аксессор игнорирует

> [!question] Что выведет код?
> ```js
> let calls = 0;
> const target = { set greeting(v) { calls++; } };
> Object.assign(target, { greeting: 'привет' });
> const spread = { ...target, greeting: 'привет' };
> console.log(calls);
> ```
> a) `0`
> b) `1`
> c) `2`
> d) `3`
>> [!success]- Answer
>> b) `1`
>> Копирование через присваивание вызывает сеттер, а раскрытие в новый литерал создаёт обычное свойство и аксессор не трогает

> [!question] Что выведет код?
> ```js
> const sym = Symbol('s');
> const obj = { b: 1, 2: 2, a: 3, 1: 4, [sym]: 5, '01': 6, '-1': 7 };
> console.log(Reflect.ownKeys(obj).map(String).join(','));
> ```
> a) `b,2,a,1,01,-1,Symbol(s)`
> b) `1,2,b,a,01,-1,Symbol(s)`
> c) `1,2,01,-1,b,a,Symbol(s)`
> d) `Symbol(s),1,2,b,a,01,-1`
>> [!success]- Answer
>> b) `1,2,b,a,01,-1,Symbol(s)`
>> Сначала целочисленные индексы по возрастанию, затем остальные строки в порядке добавления, затем символы. Ключи с ведущим нулём и минусом каноническими индексами не считаются

> [!question] Что выведет код?

> [!question] Что выведет код?

> [!question] Что выведет код?
> ```js
> const frozen = Object.freeze({ a: 1, nested: { b: 2 } });
> frozen.a = 99; frozen.nested.b = 99;
> console.log(frozen.a, frozen.nested.b, Object.isFrozen(frozen.nested));
> ```
> a) `99 99 true`
> b) `1 99 false`
> c) `1 2 true`
> d) `99 2 false`
>> [!success]- Answer
>> b) `1 99 false`
>> Заморозка поверхностная. Неизменяемой становится ссылка, а объект по ней остаётся полноценно изменяемым

> [!question] Что произойдёт при чтении?
> ```js
> const target = Object.freeze({ x: 1 });
> const p = new Proxy(target, { get: () => 'подмена' });
> p.x;
> ```
> a) вернёт `'подмена'`
> b) вернёт `1`
> c) выбросит `TypeError`
> d) вернёт `undefined`
>> [!success]- Answer
>> c) выбросит `TypeError`
>> Для неконфигурируемого неперезаписываемого свойства ловушка обязана вернуть исходное значение, иначе гарантии заморозки рухнули бы при оборачивании

> [!question] Сколько из этих ловушек выбросят исключение?
> ```js
> const t1 = {}; Object.defineProperty(t1, 'f', { value: 1, configurable: false });
> 'f' in new Proxy(t1, { has: () => false });
> Object.keys(new Proxy({}, { ownKeys: () => ['a', 'a'] }));
> Object.isExtensible(new Proxy(Object.preventExtensions({}), { isExtensible: () => true }));
> ```
> a) ни одна
> b) одна
> c) две
> d) три
>> [!success]- Answer
>> d) три
>> Нельзя скрыть неконфигурируемое свойство, вернуть дубликаты ключей и объявить нерасширяемый объект расширяемым

> [!question] Порядок собственных ключей задаёт операция `___`
>> [!success]- Answer
>> OrdinaryOwnPropertyKeys
>> Утверждение «порядок свойств не гарантирован» устарело: он зафиксирован стандартом

> [!question] Результаты ловушек прокси проверяет операция `___`
>> [!success]- Answer
>> ValidateAndApplyPropertyDescriptor
>> Без этих проверок рухнули бы гарантии заморозки, на которые опираются системы изоляции кода

> [!question] Одно свойство может быть одновременно data и accessor
>> [!success]- Answer
>> False
>> Ровно два вида, третьего не дано. Общими у них остаются только атрибуты перечисляемости и конфигурируемости
