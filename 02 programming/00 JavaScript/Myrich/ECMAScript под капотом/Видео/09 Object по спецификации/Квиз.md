> [!question] Сколько внутренних методов обязательны для любого объекта?
> a) 5
> b) 8
> c) 11
> d) 13
>> [!success]- Answer
>> c) 11
>> От GetPrototypeOf и IsExtensible до Get, Set и OwnPropertyKeys. У вызываемых объектов добавляется Call, у конструкторов — Construct

> [!question] Одно свойство может быть одновременно и data, и accessor
>> [!success]- Answer
>> False
>> Ровно два вида, третьего не дано. Data хранит Value и Writable, accessor — Get и Set; общие атрибуты Enumerable и Configurable

> [!question] Какие атрибуты получит свойство, созданное через `Object.defineProperty` без явных флагов?
> a) все истинны, как при присваивании
> b) все ложны
> c) только enumerable истинно
> d) только writable истинно
>> [!success]- Answer
>> b) все ложны
>> Свойство читается, но невидимо для Object.keys и JSON, не копируется спредом и не удаляется. Регулярный источник багов

> [!question] Что вызовет сеттер, объявленный в прототипе, — присваивание или `Object.defineProperty`?
> a) оба
> b) только присваивание
> c) только `defineProperty`
> d) ни то, ни другое
>> [!success]- Answer
>> b) только присваивание
>> Присваивание — это Set, он идёт по цепочке прототипов. DefineOwnProperty работает только с собственным свойством. Отсюда разница между Object.assign и спредом

> [!question] Порядок собственных ключей объекта задаёт операция `___`
>> [!success]- Answer
>> OrdinaryOwnPropertyKeys
>> Порядок гарантирован: целочисленные индексы по возрастанию, затем строки и символы в порядке добавления. «Порядок не гарантирован» — устаревший миф

> [!question] Что вернёт вызов?
> ```js
> console.log(Object.keys({ 100: 'a', 5: 'b', 50: 'c' }));
> ```
> a) `['100', '5', '50']`
> b) `['5', '50', '100']`
> c) `['a', 'b', 'c']`
> d) порядок не определён
>> [!success]- Answer
>> b) `['5', '50', '100']`
>> Числовые ключи всегда идут первыми и сортируются по возрастанию независимо от порядка вставки. Для упорядоченных данных нужен Map

> [!question] `Object.freeze` замораживает вложенные объекты
>> [!success]- Answer
>> False
>> Он действует только на собственные свойства верхнего уровня. Ссылка становится неизменяемой, но объект по ней — нет

> [!question] Что разрешает `Object.seal`, но запрещает `Object.freeze`?
> a) добавление свойств
> b) удаление свойств
> c) изменение существующих свойств
> d) смену прототипа
>> [!success]- Answer
>> c) изменение существующих свойств
>> Уровни целостности идут по возрастанию строгости: preventExtensions запрещает добавление, seal ещё и удаление, freeze ещё и запись

> [!question] Что произойдёт при чтении?
> ```js
> const target = Object.freeze({ x: 1 });
> const p = new Proxy(target, { get: () => 'подмена' });
> console.log(p.x);
> ```
> a) выведет `'подмена'`
> b) выведет `1`
> c) выбросит `TypeError`
> d) выведет `undefined`
>> [!success]- Answer
>> c) выбросит `TypeError`
>> Для неконфигурируемого неперезаписываемого свойства ловушка обязана вернуть исходное значение. Иначе гарантии freeze рухнули бы при оборачивании в Proxy

> [!question] Результаты ловушек Proxy проверяет операция `___`
>> [!success]- Answer
>> ValidateAndApplyPropertyDescriptor
>> Она же не даёт скрыть неконфигурируемое свойство, вернуть дубликаты ключей или объявить нерасширяемый объект расширяемым

> [!question] `Object.hasOwn` работает с объектом, созданным через `Object.create(null)`
>> [!success]- Answer
>> True
>> Это статический метод, поэтому не зависит от прототипа. Вызов hasOwnProperty на таком объекте упал бы: метода просто нет

> [!question] Зачем третий аргумент `receiver` в `Reflect.get`?
> a) чтобы задать значение по умолчанию
> b) чтобы задать `this` для наследованного геттера
> c) чтобы ограничить поиск собственными свойствами
> d) он ни на что не влияет
>> [!success]- Answer
>> b) чтобы задать `this` для наследованного геттера
>> Типовая ошибка в ловушках Proxy — потерять receiver. Тогда геттеры в прототипной цепочке начинают читать свойства не того объекта

> [!question] Что делает объект экзотическим?
> a) наличие символьных ключей
> b) переопределение хотя бы одного внутреннего метода
> c) отсутствие прототипа
> d) наличие приватных полей
>> [!success]- Answer
>> b) переопределение хотя бы одного внутреннего метода
>> Примеры: массивы из-за связи length с индексами, Proxy, объект arguments в нестрогом режиме, обёртки String, namespace-объекты модулей

> [!question] При записи в объект, у прототипа которого есть сеттер, собственное свойство не создаётся
>> [!success]- Answer
>> True
>> Сеттер перехватывает запись, а this внутри него указывает на дочерний объект. Если бы в прототипе лежало обычное свойство, появилось бы собственное свойство-тень

> [!question] Какой перебор не следует гарантированному порядку ключей?
> a) `Object.keys`
> b) `JSON.stringify`
> c) `for...in`
> d) спред-копирование
>> [!success]- Answer
>> c) `for...in`
>> Он дополнительно обходит прототипы, и порядок унаследованных свойств стандартом полностью не зафиксирован
