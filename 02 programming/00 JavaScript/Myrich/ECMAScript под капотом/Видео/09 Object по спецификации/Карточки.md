## Определение

Через что спецификация определяет объект::Через набор ==внутренних методов==, а не через структуру «ключ-значение»

Сколько обязательных внутренних методов у объекта::==Одиннадцать==. Плюс `[[Call]]` у вызываемых и `[[Construct]]` у конструкторов

Перечислите внутренние методы, связанные с прототипом и расширяемостью::`[[GetPrototypeOf]]`, `[[SetPrototypeOf]]`, `[[IsExtensible]]`, `[[PreventExtensions]]`

Перечислите внутренние методы, связанные со свойствами::`[[GetOwnProperty]]`, `[[DefineOwnProperty]]`, `[[HasProperty]]`, `[[Get]]`, `[[Set]]`, `[[Delete]]`, `[[OwnPropertyKeys]]`

Какой объект называется ordinary::Тот, у которого ==все== внутренние методы реализованы поведением по умолчанию

Назовите экзотические объекты в языке::Массивы, `arguments` в sloppy mode, Proxy, обёртки String, namespace-объекты модулей

Почему массив экзотичен::У него переопределён `[[DefineOwnProperty]]` — он поддерживает связь между `length` и индексами

## Свойства

Сколько видов свойств существует::==Два==: data property и accessor property. Третьего не дано, и совместить их нельзя

Атрибуты data property::`[[Value]]`, `[[Writable]]`, `[[Enumerable]]`, `[[Configurable]]`

Атрибуты accessor property::`[[Get]]`, `[[Set]]`, `[[Enumerable]]`, `[[Configurable]]`

Какие атрибуты по умолчанию при обычном присваивании::Все ==`true`==

Какие атрибуты по умолчанию при `defineProperty`::Все ==`false`==

Что произойдёт со свойством, созданным через `defineProperty` без флагов
?
Оно не попадёт в `Object.keys`, не сериализуется в JSON, не скопируется спредом, запись будет молча игнорироваться (в strict — `TypeError`), удаление вернёт `false`.

## Set против DefineOwnProperty

Чем `[[Set]]` отличается от `[[DefineOwnProperty]]`
?
`[[Set]]` идёт по ==цепочке прототипов==, вызывает наследованные сеттеры и уважает `[[Writable]]` родителя.
`[[DefineOwnProperty]]` работает только с ==собственным== свойством и всё это игнорирует.

Вызывает ли `Object.assign` сеттеры::==Да==, он использует присваивание, то есть `[[Set]]`

Вызывает ли спред `{ ...obj }` сеттеры целевого объекта::==Нет==, он создаёт свойства через определение

Что произойдёт при записи в объект, у прототипа которого есть сеттер
?
Сеттер перехватит запись, собственное свойство ==не создастся==:
```js
child.value = 5;
Object.hasOwn(child, 'value'); // false
```

## Порядок ключей

Гарантирован ли порядок ключей объекта::==Да==, операцией `OrdinaryOwnPropertyKeys`. «Порядок не гарантирован» — устаревший миф

Каков порядок перечисления собственных ключей::1) целочисленные индексы по ==возрастанию==, 2) остальные строки в порядке добавления, 3) символы в порядке добавления

Что считается каноническим целочисленным индексом::Строка, совпадающая с `ToString(ToNumber(строка))`, в диапазоне от `0` до `2³²−2`

Почему `'01'` и `'-1'` не попадают в первую группу::Они ==не совпадают== со своим каноническим представлением, поэтому идут в строковую группу и сохраняют порядок вставки

Что вернёт `Object.keys({ 100: 'a', 5: 'b', 50: 'c' })`::`['5', '50', '100']` — числовые ключи всплывают наверх и сортируются, а не сохраняют порядок вставки

Какой перебор не следует этому порядку::`for...in` — он дополнительно обходит прототипы, и порядок унаследованных свойств стандартом не зафиксирован

## Уровни целостности

Что запрещает `Object.preventExtensions`::Только ==добавление== новых свойств. Удалять и изменять можно

Что запрещает `Object.seal`::Добавление ==и== удаление. Изменять существующие можно

Что запрещает `Object.freeze`::Добавление, удаление ==и== изменение

Насколько глубоко работает `Object.freeze`::Только на ==верхнем уровне==. Вложенные объекты остаются изменяемыми

## Proxy

Что представляет собой Proxy с точки зрения спецификации::Экзотический объект, у которого все внутренние методы ==делегируются ловушкам==

Может ли ловушка Proxy вернуть произвольный результат::Нет. Результат проверяется операцией ==`ValidateAndApplyPropertyDescriptor`==

Что произойдёт при попытке подменить значение замороженного свойства через `get`::`TypeError` — для non-configurable non-writable свойства ловушка обязана вернуть исходное значение

Назовите ещё три инварианта, которые Proxy не может нарушить::Скрыть неконфигурируемое свойство через `has`; вернуть дубликаты из `ownKeys`; объявить нерасширяемый объект расширяемым

Зачем нужны инварианты Proxy::Иначе рухнули бы гарантии `Object.freeze`, на которые опираются системы изоляции кода

Как соотносятся `Reflect` и внутренние методы::`Reflect` повторяет их ==один к одному== и принимает те же аргументы, что и ловушки Proxy

Зачем третий параметр `receiver` в `Reflect.get`::Передаёт объект, с которого началось чтение, — без него наследованные геттеры получат ==неверный `this`==

## Прототипы

Чем `in` отличается от `Object.hasOwn`::`in` использует `[[HasProperty]]` и учитывает ==прототипы==; `Object.hasOwn` проверяет только собственные свойства

Почему `Object.hasOwn` предпочтительнее `hasOwnProperty`::Работает с объектами, созданными через `Object.create(null)`, у которых метода `hasOwnProperty` просто нет
