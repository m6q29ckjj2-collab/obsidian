## Механизм

Есть ли в спецификации термин «hoisting»::==Нет==. Есть операции инстанцирования, создающие биндинги до выполнения кода

Перемещается ли что-нибудь при поднятии::==Ничего==. Просто имена создаются в записи окружения раньше, чем начинает выполняться код

Назовите четыре операции инстанцирования::`GlobalDeclarationInstantiation`, `FunctionDeclarationInstantiation`, `BlockDeclarationInstantiation`, `EvalDeclarationInstantiation`

Как называются два списка объявлений::==`VarScopedDeclarations`== (`var` и функции) и ==`LexicallyScopedDeclarations`== (`let`, `const`, `class`)

К какому окружению привязан каждый список::`VarScopedDeclarations` — к ==VariableEnvironment==, `LexicallyScopedDeclarations` — к ==LexicalEnvironment==

## Три начальных состояния

Что получает функциональная декларация при инстанцировании::==Готовый функциональный объект== — поэтому её можно вызвать до строки объявления

Что получает `var` при инстанцировании::`undefined`

Что получают `let`, `const` и `class`::Остаются ==неинициализированными== — обращение даёт `ReferenceError`

Три типа ошибок и что каждая означает
?
`ReferenceError: X is not defined` — биндинга ==нет вовсе==
`TypeError: X is not a function` — биндинг есть, значение `undefined` (это `var`)
`ReferenceError: Cannot access X before initialization` — биндинг есть, но не инициализирован (это `let`/`const`/`class`)

## Окружение параметров

Когда создаётся отдельное окружение для списка параметров::Если есть хотя бы одно ==значение по умолчанию==, rest-параметр или деструктуризация

Что выведет код и почему
?
```js
const value = 'внешнее';
function f(a = value) {
  const value = 'внутреннее';
  return a;
}
f();
```
`'внешнее'`. Дефолт вычисляется в ==окружении параметров==, которое является родительским для окружения тела.

В каком порядке инициализируются параметры::Строго ==слева направо==. Каждый следующий видит предыдущие, обращение вперёд упирается в TDZ

## Объект arguments

Чем mapped arguments отличается от unmapped
?
**mapped** (sloppy mode) — индексы ==двусторонне связаны== с биндингами параметров через аксессоры.
**unmapped** (strict mode) — обычный снимок значений, связи нет.

Когда `arguments` становится unmapped даже в нестрогом режиме::При наличии ==дефолтов, rest или деструктуризации== в списке параметров

Есть ли `arguments` у стрелочных функций::==Нет==. Имя разрешается во внешней функции по цепочке `[[OuterEnv]]`

Что произойдёт, если назвать параметр `arguments`::Объект не создаётся — имя занято параметром

## Блоки

Где инициализируется функциональная декларация внутри блока::==В этом же блоке==, а не в начале функции

Что выведет `{ function f() {} } typeof f` в двух режимах::strict — `'undefined'`, sloppy — `'function'` по ==Annex B.3.3==

Как работает Annex B.3.3 технически
?
Дополнительно создаётся `var`-биндинг с тем же именем в функциональной области, а значение копируется в него в момент ==выполнения== декларации, а не при инстанцировании.

Что необычного в Annex B.3.3 по сравнению с остальным инстанцированием::Это ==единственный== случай, когда значение появляется в середине выполнения, а не заранее

Куда уходит `var`, объявленный внутри блока::В ==VariableEnvironment функции== — блоком не ограничивается и виден снаружи

## Глобальное окружение

Какие операции создают глобальные биндинги::`CreateGlobalVarBinding` для `var` и `CreateGlobalFunctionBinding` для функций

Почему глобальные `var` не удаляются через `delete`::Свойство создаётся с ==`[[Configurable]]: false`==

Что проверяет `GlobalDeclarationInstantiation` до создания биндингов
?
Возможность создать ==все== свойства. Если хоть одно имя конфликтует с неконфигурируемым свойством глобального объекта, не создаётся ни одного.

На каком этапе обнаруживается конфликт `var x` и `let x`::На этапе ==разбора== — `SyntaxError` до выполнения первой строки

## eval

Что делает прямой `eval` с объявлением `var` в нестрогом режиме::Добавляет биндинг в ==вызывающую== область видимости

Что происходит с `eval` в строгом режиме::Получает ==собственную== область; объявления наружу не протекают

Чем прямой вызов `eval` отличается от косвенного::Прямой — это буквально `eval(...)`. Всё остальное (`const e = eval; e(...)`) косвенный и работает в ==глобальной== области

Протекают ли лексические объявления из `eval`::==Никогда==, даже в нестрогом режиме

## Классы

Как поднимается `class`::Точно как `let` — биндинг создаётся при инстанцировании и остаётся ==неинициализированным==

Есть ли у классов особое поведение при поднятии::Нет. `new Foo()` до объявления даёт `ReferenceError`, как и для `let`
