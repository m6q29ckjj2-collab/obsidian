> [!question] Что выведет код?
> ```js
> function demo() {
>   console.log(typeof fn, typeof v);
>   function fn() {}
>   var v = 1;
> }
> demo();
> ```
> a) `function undefined`
> b) `undefined undefined`
> c) `function number`
> d) выбросит `ReferenceError`
>> [!success]- Answer
>> a) `function undefined`
>> Функциональная декларация инициализируется готовым объектом, переменная — неопределённым значением

> [!question] Какие три ошибки даст этот код?
> ```js
> notDeclared();
> varFn();
> letFn();
> var varFn = function () {};
> let letFn = function () {};
> ```
> a) три одинаковые ошибки
> b) не определено, не функция, обращение до инициализации
> c) три ошибки типа
> d) код выполнится без ошибок
>> [!success]- Answer
>> b) не определено, не функция, обращение до инициализации
>> Три разных сообщения соответствуют трём состояниям биндинга: его нет, он есть со значением, он есть но не инициализирован

> [!question] Что произойдёт при вызове?
> ```js
> function f(cb = () => helper()) {
>   function helper() { return 'из тела'; }
>   return cb();
> }
> f();
> ```
> a) вернёт `'из тела'`
> b) выбросит `ReferenceError`
> c) вернёт `undefined`
> d) выбросит `TypeError`
>> [!success]- Answer
>> b) выбросит `ReferenceError`
>> Значение по умолчанию замкнулось на окружении списка параметров, а объявление функции живёт в дочернем окружении тела. Изнутри параметров оно не видно

> [!question] Что выведет код?
> ```js
> function ok(a = 1, b = a + 1) { return [a, b]; }
> function bad(a = b, b = 2) { return [a, b]; }
> console.log(ok());
> ```
> a) `[1, 2]`, а вызов второй функции упадёт
> b) `[1, 2]`, вторая тоже отработает
> c) обе упадут
> d) `[1, NaN]`
>> [!success]- Answer
>> a) `[1, 2]`, а вызов второй функции упадёт
>> Параметры инициализируются слева направо. Назад смотреть можно, вперёд — нет

> [!question] Что выведет код в нестрогом режиме?

> console.log(f(1));
> ```
> a) `1`
> b) `99`
> c) `undefined`
> d) `TypeError`
>> [!success]- Answer
>> b) `99`
>> В нестрогом режиме объект аргументов связан с параметрами двусторонне через специальные аксессоры

> [!question] Что выведет код?

> a) `1`
> b) `99`

> d) `TypeError`
>> [!success]- Answer

> [!question] Что выведет код в нестрогом режиме?
> ```js
> function f(a = 0) { a = 99; return arguments[0]; }
> console.log(f(1));
> ```
> a) `99`
> b) `1`
> c) `0`
> d) `undefined`
>> [!success]- Answer
>> b) `1`
>> Наличие значения по умолчанию разрывает связь независимо от режима: при сложном списке параметров однозначного соответствия уже нет

> [!question] Что выведет код?
> ```js
> const arrow = () => typeof arguments;
> function outer() { return arrow(); }
> console.log(typeof arguments === 'undefined' ? 'нет своего' : 'есть');
> ```
> a) `нет своего`
> b) `есть`
> c) `TypeError`
> d) `ReferenceError`
>> [!success]- Answer
>> a) `нет своего`
>> У стрелочных функций собственного объекта аргументов не существует — имя разрешается во внешней функции по цепочке окружений

> [!question] Что выведет код в нестрогом режиме?
> ```js
> console.log(typeof g);
> { function g() {} }
> console.log(typeof g);
> ```
> a) `function function`
> b) `undefined function`
> c) `undefined undefined`
> d) `ReferenceError`
>> [!success]- Answer
>> b) `undefined function`
>> Дополнительный биндинг создаётся заранее с неопределённым значением, а копирование происходит в момент выполнения декларации. Единственный случай отложенной инициализации

> [!question] Чем прямой вызов отличается от косвенного?
> a) прямой быстрее

> c) косвенный не может объявлять переменные
> d) различия нет

>> b) косвенный всегда работает в глобальной области

> [!question] Сколько операций инстанцирования описано в спецификации?
> a) одна общая
> b) две
> c) четыре — по видам кода
> d) по одной на каждый вид объявления
>> [!success]- Answer
>> c) четыре — по видам кода
>> Для скрипта, функции, блока и динамического выполнения строки

> [!question] Биндинги при вызове функции создаёт операция `___`
>> [!success]- Answer
>> FunctionDeclarationInstantiation
>> Она же создаёт объект аргументов и решает, нужно ли отдельное окружение для списка параметров

> [!question] Два списка, на которые спецификация делит объявления, называются `___`
>> [!success]- Answer
>> VarScopedDeclarations, LexicallyScopedDeclarations
>> Первый привязывается к окружению переменных, второй к лексическому. Из этого разделения растёт всё остальное поведение

> [!question] При наличии значений по умолчанию создаётся отдельное окружение для списка параметров
>> [!success]- Answer
>> True
>> То же происходит при наличии остаточного параметра или деструктуризации. Тело функции получает дочернее окружение

> [!question] Что проверяет операция инстанцирования глобального кода до создания хотя бы одного биндинга?
> a) наличие строгого режима
> b) возможность создать все свойства без конфликтов
> c) размер доступной памяти
> d) порядок объявлений
>> [!success]- Answer
>> b) возможность создать все свойства без конфликтов
>> Если хоть одно имя конфликтует с неконфигурируемым свойством глобального объекта, не создаётся ни одного

> [!question] Что необычного в правиле о функциях в блоках из приложения B?
> a) оно работает только в модулях
> b) значение появляется в момент выполнения, а не при инстанцировании
> c) оно создаёт два биндинга в одной записи
> d) оно отключает строгий режим
>> [!success]- Answer
>> b) значение появляется в момент выполнения, а не при инстанцировании
>> Во всех остальных случаях начальное состояние биндинга задаётся заранее и в середине выполнения не меняется
