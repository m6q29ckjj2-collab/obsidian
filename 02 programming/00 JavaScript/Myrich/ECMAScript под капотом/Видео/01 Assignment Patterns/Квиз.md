### 1. Почему первая строка падает, а вторая нет

```js
let a;
{ a } = { a: 1 };
({ a } = { a: 1 });
```

> [!success]- Ответ
> `SyntaxError` в первом случае.
>
> Инструкция, начинающаяся с `{`, разбирается парсером как **блок**, и `a` внутри читается как метка или выражение. Скобки переводят конструкцию в позицию выражения, где `{` однозначно означает объектный литерал.
>
> У массивного паттерна такой проблемы нет — `[` в начале инструкции ни с чем не конфликтует.

### 2. Что окажется в `arr` и чему будет равна длина

```js
const arr = [];
[arr[0], arr[5]] = ['первый', 'шестой'];
console.log(arr.length, arr);
```

> [!success]- Ответ
> `6` и массив с дырками: `['первый', <4 empty items>, 'шестой']`.
>
> Слева в паттерне присваивания стоит `AssignmentTarget` — любое место, куда можно писать. Запись в `arr[5]` растягивает массив через exotic-поведение `[[DefineOwnProperty]]` у `length`.

### 3. Что выведет код

```js
const logged = {
  set value(v) { console.log('сеттер:', v); }
};
[logged.value] = [42];
```

> [!success]- Ответ
> `сеттер: 42`
>
> Деструктуризация в свойство выполняет полноценную операцию `[[Set]]`, а не прямую запись в слот. Все аксессоры срабатывают штатно.

### 4. Какие дефолты сработают

```js
const data = [undefined, null, 0, '', NaN, false];
const [a = 'д', b = 'д', c = 'д', d = 'д', e = 'д', f = 'д'] = data;
console.log(a, b, c, d, e, f);
```

> [!success]- Ответ
> `'д' null 0 '' NaN false`
>
> Сработал **только первый**. Проверка — строгое сравнение с `undefined`; ни falsy-значения, ни `null` дефолт не активируют.
>
> Для данных, где «пусто» приходит как `null`, дефолты деструктуризации бесполезны — нужен `??`.

### 5. Сколько раз вызовется функция

```js
let calls = 0;
const compute = () => { calls++; return 'вычислено'; };

const [a = compute()] = ['есть'];
const [b = compute()] = [];
const [c = compute()] = [null];
console.log(calls);
```

> [!success]- Ответ
> `1` — только для `b`.
>
> Выражение в значении по умолчанию вычисляется **лениво**: движок обращается к нему лишь тогда, когда извлечённое значение оказалось `undefined`. Для `'есть'` и для `null` дефолт не понадобился.

### 6. Что выведет код

```js
const value = 'внешнее';

function scope(a = value) {
  const value = 'внутреннее';
  return a;
}

console.log(scope());
```

> [!success]- Ответ
> `'внешнее'`
>
> Если хотя бы у одного параметра есть значение по умолчанию, спецификация создаёт **отдельное окружение для списка параметров**, а тело функции получает дочернее окружение.
>
> Дефолт вычисляется в родительском — там `value` ещё внешнее. Объявление в теле на него повлиять не может.

### 7. В каком порядке выведутся строки

```js
function* source() {
  try {
    yield 'первый';
    yield 'второй';
  } finally {
    console.log('ресурс освобождён');
  }
}

const [only] = source();
console.log(only);
```

> [!success]- Ответ
> Сначала `ресурс освобождён`, затем `первый`.
>
> Массивная деструктуризация идёт через протокол итератора. Паттерн короче последовательности, поэтому после извлечения нужного количества элементов вызывается **`IteratorClose`** — он дёргает `return()` генератора и запускает `finally`.
>
> Это происходит **до** возврата управления, поэтому сообщение из `finally` печатается раньше. Свойство делает деструктуризацию безопасной для ресурсов: дескриптор или соединение закроются, даже если взят только первый элемент.

### 8. Почему одно работает, а другое нет

```js
const arrayLike = { 0: 'a', 1: 'b', length: 2 };

const { 0: first } = arrayLike;  // ?
const [second] = arrayLike;      // ?
```

> [!success]- Ответ
> Первая строка работает и даёт `'a'`. Вторая бросает `TypeError: arrayLike is not iterable`.
>
> Объектная деструктуризация читает свойства по ключам через `GetV` — ей достаточно любого объекта. Массивная требует протокола итератора, которого у array-like нет.
>
> Обходной путь: `const [second] = Array.from(arrayLike)`.

### 9. Что выведет код

```js
const parent = { inherited: 'от прототипа' };
const child = Object.create(parent);
child.own = 'своё';

const { inherited, ...rest } = child;
console.log(inherited, rest);
```

> [!success]- Ответ
> `'от прототипа'` и `{ own: 'своё' }`.
>
> Разное поведение в одной строке: обычная деструктуризация по ключу **обходит прототипную цепочку** (операция `GetV`), а rest использует `CopyDataProperties`, который берёт только **собственные перечисляемые** свойства.

### 10. Что попадёт в `copy`

```js
class Model {
  constructor() { this.id = 1; }
  get computed() { return 2; }
}

const { ...copy } = new Model();
console.log(copy, copy instanceof Model);
```

> [!success]- Ответ
> `{ id: 1 }` и `false`.
>
> Геттер `computed` объявлен в `Model.prototype`, а `CopyDataProperties` копирует только собственные перечисляемые свойства — унаследованный аксессор не попадает. Прототип тоже теряется, поэтому `instanceof` ложен.
>
> Если бы геттер был собственным (объявленным в литерале), он бы **вызвался**, и в копию легло бы вычисленное значение, а не сам аксессор.

### 11. Какие имена окажутся доступны

```js
const config = { server: { host: 'localhost', port: 8080 } };
const { server: { port } } = config;
```

> [!success]- Ответ
> Доступен только `port`. Обращение к `server` даст `ReferenceError`.
>
> Вложенный паттерн — инструкция «зайти внутрь», а не объявление промежуточного имени. Чтобы получить оба, паттерн указывают дважды:
>
> ```js
> const { server, server: { port } } = config;
> ```

### 12. Почему падает и как починить

```js
function connect({ auth: { user } }) { return user; }
connect({});
```

> [!success]- Ответ
> `TypeError: Cannot destructure property 'user' of 'undefined'`.
>
> Ключа `auth` в аргументе нет, внутри оказывается `undefined`, а читать свойство у него нельзя. Защищать нужно **каждый уровень отдельно**:
>
> ```js
> function connect({ auth: { user = 'guest' } = {} } = {}) { return user; }
> connect();    // 'guest'
> connect({});  // 'guest'
> ```
>
> Внешний `= {}` разрешает вызов вообще без аргумента, внутренний — без секции `auth`.
