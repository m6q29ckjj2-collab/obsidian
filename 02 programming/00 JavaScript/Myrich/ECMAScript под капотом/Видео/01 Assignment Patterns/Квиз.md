> [!question] Что выведет код?
> ```js
> const [a = 'д'] = [null];
> const [b = 'д'] = [undefined];
> const [c = 'д'] = [];
> console.log(a, b, c);
> ```
> a) `д д д`
> b) `null д д`
> c) `null undefined д`
> d) `null д undefined`
>> [!success]- Answer
>> b) `null д д`
>> Дефолт срабатывает строго на undefined. Пустой слот даёт undefined, поэтому там он тоже работает

> [!question] Что выведет код?
> ```js
> const data = { user: null, count: 0, name: '' };
> const { user = 'U', count = 10, name = 'N' } = data;
> console.log(user, count, name);
> ```
> a) `U 10 N`
> b) `null 0 ''`
> c) `U 0 ''`
> d) `null 10 N`
>> [!success]- Answer
>> b) `null 0 ''`
>> Ни один дефолт не сработал. Для данных, где «пусто» приходит как null, нужен оператор ??

> [!question] Что выведет код?
> ```js
> const arr = [];
> [arr[0], arr[3]] = ['a', 'b'];
> console.log(arr.length, 1 in arr);
> ```
> a) `4 false`
> b) `2 false`
> c) `4 true`
> d) `2 true`
>> [!success]- Answer
>> a) `4 false`
>> Запись в индекс 3 растянула массив, между элементами остались дырки — то есть отсутствующие свойства, а не undefined

> [!question] Что выведет код?
> ```js
> const obj = { _v: 0, set value(v) { this._v = v * 2; } };
> [obj.value] = [21];
> console.log(obj._v);
> ```
> a) `21`
> b) `42`
> c) `0`
> d) `undefined`
>> [!success]- Answer
>> b) `42`
>> Деструктуризация в свойство выполняет полноценную операцию записи, поэтому аксессор срабатывает штатно

> [!question] Что произойдёт при выполнении второй строки?
> ```js
> let a;
> { a } = { a: 1 };
> ```
> a) `a` станет равно 1
> b) `SyntaxError`
> c) `ReferenceError`
> d) `TypeError`
>> [!success]- Answer
>> b) `SyntaxError`
>> Инструкция, начинающаяся с фигурной скобки, разбирается как блок. Нужны скобки вокруг всего выражения

> [!question] Что выведет код?
> ```js
> const x = 1
> const y = [2, 3]
> const [p, q] = y
> console.log(p, q)
> ```
> a) `2 3`
> b) `TypeError`
> c) `SyntaxError`
> d) `undefined undefined`
>> [!success]- Answer
>> a) `2 3`
>> Здесь всё в порядке. Ловушка возникла бы, начнись строка со скобки или квадратной скобки — тогда она приклеилась бы к предыдущей

> [!question] Что выведет код?
> ```js
> function* g() {
>   try { yield 1; yield 2; yield 3; }
>   finally { console.log('close'); }
> }
> const [a, b] = g();
> console.log(a, b);
> ```
> a) `1 2` затем `close`
> b) `close` затем `1 2`
> c) `1 2` без `close`
> d) `close` затем `1 2 3`
>> [!success]- Answer
>> b) `close` затем `1 2`
>> Паттерн короче последовательности, поэтому итератор закрывается сразу после извлечения двух значений — до возврата управления

> [!question] Что выведет код?
> ```js
> function* g() {
>   try { yield 1; yield 2; }
>   finally { console.log('close'); }
> }
> const [head, ...tail] = g();
> console.log(head, tail);
> ```
> a) `close` затем `1 [2]`
> b) `1 [2]` затем `close`
> c) `1 [2]` без `close`
> d) зависнет
>> [!success]- Answer
>> a) `close` затем `1 [2]`
>> Rest дочитывает итератор до конца, генератор завершается естественно и выполняет finally — тоже до возврата управления

> [!question] Что произойдёт?
> ```js
> function* naturals() { let n = 1; while (true) yield n++; }
> const [...all] = naturals();
> ```
> a) вернутся первые 100 чисел
> b) вернётся пустой массив
> c) код зависнет
> d) `RangeError`
>> [!success]- Answer
>> c) код зависнет
>> Rest дочитывает итератор до конца, а конца нет. Брать из бесконечной последовательности можно только фиксированное число элементов

> [!question] Что выведет код?
> ```js
> const arrayLike = { 0: 'a', 1: 'b', length: 2 };
> const { 0: first } = arrayLike;
> console.log(first);
> const [second] = arrayLike;
> ```
> a) `a`, затем `TypeError`
> b) `a`, затем `b`
> c) `TypeError` сразу
> d) `undefined`, затем `TypeError`
>> [!success]- Answer
>> a) `a`, затем `TypeError`
>> Объектная деструктуризация читает свойства по ключам и работает. Массивная требует протокола итератора, которого у array-like нет

> [!question] Что выведет код?
> ```js
> const parent = { inherited: 'да' };
> const child = Object.create(parent);
> child.own = 'своё';
> const { inherited, ...rest } = child;
> console.log(inherited, rest);
> ```
> a) `да { own: 'своё', inherited: 'да' }`
> b) `да { own: 'своё' }`
> c) `undefined { own: 'своё' }`
> d) `да {}`
>> [!success]- Answer
>> b) `да { own: 'своё' }`
>> Чтение по ключу обходит прототипную цепочку, а rest копирует только собственные перечисляемые свойства. Два разных механизма в одной строке

> [!question] Что выведет код?
> ```js
> let calls = 0;
> const src = { a: 1, get b() { calls++; return 2; } };
> const { ...copy } = src;
> console.log(calls, copy.b);
> ```
> a) `0 2`
> b) `1 2`
> c) `0 undefined`
> d) `2 2`
>> [!success]- Answer
>> b) `1 2`
>> Rest вызывает геттер и кладёт в результат вычисленное значение. Ленивость теряется — для дорогого геттера это неявный вызов

> [!question] Что выведет код?
> ```js
> class M { constructor() { this.id = 1; } get computed() { return 2; } }
> const { ...copy } = new M();
> console.log(JSON.stringify(copy), copy instanceof M);
> ```
> a) `{"id":1,"computed":2} true`
> b) `{"id":1} false`
> c) `{"id":1,"computed":2} false`
> d) `{} false`
>> [!success]- Answer
>> b) `{"id":1} false`
>> Геттер объявлен в прототипе, а копируются только собственные свойства. Прототип тоже теряется

> [!question] Что выведет код?
> ```js
> const value = 'внешнее';
> function f(a = value) {
>   const value = 'внутреннее';
>   return a;
> }
> console.log(f());
> ```
> a) `внешнее`
> b) `внутреннее`
> c) `undefined`
> d) `ReferenceError`
>> [!success]- Answer
>> a) `внешнее`
>> Наличие дефолта создаёт отдельное окружение для списка параметров. Тело функции получает дочернее, и объявление в нём на дефолт не влияет

> [!question] Что выведет код?
> ```js
> function f(a = 1, b = a + 1, c = b * 2) { return [a, b, c]; }
> console.log(f());
> ```
> a) `[1, 2, 4]`
> b) `[1, NaN, NaN]`
> c) `ReferenceError`
> d) `[1, undefined, NaN]`
>> [!success]- Answer
>> a) `[1, 2, 4]`
>> Параметры инициализируются слева направо, каждый следующий видит уже готовые предыдущие

> [!question] Что выведет код?
> ```js
> function f(a = b, b = 2) { return [a, b]; }
> console.log(f());
> ```
> a) `[undefined, 2]`
> b) `[2, 2]`
> c) `ReferenceError`
> d) `[NaN, 2]`
>> [!success]- Answer
>> c) `ReferenceError`
>> Обращение вперёд упирается в TDZ. Направление имеет значение: назад смотреть можно, вперёд нет

> [!question] Что выведет код?
> ```js
> let n = 0;
> const compute = () => { n++; return 'c'; };
> const [a = compute()] = ['есть'];
> const [b = compute()] = [null];
> const [c = compute()] = [];
> console.log(n);
> ```
> a) `0`
> b) `1`
> c) `2`
> d) `3`
>> [!success]- Answer
>> b) `1`
>> Дефолт вычисляется лениво и только для undefined. Значение 'есть' и значение null его не активировали

> [!question] Что выведет код?
> ```js
> const cfg = { server: { port: 8080 } };
> const { server: { port } } = cfg;
> console.log(port, typeof server);
> ```
> a) `8080 object`
> b) `8080 undefined`
> c) `ReferenceError`
> d) `undefined undefined`
>> [!success]- Answer
>> b) `8080 undefined`
>> Здесь сходятся два правила. Вложенный паттерн не объявляет промежуточное имя, поэтому server не существует. Но typeof для необъявленного имени безопасен и возвращает строку undefined — бросает он только на переменной в TDZ. Простое обращение к server дало бы ReferenceError

> [!question] Какая строка упадёт?
> ```js
> const empty = {};
> const { a: { b } = {} } = empty;        // 1
> const { c: { d } } = empty;             // 2
> const { e } = empty;                    // 3
> ```
> a) только 1
> b) только 2
> c) 2 и 3
> d) ни одна
>> [!success]- Answer
>> b) только 2
>> Защищать нужно каждый уровень вложенности отдельно. Первая строка спасена дефолтом, третья читает отсутствующий ключ и просто даёт undefined

> [!question] Что выведет код?
> ```js
> function connect({ auth: { user = 'guest' } = {} } = {}) { return user; }
> console.log(connect(), connect({}), connect({ auth: {} }));
> ```
> a) `guest guest guest`
> b) `TypeError`
> c) `undefined undefined guest`
> d) `guest TypeError guest`
>> [!success]- Answer
>> a) `guest guest guest`
>> Внешний дефолт разрешает вызов без аргумента, внутренний — без секции auth, третий — без самого поля

> [!question] Что выведет код?
> ```js
> let a = 1, b = 2, c = 3;
> [a, b, c] = [c, a, b];
> console.log(a, b, c);
> ```
> a) `3 1 2`
> b) `1 2 3`
> c) `3 3 3`
> d) `2 3 1`
>> [!success]- Answer
>> a) `3 1 2`
>> Правая часть вычисляется полностью до присваивания, поэтому циклический сдвиг корректен без временных переменных

> [!question] Что выведет код?
> ```js
> const [, , third] = ['a', 'b', 'c'];
> console.log(third);
> ```
> a) `a`
> b) `c`
> c) `undefined`
> d) `SyntaxError`
>> [!success]- Answer
>> b) `c`
>> Элизия пропускает результат, но итератор всё равно продвигается — для генератора с побочными эффектами это заметно

> [!question] Что выведет код?
> ```js
> const m = new Map([['k1', 'v1'], ['k2', 'v2']]);
> const [[key, val]] = m;
> console.log(key, val);
> ```
> a) `k1 v1`
> b) `k1 k2`
> c) `TypeError`
> d) `undefined undefined`
>> [!success]- Answer
>> a) `k1 v1`
>> Map итерируем и отдаёт пары, вложенный паттерн разбирает первую из них

> [!question] Что выведет код?
> ```js
> const key = 'dyn';
> const { [key]: extracted } = { dyn: 'значение' };
> console.log(extracted);
> ```
> a) `значение`
> b) `undefined`
> c) `SyntaxError`
> d) `dyn`
>> [!success]- Answer
>> a) `значение`

> [!question] Что выведет код?
> ```js
> const { length } = 'привет';
> const { toFixed } = 42;
> console.log(length, typeof toFixed);
> ```
> a) `6 function`
> b) `TypeError`
> c) `undefined undefined`
> d) `6 undefined`
>> [!success]- Answer
>> a) `6 function`
>> Примитив проходит через приведение к объекту, поэтому свойства и методы прототипа доступны

> [!question] Какое выражение НЕ выбросит исключение?
> a) `const { a } = null`
> b) `const { a } = undefined`
> c) `const { a } = 0`
> d) `const [a] = {}`
>> [!success]- Answer
>> c) `const { a } = 0`
>> Число оборачивается в объект, свойства a у него нет, переменная получает undefined. Первые два падают на приведении, четвёртый — на отсутствии итератора

> [!question] Деструктуризация массива читает элементы по индексам
>> [!success]- Answer
>> False
>> Она вызывает итератор нужное число раз. Поэтому работает с Set и строкой, но падает на array-like объекте

> [!question] Rest-элемент можно поставить в середине паттерна, если он единственный
>> [!success]- Answer
>> False
>> Он обязан быть последним, иначе синтаксическая ошибка — и для массивов, и для объектов

> [!question] Деструктуризацию при присваивании вычисляет операция `___`
>> [!success]- Answer
>> DestructuringAssignmentEvaluation
>> При объявлении работает другая продукция — BindingPattern с операцией BindingInitialization

> [!question] Какой приём корректно выбрасывает чувствительные поля из объекта?
> a) `delete user.password`
> b) `const { password, token, ...safe } = user`
> c) `JSON.parse(JSON.stringify(user))`
> d) `Object.freeze(user)`
>> [!success]- Answer
>> b) `const { password, token, ...safe } = user`
>> Исходный объект не мутируется, в результат попадают только оставшиеся собственные перечисляемые свойства. Линтер глушится опцией ignoreRestSiblings
