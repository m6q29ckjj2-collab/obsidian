> [!question] Что окажется в переменной?
> ```js
> const [a = 'дефолт'] = [null];
> ```
> a) `'дефолт'`
> b) `null`
> c) `undefined`
> d) `TypeError`
>> [!success]- Answer
>> b) `null`
>> Проверка идёт строгим сравнением с undefined. Ни null, ни другие falsy-значения дефолт не активируют — для null нужен оператор ??

> [!question] Значение по умолчанию в деструктуризации срабатывает и на `null` тоже
>> [!success]- Answer
>> False
>> Только на undefined. Это регулярная причина багов с данными из API, где «пусто» приходит как null

> [!question] В каком порядке выведутся строки?
> ```js
> function* src() {
>   try { yield 'первый'; yield 'второй'; }
>   finally { console.log('закрыт'); }
> }
> const [only] = src();
> console.log(only);
> ```
> a) `первый`, затем `закрыт`
> b) `закрыт`, затем `первый`
> c) только `первый`
> d) только `закрыт`
>> [!success]- Answer
>> b) `закрыт`, затем `первый`
>> Паттерн короче последовательности, поэтому вызывается IteratorClose — он дёргает return() генератора и запускает finally до возврата управления

> [!question] Как называется операция спецификации, которая закрывает итератор при досрочном выходе из деструктуризации?
>> [!success]- Answer
>> IteratorClose
>> Та же операция срабатывает при break в for...of и при исключении внутри цикла — именно она делает деструктуризацию безопасной для ресурсов

> [!question] Объектная деструктуризация, как и массивная, использует протокол итератора
>> [!success]- Answer
>> False
>> Она читает свойства по ключам через GetV, поэтому применима к любому объекту, включая неитерируемый, и видит унаследованные свойства

> [!question] Чему будет равна длина массива?
> ```js
> const arr = [];
> [arr[0], arr[5]] = ['первый', 'шестой'];
> console.log(arr.length);
> ```
> a) 2
> b) 5
> c) 6
> d) 0
>> [!success]- Answer
>> c) 6
>> Слева в паттерне присваивания стоит любой AssignmentTarget. Запись в arr[5] растягивает массив через экзотическое поведение length, между элементами остаются дырки

> [!question] Почему `{ a } = obj` без скобок даёт SyntaxError?
> a) объектный паттерн запрещён при присваивании
> b) инструкция, начинающаяся с фигурной скобки, разбирается как блок
> c) нужно указать тип объявления
> d) требуется точка с запятой в конце
>> [!success]- Answer
>> b) инструкция, начинающаяся с фигурной скобки, разбирается как блок
>> Скобки переводят конструкцию в позицию выражения. У массивного паттерна проблемы нет — квадратная скобка в начале инструкции однозначна

> [!question] Объектный rest вызывает геттеры источника и кладёт в результат уже вычисленное значение
>> [!success]- Answer
>> True
>> CopyDataProperties берёт собственные перечисляемые свойства, вызывая аксессоры. Ленивость, прототип и дескрипторы теряются

> [!question] Деструктуризацию при присваивании вычисляет операция `___`
>> [!success]- Answer
>> DestructuringAssignmentEvaluation
>> При объявлении работает другая продукция — BindingPattern с операцией BindingInitialization. Это две независимые грамматики

> [!question] Что произойдёт?
> ```js
> const { a } = null;
> ```
> a) `a` будет равно `undefined`
> b) `a` будет равно `null`
> c) `TypeError`
> d) `ReferenceError`
>> [!success]- Answer
>> c) `TypeError`
>> Объектная деструктуризация пропускает значение через ToObject, а он бросает на null и undefined. Безопасный вариант — деструктурировать из `obj ?? {}`

> [!question] Что вернёт вызов?
> ```js
> function f(a = b, b = 2) { return [a, b]; }
> f();
> ```
> a) `[undefined, 2]`
> b) `[2, 2]`
> c) `ReferenceError`
> d) `[NaN, 2]`
>> [!success]- Answer
>> c) `ReferenceError`
>> Параметры инициализируются строго слева направо в одном окружении. Обращение вперёд упирается в TDZ — тот же механизм, что у let

> [!question] Выражение `const { a: { b } } = {}` бросает исключение
>> [!success]- Answer
>> True
>> Внутри a лежит undefined, читать у него свойство нельзя. Защищать нужно каждый уровень: `{ a: { b } = {} }`

> [!question] Какие имена окажутся объявлены?
> ```js
> const config = { server: { host: 'localhost', port: 8080 } };
> const { server: { port } } = config;
> ```
> a) только `port`
> b) только `server`
> c) и `server`, и `port`
> d) `config`, `server` и `port`
>> [!success]- Answer
>> a) только `port`
>> Вложенный паттерн — инструкция «зайти внутрь», а не объявление промежуточного имени. Чтобы получить оба, паттерн указывают дважды

> [!question] Что выведет код?
> ```js
> let calls = 0;
> const compute = () => { calls++; return 'c'; };
> const [a = compute()] = ['есть'];
> const [b = compute()] = [];
> const [c = compute()] = [null];
> console.log(calls);
> ```
> a) 0
> b) 1
> c) 2
> d) 3
>> [!success]- Answer
>> b) 1
>> Выражение в дефолте вычисляется лениво — только когда извлечённое значение оказалось undefined. Для 'есть' и для null оно не понадобилось
