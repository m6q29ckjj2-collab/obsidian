## 1. Две разные грамматики

Главная мысль темы: деструктуризация **при объявлении** и **при присваивании** — это не одна конструкция с разным синтаксическим сахаром, а два независимых набора грамматических продукций.

| | Объявление | Присваивание |
|---|---|---|
| Продукция | `BindingPattern` | `AssignmentPattern` |
| Операция | `BindingInitialization` | `DestructuringAssignmentEvaluation` |
| Что слева | только новые имена | любой `AssignmentTarget` |
| Скобки | не нужны | нужны для объекта |

```js
// BindingPattern — создаются биндинги
const { a, b } = source;

// AssignmentPattern — пишем в существующие места
let a, b;
({ a, b } = source);
```

Из этого разделения растут почти все неочевидности темы.

## 2. Целью может быть что угодно, куда можно писать

При присваивании слева стоит не имя, а **AssignmentTarget** — то же самое, что допустимо слева от обычного `=`.

```js
const target = {};
const arr = [];
const map = new Map();

[target.x, target.y] = [1, 2];          // свойства
[arr[0], arr[5]] = ['первый', 'шестой']; // индексы, дырки посередине
({ len: target['dynamic-key'] } = { len: 10 }); // вычисляемое имя свойства

console.log(arr.length); // 6 — присваивание в arr[5] растянуло массив
```

Работают и сеттеры — деструктуризация выполняет полноценную операцию `[[Set]]`:

```js
const logged = {
  _v: null,
  set value(v) { console.log('записано:', v); this._v = v; }
};

[logged.value] = [42]; // 'записано: 42'
```

### Почему объектному паттерну нужны скобки

```js
let a;
// { a } = { a: 1 };   // SyntaxError
({ a } = { a: 1 });    // работает
```

Инструкция, начинающаяся с `{`, разбирается парсером как **блок**, а не как объектный литерал. Скобки переводят конструкцию в выражение. У массивного паттерна проблемы нет — `[` в начале инструкции однозначен.

> [!warning] Ловушка с ASI
> Строка, начинающаяся с `(` или `[`, склеивается с предыдущей, если та не закрыта точкой с запятой:
> ```js
> const x = 1
> ({ a } = obj)  // TypeError: 1 is not a function
> ```
> В кодовой базе без точек с запятой такую строку начинают с `;`.

## 3. Дырки и элизии

```js
const [, , third] = ['a', 'b', 'c'];
console.log(third); // 'c'

const [x, , z] = [1, 2, 3]; // средний элемент пропущен, но итератор шагнул
```

Элизия — не «пропуск чтения». Итератор всё равно продвигается, просто результат отбрасывается. Для генератора с побочными эффектами это значимо.

## 4. Значения по умолчанию

### Только `undefined`, ничего больше

```js
const [a = 'дефолт'] = [undefined]; // 'дефолт'
const [b = 'дефолт'] = [null];      // null
const [c = 'дефолт'] = [0];         // 0
const [d = 'дефолт'] = ['']         // ''
const [e = 'дефолт'] = [];          // 'дефолт' — итератор исчерпан
const [f = 'дефолт'] = [NaN];       // NaN
```

Проверка — строгое сравнение с `undefined`. Ни falsy, ни `null` дефолт не активируют.

> [!danger] Практическое следствие
> API, отдающие «пусто» как `null`, обходят механизм дефолтов целиком:
> ```js
> const { avatar = '/default.png' } = { avatar: null };
> console.log(avatar); // null — картинка не загрузится
> ```
> Рабочий вариант — `??`:
> ```js
> const avatar = response.avatar ?? '/default.png';
> ```

### Вычисление ленивое

```js
const expensive = () => { console.log('вызвано'); return 'дорого'; };

const [p = expensive()] = ['есть']; // тишина
const [q = expensive()] = [];       // 'вызвано'
```

Значение по умолчанию — это выражение, вычисляемое только в момент, когда оно понадобилось. Поэтому туда безопасно ставить тяжёлые вызовы, но небезопасно — выражения с побочными эффектами, на которые кто-то рассчитывает.

### Порядок и TDZ

```js
function ok(a = 1, b = a + 1, c = b * 2) { return [a, b, c]; }
ok(); // [1, 2, 4] — каждый следующий видит предыдущие

function broken(a = b, b = 2) { return [a, b]; }
broken(); // ReferenceError: Cannot access 'b' before initialization
```

Параметры инициализируются строго слева направо в одной области видимости. Обращение «вперёд» упирается в TDZ — тот же механизм, что у `let`.

### Отдельная область видимости параметров

```js
const value = 'внешнее';

function scope(a = value) {
  const value = 'внутреннее';
  return a;
}

console.log(scope()); // 'внешнее'
```

Если хотя бы у одного параметра есть значение по умолчанию, спецификация создаёт **отдельное окружение для списка параметров**. Тело функции получает своё, дочернее. Поэтому объявление в теле не влияет на дефолты — они уже вычислены в родительском окружении.

## 5. Массив идёт через итератор

Ключевой факт: массивная деструктуризация **не читает индексы**. Она вызывает `GetIterator`, затем `IteratorStep` столько раз, сколько элементов в паттерне, и `IteratorClose` при досрочном завершении.

```js
const set = new Set(['a', 'b', 'c']);
const [s1, s2] = set;      // работает — Set итерируем

const str = 'привет';
const [ch] = str;          // 'п' — строка итерируема

const map = new Map([['k', 'v']]);
const [[key, val]] = map;  // вложенный паттерн по записи Map

const arrayLike = { 0: 'a', 1: 'b', length: 2 };
// const [z] = arrayLike;  // TypeError: arrayLike is not iterable
const [z] = Array.from(arrayLike); // так корректно
```

### IteratorClose — то, что упускают

```js
function* source() {
  try {
    yield 'первый';
    yield 'второй';
    yield 'третий';
  } finally {
    console.log('ресурс освобождён');
  }
}

const [only] = source();
// 'ресурс освобождён' — печатается ДО следующей строки
console.log(only); // 'первый'
```

Когда паттерн короче последовательности, спецификация обязана закрыть итератор — вызвать его `return()`. Для генератора это запускает `finally`, что делает деструктуризацию безопасной для ресурсов: файловый дескриптор или соединение закроются, даже если вы взяли только первый элемент.

```js
// rest дочитывает итератор до конца
const [head, ...tail] = source();
console.log(head, tail); // 'первый' ['второй', 'третий'], затем 'ресурс освобождён'
```

### Бесконечные последовательности

```js
function* naturals() { let n = 1; while (true) yield n++; }

const [one, two, three] = naturals(); // 1 2 3 — берётся ровно три шага
// const [...all] = naturals();       // зависание: rest дочитывает до конца
```

## 6. Объект читает свойства

Объектная деструктуризация итератор не использует — она выполняет `GetV` по каждому ключу. Отсюда три следствия.

```js
// 1. Работает с любым объектом, включая неитерируемый
const { length } = { length: 5 };

// 2. Видит унаследованные свойства
const parent = { inherited: 'да' };
const child = Object.create(parent);
const { inherited } = child; // 'да' — прототипная цепочка обходится

// 3. Работает с примитивами через ToObject
const { length: strLen } = 'привет'; // 6
const { toFixed } = 42;              // функция из Number.prototype
```

```js
// null и undefined деструктурировать нельзя — ToObject бросает
// const { a } = null;      // TypeError: Cannot destructure 'null'
const { a } = null ?? {};   // безопасно
```

### Вычисляемые ключи

```js
const key = 'dynamic';
const { [key]: extracted } = { dynamic: 'значение' };
console.log(extracted); // 'значение'

// ключ может быть выражением
const i = 1;
const { [`item${i}`]: item } = { item1: 'первый' };
```

При вычисляемом ключе переименование обязательно — синтаксис не даёт вывести имя переменной из выражения.

## 7. Rest: два разных механизма

```js
// Массивный rest — всегда новый массив, дочитывает итератор
const [first, ...others] = 'абвг';
console.log(others); // ['б', 'в', 'г']

// Объектный rest — CopyDataProperties
const source = {
  a: 1,
  b: 2,
  get computed() { console.log('геттер вызван'); return 3; }
};
const { a: taken, ...rest } = source;
// 'геттер вызван'
console.log(rest); // { b: 2, computed: 3 }
```

Объектный rest **вызывает геттеры** и кладёт в результат вычисленное значение. Ленивость теряется. Также теряются прототип, неперечисляемые свойства и дескрипторы:

```js
class Model { constructor() { this.id = 1; } get computed() { return 2; } }
const model = new Model();
const { ...copy } = model;

console.log(copy);                  // { id: 1 } — геттер из прототипа не скопирован
console.log(copy instanceof Model); // false — прототип потерян
```

Геттер в примере лежит в `Model.prototype`, а `CopyDataProperties` берёт только **собственные перечисляемые** свойства — поэтому он не попал в копию. Собственный геттер (объявленный в литерале) попал бы, но как обычное значение.

```js
// rest обязан быть последним
// const [...init, last] = [1, 2, 3];  // SyntaxError: Rest element must be last
// const { ...all, a } = obj;          // SyntaxError
```

### Практическое применение — исключение полей

```js
const user = { id: 1, name: 'Аня', password: 'секрет', token: 'abc' };
const { password, token, ...safe } = user;
console.log(safe); // { id: 1, name: 'Аня' }
```

Идиома «выкинуть чувствительные поля». Линтер обычно ругается на неиспользуемые `password` и `token` — в ESLint это лечится опцией `ignoreRestSiblings`.

## 8. Вложенность

```js
const config = { server: { host: 'localhost', port: 8080 } };

const { server: { port } } = config;
console.log(port);   // 8080
// console.log(server); // ReferenceError — промежуточное имя НЕ создано
```

Вложенный паттерн — это инструкция «зайти внутрь», а не объявление. Чтобы получить и родителя, и потомка, его указывают дважды:

```js
const { server, server: { port: p } } = config; // оба имени доступны
```

### Каждый уровень нужно защищать отдельно

```js
const empty = {};

// const { server: { port } } = empty; // TypeError: Cannot destructure

const { server: { port: safe } = {} } = empty;
console.log(safe); // undefined
```

```js
// боевой приём — сквозные дефолты
function connect({
  host = 'localhost',
  port = 5432,
  auth: { user = 'guest', password = '' } = {},
  retry: { attempts = 3, delay = 1000 } = {},
} = {}) {
  return { host, port, user, password, attempts, delay };
}

connect();                              // всё по умолчанию
connect({ auth: { user: 'admin' } });   // частичное переопределение
```

Внешний `= {}` позволяет вызвать функцию вообще без аргумента, внутренние — опустить целые секции.

## 9. Где ещё встречается паттерн

```js
// for-of
const entries = [['a', 1], ['b', 2]];
for (const [k, v] of entries) console.log(k, v);

for (const { id, name } of users) console.log(id, name);

// catch
try { throw { code: 404, message: 'не найдено' }; }
catch ({ code, message }) { console.log(code, message); }

// параметры коллбэка
Object.entries(obj).map(([key, value]) => `${key}=${value}`);
promise.then(({ data: { items = [] } = {} }) => items);
```

> [!tip] Обмен без временной переменной
> ```js
> let a = 1, b = 2;
> [a, b] = [b, a];
> ```
> Правая часть вычисляется полностью до присваивания, поэтому обмен корректен. Циклический сдвиг работает так же: `[a, b, c] = [c, a, b]`.

## 10. Итог

> [!success] Что забирать
> - Объявление и присваивание используют **разные грамматики**; целью присваивания может быть любое место для записи, включая свойства и сеттеры
> - `({ } = )` требует скобок из-за конфликта с блоком; строку стоит начинать с `;` в проектах без точек с запятой
> - Дефолт срабатывает **только на `undefined`**; для `null` нужен `??`
> - Дефолты ленивы, вычисляются слева направо и живут в отдельной области видимости параметров
> - Массив деструктурируется **через итератор** с обязательным `IteratorClose` — это делает конструкцию безопасной для ресурсов
> - Объект читает свойства, видит прототип, работает с примитивами и падает на `null`/`undefined`
> - Объектный rest **вызывает геттеры**, теряет прототип и дескрипторы
> - Вложенный паттерн не создаёт промежуточных имён и требует дефолта на каждом уровне
