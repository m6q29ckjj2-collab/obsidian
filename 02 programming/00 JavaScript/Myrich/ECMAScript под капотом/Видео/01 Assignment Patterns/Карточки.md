## Грамматика

Какая продукция работает при деструктуризации в объявлении::`BindingPattern`, через операцию `BindingInitialization`

Какая продукция работает при деструктуризации в присваивании::`AssignmentPattern`, через операцию `DestructuringAssignmentEvaluation`

Что может стоять слева в паттерне присваивания::Любой `AssignmentTarget` — имя, свойство объекта, элемент массива, вычисляемый ключ. Всё, что допустимо слева от обычного `=`

Почему `{ a } = obj` без скобок даёт SyntaxError::Инструкция, начинающаяся с `{`, разбирается парсером как ==блок==, а не объектный литерал. Скобки переводят её в выражение

Почему строку с деструктуризацией начинают с `;` в проектах без точек с запятой
?
Строка, начинающаяся с `(` или `[`, приклеивается к предыдущей при автоподстановке точки с запятой:
```js
const x = 1
({ a } = obj)  // TypeError: 1 is not a function
```

Вызываются ли сеттеры при деструктуризации в свойство::Да, выполняется полноценная операция `[[Set]]`

Продвигается ли итератор на элизии `[, , x]`::Да. Шаг делается, результат отбрасывается — для генератора с побочными эффектами это заметно

## Значения по умолчанию

На какое значение срабатывает дефолт::Только на ==`undefined`==. Строгое сравнение, ни falsy, ни `null` его не активируют

Что вернёт `const [a = 'д'] = [null]`::`null` — дефолт не срабатывает

Что вернёт `const [a = 'д'] = []`::`'д'` — итератор исчерпан, значение равно `undefined`

Почему дефолты бесполезны для API, отдающих `null`
?
Проверка идёт строго на `undefined`. Для `null` нужен `??`:
```js
const avatar = response.avatar ?? '/default.png';
```

Когда вычисляется выражение в значении по умолчанию::==Лениво== — только если значение оказалось `undefined`

Что выведет код
?
```js
function broken(a = b, b = 2) { return [a, b]; }
broken();
```
`ReferenceError: Cannot access 'b' before initialization` — параметры инициализируются слева направо, `b` ещё в TDZ

Что выведет код и почему
?
```js
const value = 'внешнее';
function scope(a = value) {
  const value = 'внутреннее';
  return a;
}
scope();
```
`'внешнее'`. При наличии дефолтов создаётся ==отдельное окружение для списка параметров==, тело функции получает дочернее. Объявление в теле на дефолты не влияет.

## Итератор

Какой механизм использует массивная деструктуризация::==Протокол итератора==: `GetIterator` → `IteratorStep` → `IteratorClose` при досрочном выходе

Что произойдёт при деструктуризации не-итерируемого объекта::`TypeError: ... is not iterable`. Лечится через `Array.from`

Что выведет код
?
```js
function* src() {
  try { yield 1; yield 2; } finally { console.log('закрыт'); }
}
const [only] = src();
console.log(only);
```
`'закрыт'`, затем `1`. `IteratorClose` вызывает `return()` генератора до продолжения кода

Почему деструктуризация безопасна для ресурсов::Досрочный выход обязан закрыть итератор — `finally` генератора отработает, дескриптор или соединение освободятся

Что произойдёт при `const [...all] = infiniteGenerator()`::==Зависание==. Rest дочитывает итератор до конца, а конца нет

Можно ли деструктурировать Set и строку::Да, оба итерируемы: `const [a, b] = new Set([1, 2])`, `const [ch] = 'текст'`

## Объектный паттерн

Использует ли объектная деструктуризация итератор::Нет, читает свойства по ключам через `GetV`

Видит ли объектная деструктуризация унаследованные свойства::==Да==, прототипная цепочка обходится

Что вернёт `const { length } = 'привет'`::`6` — примитив проходит через `ToObject`

Что произойдёт при `const { a } = null`::`TypeError: Cannot destructure 'null'` — `ToObject` бросает на `null` и `undefined`

Как деструктурировать по вычисляемому ключу::`const { [key]: name } = obj` — переименование обязательно, имя из выражения не выводится

## Rest

Что делает объектный rest с геттерами::==Вызывает их== через `CopyDataProperties` и кладёт вычисленное значение. Ленивость теряется

Что теряется при объектном rest::Прототип, неперечисляемые свойства, дескрипторы, ленивость геттеров

Что вернёт `copy instanceof Model` после `const { ...copy } = new Model()`::`false` — прототип не копируется

Почему `const [...init, last] = arr` — синтаксическая ошибка::Rest обязан быть ==последним== элементом паттерна

Идиома исключения полей из объекта
?
```js
const { password, token, ...safe } = user;
```
В ESLint неиспользуемые `password` и `token` глушатся опцией `ignoreRestSiblings`.

## Вложенность

Создаётся ли промежуточное имя при `const { a: { b } } = obj`::Нет. Вложенный паттерн — инструкция «зайти внутрь», доступен только `b`

Как получить и родителя, и потомка::Указать дважды: `const { server, server: { port } } = config`

Почему `const { a: { b } } = {}` бросает TypeError::Внутри `a` лежит `undefined`, чтение свойства у него невозможно. Спасает дефолт: `{ a: { b } = {} }`

Зачем внешний `= {}` в `function f({ x = 1 } = {})`::Чтобы функцию можно было вызвать ==без аргумента вообще==. Иначе `f()` попытается деструктурировать `undefined`

Почему обмен `[a, b] = [b, a]` работает::Правая часть вычисляется ==полностью== до присваивания. Так же работает циклический сдвиг `[a, b, c] = [c, a, b]`
