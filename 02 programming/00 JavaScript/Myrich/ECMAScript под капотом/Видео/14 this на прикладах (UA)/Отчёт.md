## Как определить `this` за четыре вопроса

Прежде чем разбирать случаи, зафиксируем процедуру. Она выводится прямо из спецификации и покрывает все варианты.

1. **Это стрелочная функция?** Если да — своего `this` нет, `GetThisEnvironment` идёт вверх по `[[OuterEnv]]`. Всё остальное неважно
2. **Вызвана через `new`?** Тогда `this` — новый объект с прототипом из `Ctor.prototype`
3. **Указан явно через `call` / `apply` / `bind`?** Тогда это переданное значение (в sloppy mode примитивы проходят `ToObject`)
4. **Есть база вызова — `obj.method()`?** Тогда `this` — это `obj`. Иначе `undefined` в strict mode или `globalThis` в sloppy

Порядок важен: первый подошедший пункт побеждает.

## Ситуация 1. Метод оторвали от объекта

Самый частый случай в реальном коде.

```js
const counter = {
  count: 0,
  increment() { this.count++; return this.count; },
};

console.log(counter.increment()); // 1 — база вызова есть

const detached = counter.increment;
// detached();  // strict: TypeError · sloppy: молча портит globalThis
```

Отрыв происходит незаметно:

```js
// передача коллбэком
[1, 2, 3].forEach(counter.increment);          // this потерян
setTimeout(counter.increment, 100);            // потерян
element.addEventListener('click', counter.increment); // this станет элементом

// присваивание в переменную
const { increment } = counter;                 // деструктуризация тоже отрывает
```

Четыре способа починить:

```js
// 1. bind — создаёт новую функцию с зафиксированным this
setTimeout(counter.increment.bind(counter), 100);

// 2. стрелка-обёртка — вызов остаётся полным
setTimeout(() => counter.increment(), 100);

// 3. второй аргумент, если метод его поддерживает
[1, 2, 3].forEach(counter.increment, counter);

// 4. поле-стрелка в классе — this захвачен при конструировании
class Counter {
  count = 0;
  increment = () => { this.count++; };
}
```

> [!warning] У `bind` есть цена
> `bind` создаёт **новый функциональный объект** при каждом вызове. Поэтому `element.addEventListener('click', fn.bind(obj))` невозможно снять через `removeEventListener` с новым `bind` — это будет другая функция. Ссылку нужно сохранить.
> ```js
> const handler = fn.bind(obj);
> element.addEventListener('click', handler);
> element.removeEventListener('click', handler); // работает
> ```

## Ситуация 2. Стрелка там, где нужен динамический `this`

Стрелка захватывает `this` **лексически** и не поддаётся `call`, `apply`, `bind` и `new`.

```js
const obj = {
  value: 'из объекта',
  regular() { return this.value; },
  arrow: () => this?.value,   // this взят из внешней области, не из obj
};

console.log(obj.regular()); // 'из объекта'
console.log(obj.arrow());   // undefined
```

```js
const arrow = () => this;
console.log(arrow.call({ a: 1 })); // не {a:1} — call проигнорирован
// new arrow();                    // TypeError: arrow is not a constructor
```

Классическая ошибка — стрелка как метод прототипа или как обработчик, которому нужен элемент:

```js
// не работает: this не станет элементом
element.addEventListener('click', () => console.log(this));

// работает
element.addEventListener('click', function () { console.log(this); });
// либо явно через параметр события
element.addEventListener('click', e => console.log(e.currentTarget));
```

И обратная сторона: именно лексический захват решает старую проблему с коллбэками.

```js
class Timer {
  seconds = 0;
  start() {
    setInterval(() => { this.seconds++; }, 1000); // this из start
  }
  startBroken() {
    setInterval(function () { this.seconds++; }, 1000); // this не тот
  }
}
```

## Ситуация 3. Вложенная обычная функция

```js
const obj = {
  items: ['a', 'b'],
  process() {
    console.log(this.items);         // работает

    function helper() {
      // console.log(this.items);    // TypeError в strict — this равен undefined
    }
    helper();                        // вызов без базы!

    const arrowHelper = () => this.items; // работает
    return arrowHelper();
  },
};
```

Внутренняя функция вызывается **без базы**, поэтому получает `undefined` (strict) или `globalThis` (sloppy). Это не «потеря» `this` — просто у неё свой собственный, определённый правилами вызова.

## Ситуация 4. Класс и приватные поля

```js
class Counter {
  #count = 0;
  increment() { this.#count++; return this.#count; }
}

const c = new Counter();
const m = c.increment;
// m(); // TypeError: Cannot read private member #count from an object
      //  whose class did not declare it
```

Тела классов **всегда строгие**, поэтому оторванный метод получает `undefined`, а не `globalThis`. Сообщение об ошибке при этом упоминает приватное поле, что сбивает с толку — настоящая причина в потерянном `this`.

### Производный конструктор

```js
class Base { constructor() { this.base = true; } }

class Derived extends Base {
  constructor() {
    // console.log(this); // ReferenceError
    super();              // здесь this создаётся
    console.log(this.base); // true
  }
}
```

В производном классе `[[ThisBindingStatus]]` равен `uninitialized` до вызова `super()`. Механизм тот же, что у TDZ для `let`.

```js
// повторный super() тоже ошибка
class Twice extends Base {
  constructor() { super(); /* super(); */ } // ReferenceError при повторе
}
```

### Поле-стрелка против метода

```js
class Button {
  label = 'ok';
  asMethod() { return this.label; }
  asArrow = () => this.label;
}

const btn = new Button();
const [m, a] = [btn.asMethod, btn.asArrow];
// m(); // TypeError
console.log(a()); // 'ok'
```

Метод лежит в `Button.prototype` в единственном экземпляре и получает `this` из вызова. Поле-стрелка создаётся **заново для каждого объекта** при конструировании и захватывает `this` лексически.

Цена: тысяча экземпляров — тысяча функциональных объектов. Для часто создаваемых объектов предпочтительнее метод плюс `bind` в конструкторе, а лучше — обработчик, не зависящий от `this`.

## Ситуация 5. `this` в геттерах, сеттерах и `Reflect`

```js
const base = { get self() { return this; } };
const derived = Object.create(base);

console.log(derived.self === derived); // true — this это объект, с которого читали
console.log(base.self === base);       // true
```

Геттер получает `this` по тому же правилу базы вызова — им становится объект, **с которого началось чтение**, а не тот, в котором геттер объявлен.

```js
// в Reflect это управляется третьим аргументом
console.log(Reflect.get(base, 'self', derived) === derived); // true
console.log(Reflect.get(base, 'self') === base);             // true
```

Отсюда типовая ошибка в ловушках Proxy:

```js
// неправильно: receiver потерян, наследованные геттеры получат не тот this
const bad = new Proxy(target, {
  get(t, k) { return Reflect.get(t, k); }
});

// правильно
const good = new Proxy(target, {
  get(t, k, receiver) { return Reflect.get(t, k, receiver); }
});
```

## Ситуация 6. Верхний уровень

```js
// в модуле ESM
console.log(this); // undefined

// в обычном скрипте (sloppy)
console.log(this); // globalThis

// в CommonJS-модуле Node
console.log(this === module.exports); // true
```

Три разных значения в трёх разных контекстах — источник путаницы при переносе кода между системами модулей. Универсальная ссылка на глобальный объект — `globalThis`, работающий везде.

## Ситуация 7. Экзотика, о которой стоит знать

```js
// bind нельзя переопределить повторно
function f() { return this.tag; }
const once = f.bind({ tag: 'первый' });
const twice = once.bind({ tag: 'второй' });
console.log(twice()); // 'первый' — второй bind проигнорирован
```

Связанная функция — экзотический объект со слотом `[[BoundThis]]`. Повторный `bind` оборачивает уже связанную функцию, но внутренний `this` перезаписать не может.

```js
// но new на связанной функции this игнорирует
function Ctor() { this.created = true; }
const Bound = Ctor.bind({ ignored: true });
const inst = new Bound();
console.log(inst.created);  // true — new важнее bind
console.log(inst.ignored);  // undefined
```

```js
// getter/setter и this в цепочке при записи
const proto = { set value(v) { this.stored = v; } };
const child = Object.create(proto);
child.value = 42;
console.log(child.stored);                    // 42 — this это child
console.log(Object.hasOwn(child, 'value'));   // false — сеттер перехватил запись
```

## Итог

> [!success] Что забирать
> - Процедура из четырёх вопросов покрывает все случаи: стрелка → `new` → явное указание → база вызова
> - Отрыв метода происходит незаметно: коллбэк, `setTimeout`, деструктуризация, слушатель события
> - `bind` создаёт **новую функцию** — ссылку нужно сохранять, иначе `removeEventListener` не сработает
> - Стрелка не поддаётся `call`, `apply`, `bind` и `new`; как обработчик события она не получит элемент
> - Вложенная обычная функция вызывается без базы и получает `undefined` в strict
> - Тела классов всегда строгие, поэтому оторванный метод даёт `TypeError`, а не тихую порчу глобального объекта
> - В производном конструкторе `this` находится в состоянии `uninitialized` до `super()`
> - Поле-стрелка переживает отрыв, но создаётся заново для каждого экземпляра
> - Геттер получает объект, **с которого началось чтение**; в ловушках Proxy это требует проброса `receiver`
> - На верхнем уровне `this` равен `undefined` в ESM, `globalThis` в скрипте и `module.exports` в CommonJS
> - Повторный `bind` не перезаписывает `this`, но `new` игнорирует связывание
