> [!question] В каком из вариантов `this` НЕ потеряется?
> a) `setTimeout(counter.increment, 100)`
> b) `[1, 2].forEach(counter.increment)`
> c) `const { increment } = counter`
> d) `counter.increment()`
>> [!success]- Answer
>> d) `counter.increment()`
>> Только здесь у вызова есть база. Все остальные варианты передают саму функцию, и в момент срабатывания вызов идёт без базы

> [!question] Почему слушатель, добавленный как `handler.bind(obj)`, невозможно снять тем же выражением?
> a) `removeEventListener` не работает со связанными функциями
> b) `bind` создаёт новый функциональный объект при каждом вызове
> c) связанная функция не хранит ссылку на исходную
> d) браузер игнорирует повторные вызовы
>> [!success]- Answer
>> b) `bind` создаёт новый функциональный объект при каждом вызове
>> Две строки создают две разные функции. Ссылку нужно сохранить в переменную — та же ловушка со стрелкой-обёрткой

> [!question] Стрелочную функцию можно перенаправить методом `call`
>> [!success]- Answer
>> False
>> Своего связывания this у неё нет, поэтому менять нечего. Не действуют ни call, ни apply, ни bind, ни new

> [!question] Что вернёт вызов?
> ```js
> const obj = { value: 'из объекта', get: () => this?.value };
> console.log(obj.get());
> ```
> a) `'из объекта'`
> b) `undefined`
> c) сам объект
> d) `TypeError`
>> [!success]- Answer
>> b) `undefined`
>> Объектный литерал области видимости не создаёт, поэтому стрелка захватывает внешний this. В литерале она никогда не получит сам объект

> [!question] Что получит `this` во вложенной обычной функции внутри метода в строгом режиме?
> a) объект, на котором вызван метод
> b) `undefined`
> c) `globalThis`
> d) саму функцию
>> [!success]- Answer
>> b) `undefined`
>> Она вызывается без базы, значит получает своё связывание по общим правилам. Решение — стрелка, у которой своего связывания нет

> [!question] Почему оторванный метод класса даёт `TypeError`, а не портит глобальный объект?
> a) приватные поля защищены от записи
> b) тела классов всегда строгие
> c) методы класса неперезаписываемы
> d) классы автоматически привязывают `this`
>> [!success]- Answer
>> b) тела классов всегда строгие
>> Поэтому this равен undefined, а не globalThis. Сообщение об ошибке при этом упоминает приватное поле, что сбивает с толку при отладке

> [!question] Обращение к `this` в производном конструкторе до вызова `super()` даёт ошибку
>> [!success]- Answer
>> True
>> Слот состояния связывания равен uninitialized. Заполняет его вызов super — механизм тот же, что у TDZ для let

> [!question] Чем расплачиваются за поле-стрелку в классе вместо метода?
> a) потерей доступа к приватным полям
> b) новым функциональным объектом на каждый экземпляр
> c) невозможностью переопределить в подклассе
> d) замедлением вызова
>> [!success]- Answer
>> b) новым функциональным объектом на каждый экземпляр
>> Метод лежит в прототипе в единственном экземпляре. Для часто создаваемых объектов лучше метод, а ещё лучше обработчик, не зависящий от this

> [!question] Какой объект получает `this` внутри геттера?
> a) тот, в котором геттер объявлен
> b) тот, с которого началось чтение
> c) всегда `globalThis`
> d) прототип объекта
>> [!success]- Answer
>> b) тот, с которого началось чтение
>> То же правило базы вызова. В Reflect.get этим управляет третий аргумент receiver

> [!question] Что произойдёт, если в ловушке `get` у Proxy не пробросить `receiver`?
> a) ничего, аргумент необязателен
> b) наследованные геттеры получат неверный `this`
> c) ловушка перестанет вызываться
> d) выбросится `TypeError`
>> [!success]- Answer
>> b) наследованные геттеры получат неверный `this`
>> Баг проявляется только на наследовании, поэтому легко проходит проверку на простых объектах

> [!question] Чему равен `this` на верхнем уровне модуля ESM?
> a) `globalThis`
> b) `undefined`
> c) `module.exports`
> d) пустому объекту
>> [!success]- Answer
>> b) `undefined`
>> В обычном скрипте это globalThis, в CommonJS — module.exports. Три разных значения, отсюда баги при сборке в несколько форматов

> [!question] Что вернёт код?
> ```js
> function f() { return this.tag; }
> console.log(f.bind({ tag: 'a' }).bind({ tag: 'b' })());
> ```
> a) `'a'`
> b) `'b'`
> c) `undefined`
> d) `TypeError`
>> [!success]- Answer
>> a) `'a'`
>> Повторный bind оборачивает уже связанную функцию, но её внутреннее связывание перезаписать не может. Первый bind побеждает всегда

> [!question] Оператор `new` игнорирует связывание, установленное через `bind`
>> [!success]- Answer
>> True
>> Внутренний метод конструирования создаёт новый объект обычным образом. Это согласуется с общим порядком: new определяет this раньше явного связывания

> [!question] Какой способ передать метод коллбэком НЕ сохраняет `this`?
> a) `fn.bind(obj)`
> b) стрелка-обёртка `() => obj.fn()`
> c) второй аргумент `forEach(fn, obj)`
> d) присваивание в переменную и передача переменной
>> [!success]- Answer
>> d) присваивание в переменную и передача переменной
>> Именно так база вызова и теряется. Первые три варианта сохраняют её разными способами
