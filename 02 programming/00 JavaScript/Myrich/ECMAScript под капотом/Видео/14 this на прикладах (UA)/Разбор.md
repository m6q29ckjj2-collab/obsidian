### 1. Сформулируйте процедуру определения `this` из четырёх вопросов

> [!success]- Ответ
> 1. **Стрелочная функция?** Своего `this` нет — `GetThisEnvironment` идёт вверх по `[[OuterEnv]]`. Остальные пункты не рассматриваются
> 2. **Вызов через `new`?** `this` — новый объект с прототипом из `Ctor.prototype`
> 3. **Указан явно через `call`, `apply` или `bind`?** Это переданное значение; в sloppy mode примитивы проходят `ToObject`
> 4. **Есть база вызова `obj.method()`?** Это `obj`. Иначе `undefined` в strict, `globalThis` в sloppy
>
> Порядок существенен: побеждает первый подошедший пункт. Стрелка «выигрывает» у всего остального.

### 2. Найдите все места, где `this` теряется

```js
const counter = { count: 0, increment() { this.count++; } };

[1, 2].forEach(counter.increment);
setTimeout(counter.increment, 100);
element.addEventListener('click', counter.increment);
const { increment } = counter;
```

> [!success]- Ответ
> Во всех четырёх.
>
> Каждая строка передаёт **саму функцию** без базы вызова. В момент срабатывания вызов происходит как `increment()`, а не `counter.increment()`.
>
> У обработчика события есть нюанс: `this` там не `undefined`, а сам элемент — DOM вызывает обработчик с элементом в роли базы. Результат всё равно неверный: свойство `count` увеличивается на элементе.
>
> Деструктуризация тоже отрывает, хотя выглядит безобидно.

### 3. Почему этот слушатель невозможно снять

```js
element.addEventListener('click', handler.bind(obj));
element.removeEventListener('click', handler.bind(obj));
```

> [!success]- Ответ
> `bind` создаёт **новый функциональный объект** при каждом вызове. Две строки создают две разные функции, и `removeEventListener` не находит совпадения.
>
> ```js
> const bound = handler.bind(obj);
> element.addEventListener('click', bound);
> element.removeEventListener('click', bound); // работает
> ```
>
> Та же ловушка с `() => handler()`: каждая стрелка — новый объект. Ссылку нужно сохранять всегда.

### 4. Что выведет код

```js
const obj = {
  value: 'из объекта',
  regular() { return this.value; },
  arrow: () => this?.value,
};
console.log(obj.regular(), obj.arrow());
```

> [!success]- Ответ
> `'из объекта' undefined`.
>
> Стрелка захватывает `this` **лексически** — из области, где она создана. Объектный литерал области видимости не создаёт, поэтому `this` берётся из внешнего контекста: `undefined` в модуле, `globalThis` в скрипте.
>
> Ключевое: стрелка в литерале объекта **никогда** не получит сам объект. Для методов нужна обычная функция или сокращённая запись.

### 5. Что произойдёт при этих вызовах

```js
const arrow = () => this;
arrow.call({ a: 1 });
new arrow();
```

> [!success]- Ответ
> `call` вернёт внешний `this`, проигнорировав аргумент. `new arrow()` бросит `TypeError: arrow is not a constructor`.
>
> У стрелки `[[ThisBindingStatus]]` равен `lexical` — своего связывания нет, значит менять нечего. `call`, `apply` и `bind` на неё не действуют.
>
> Конструктором она быть не может, потому что у неё нет внутреннего метода `[[Construct]]` и нет свойства `prototype`.

### 6. Почему внутренняя функция не видит `this`

```js
const obj = {
  items: ['a', 'b'],
  process() {
    function helper() { return this.items; }
    return helper();
  },
};
obj.process();
```

> [!success]- Ответ
> `TypeError: Cannot read properties of undefined` в строгом режиме.
>
> `helper()` вызывается **без базы** — это обычный вызов, а не `obj.helper()`. По четвёртому правилу `this` становится `undefined` в strict или `globalThis` в sloppy.
>
> Это не «потеря» `this`: у внутренней функции просто своё связывание, определённое формой вызова. Решение — стрелка, которая своего связывания не имеет и найдёт `this` метода:
>
> ```js
> const helper = () => this.items;
> ```

### 7. Объясните ошибку

```js
class Counter {
  #count = 0;
  increment() { this.#count++; }
}
const m = new Counter().increment;
m();
```

> [!success]- Ответ
> `TypeError: Cannot read private member #count from an object whose class did not declare it`.
>
> Тела классов **всегда строгие**, поэтому оторванный метод получает `this === undefined`. Дальше попытка прочитать приватное поле у `undefined` и даёт ошибку.
>
> Сообщение сбивает с толку: оно говорит о приватном поле, хотя настоящая причина — потерянный `this`. Это стоит помнить при отладке.

### 8. Почему падает первая строка конструктора

```js
class Base { constructor() { this.base = true; } }
class Derived extends Base {
  constructor() { console.log(this); super(); }
}
new Derived();
```

> [!success]- Ответ
> `ReferenceError: Must call super constructor before accessing 'this'`.
>
> В производном классе связывание `this` не создаётся при входе в конструктор: слот `[[ThisBindingStatus]]` равен `uninitialized`. Заполняет его операция `BindThisValue`, вызываемая из `super()`.
>
> Механизм тот же, что у TDZ для `let`. По той же причине повторный вызов `super()` даёт `ReferenceError` — связывание уже инициализировано.

### 9. Сравните два подхода и оцените цену

```js
class Button {
  label = 'ok';
  asMethod() { return this.label; }
  asArrow = () => this.label;
}
```

> [!success]- Ответ
> `asMethod` лежит в `Button.prototype` в **единственном экземпляре** и получает `this` из вызова — теряется при отрыве.
>
> `asArrow` — поле экземпляра: новый функциональный объект создаётся **для каждого объекта** при конструировании и лексически захватывает `this`. Отрыв переживает.
>
> Цена: тысяча экземпляров — тысяча функциональных объектов вместо одного. Для часто создаваемых объектов (элементы списка, ячейки таблицы) предпочтительнее метод плюс `bind` в конструкторе, а лучше — обработчик, вовсе не зависящий от `this`.

### 10. Что вернёт каждая строка

```js
const base = { get self() { return this; } };
const derived = Object.create(base);

console.log(derived.self === derived);
console.log(Reflect.get(base, 'self', derived) === derived);
console.log(Reflect.get(base, 'self') === base);
```

> [!success]- Ответ
> `true`, `true`, `true`.
>
> Геттер получает `this` по правилу базы вызова: им становится объект, **с которого началось чтение**, а не тот, в котором геттер объявлен.
>
> В `Reflect.get` это управляется третьим аргументом `receiver`. Отсюда типовая ошибка в ловушках Proxy — потеря `receiver`:
>
> ```js
> get(t, k) { return Reflect.get(t, k); }        // наследованные геттеры сломаются
> get(t, k, r) { return Reflect.get(t, k, r); }  // правильно
> ```

### 11. Чему равен `this` на верхнем уровне в трёх системах

> [!success]- Ответ
> **Модуль ESM** — `undefined`. Спецификация явно задаёт это значение для модульного кода.
>
> **Обычный скрипт (sloppy)** — `globalThis`.
>
> **Модуль CommonJS в Node** — `module.exports`, то есть пустой объект на старте.
>
> Три разных значения — регулярный источник багов при переносе кода между системами модулей, особенно в библиотеках, собираемых в оба формата. Универсальная ссылка на глобальный объект — `globalThis`.

### 12. Что выведет код

```js
function f() { return this.tag; }
const once = f.bind({ tag: 'первый' });
const twice = once.bind({ tag: 'второй' });
console.log(twice());

function Ctor() { this.created = true; }
const Bound = Ctor.bind({ ignored: true });
console.log(new Bound().created, new Bound().ignored);
```

> [!success]- Ответ
> `'первый'`, затем `true undefined`.
>
> Связанная функция — экзотический объект со слотами `[[BoundTargetFunction]]` и `[[BoundThis]]`. Повторный `bind` оборачивает уже связанную функцию, но внутреннее связывание перезаписать не может — первый `bind` побеждает.
>
> При этом `new` **важнее** `bind`: внутренний метод `[[Construct]]` связанной функции игнорирует `[[BoundThis]]` и создаёт новый объект обычным образом. Это соответствует второму пункту процедуры — `new` стоит выше явного указания.
