## Процедура определения

Четыре вопроса для определения `this` по порядку
?
1. Это ==стрелочная функция==? Своего `this` нет, поиск идёт вверх по `[[OuterEnv]]`
2. Вызов через ==`new`==? `this` — новый объект
3. Указан явно через ==`call`/`apply`/`bind`==? Это переданное значение
4. Есть ==база вызова== `obj.method()`? Это `obj`. Иначе `undefined` (strict) или `globalThis` (sloppy)

Почему порядок вопросов важен::Побеждает ==первый подошедший== пункт. Стрелка игнорирует и `new`, и `call`, и базу вызова

## Отрыв метода

Назовите способы незаметно оторвать метод от объекта::Передача коллбэком, `setTimeout`, `addEventListener`, деструктуризация, присваивание в переменную

Что произойдёт при вызове оторванного метода::strict — `TypeError` при обращении к свойству `undefined`; sloppy — молча портит `globalThis`

Четыре способа сохранить `this` при передаче метода
?
1. `fn.bind(obj)`
2. Стрелка-обёртка `() => obj.fn()`
3. Второй аргумент `forEach(fn, obj)`, если метод его поддерживает
4. Поле-стрелка в классе

Почему `removeEventListener` не снимает слушатель, добавленный через `bind`::`bind` создаёт ==новый функциональный объект== при каждом вызове. Ссылку нужно сохранить в переменную

## Стрелки

Поддаётся ли стрелка методам `call`, `apply` и `bind`::==Нет==. Своего `this` у неё нет, менять нечего

Можно ли вызвать стрелку через `new`::Нет — `TypeError: arrow is not a constructor`

Почему стрелка не годится обработчиком события, которому нужен элемент::Она захватит `this` из внешней области, а не получит элемент. Нужна обычная функция либо `e.currentTarget`

В чём стрелка как раз незаменима::В коллбэках внутри методов — `setInterval(() => this.x++, 1000)` сохраняет `this` метода

Что получит `this` во вложенной обычной функции внутри метода::`undefined` в strict, `globalThis` в sloppy — она вызывается ==без базы==

## Классы

Почему оторванный метод класса даёт `TypeError`, а не портит глобальный объект::Тела классов ==всегда строгие==, поэтому `this` равен `undefined`

Почему сообщение об ошибке упоминает приватное поле::Обращение `this.#count` падает первым, хотя настоящая причина — потерянный `this`

В каком состоянии `this` в производном конструкторе до `super()`::`[[ThisBindingStatus]]` равен ==`uninitialized`== — обращение даёт `ReferenceError`

Что произойдёт при повторном вызове `super()`::`ReferenceError` — связывание уже инициализировано

Чем поле-стрелка отличается от метода по расположению и цене
?
**Метод** лежит в прототипе в ==единственном экземпляре==, получает `this` из вызова, теряется при отрыве.
**Поле-стрелка** создаётся ==заново для каждого объекта==, переживает отрыв, стоит памяти.

## Геттеры и Reflect

Какой объект получает `this` внутри геттера::Тот, ==с которого началось чтение==, а не тот, в котором геттер объявлен

Что вернёт `Reflect.get(base, 'self', derived)` при `get self() { return this }`::`derived` — третий аргумент задаёт `this` для геттера

Типовая ошибка в ловушке `get` у Proxy
?
Потеря `receiver`:
```js
get(t, k) { return Reflect.get(t, k); }        // неправильно
get(t, k, r) { return Reflect.get(t, k, r); }  // правильно
```
Без проброса наследованные геттеры получат неверный `this`.

Что произойдёт при записи, если у прототипа есть сеттер::Сеттер перехватит запись, `this` внутри него будет ==дочерним объектом==, собственное свойство не создастся

Чему равен `this` на верхнем уровне модуля CommonJS::`module.exports`

Какая ссылка на глобальный объект работает везде::==`globalThis`==

## Экзотика bind

Что вернёт повторно связанная функция
?
```js
const once = f.bind({ tag: 'первый' });
const twice = once.bind({ tag: 'второй' });
twice();
```
`'первый'`. Связанная функция — экзотический объект со слотом `[[BoundThis]]`, повторный `bind` его не перезаписывает.

Что важнее — `new` или `bind`::==`new`==. При конструировании связанной функции `[[BoundThis]]` игнорируется, создаётся новый объект
