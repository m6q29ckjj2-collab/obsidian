## 1. Разрыв между фольклором и механикой

Центральный тезис: массовые материалы описывают JavaScript **метафорами**, а спецификация описывает его **алгоритмами**. Метафора удобна, потому что даёт быстрый прогноз в типовых случаях. Она же и подводит — ровно на границах, где типовое заканчивается.

| Фольклор | Что происходит на самом деле |
|---|---|
| «Переменные всплывают наверх» | Биндинги создаются на стадии инстанцирования, до выполнения кода |
| «`let` не поднимается» | Поднимается, но остаётся неинициализированным |
| «Приведение типов меняет тип» | Абстрактные операции порождают новые значения |
| «`this` — это контекст вызова» | `this` берётся из ближайшего Function Environment Record |
| «Замыкание запоминает значения» | Захватывается запись окружения целиком |
| «Порядок свойств не гарантирован» | Гарантирован операцией `OrdinaryOwnPropertyKeys` |
| «Строка — набор символов» | Последовательность 16-битных единиц |
| «NaN — это одно число» | Одно значение языка, ~9 × 10¹⁵ представлений |

Каждая строка левой колонки работает в 90% случаев. Оставшиеся 10% — это ровно те задачи, которые дают на собеседованиях и которые ломают продакшн.

## 2. Три исторические причины

### Скорость создания

Язык был спроектирован в предельно сжатые сроки под коммерческий дедлайн, что зафиксировало решения, которые в спокойной обстановке были бы пересмотрены: `typeof null`, автоматическая вставка точек с запятой, приведение типов в операторе `==`, глобальный объект как область видимости.

### «Не сломать веб»

Главное ограничение TC39: любое изменение должно оставлять работоспособным код, написанный двадцать лет назад. Это ограничение сильнее эстетики, стройности и здравого смысла.

```js
// нельзя исправить, потому что на этом стоят миллионы страниц
console.log(typeof null);        // 'object'
console.log(0.1 + 0.2);          // 0.30000000000000004 — требование IEEE 754
console.log([] + {});            // '[object Object]'
```

Именно поэтому появился **Annex B** — приложение, легализующее браузерное поведение, которое формально не должно было существовать:

```js
// функции в блоках в нестрогом режиме
{ function f() {} }
typeof f; // 'function' — Annex B.3.3

// строковые методы, придуманные Netscape
'текст'.blink();  // '<blink>текст</blink>'
'текст'.fontsize(7);

// escape/unescape вместо encodeURIComponent
escape('привет');
```

Annex B помечен как нормативно-опциональный для не-браузерных сред, но в браузерах реализован везде — на практике это обязательная часть языка.

### Разрыв стандарта и реальности

Между версиями ES3 и ES5 прошло десять лет, ES4 был отменён целиком. За это время сложился слой практик, книг и туториалов, описывающих язык так, как он выглядел до стандартизации многих вещей. Этот слой пережил стандарт и продолжает воспроизводиться.

## 3. Как устроена спецификация

Понимание нотации — половина дела. Спецификация написана как формальный алгоритм, а не как проза.

### Абстрактные операции

Функции, существующие только в тексте стандарта: `ToPrimitive`, `GetValue`, `OrdinaryGet`, `CreatePerIterationEnvironment`. Вызвать их из кода нельзя, но именно они описывают, что делает движок.

Правило поиска: не ищите «hoisting» или «coercion» — таких терминов нет. Ищите имя операции.

| Что вы ищете | Как это называется в стандарте |
|---|---|
| hoisting | `FunctionDeclarationInstantiation`, `GlobalDeclarationInstantiation` |
| приведение типов | `ToPrimitive`, `ToNumber`, `ToString` |
| замыкание | `Environment Record`, слот `[[Environment]]` |
| контекст вызова | `OrdinaryCallBindThis` |
| порядок свойств | `OrdinaryOwnPropertyKeys` |
| нестрогое равенство | `IsLooselyEqual` |

### Completion Record

Результат любого шага — запись `{ [[Type]], [[Value]], [[Target]] }`, где тип это `normal`, `throw`, `return`, `break` или `continue`. Отсюда два значка:

- **`? expr`** — `ReturnIfAbrupt`: если внутри произошёл `throw`, немедленно пробросить наружу
- **`! expr`** — утверждение «исключение здесь невозможно»; его срабатывание означало бы ошибку в движке или в самой спецификации

Практическая польза: по расстановке `?` и `!` сразу видно, где алгоритм может выбросить исключение, а где нет.

### Внутренние слоты

Записываются как `[[Environment]]`, `[[ThisValue]]`, `[[Prototype]]`, `[[StringData]]`. Это состояние, недоступное из JavaScript напрямую. Некоторые слоты видны косвенно — например `[[Prototype]]` через `Object.getPrototypeOf`.

## 4. Как отвечать на вопрос о поведении

Рабочий порядок действий, который избавляет от догадок:

1. **Сформулировать вопрос в терминах операции.** Не «почему `let` не работает здесь», а «что делает `BlockDeclarationInstantiation` с этим объявлением»
2. **Найти операцию в [tc39.es/ecma262](https://tc39.es/ecma262/)** поиском по странице
3. **Проверить экспериментом** — но помнить, что эксперимент показывает поведение *конкретного движка*, а не требование стандарта
4. **Свериться с [Test262](https://github.com/tc39/test262)** — официальным набором тестов. Это фактически каталог краевых случаев, где на каждое требование есть проверка

```js
'use strict';
const sum = (n, acc = 0) => n === 0 ? acc : sum(n - 1, acc + n);
sum(1e6);
// Safari: 500000500000 — proper tail calls реализованы
// V8, SpiderMonkey: RangeError — требование стандарта не выполнено
```

Здесь расходится не понимание, а **реализация**: спецификация требует переиспользовать фрейм при хвостовом вызове, и два движка из трёх этого не делают. Ответ «по стандарту» и ответ «на практике» различаются, и знать нужно оба — причём в кроссбраузерном коде решает второй.

## 5. Процесс TC39 — почему язык меняется медленно

Предложение проходит пять стадий:

| Стадия | Смысл |
|---|---|
| 0 Strawperson | идея высказана |
| 1 Proposal | задача описана, есть чемпион |
| 2 Draft | синтаксис и семантика черновиком |
| 2.7 | семантика зафиксирована, нужны тесты |
| 3 Candidate | спецификация готова, ожидается обратная связь от реализаций |
| 4 Finished | две реализации, тесты в Test262, войдёт в следующую редакцию |

```js
// пример пути: приватные поля прошли этот путь несколько лет
class Counter {
  #count = 0;             // stage 3 держалось долго
  static #instances = 0;
  #increment() { this.#count++; }
  static { Counter.#instances = 0; } // статический блок — отдельное предложение
}
```

Медлительность — не недостаток процесса, а следствие того же ограничения: ошибка в стандарте необратима, потому что её нельзя исправить не сломав веб.

## 6. Практический вывод

> [!success] Что забирать
> - Массовые материалы описывают язык метафорами, спецификация — алгоритмами; метафора верна в типовых случаях и ломается на краевых
> - Три причины разрыва: сжатые сроки создания, ограничение «не сломать веб», десятилетний застой между ES3 и ES5
> - **Annex B** легализует историческое браузерное поведение и на практике обязателен
> - В стандарте нет терминов «hoisting» и «coercion» — искать нужно имена абстрактных операций
> - `? expr` означает `ReturnIfAbrupt`, `! expr` — утверждение о невозможности исключения
> - Эксперимент показывает поведение движка, а не требование стандарта; расхождения бывают в обе стороны
> - Test262 — практичный каталог краевых случаев
> - Пять стадий TC39 и медленный процесс — следствие необратимости ошибок в стандарте

> [!tip] Что делать с этим знанием
> Заведите привычку при любом «странном» поведении открывать спецификацию и находить операцию. Через десяток таких заходов пропадает целый класс вопросов — вместо запоминания частных случаев появляется модель, из которой они выводятся.
