> [!question] Замените фольклорную формулировку на механизм: «переменные всплывают наверх»
> a) объявления физически перемещаются в начало функции
> b) биндинги создаются операцией инстанцирования до выполнения кода
> c) движок выполняет код дважды
> d) интерпретатор сортирует инструкции
>> [!success]- Answer
>> b) биндинги создаются операцией инстанцирования до выполнения кода
>> Ничто никуда не перемещается. Просто имена появляются в записи окружения раньше, чем начинает выполняться код

> [!question] Термин «hoisting» присутствует в тексте стандарта
>> [!success]- Answer
>> False
>> Есть четыре операции инстанцирования по видам кода. Общее правило поиска — переводить фольклорный термин в имя абстрактной операции

> [!question] Значок вопроса перед вызовом операции — сокращение для `___`
>> [!success]- Answer
>> ReturnIfAbrupt
>> Если внутри случился выброс, он немедленно пробрасывается наружу. По расстановке значков видно, где алгоритм может выбросить исключение

> [!question] Что означает восклицательный знак перед вызовом абстрактной операции?
> a) операция обязательно выбросит исключение
> b) исключение здесь невозможно
> c) операция выполняется асинхронно
> d) результат следует проигнорировать
>> [!success]- Answer
>> b) исключение здесь невозможно
>> Это утверждение автора стандарта. Срабатывание такого исключения означало бы ошибку в движке или в самой спецификации

> [!question] Из каких полей состоит запись о завершении шага алгоритма?
> a) значение и тип
> b) тип, значение и цель
> c) только значение
> d) тип, значение, цель и стек
>> [!success]- Answer
>> b) тип, значение и цель
>> Тип принимает одно из пяти значений: обычное завершение, выброс, возврат, прерывание и продолжение

> [!question] Как называется в стандарте механизм, который зовут «приведением типов»?
> a) одна операция преобразования
> b) набор абстрактных операций, порождающих новые значения
> c) неявное изменение типа переменной
> d) такого механизма нет вовсе
>> [!success]- Answer
>> b) набор абстрактных операций, порождающих новые значения
>> Единой операции «приведения» не существует. Есть преобразование к примитиву, к числу, к строке и другие

> [!question] Что выведет код в нестрогом режиме?

> [!question] Почему `typeof null` до сих пор возвращает `'object'`?
> a) это логично с точки зрения системы типов
> b) исправление сломало бы существующий код
> c) так требует стандарт чисел
> d) в новых версиях это уже исправлено
>> [!success]- Answer
>> b) исправление сломало бы существующий код
>> Ограничение «не сломать веб» сильнее эстетики. За тридцать лет на текущее поведение опёрлись миллионы страниц

> [!question] Что из этого невозможно исправить в принципе, а не из-за совместимости?
> a) `typeof null`
> b) результат сложения `0.1` и `0.2`
> c) приведение типов в нестрогом равенстве

>> [!success]- Answer
>> b) результат сложения `0.1` и `0.2`
>> Это свойство двоичной арифметики, а не решение авторов языка. Остальные три — исторический долг

> [!question] Что показывает эксперимент с хвостовой рекурсией, работающий в одном браузере и падающий в другом?

> [!question] Замените фольклор на механизм: «замыкание запоминает значения»
> a) значения копируются в момент создания функции
> b) захватывается запись окружения целиком

> [!question] Замените фольклор на механизм: «порядок свойств объекта не гарантирован»

>> [!success]- Answer
>> b) он зафиксирован операцией перечисления собственных ключей
>> Целые индексы по возрастанию, затем строки и символы в порядке добавления. Утверждение из левой колонки устарело
