## Суть спора и почему он решается механикой

Обсуждение «что использовать» обычно ведётся в терминах вкуса: читаемость, привычка, «const везде — это догма». Спецификация переводит разговор в другую плоскость: три ключевых слова различаются **тремя независимыми характеристиками**, и каждая имеет наблюдаемые последствия.

| | `var` | `let` | `const` |
|---|---|---|---|
| Область видимости | функция | блок | блок |
| Состояние до инициализации | `undefined` | TDZ | TDZ |
| Повторное присваивание | да | да | **нет** |
| Повторное объявление | да | нет | нет |
| Попадает в `globalThis` | да | нет | нет |
| Своё окружение на итерацию | нет | да | да |

Ни одна из строк не является вопросом стиля. Это разные механизмы.

## 1. Куда попадает биндинг

```js
var viaVar = 1;
let viaLet = 2;
const viaConst = 3;
function viaFn() {}

console.log(globalThis.viaVar);   // 1
console.log(globalThis.viaFn);    // функция
console.log(globalThis.viaLet);   // undefined
console.log(globalThis.viaConst); // undefined
```

Глобальное окружение — гибрид двух записей. `var` и функциональные декларации идут в **Object Environment Record** поверх глобального объекта и становятся его свойствами. Лексические объявления идут в **Declarative Environment Record**, невидимую снаружи.

Практическое следствие — коллизии:

```js
var name = 'моё значение'; // в браузере затирает window.name
let title = 'моё';         // безопасно, глобальный объект не тронут
```

```js
var notDeletable = 1;
console.log(delete globalThis.notDeletable); // false — [[Configurable]]: false

globalThis.assigned = 2;
console.log(delete globalThis.assigned);     // true — обычное свойство
```

## 2. Состояние до инициализации

Все три создаются на стадии инстанцирования — «поднимаются» одинаково. Различие в **начальном значении**.

```js
console.log(v); // undefined — биндинг есть, значение есть
var v = 1;

console.log(l); // ReferenceError: Cannot access 'l' before initialization
let l = 1;
```

Формулировка «`let` не поднимается» неверна. Биндинг существует с начала блока — иначе не было бы разницы между этими двумя случаями:

```js
let shadowed = 'внешнее';
{
  // console.log(shadowed); // ReferenceError, а НЕ 'внешнее'
  let shadowed = 'внутреннее';
}
```

Если бы внутренний `let` не создавал биндинг заранее, обращение нашло бы внешнюю переменную. Оно этого не делает — значит биндинг есть, просто неинициализированный.

### Единственный случай, когда `typeof` бросает

```js
console.log(typeof neverDeclared); // 'undefined' — безопасно
console.log(typeof inTDZ);         // ReferenceError
let inTDZ = 1;
```

Приём «проверю существование через `typeof`» с приходом лексических объявлений перестал быть надёжным.

## 3. `const` — про связывание, а не про неизменяемость

```js
const obj = { a: 1 };
obj.a = 2;          // работает — меняется объект, не связывание
obj.b = 3;          // работает
// obj = {};        // TypeError: Assignment to constant variable

const arr = [1, 2];
arr.push(3);        // работает
```

`const` запрещает **переприсваивание биндинга**. Содержимое объекта к этому отношения не имеет — для него нужен `Object.freeze`, и тот поверхностный.

```js
// const без инициализатора невозможен
// const x;  // SyntaxError: Missing initializer in const declaration

// а в for...of — вполне, потому что связывание создаётся заново каждую итерацию
for (const item of [1, 2, 3]) console.log(item);

// в классическом for — нет, там связывание одно и его инкрементируют
// for (const i = 0; i < 3; i++) {} // TypeError на i++
```

## 4. Повторное объявление

```js
var a = 1;
var a = 2;        // допустимо

let b = 1;
// let b = 2;     // SyntaxError: Identifier 'b' has already been declared

// смешение тоже запрещено
var c = 1;
// let c = 2;     // SyntaxError
```

Ошибка **синтаксическая**, то есть возникает на этапе разбора — до выполнения хотя бы одной строки модуля. Проверку выполняет операция инстанцирования, сверяя списки `VarDeclaredNames` и `LexicallyDeclaredNames`.

```js
// в разных блоках — не конфликт
let d = 1;
{ let d = 2; }    // отдельная запись окружения
```

## 5. Циклы

```js
const byVar = [];
for (var i = 0; i < 3; i++) byVar.push(() => i);
console.log(byVar.map(f => f())); // [3, 3, 3]

const byLet = [];
for (let j = 0; j < 3; j++) byLet.push(() => j);
console.log(byLet.map(f => f())); // [0, 1, 2]
```

Разницу делает операция `CreatePerIterationEnvironment`, предписанная спецификацией для цикла с лексическим объявлением: перед каждой итерацией создаётся новая запись окружения с копией текущих значений. Подробный разбор — в [[03 Замыкания по спецификации/Отчёт|видео 03]].

Кроме того, `var` в цикле протекает наружу:

```js
for (var k = 0; k < 3; k++) {}
console.log(k); // 3 — переменная жива после цикла

for (let m = 0; m < 3; m++) {}
// console.log(m); // ReferenceError
```

## 6. Мифы, которые стоит закрыть

> [!warning] «`const` работает быстрее»
> Нет. Современные движки выводят неизменяемость биндинга из анализа кода независимо от ключевого слова. Разница в производительности между `let` и `const` не измеряется в реальном коде.

> [!warning] «`let` не поднимается»
> Поднимается. Биндинг создаётся на стадии инстанцирования, но остаётся неинициализированным. Именно поэтому TDZ даёт `ReferenceError`, а не находит внешнюю переменную.

> [!warning] «TDZ — это ошибка проектирования»
> Наоборот, это защита. Без неё `const` мог бы читаться до присваивания и возвращать `undefined` — то есть константа наблюдалась бы в двух разных состояниях.

## 7. Жирная точка

> [!success] Итог
> - Различия **механические**, а не стилистические: область видимости, начальное состояние, право на переприсваивание
> - `var` попадает в `globalThis` и не удаляется через `delete`; лексические объявления — нет
> - Все три поднимаются; отличается начальное значение — `undefined` против неинициализированного состояния
> - TDZ — единственное место, где `typeof` бросает исключение
> - `const` ограничивает связывание, а не значение; для содержимого нужен `Object.freeze`
> - Повторное объявление лексической переменной — **синтаксическая** ошибка, обнаруживаемая до выполнения
> - `let` в цикле работает за счёт `CreatePerIterationEnvironment`; `var` протекает наружу
> - Разговоры о производительности `const` беспочвенны
>
> Практический вывод, вытекающий из механики, а не из вкуса: `const` по умолчанию, `let` там, где переприсваивание необходимо, `var` — только при работе с legacy-кодом, где его поведение осознанно требуется.
