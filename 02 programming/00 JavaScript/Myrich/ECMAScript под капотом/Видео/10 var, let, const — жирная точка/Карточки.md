## Различия по существу

Три независимые характеристики, по которым различаются объявления::==Область видимости==, ==состояние до инициализации==, ==право на переприсваивание==

Область видимости `var` против `let` и `const`::`var` — функциональная, `let` и `const` — блочная

Какие объявления попадают в `globalThis`::Только `var` и ==функциональные декларации==. Лексические объявления идут в Declarative Environment Record

Почему `delete globalThis.someVar` возвращает `false`::Свойство создано с ==`[[Configurable]]: false`==. Свойство от простого присваивания удаляется нормально

Чем опасен глобальный `var` в браузере::Затирает свойства `window` — например `var name` перезаписывает `window.name`

## Поднятие и TDZ

Поднимается ли `let`::==Да==. Биндинг создаётся на стадии инстанцирования, но остаётся неинициализированным

Какое доказательство того, что `let` поднимается
?
```js
let x = 'внешнее';
{
  console.log(x); // ReferenceError, а НЕ 'внешнее'
  let x = 'внутреннее';
}
```
Если бы биндинг не создавался заранее, обращение нашло бы внешнюю переменную.

Начальное значение `var` после инстанцирования::`undefined`

Начальное состояние `let`, `const` и `class`::*uninitialized* — обращение даёт `ReferenceError`

Единственный случай, когда `typeof` бросает исключение::Обращение к переменной в ==TDZ==

Является ли TDZ ошибкой проектирования::Нет, это ==защита==. Без неё `const` можно было бы прочитать до присваивания и увидеть `undefined` — константа наблюдалась бы в двух состояниях

## const

Что именно запрещает `const`::==Переприсваивание биндинга==, а не изменение значения

Что произойдёт при `const obj = {}; obj.a = 1`::Работает. Меняется объект, а не связывание

Как сделать содержимое неизменяемым::`Object.freeze`, но он ==поверхностный== — вложенные объекты нужно обходить рекурсивно

Почему `const x;` — синтаксическая ошибка::`Missing initializer in const declaration` — связывание обязано быть инициализировано сразу

Почему `for (const item of arr)` работает, а `for (const i = 0; i < 3; i++)` нет
?
В `for...of` связывание создаётся ==заново на каждой итерации==.
В классическом `for` связывание одно, и `i++` пытается его переприсвоить — `TypeError`.

---

## Повторное объявление

Можно ли объявить `var` дважды::Да, повторное объявление допустимо

Что произойдёт при повторном объявлении `let`::==SyntaxError==: `Identifier has already been declared`

На каком этапе обнаруживается эта ошибка::На этапе ==разбора==, до выполнения первой строки. Проверку делает инстанцирование, сверяя `VarDeclaredNames` и `LexicallyDeclaredNames`

Конфликтуют ли `let` в разных блоках::Нет — это разные записи окружения

## Циклы

Что выведет код
?
```js
const a = [], b = [];
for (var i = 0; i < 3; i++) a.push(() => i);
for (let j = 0; j < 3; j++) b.push(() => j);
console.log(a.map(f => f()), b.map(f => f()));
```
`[3, 3, 3]` и `[0, 1, 2]`

Какая операция обеспечивает корректность `let` в цикле::==`CreatePerIterationEnvironment`== — новая запись окружения перед каждой итерацией

Что произойдёт с `var`-переменной после цикла::Останется ==доступной==: `for (var k = 0; k < 3; k++) {}` оставляет `k === 3`

## Мифы

Работает ли `const` быстрее `let`::==Нет==. Движки выводят неизменяемость из анализа кода независимо от ключевого слова

Верно ли утверждение «`let` не поднимается»::==Неверно==. Поднимается, но остаётся неинициализированным — отсюда `ReferenceError` вместо поиска внешней переменной

Практический вывод из механики::`const` по умолчанию, `let` при необходимости переприсваивания, `var` — только в legacy-коде, где его поведение требуется осознанно
