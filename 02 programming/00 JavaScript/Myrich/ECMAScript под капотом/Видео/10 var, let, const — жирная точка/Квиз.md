> [!question] Что выведет код?
> ```js
> console.log(typeof v, typeof f);
> var v = 1;
> function f() {}
> ```
> a) `undefined function`
> b) `undefined undefined`
> c) `number function`
> d) выбросит `ReferenceError`
>> [!success]- Answer
>> a) `undefined function`
>> Функциональная декларация инициализируется готовым объектом, а переменная — неопределённым значением. Оба биндинга созданы заранее

> [!question] Что выведет код?
> ```js
> console.log(typeof neverDeclared);
> console.log(typeof inTDZ);
> let inTDZ = 1;
> ```
> a) `undefined undefined`
> b) `undefined` затем `ReferenceError`
> c) `ReferenceError` сразу
> d) `undefined object`
>> [!success]- Answer
>> b) `undefined` затем `ReferenceError`
>> Единственная ситуация в языке, где оператор проверки типа бросает. Для необъявленного имени он остаётся безопасным

> [!question] Что выведет код на верхнем уровне обычного скрипта?
> ```js
> var a = 1;
> let b = 2;
> const c = 3;
> function d() {}
> console.log(globalThis.a, globalThis.b, globalThis.c, typeof globalThis.d);
> ```
> a) `1 2 3 function`
> b) `1 undefined undefined function`
> c) `undefined undefined undefined undefined`
> d) `1 2 undefined function`
>> [!success]- Answer
>> b) `1 undefined undefined function`
>> Переменные и функциональные декларации идут в объектную часть глобального окружения, лексические объявления — в декларативную

> [!question] Что вернёт код?
> ```js
> var x = 1;
> globalThis.y = 2;
> console.log(delete globalThis.x, delete globalThis.y);
> ```
> a) `true true`
> b) `false true`
> c) `true false`
> d) `false false`
>> [!success]- Answer
>> b) `false true`
>> Объявление создаёт неконфигурируемое свойство. Простое присваивание — обычное, и оно удаляется

> [!question] Что выведет код?
> ```js
> const obj = { a: 1 };
> obj.a = 2;
> obj.b = 3;
> console.log(obj.a, obj.b);
> ```
> a) `1 undefined`
> b) `2 3`
> c) выбросит `TypeError`
> d) `1 3`
>> [!success]- Answer
>> b) `2 3`
>> Ограничивается переприсваивание связывания, а не содержимое объекта. Для содержимого нужна заморозка, и та поверхностная

> [!question] Что произойдёт?
> ```js
> const obj = { a: 1 };
> obj = { a: 2 };
> ```
> a) объект заменится
> b) выбросит `TypeError`
> c) выбросит `SyntaxError`
> d) присваивание молча проигнорируется
>> [!success]- Answer
>> b) выбросит `TypeError`
>> Сообщение прямо говорит о присваивании константе. Это ошибка времени выполнения, а не разбора

> [!question] Что произойдёт с каждым циклом?
> ```js
> for (const v of [1, 2, 3]) {}
> for (const i = 0; i < 3; i++) {}
> ```
> a) оба отработают
> b) первый отработает, второй выбросит `TypeError`
> c) первый выбросит, второй отработает
> d) оба выбросят
>> [!success]- Answer
>> b) первый отработает, второй выбросит `TypeError`
>> В переборе связывание создаётся заново на каждой итерации. В классическом цикле оно одно, и выражение инкремента пытается его изменить

> [!question] Что выведет код?
> ```js
> let x = 1;
> { let x = x + 1; }
> ```
> a) `x` во внешней области станет `2`
> b) во внутренней области `x` станет `2`
> c) выбросит `ReferenceError`
> d) выбросит `TypeError`
>> [!success]- Answer
>> c) выбросит `ReferenceError`
>> Внутреннее объявление затеняет внешнее с самого начала блока. К моменту вычисления правой части оно ещё не инициализировано, поэтому обращение падает, а не берёт внешнее значение

> [!question] Что выведет код?
> ```js
> for (var k = 0; k < 3; k++) {}
> console.log(k);
> ```
> a) `0`
> b) `2`
> c) `3`
> d) `ReferenceError`
>> [!success]- Answer
>> c) `3`
>> Переменная переживает цикл и остаётся в области видимости функции. С лексическим объявлением обращение упало бы

> [!question] На каком этапе обнаружится проблема?
> ```js
> console.log('первая строка');
> let x = 1;
> let x = 2;
> ```
> a) выведет первую строку, затем ошибка
> b) ошибка до выполнения, первая строка не выведется
> c) выполнится без ошибок
> d) ошибка при обращении к переменной
>> [!success]- Answer
>> b) ошибка до выполнения, первая строка не выведется
>> Это синтаксическая ошибка, обнаруживаемая при разборе. Операция инстанцирования сверяет списки объявленных имён

> [!question] Что произойдёт?
> ```js
> var c = 1;
> let c = 2;
> ```
> a) вторая строка перезапишет первую
> b) `SyntaxError`
> c) `TypeError`
> d) обе переменные будут существовать независимо
>> [!success]- Answer
>> b) `SyntaxError`
>> Смешение видов объявления в одной области запрещено, и это тоже проверяется до выполнения

> [!question] Что выведет код?
> ```js
> let d = 1;
> { let d = 2; console.log(d); }
> console.log(d);
> ```
> a) `2` затем `1`
> b) `1` затем `1`
> c) `2` затем `2`
> d) `SyntaxError`
>> [!success]- Answer
>> a) `2` затем `1`
>> В разных блоках это разные записи окружения, конфликта нет. Внутреннее имя затеняет внешнее только внутри блока

> [!question] Что выведет код?
> ```js
> function f() {
>   if (true) { var a = 1; let b = 2; }
>   return [typeof a, typeof b];
> }
> console.log(f());
> ```
> a) `['number','number']`
> b) `['number','undefined']`
> c) `['undefined','undefined']`
> d) выбросит `ReferenceError`
>> [!success]- Answer
>> b) `['number','undefined']`
>> Переменная уходит в окружение переменных функции и переживает блок. Лексическое объявление ограничено блоком

> [!question] Что докажет этот код?
> ```js
> let value = 'внешнее';
> {
>   console.log(value);
>   let value = 'внутреннее';
> }
> ```
> a) что лексическое объявление не поднимается
> b) что оно поднимается, но остаётся неинициализированным
> c) что блоки не создают области видимости
> d) ничего, код выведет внешнее значение
>> [!success]- Answer
>> b) что оно поднимается, но остаётся неинициализированным
>> Если бы биндинг не создавался заранее, поиск ушёл бы наружу и нашёл внешнее значение. Вместо этого будет ошибка доступа

> [!question] Верно ли, что `const` работает быстрее `let`?
>> [!success]- Answer
>> False
>> Движки выводят неизменяемость связывания из статического анализа независимо от ключевого слова. Аргументы в пользу константы — читаемость и защита от случайной записи

> [!question] Является ли временная мёртвая зона ошибкой проектирования?
> a) да, она усложняет код без пользы
> b) нет, без неё константу можно было бы прочитать до присваивания
> c) да, она появилась случайно
> d) нет, она нужна только для оптимизаций
>> [!success]- Answer
>> b) нет, без неё константу можно было бы прочитать до присваивания
>> Тогда одна и та же константа наблюдалась бы в двух состояниях: сначала неопределённой, потом со значением

> [!question] Корректность замыканий в цикле обеспечивает операция `___`
>> [!success]- Answer
>> CreatePerIterationEnvironment
>> Новая запись окружения создаётся перед каждым инкрементом, и в неё копируются текущие значения

> [!question] Что выведет код?
> ```js
> const arr = [1, 2, 3];
> arr.push(4);
> Object.freeze(arr);
> arr.push(5);
> ```
> a) массив станет из пяти элементов
> b) выбросит `TypeError`
> c) молча проигнорируется
> d) массив станет из четырёх элементов без ошибок
>> [!success]- Answer
>> b) выбросит `TypeError`
>> Добавление в замороженный массив бросает независимо от режима, потому что метод не может изменить длину. До заморозки изменение проходило нормально
