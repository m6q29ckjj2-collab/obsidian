> [!question] Объявление `let` не поднимается, в отличие от `var`
>> [!success]- Answer
>> False
>> Поднимаются все три. Различается начальное значение: у var это undefined, у let и const биндинг остаётся неинициализированным

> [!question] Что выведет код на верхнем уровне скрипта?
> ```js
> var viaVar = 1;
> let viaLet = 2;
> console.log(globalThis.viaVar, globalThis.viaLet);
> ```
> a) `1 2`
> b) `1 undefined`
> c) `undefined undefined`
> d) `undefined 2`
>> [!success]- Answer
>> b) `1 undefined`
>> var и функциональные декларации идут в объектную часть глобального окружения и становятся свойствами globalThis. Лексические — в декларативную

> [!question] Что вернёт `delete globalThis.x` для переменной, объявленной как `var x = 1`?
> a) `true`
> b) `false`
> c) `undefined`
> d) выбросит `TypeError`
>> [!success]- Answer
>> b) `false`
>> Свойство создаётся с configurable false. Свойство, созданное простым присваиванием без объявления, удаляется нормально

> [!question] Что произойдёт при `typeof` для переменной в TDZ?
> a) вернётся `'undefined'`
> b) вернётся `'object'`
> c) выбросит `ReferenceError`
> d) выбросит `TypeError`
>> [!success]- Answer
>> c) выбросит `ReferenceError`
>> Единственная ситуация в языке, где typeof бросает. Для необъявленного имени он по-прежнему безопасен, поэтому старая проверка существования перестала быть надёжной

> [!question] Объявление `const` делает значение неизменяемым
>> [!success]- Answer
>> False
>> Оно запрещает переприсваивание связывания. Содержимое объекта меняется свободно, для неизменяемости нужен Object.freeze, и тот поверхностный

> [!question] Что произойдёт с этим циклом?
> ```js
> for (const i = 0; i < 3; i++) console.log(i);
> ```
> a) выведет 0, 1, 2
> b) выведет 0 и завершится
> c) выбросит `TypeError` при инкременте
> d) выбросит `SyntaxError`
>> [!success]- Answer
>> c) выбросит `TypeError` при инкременте
>> В классическом for связывание одно на весь цикл. В for...of оно создаётся заново на каждой итерации, поэтому там const допустим

> [!question] На каком этапе обнаружится повторное объявление `let x` в той же области?
> a) при первом обращении к переменной
> b) при выполнении второй строки объявления
> c) на этапе разбора, до выполнения кода
> d) не обнаружится вовсе
>> [!success]- Answer
>> c) на этапе разбора, до выполнения кода
>> Это SyntaxError. Проверку делает операция инстанцирования, сверяя списки объявленных имён. Ни одна строка модуля выполнена не будет

> [!question] Объявление `const` работает быстрее `let`
>> [!success]- Answer
>> False
>> Движки выводят неизменяемость связывания из статического анализа независимо от ключевого слова. Аргументы в пользу const — читаемость и защита от случайной записи

> [!question] Корректность замыканий с `let` в цикле обеспечивает операция `___`
>> [!success]- Answer
>> CreatePerIterationEnvironment
>> Новая запись окружения создаётся перед каждым инкрементом, и в неё копируются текущие значения

> [!question] Что выведет последняя строка?
> ```js
> for (var k = 0; k < 3; k++) {}
> console.log(k);
> ```
> a) `0`
> b) `3`
> c) `undefined`
> d) `ReferenceError`
>> [!success]- Answer
>> b) `3`
>> Переменная var переживает цикл и остаётся в области видимости функции. С let обращение дало бы ReferenceError

> [!question] Является ли TDZ ошибкой проектирования языка?
> a) да, она усложняет код без пользы
> b) нет, без неё константу можно было бы прочитать до присваивания
> c) да, она появилась случайно
> d) нет, она нужна только для оптимизаций
>> [!success]- Answer
>> b) нет, без неё константу можно было бы прочитать до присваивания
>> Тогда одна и та же const наблюдалась бы в двух состояниях: сначала undefined, потом со значением
