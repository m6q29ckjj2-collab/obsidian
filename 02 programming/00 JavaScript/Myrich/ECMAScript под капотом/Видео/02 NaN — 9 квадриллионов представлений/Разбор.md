### 1. Посчитайте, сколько существует битовых представлений NaN, и объясните формулу

> [!success]- Ответ
> `2 × (2⁵² − 1) = 9 007 199 254 740 990`
>
> NaN кодируется единичной экспонентой (`0x7FF`) и **ненулевой** мантиссой. Под мантиссу отведено 52 бита, из них годится любое ненулевое сочетание — отсюда `2⁵² − 1`. Знаковый бит на смысл значения не влияет, но битовую комбинацию меняет, поэтому множитель `2`.

### 2. Чем на уровне битов отличается `Infinity` от `NaN`

> [!success]- Ответ
> Экспонента у обоих полностью единичная. Различает их **мантисса**: у бесконечности она нулевая, у NaN — ненулевая. Знаковый бит у бесконечности задаёт направление, у NaN смысла не несёт.

### 3. Что выведет код и о чём это говорит

```js
const buf = new ArrayBuffer(8);
const f64 = new Float64Array(buf);
const u8  = new Uint8Array(buf);

u8.set([0x2a, 0, 0, 0, 0, 0, 0xf8, 0x7f]);

console.log(f64[0]);
console.log(Number.isNaN(f64[0]));
console.log(u8[0]);
```

> [!success]- Ответ
> `NaN`, `true`, `42`.
>
> Payload физически лежит в буфере и виден через байтовое представление, но само число ведёт себя как обыкновенный NaN. Спецификация утверждает, что тип Number содержит **ровно одно** значение NaN, и различить представления средствами языка нельзя.
>
> Более того, стандарт разрешает движку при записи NaN подставить любое представление (canonicalization) — полагаться на конкретные биты нельзя.

### 4. Что такое NaN-boxing и какие движки его применяют

> [!success]- Ответ
> Приём хранения значений разных типов в одной 64-битной ячейке: настоящие числа лежат как double, а всё остальное упаковывается в пространство NaN — единичная экспонента, затем тег типа и 48-битный указатель.
>
> Работает потому, что указатели на 64-битных платформах фактически используют 48 бит, а в мантиссе NaN свободен 51.
>
> Применяют **JavaScriptCore** и **SpiderMonkey**. V8 пошёл другим путём — pointer tagging через младший бит (SMI) плюс pointer compression.

### 5. Объясните каждую строку

```js
console.log(NaN === NaN);
console.log(Object.is(NaN, NaN));
console.log([NaN].includes(NaN));
console.log([NaN].indexOf(NaN));
console.log(new Set([NaN, NaN]).size);
```

> [!success]- Ответ
> `false`, `true`, `true`, `-1`, `1`.
>
> Работают три разных алгоритма:
>
> | Алгоритм | Где | NaN ≡ NaN | 0 ≡ −0 |
> |---|---|:---:|:---:|
> | `IsStrictlyEqual` | `===`, `indexOf`, `switch` | нет | да |
> | `SameValue` | `Object.is` | да | нет |
> | `SameValueZero` | `includes`, Set, Map | да | да |

### 6. Почему эта ветка недостижима

```js
switch (NaN) {
  case NaN: console.log('совпало'); break;
  default:  console.log('не совпало');
}
```

> [!success]- Ответ
> Выведет `не совпало`.
>
> `switch` сравнивает через `IsStrictlyEqual`, а `NaN === NaN` ложно. Никакое значение NaN не совпадёт с `case NaN` — ветка мертва по построению.

### 7. Почему `NaN !== NaN` — это не прихоть JavaScript

> [!success]- Ответ
> Это требование **IEEE 754**. NaN обозначает не значение, а факт отсутствия осмысленного результата. Два независимых сбойных вычисления не имеют оснований считаться равными друг другу.
>
> Историческое следствие — идиома проверки до появления `Number.isNaN`: `x !== x` истинно ровно для NaN.

### 8. Объясните расхождение

```js
console.log(isNaN('abc'), Number.isNaN('abc'));
console.log(isNaN(''),    Number.isNaN(''));
console.log(isNaN([]),    isNaN([1, 2]));
```

> [!success]- Ответ
> `true false`, `false false`, `false true`.
>
> Глобальный `isNaN` сначала применяет `ToNumber` и отвечает на вопрос «**не приводится** к числу». `Number.isNaN` проверяет, что аргумент — именно значение NaN типа Number.
>
> Пустая строка приводится к `0`, поэтому `isNaN('')` ложно. `[]` через `ToPrimitive` даёт `''` → `0`, а `[1,2]` даёт `'1,2'` → NaN.

### 9. Найдите проблему и предложите исправление

```js
const prices = [10, 20, Number('н/д'), 40];
const total = prices.reduce((a, b) => a + b, 0);
```

> [!success]- Ответ
> `total === NaN`, причём непонятно, какая именно позиция сломалась — в этом и коварство.
>
> NaN **заразен**: любая арифметика с ним даёт NaN, и одно повреждённое значение бесшумно распространяется по всей цепочке.
>
> ```js
> const total = prices.filter(Number.isFinite).reduce((a, b) => a + b, 0); // 70
> ```
>
> `Number.isFinite` предпочтительнее `Number.isNaN`, потому что одной проверкой отсекает и NaN, и бесконечности, и значения других типов.

### 10. Что не так с сортировкой

```js
[3, NaN, 1, 2].sort((a, b) => a - b);
```

> [!success]- Ответ
> Результат непредсказуем и может отличаться между движками.
>
> Компаратор обязан возвращать число, а `a - b` с участием NaN даёт NaN. Спецификация трактует такой результат как «считать элементы равными», из-за чего порядок перестаёт быть определённым.
>
> Единственное надёжное решение — отфильтровать данные до сортировки: `arr.filter(Number.isFinite).sort((a, b) => a - b)`.

### 11. Что выведет код и можно ли восстановить исходные значения

```js
console.log(JSON.stringify({ a: NaN, b: Infinity, c: -Infinity }));
```

> [!success]- Ответ
> `'{"a":null,"b":null,"c":null}'`
>
> В формате JSON нет ни NaN, ни бесконечностей, поэтому `JSON.stringify` молча заменяет их на `null`. Восстановить исходные значения из результата невозможно — все три схлопнулись в одно.
>
> Если такие значения значимы, нужно собственное соглашение: строковые маркеры или замена через параметр `replacer`.

### 12. Что различает старший бит мантиссы и почему это неважно для прикладного кода

> [!success]- Ответ
> Взведённый старший бит мантиссы означает **quiet NaN** — он тихо распространяется через вычисления. Сброшенный при ненулевом payload означает **signaling NaN**, который по стандарту IEEE должен возбуждать исключение операции.
>
> JavaScript не даёт доступа к флагам исключений IEEE, поэтому наблюдаемой разницы нет — оба ведут себя одинаково. Знание полезно для понимания того, почему движки резервируют этот бит и не используют его под NaN-boxing.
