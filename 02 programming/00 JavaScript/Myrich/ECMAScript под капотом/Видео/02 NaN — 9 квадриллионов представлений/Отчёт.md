## 1. Число в JavaScript — это IEEE 754 binary64

Тип Number описан спецификацией как множество значений двойной точности по стандарту IEEE 754-2019. 64 бита раскладываются так:

| Поле | Битов | Позиции |
|---|---:|---|
| Знак | 1 | 63 |
| Экспонента | 11 | 62–52 |
| Мантисса | 52 | 51–0 |

Значение экспоненты `0x7FF` (все одиннадцать бит единичные) зарезервировано под особые случаи:

- мантисса **нулевая** → бесконечность, знак берётся из старшего бита
- мантисса **ненулевая** → NaN

```js
const buf = new ArrayBuffer(8);
const f64 = new Float64Array(buf);
const u8  = new Uint8Array(buf);

const bits = n => {
  f64[0] = n;
  return [...u8].reverse().map(b => b.toString(2).padStart(8, '0')).join(' ');
};

console.log(bits(Infinity));  // 01111111 11110000 ... — экспонента единицы, мантисса нули
console.log(bits(-Infinity)); // 11111111 11110000 ...
console.log(bits(NaN));       // 01111111 11111000 ... — старший бит мантиссы взведён
```

## 2. Откуда девять квадриллионов

Под мантиссу отведено 52 бита, и любое **ненулевое** их сочетание при единичной экспоненте даёт NaN. Знаковый бит на смысл не влияет, но битовую комбинацию меняет.

$$2 \times (2^{52} - 1) = 9\,007\,199\,254\,740\,990$$

```js
const count = 2 * (2 ** 52 - 1);
console.log(count);                    // 9007199254740990
console.log(count === Number.MAX_SAFE_INTEGER - 1); // true — забавное совпадение
```

Отсюда и формулировка «диапазон из девяти квадриллионов». Это ровно на два меньше, чем удвоенный `Number.MAX_SAFE_INTEGER` — совпадение не случайное: и то, и другое упирается в те же 52 бита мантиссы.

## 3. Что об этом говорит спецификация

Позиция стандарта категорична: тип Number содержит **ровно одно** значение NaN.

Более того, спецификация прямо разрешает реализации при записи в буфер подставлять произвольное представление, а при чтении — не сохранять исходные биты. Формально это описано в операциях `SetValueInBuffer` и `GetValueFromBuffer` через понятие *NaN canonicalization*.

```js
const buf = new ArrayBuffer(8);
const f64 = new Float64Array(buf);
const u8  = new Uint8Array(buf);

// записываем NaN силами движка
f64[0] = NaN;
console.log([...u8].map(b => b.toString(16).padStart(2, '0')).join(' '));
// типично: 00 00 00 00 00 00 f8 7f — канонический quiet NaN

// вручную конструируем другое представление с payload
u8.set([0x2a, 0, 0, 0, 0, 0, 0xf8, 0x7f]);

console.log(f64[0]);               // NaN
console.log(Number.isNaN(f64[0])); // true
console.log(u8[0]);                // 42 — payload на месте в памяти
```

Payload физически сохраняется в буфере, но средствами языка его не увидеть: любая арифметика или сравнение работают с «тем самым единственным NaN».

## 4. Quiet и signaling

Старший бит мантиссы (позиция 51) различает два вида:

- взведён → **quiet NaN**: тихо распространяется через вычисления
- сброшен → **signaling NaN**: по стандарту IEEE должен возбуждать исключение операции

```js
const buf = new ArrayBuffer(8);
const f64 = new Float64Array(buf);
const u32 = new Uint32Array(buf);

// signaling NaN: экспонента единичная, старший бит мантиссы сброшен, payload ненулевой
u32[1] = 0x7ff00000;
u32[0] = 0x00000001;

console.log(Number.isNaN(f64[0])); // true
console.log(f64[0] + 1);           // NaN — тихо распространился
```

JavaScript не даёт доступа к флагам исключений IEEE, поэтому различие для прикладного кода неощутимо. Практическая ценность знания — понимать, почему движки резервируют старший бит и не используют его под свои нужды.

## 5. NaN-boxing — зачем движкам свободные биты

Динамическому языку нужно хранить в одной ячейке значения разных типов. Один из подходов: положить всё в 64-битный double и использовать пространство NaN под теги и указатели.

Указатели на 64-битных платформах фактически занимают 48 бит. В мантиссе NaN свободно 51 бит — этого достаточно, чтобы уместить и указатель, и тег типа.

```js
// концептуально: одна 64-битная ячейка
// [ настоящий double ]                        → число
// [ экспонента 0x7FF | тег | 48-битный адрес ] → объект, строка, символ
```

Так устроены **JavaScriptCore** и **SpiderMonkey**. V8 исторически использует другой подход — pointer tagging с младшим битом (SMI), а с включённым pointer compression хранит 32-битные смещения.

Прикладное следствие одно: битовая картина NaN, которую вы наблюдаете, — это внутреннее дело движка, и полагаться на неё нельзя.

## 6. Три алгоритма сравнения

В спецификации их именно три, и расходятся они ровно на NaN и знаковом нуле.

| Алгоритм | Где применяется | `NaN` ≡ `NaN` | `0` ≡ `−0` |
|---|---|:---:|:---:|
| `IsStrictlyEqual` | `===`, `!==`, `indexOf`, `switch` | нет | да |
| `SameValue` | `Object.is`, `defineProperty` | да | нет |
| `SameValueZero` | `includes`, `Set`, `Map`, `Array.prototype.at` | да | да |

```js
console.log(NaN === NaN);               // false
console.log(Object.is(NaN, NaN));       // true
console.log([NaN].includes(NaN));       // true
console.log([NaN].indexOf(NaN));        // -1
console.log(new Set([NaN, NaN]).size);  // 1
console.log(new Map([[NaN, 'a']]).get(NaN)); // 'a'

console.log(Object.is(0, -0));          // false
console.log([0].includes(-0));          // true
console.log(0 === -0);                  // true
```

`SameValueZero` — это `SameValue`, в котором нули объявлены равными. Выбор для коллекций осознанный: он позволяет **находить** `NaN` в множестве и при этом не плодить дубли из-за знака нуля.

```js
// switch использует строгое равенство — ветка недостижима
switch (NaN) {
  case NaN: console.log('никогда'); break;
  default:  console.log('всегда');
}
```

## 7. Почему `NaN !== NaN`

Это не прихоть JavaScript, а требование IEEE 754. NaN означает «результат не является числом» — это не значение, а маркер отсутствия результата. Два разных сбойных вычисления не имеют оснований считаться равными.

Историческое следствие — идиома проверки до появления `Number.isNaN`:

```js
const isNaNLegacy = x => x !== x; // работает, потому что только NaN не равен себе
```

## 8. `isNaN` против `Number.isNaN`

```js
console.log(isNaN('abc'));           // true  — глобальная функция
console.log(Number.isNaN('abc'));    // false

console.log(isNaN(undefined));       // true
console.log(Number.isNaN(undefined));// false

console.log(isNaN('123'));           // false — строка приводится к числу
console.log(isNaN(''));              // false — пустая строка это 0
console.log(isNaN([]));              // false — [] → '' → 0
console.log(isNaN([1, 2]));          // true  — '1,2' не число
```

Глобальный `isNaN` сначала применяет `ToNumber` и отвечает на вопрос «**не приводится** к числу». `Number.isNaN` проверяет, что аргумент — именно значение NaN типа Number, без всяких преобразований.

В прикладном коде почти всегда нужен второй. Первый оправдан ровно тогда, когда вопрос действительно звучит как «можно ли это трактовать как число», — но и там честнее написать проверку явно.

## 9. Откуда NaN берётся на практике

```js
console.log(0 / 0);                  // NaN
console.log(Infinity - Infinity);    // NaN
console.log(Infinity * 0);           // NaN
console.log(Math.sqrt(-1));          // NaN
console.log(Number('не число'));     // NaN
console.log(parseInt('abc'));        // NaN
console.log(undefined + 1);          // NaN
console.log(+{});                    // NaN
console.log(new Date('чепуха').getTime()); // NaN
```

Ключевое свойство — **заразность**: любая арифметика с NaN даёт NaN, поэтому одно повреждённое значение бесшумно распространяется через всю цепочку вычислений.

```js
const prices = [10, 20, Number('н/д'), 40];
const total = prices.reduce((a, b) => a + b, 0);
console.log(total); // NaN — какая именно позиция сломалась, неизвестно

// защита на входе
const safeTotal = prices
  .filter(Number.isFinite)  // отсекает NaN, Infinity и не-числа
  .reduce((a, b) => a + b, 0);
console.log(safeTotal); // 70
```

`Number.isFinite` удобнее `Number.isNaN`, потому что одной проверкой отсекает и NaN, и бесконечности, и значения других типов.

## 10. NaN в сортировке и сериализации

```js
console.log([3, NaN, 1, 2].sort((a, b) => a - b));
// [3, NaN, 1, 2] или иной порядок — компаратор возвращает NaN, сравнение неопределено
```

Компаратор обязан возвращать число. `a - b` с участием NaN даёт NaN, спецификация трактует это как «считать равными», и результат сортировки становится непредсказуемым — вплоть до различий между движками.

```js
const clean = arr => arr.filter(Number.isFinite).sort((a, b) => a - b);
console.log(clean([3, NaN, 1, 2])); // [1, 2, 3]
```

```js
console.log(JSON.stringify({ v: NaN }));       // '{"v":null}'
console.log(JSON.stringify([NaN, Infinity]));  // '[null,null]'
```

В JSON нет ни NaN, ни бесконечностей, поэтому `JSON.stringify` молча превращает их в `null`. Обратное преобразование восстановить невозможно — если такие значения важны, их сериализуют отдельным соглашением.

## 11. Итог

> [!success] Что забирать
> - Number — это IEEE 754 binary64; NaN кодируется единичной экспонентой и **ненулевой** мантиссой
> - Битовых представлений `2 × (2⁵² − 1)` ≈ 9 × 10¹⁵, значений языка — **ровно одно**
> - Спецификация разрешает движку канонизировать NaN при записи в буфер; payload средствами языка недоступен
> - Старший бит мантиссы делит NaN на quiet и signaling; JS к флагам IEEE доступа не даёт
> - Свободные биты используются под **NaN-boxing** в JavaScriptCore и SpiderMonkey
> - Три алгоритма сравнения расходятся на NaN и `-0`; коллекции используют `SameValueZero`
> - `NaN !== NaN` — требование IEEE, отсюда историческая идиома `x !== x`
> - `isNaN` отвечает «не приводится к числу», `Number.isNaN` — «это NaN»; на практике почти всегда нужен `Number.isFinite`
> - NaN заразен, ломает сортировку и превращается в `null` при сериализации в JSON
