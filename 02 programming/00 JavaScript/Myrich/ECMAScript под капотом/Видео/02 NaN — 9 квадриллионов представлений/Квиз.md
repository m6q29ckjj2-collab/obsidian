> [!question] Сколько существует различных битовых представлений NaN в binary64?
> a) 1
> b) 2048
> c) 9 007 199 254 740 990
> d) 18 446 744 073 709 551 615
>> [!success]- Answer
>> c) 9 007 199 254 740 990
>> Формула 2 × (2⁵² − 1): под мантиссу отведено 52 бита, годится любое ненулевое сочетание, а знаковый бит удваивает число комбинаций

> [!question] Согласно спецификации, тип Number содержит несколько различных значений NaN
>> [!success]- Answer
>> False
>> Ровно одно. Различить представления средствами языка нельзя, и стандарт прямо разрешает движку подставлять любое из них при записи в буфер

> [!question] Чем на уровне битов NaN отличается от Infinity?
> a) значением экспоненты
> b) значением мантиссы
> c) знаковым битом
> d) длиной записи
>> [!success]- Answer
>> b) значением мантиссы
>> Экспонента у обоих полностью единичная. У бесконечности мантисса нулевая, у NaN — ненулевая

> [!question] Что вернут эти два вызова?
> ```js
> console.log([NaN].includes(NaN), [NaN].indexOf(NaN));
> ```
> a) `true -1`
> b) `true 0`
> c) `false -1`
> d) `false 0`
>> [!success]- Answer
>> a) `true -1`
>> includes использует SameValueZero, где NaN равен NaN. indexOf сравнивает строгим равенством, а оно на NaN ложно

> [!question] `Object.is(0, -0)` возвращает `true`
>> [!success]- Answer
>> False
>> SameValue различает знак нуля. Равными их считает только SameValueZero, который используется в includes, Set и Map

> [!question] Какой алгоритм сравнения используют `Set`, `Map` и `Array.prototype.includes`?
>> [!success]- Answer
>> SameValueZero
>> Выбор осознанный: он позволяет находить NaN в коллекции и при этом не плодить дубли из-за знака нуля

> [!question] Что вернёт вызов?
> ```js
> console.log(isNaN(''));
> ```
> a) `true`
> b) `false`
> c) `NaN`
> d) `TypeError`
>> [!success]- Answer
>> b) `false`
>> Глобальный isNaN сначала применяет ToNumber, а пустая строка превращается в ноль. Он отвечает на вопрос «не приводится к числу», а не «это NaN»

> [!question] То, что `NaN !== NaN`, — особенность JavaScript, а не требование стандарта чисел
>> [!success]- Answer
>> False
>> Это требование IEEE 754. NaN обозначает отсутствие осмысленного результата, и два разных сбоя не обязаны считаться равными

> [!question] Во что превратится значение при сериализации?
> ```js
> console.log(JSON.stringify({ a: NaN, b: Infinity }));
> ```
> a) `{"a":NaN,"b":Infinity}`
> b) `{"a":null,"b":null}`
> c) `{"a":0,"b":0}`
> d) выбросит `TypeError`
>> [!success]- Answer
>> b) `{"a":null,"b":null}`
>> В JSON нет ни NaN, ни бесконечностей. Все три значения схлопываются в null, и обратно их не восстановить

> [!question] Что выведет код?
> ```js
> switch (NaN) {
>   case NaN: console.log('совпало'); break;
>   default:  console.log('не совпало');
> }
> ```
> a) `совпало`
> b) `не совпало`
> c) ничего
> d) `TypeError`
>> [!success]- Answer
>> b) `не совпало`
>> switch сравнивает через строгое равенство, поэтому ветка case NaN недостижима по построению

> [!question] Какая проверка одной операцией отсекает и NaN, и обе бесконечности, и значения других типов?
>> [!success]- Answer
>> Number.isFinite
>> Практичнее, чем Number.isNaN: перед арифметикой обычно нужно отсечь всё, что не является конечным числом

> [!question] Упаковка указателей и тегов типов в свободные биты мантиссы NaN называется `___`
>> [!success]- Answer
>> NaN-boxing
>> Работает потому, что указатели на 64-битных платформах занимают 48 бит, а в мантиссе NaN свободен 51

> [!question] Какие движки применяют NaN-boxing?
> a) только V8
> b) JavaScriptCore и SpiderMonkey
> c) все три мейнстримных движка
> d) ни один, это теоретический приём
>> [!success]- Answer
>> b) JavaScriptCore и SpiderMonkey
>> V8 пошёл другим путём — pointer tagging через младший бит плюс pointer compression

> [!question] Старший бит мантиссы отличает quiet NaN от signaling NaN
>> [!success]- Answer
>> True
>> Взведённый бит означает quiet. Для прикладного кода разницы нет: JavaScript не даёт доступа к флагам исключений IEEE

> [!question] Что произойдёт с массивом?
> ```js
> console.log([3, NaN, 1, 2].sort((a, b) => a - b));
> ```
> a) отсортируется как `[1, 2, 3, NaN]`
> b) отсортируется как `[NaN, 1, 2, 3]`
> c) порядок непредсказуем
> d) выбросит `TypeError`
>> [!success]- Answer
>> c) порядок непредсказуем
>> Компаратор с участием NaN возвращает NaN, спецификация трактует это как «считать равными», и результат может отличаться между движками. Данные нужно фильтровать до сортировки
