> [!question] Что выведет код?
> ```js
> console.log(NaN === NaN, Object.is(NaN, NaN));
> ```
> a) `true true`
> b) `false true`
> c) `false false`
> d) `true false`
>> [!success]- Answer
>> b) `false true`
>> Строгое равенство следует IEEE и считает NaN не равным себе. Object.is использует SameValue, где он равен себе

> [!question] Что выведет код?
> ```js
> console.log([NaN].includes(NaN), [NaN].indexOf(NaN), [NaN].lastIndexOf(NaN));
> ```
> a) `true -1 -1`
> b) `true 0 0`
> c) `false -1 -1`
> d) `true 0 -1`
>> [!success]- Answer
>> a) `true -1 -1`
>> includes использует SameValueZero, оба варианта indexOf — строгое равенство, поэтому не находят ничего

> [!question] Что выведет код?
> ```js
> console.log(new Set([NaN, NaN, 0, -0]).size);
> ```
> a) `4`
> b) `3`
> c) `2`
> d) `1`
>> [!success]- Answer
>> c) `2`
>> SameValueZero схлопывает и оба NaN, и оба нуля. Остаются одно NaN и один ноль

> [!question] Что выведет код?
> ```js
> console.log(Object.is(0, -0), [0].includes(-0), 0 === -0);
> ```
> a) `true true true`
> b) `false true true`
> c) `false false true`
> d) `false true false`
>> [!success]- Answer
>> b) `false true true`
>> Только SameValue различает знак нуля. На NaN расхождение обратное: там знак нуля ни при чём, а различается сам NaN

> [!question] Что выведет код?

> a) `найдено найдено`

>> [!success]- Answer
>> a) `найдено найдено`

> [!question] Что выведет код?

> [!question] Что выведет код?
> ```js
> console.log(isNaN(''), isNaN(' '), isNaN([]), isNaN([1, 2]), isNaN('12px'));
> ```
> a) `true true true true true`
> b) `false false false true true`
> c) `false false true true true`
> d) `true true false false true`
>> [!success]- Answer
>> b) `false false false true true`
>> Глобальный isNaN сначала приводит к числу. Пустая строка, пробел и пустой массив дают ноль, а массив из двух элементов даёт строку с запятой

> [!question] Что выведет код?

> [!question] Что выведет код?
> ```js
> const vals = [0/0, Infinity - Infinity, Infinity * 0, Math.sqrt(-1), parseInt('abc')];
> console.log(vals.every(Number.isNaN));
> ```
> a) `true`
> b) `false`
> c) `undefined`
> d) `TypeError`
>> [!success]- Answer
>> a) `true`
>> Все пять — типовые способы получить NaN. Каждый возникает там, где результат математически не определён или разбор не удался

> [!question] Что выведет код?
> ```js
> console.log(JSON.stringify({ a: NaN, b: Infinity, c: -Infinity }));
> ```
> a) `{"a":NaN,"b":Infinity,"c":-Infinity}`
> b) `{"a":null,"b":null,"c":null}`
> c) `{"a":0,"b":0,"c":0}`
> d) выбросит `TypeError`
>> [!success]- Answer
>> b) `{"a":null,"b":null,"c":null}`
>> В формате JSON таких значений нет. Все три схлопываются в null, и различить их после сериализации невозможно

> [!question] Что выведет код?
> ```js
> const prices = [10, 20, Number('н/д'), 40];
> console.log(prices.reduce((a, b) => a + b, 0));
> console.log(prices.filter(Number.isFinite).reduce((a, b) => a + b, 0));
> ```
> a) `70` и `70`
> b) `NaN` и `70`
> c) `NaN` и `NaN`
> d) `30` и `70`
>> [!success]- Answer
>> b) `NaN` и `70`
>> NaN заразен: одно повреждённое значение проходит через всю цепочку. Фильтр по Number.isFinite отсекает и его, и бесконечности

> [!question] Что выведет код?
> ```js
> console.log([1, NaN, 2].findIndex(Number.isNaN));
> console.log([1, NaN, 2].indexOf(NaN));
> ```
> a) `1` и `1`
> b) `1` и `-1`
> c) `-1` и `-1`
> d) `-1` и `1`
>> [!success]- Answer
>> b) `1` и `-1`
>> Поиск по предикату находит NaN, поиск по значению — нет. Это стандартный обходной приём

> [!question] Что выведет код?
> ```js
> console.log(NaN | 0, NaN >>> 0, Math.trunc(NaN));
> ```
> a) `0 0 NaN`
> b) `NaN NaN NaN`
> c) `0 0 0`
> d) `NaN 0 NaN`
>> [!success]- Answer
>> a) `0 0 NaN`
>> Побитовые операторы приводят через ToInt32 и ToUint32, где NaN превращается в ноль. Math.trunc приведения не делает

> [!question] Что выведет код?
> ```js
> const buf = new ArrayBuffer(8);
> const f64 = new Float64Array(buf);
> const u8 = new Uint8Array(buf);
> u8.set([0x2a, 0, 0, 0, 0, 0, 0xf8, 0x7f]);
> console.log(f64[0], Number.isNaN(f64[0]), u8[0]);
> ```
> a) `NaN true 42`
> b) `42 false 42`
> c) `NaN true 0`
> d) `Infinity false 42`
>> [!success]- Answer
>> a) `NaN true 42`
>> Полезная нагрузка физически лежит в буфере и видна побайтово, но само число ведёт себя как обычный NaN — из него её не извлечь

> [!question] Сколько существует битовых представлений NaN?
> a) `2 ** 52`
> b) `2 * (2 ** 52 - 1)`
> c) `2 ** 64`
> d) одно
>> [!success]- Answer
>> b) `2 * (2 ** 52 - 1)`
>> Это 9 007 199 254 740 990. Под мантиссу отведено 52 бита, годится любое ненулевое сочетание, знаковый бит удваивает число комбинаций

> [!question] Чем на уровне битов NaN отличается от бесконечности?
> a) значением экспоненты
> b) значением мантиссы
> c) знаковым битом
> d) длиной записи
>> [!success]- Answer
>> b) значением мантиссы
>> Экспонента у обоих полностью единичная. У бесконечности мантисса нулевая, у NaN — ненулевая

> [!question] Согласно спецификации в типе Number существует несколько различных значений NaN
>> [!success]- Answer
>> False
>> Ровно одно. Стандарт прямо разрешает движку подставлять любое битовое представление при записи в буфер

> [!question] Что выведет код?
> ```js
> console.log([3, NaN, 1].sort((a, b) => a - b).length);
> ```
> a) `3`
> b) `2`
> c) `NaN`
> d) выбросит `TypeError`
>> [!success]- Answer
>> a) `3`
>> Длина не меняется — ломается порядок, а не состав. Компаратор возвращает NaN, спецификация трактует это как «считать равными», и результат становится непредсказуемым

> [!question] Что выведет код?

> ```
> a) `NaN NaN`

> c) `-Infinity Infinity`

>> [!success]- Answer
>> c) `-Infinity Infinity`
>> Это нейтральные элементы операций, а не NaN. NaN появился бы при передаче аргумента, не приводимого к числу

> [!question] Упаковка указателей и тегов типов в свободные биты мантиссы NaN называется `___`
>> [!success]- Answer
>> NaN-boxing
>> Применяется в JavaScriptCore и SpiderMonkey. Указатель занимает 48 бит, а в мантиссе свободен 51

> [!question] Старший бит мантиссы отличает quiet NaN от signaling NaN
>> [!success]- Answer
>> True
>> Для прикладного кода разницы нет: JavaScript не даёт доступа к флагам исключений IEEE. Знание объясняет, почему движки резервируют этот бит
