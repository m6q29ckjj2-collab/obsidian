## Прототипы

### Чем `__proto__` отличается от `[[Prototype]]` и `prototype`

Три разные вещи, которые постоянно путают.

- **`[[Prototype]]`** — внутренний слот объекта, ссылка на родителя в цепочке
- **`__proto__`** — исторический аксессор в `Object.prototype`, читающий и пишущий этот слот. Формально описан в Annex B
- **`prototype`** — обычное свойство **функции**, которое станет `[[Prototype]]` объектов, созданных через `new`

```js
function Ctor() {}
const obj = new Ctor();

console.log(Object.getPrototypeOf(obj) === Ctor.prototype); // true
console.log(obj.__proto__ === Ctor.prototype);              // true
console.log(obj.prototype);                                 // undefined — у экземпляра его нет
```

```js
// современный способ — без Annex B
const clean = Object.create(null);
console.log(clean.__proto__);       // undefined — нет Object.prototype, нет аксессора
console.log(Object.getPrototypeOf(clean)); // null
```

Объект с прототипом `null` — правильный выбор для словаря: в него не протекают `toString`, `constructor` и прочее.

### Почему изменение прототипа убивает производительность

```js
const obj = { a: 1 };
Object.setPrototypeOf(obj, { b: 2 }); // деоптимизация
```

Движки строят скрытые классы (hidden classes / shapes) и inline-кеши в расчёте на то, что структура объекта стабильна. Смена прототипа инвалидирует всё, что было накоплено для этого объекта и для всех, кто через него читался. Правильный путь — задать прототип **при создании**: `Object.create(proto)` или литерал с `__proto__`.

### Что делает `super` и почему он не эквивалентен `this.__proto__`

```js
class Base { greet() { return 'база'; } }
class Derived extends Base {
  greet() { return super.greet() + ' → потомок'; }
}
```

`super.greet()` использует внутренний слот метода **`[[HomeObject]]`** — ссылку на объект, в котором метод определён. Поиск идёт от прототипа `[[HomeObject]]`, а не от прототипа `this`. Без этого при трёхуровневой иерархии возникла бы бесконечная рекурсия.

```js
// именно поэтому super работает только в сокращённой записи метода
const broken = { greet: function () { /* super здесь SyntaxError */ } };
const works  = { greet() { /* [[HomeObject]] есть */ } };
```

## Итераторы и генераторы

### Протокол

Итерируемым объект делает метод `[Symbol.iterator]`, возвращающий итератор — объект с методом `next()`, дающим `{ value, done }`.

```js
class Range {
  constructor(from, to) { this.from = from; this.to = to; }
  *[Symbol.iterator]() {
    for (let i = this.from; i <= this.to; i++) yield i;
  }
}
console.log([...new Range(1, 4)]); // [1, 2, 3, 4]
```

### `return` и `throw` — то, что делает итератор закрываемым

```js
function* resource() {
  try {
    yield 'данные 1';
    yield 'данные 2';
  } finally {
    console.log('освобождено');
  }
}

for (const v of resource()) {
  console.log(v);
  break; // 'освобождено' — for...of вызывает return() при досрочном выходе
}
```

Тот же механизм срабатывает при деструктуризации (см. [[Видео/01 Assignment Patterns/Отчёт|видео 01]]), при `throw` внутри цикла и при досрочном `return` из функции.

### Делегирование

```js
function* inner() { yield 1; yield 2; return 'результат inner'; }
function* outer() {
  const r = yield* inner(); // значение return попадает сюда
  console.log(r);           // 'результат inner'
  yield 3;
}
console.log([...outer()]); // [1, 2, 3]
```

`yield*` пробрасывает не только значения, но и `next(v)`, `return()` и `throw()` — полноценная передача управления, а не цикл по значениям.

### Генератор как сопрограмма

```js
function* dialog() {
  const name = yield 'как вас зовут?';
  const age  = yield `привет, ${name}. сколько лет?`;
  return `${name}, ${age}`;
}

const d = dialog();
console.log(d.next().value);        // 'как вас зовут?'
console.log(d.next('Аня').value);   // 'привет, Аня. сколько лет?'
console.log(d.next(30).value);      // 'Аня, 30'
```

Значение, переданное в `next(v)`, становится результатом **приостановленного** `yield`. Первый `next()` аргумент игнорирует — приостановленного выражения ещё нет.

## Асинхронность

### Во что разворачивается `await`

`await` — синтаксис поверх промисов. Продолжение функции ставится в очередь микрозадач.

```js
async function f() {
  console.log('1');
  await null;          // даже не-промис уходит через микрозадачу
  console.log('3');
}
f();
console.log('2');
// 1 2 3
```

Важно: `await` над обычным значением всё равно откладывает продолжение — тело после него никогда не выполняется синхронно.

### Порядок, на котором ошибаются

```js
async function a() { console.log('a1'); await b(); console.log('a2'); }
async function b() { console.log('b1'); }

console.log('start');
a();
Promise.resolve().then(() => console.log('micro'));
console.log('end');

// start · a1 · b1 · end · a2 · micro
```

`a2` опережает `micro`, потому что продолжение `a` встало в очередь раньше — в момент `await b()`, до того как выполнилась строка с `then`.

### `for await...of` и асинхронные итераторы

```js
async function* stream() {
  for (let i = 1; i <= 3; i++) {
    await new Promise(r => setTimeout(r, 10));
    yield i;
  }
}

for await (const chunk of stream()) console.log(chunk); // 1 2 3
```

Асинхронный итератор объявляется через `Symbol.asyncIterator` и возвращает промисы записей, а не сами записи.

### Комбинаторы промисов

```js
const ok   = Promise.resolve('успех');
const fail = Promise.reject(new Error('сбой'));

await Promise.all([ok, fail]);        // отклоняется первой ошибкой
await Promise.allSettled([ok, fail]); // всегда исполняется, статусы внутри
await Promise.race([ok, fail]);       // первый завершившийся любым образом
await Promise.any([fail, ok]);        // первый успешный; все отказы → AggregateError
```

> [!warning] Необработанные отклонения в `Promise.all`
> Если отклонятся два промиса, `all` вернёт первую ошибку, а вторая останется необработанной и вызовет `unhandledrejection`. Для сбора всех результатов нужен `allSettled`.

## Модули

### Живые связывания

```js
// counter.js
export let count = 0;
export const inc = () => count++;

// main.js
import { count, inc } from './counter.js';
console.log(count); // 0
inc();
console.log(count); // 1 — значение обновилось само
```

Импорт — не копия, а **индирект-биндинг** на ячейку исходного модуля. При этом импортированное имя доступно только на чтение: попытка присвоить даёт `TypeError`.

### Порядок и TDZ

```js
console.log(value); // ReferenceError — TDZ, хотя импорт «поднят»
import { value } from './mod.js';
```

Объявления импорта обрабатываются до выполнения тела модуля, поэтому имена существуют с самого начала — но остаются неинициализированными, пока зависимость не выполнится.

### Циклические зависимости

```js
// a.js
import { b } from './b.js';
export const a = 'A';
console.log('a видит b:', b);

// b.js
import { a } from './a.js';
export const b = 'B';
console.log('b видит a:', a); // ReferenceError — a ещё в TDZ
```

Модули связываются до выполнения, поэтому цикл не падает на этапе разрешения — но модуль, выполняемый первым, увидит неинициализированные биндинги партнёра. С `var` и CommonJS вместо ошибки получалось бы `undefined`, что хуже: сбой становился тихим.

## Символы

```js
const local = Symbol('описание');
const global = Symbol.for('ключ');

console.log(Symbol('a') === Symbol('a'));         // false — всегда уникален
console.log(Symbol.for('a') === Symbol.for('a')); // true — общий реестр
console.log(Symbol.keyFor(global));               // 'ключ'
console.log(Symbol.keyFor(local));                // undefined
```

Хорошо известные символы меняют поведение встроенных операций:

```js
class Collection {
  static [Symbol.hasInstance](x) { return Array.isArray(x); }
}
console.log([] instanceof Collection); // true — instanceof переопределён

const obj = {
  [Symbol.toStringTag]: 'Кастом',
  [Symbol.toPrimitive](hint) { return hint === 'number' ? 42 : 'строка'; },
};
console.log(Object.prototype.toString.call(obj)); // '[object Кастом]'
console.log(+obj, `${obj}`);                      // 42 'строка'
```

Символьные ключи не попадают в `Object.keys`, `for...in` и `JSON.stringify`, но видны через `Object.getOwnPropertySymbols` и `Reflect.ownKeys` — это не приватность, а лишь отсутствие в обычных перечислениях.

## Слабые ссылки

```js
const cache = new WeakMap();

function attach(node, data) { cache.set(node, data); }
// когда node станет недостижим, запись исчезнет автоматически
```

`WeakMap` и `WeakSet` не мешают сборке мусора и потому **не перечисляемы** — иначе результат зависел бы от момента сборки, что недетерминированно.

```js
const ref = new WeakRef(someObject);
const value = ref.deref(); // объект или undefined, если уже собран

const registry = new FinalizationRegistry(key => {
  console.log('объект собран, ключ:', key);
});
registry.register(someObject, 'идентификатор');
```

> [!danger] `FinalizationRegistry` не гарантирует вызов
> Спецификация не обещает, что коллбэк вообще выполнится — при завершении программы он может не сработать. Использовать его для освобождения критичных ресурсов нельзя; только для необязательной уборки вроде очистки кеша.

## Мелочи, на которых спотыкаются

### Дырки в массивах

```js
const holes = [1, , 3];
console.log(holes.length);        // 3
console.log(1 in holes);          // false — элемента нет, не undefined

console.log(holes.map(x => 2));   // [2, <дырка>, 2] — map пропускает
console.log(holes.forEach(() => {})); // коллбэк вызван дважды
console.log([...holes]);          // [1, undefined, 3] — итератор дырки заполняет
console.log(Array.from(holes));   // [1, undefined, 3]
console.log(holes.includes(undefined)); // true
console.log(holes.indexOf(undefined));  // -1
```

Старые методы (`map`, `forEach`, `filter`) дырки пропускают, новые (`find`, `includes`, спред, `Array.from`) трактуют их как `undefined`. Единственный надёжный вывод — не создавать разрежённых массивов.

### `Object.freeze` поверхностный

```js
const config = Object.freeze({ nested: { value: 1 } });
config.nested.value = 2;
console.log(config.nested.value); // 2 — вложенный объект не заморожен

const deepFreeze = o => {
  Object.values(o).forEach(v => {
    if (v && typeof v === 'object') deepFreeze(v);
  });
  return Object.freeze(o);
};
```

### `typeof` и `instanceof`

```js
console.log(typeof null);          // 'object' — историческая ошибка, исправить нельзя
console.log(typeof function () {}); // 'function'
console.log(typeof Symbol());       // 'symbol'
console.log(typeof 1n);             // 'bigint'

// instanceof ломается через границу realm
// в iframe: array instanceof Array → false
console.log(Array.isArray([]));     // true — работает всегда
```

### Опциональная цепочка

```js
const obj = { a: { b: null } };

console.log(obj?.a?.b?.c);        // undefined — короткое замыкание
console.log(obj.a.b?.c.d.e);      // undefined — вся цепочка обрывается сразу
console.log(obj.missing?.());     // undefined — вызов тоже защищён
console.log(obj.missing?.[0]);    // undefined — и индексация

// но: защищает только от null и undefined
// console.log(obj.a.b.c);        // TypeError
```

### Ошибки с причиной

```js
try {
  try { JSON.parse('{битый'); }
  catch (e) { throw new Error('не удалось прочитать конфиг', { cause: e }); }
} catch (e) {
  console.log(e.message, '←', e.cause.name); // сохранена исходная ошибка
}
```

## Итог

> [!success] Что забирать
> - `[[Prototype]]`, `__proto__` и `prototype` — три разные сущности; для словарей использовать `Object.create(null)`
> - Смена прототипа после создания инвалидирует скрытые классы и inline-кеши
> - `super` работает через `[[HomeObject]]`, а не через прототип `this` — потому и доступен только в сокращённой записи метода
> - Итератор закрывается через `return()`: `for...of` с `break`, деструктуризация, исключение
> - `yield*` пробрасывает `next`, `return` и `throw`, а не просто перебирает значения
> - `await` откладывает продолжение в микрозадачу даже для не-промиса
> - Импорт — живое индирект-связывание, доступное только на чтение; циклы дают `ReferenceError` вместо тихого `undefined`
> - Символьные ключи не приватны — видны через `Reflect.ownKeys`
> - `FinalizationRegistry` не гарантирует вызов коллбэка
> - Дырки в массивах старые методы пропускают, новые считают `undefined`
> - `Object.freeze` замораживает только верхний уровень; `instanceof` ломается через границу realm
