## Прототипы

Чем различаются `[[Prototype]]`, `__proto__` и `prototype`
?
`[[Prototype]]` — ==внутренний слот== объекта, ссылка на родителя
`__proto__` — исторический аксессор в `Object.prototype` (Annex B), читающий этот слот
`prototype` — обычное свойство ==функции==, которое станет `[[Prototype]]` объектов, созданных через `new`

Почему `Object.create(null)` — правильный выбор для словаря::В такой объект не протекают `toString`, `constructor` и прочее из `Object.prototype`. У него нет и аксессора `__proto__`

Почему `Object.setPrototypeOf` убивает производительность::Инвалидирует ==скрытые классы== и inline-кеши для объекта и всех, кто через него читался. Прототип нужно задавать при создании

Через какой слот работает `super`::==`[[HomeObject]]`== — ссылка на объект, в котором определён метод. Поиск идёт от прототипа `[[HomeObject]]`, а не от прототипа `this`

Почему `super` недоступен в `{ method: function () {} }`::`[[HomeObject]]` устанавливается только для ==сокращённой записи метода==. У обычного функционального выражения слота нет

## Итераторы и генераторы

Что делает объект итерируемым::Метод `[Symbol.iterator]`, возвращающий итератор — объект с `next()`, дающим `{ value, done }`

Когда вызывается `return()` итератора::При досрочном выходе: `break` в `for...of`, деструктуризация короче последовательности, исключение внутри цикла

Что пробрасывает `yield*` помимо значений::==`next(v)`, `return()` и `throw()`== — это полноценная передача управления, а не перебор

Куда попадает значение `return` вложенного генератора при `yield*`::Становится ==значением самого выражения== `yield*`

Что становится результатом приостановленного `yield`::Аргумент следующего вызова `next(v)`

Почему первый `next()` игнорирует аргумент::Приостановленного выражения `yield` ещё не существует — передавать значение некуда

## Асинхронность

Выполняется ли код после `await null` синхронно::==Нет==. `await` над любым значением, включая не-промис, откладывает продолжение в микрозадачу

Что выведет код
?
```js
async function a() { console.log('a1'); await b(); console.log('a2'); }
async function b() { console.log('b1'); }
console.log('start'); a();
Promise.resolve().then(() => console.log('micro'));
console.log('end');
```
`start · a1 · b1 · end · a2 · micro` — продолжение `a` встало в очередь раньше, чем зарегистрировался `then`

Как объявляется асинхронный итератор::Через `Symbol.asyncIterator`; возвращает ==промисы записей==, а не сами записи

Поведение четырёх комбинаторов промисов
?
`Promise.all` — отклоняется первой ошибкой
`Promise.allSettled` — всегда исполняется, статусы внутри
`Promise.race` — первый завершившийся любым образом
`Promise.any` — первый успешный, все отказы дают `AggregateError`

Чем опасен `Promise.all` при нескольких отказах::Вернётся только первая ошибка, вторая останется ==необработанной== и вызовет `unhandledrejection`

## Модули

Что представляет собой импортированное имя::==Живое индирект-связывание== на ячейку исходного модуля, доступное только на чтение

Что произойдёт при присваивании импортированному имени::`TypeError` — биндинг доступен только на чтение

Почему обращение к импорту до строки `import` даёт ReferenceError::Имя существует с начала выполнения (объявления обрабатываются заранее), но остаётся ==неинициализированным==, пока зависимость не выполнится

Что происходит при циклической зависимости модулей::Связывание проходит успешно, но модуль, выполняемый первым, увидит партнёра в ==TDZ== и получит `ReferenceError`

Чем поведение циклов в ESM лучше, чем в CommonJS::В CommonJS вместо ошибки получается `undefined` — сбой становится ==тихим==

## Символы

Чем `Symbol()` отличается от `Symbol.for()`::`Symbol()` всегда создаёт уникальный символ, `Symbol.for()` берёт из ==глобального реестра== по ключу

Что вернёт `Symbol.keyFor(Symbol('a'))`::`undefined` — символ не из глобального реестра

Что делает `Symbol.hasInstance`::Переопределяет поведение оператора ==`instanceof`== для конструктора

Что делает `Symbol.toStringTag`::Меняет результат `Object.prototype.toString.call(obj)` на `[object ВашеЗначение]`

Являются ли символьные ключи приватными::==Нет==. Они не попадают в `Object.keys`, `for...in` и `JSON.stringify`, но видны через `Object.getOwnPropertySymbols` и `Reflect.ownKeys`

## Слабые ссылки

Почему `WeakMap` и `WeakSet` не перечисляемы::Иначе результат зависел бы от момента сборки мусора — поведение стало бы ==недетерминированным==

Что возвращает `WeakRef.prototype.deref()`::Объект либо `undefined`, если он уже собран

Гарантирует ли `FinalizationRegistry` вызов коллбэка::==Нет==. Спецификация не обещает выполнения; для критичных ресурсов использовать нельзя

## Мелочи

Чем дырка в массиве отличается от `undefined`
?
```js
const holes = [1, , 3];
1 in holes;              // false — элемента нет
holes.map(x => 2);       // [2, <дырка>, 2] — map пропускает
[...holes];              // [1, undefined, 3] — итератор заполняет
holes.includes(undefined); // true
holes.indexOf(undefined);  // -1
```

Какие методы пропускают дырки, а какие считают их `undefined`::Пропускают старые — `map`, `forEach`, `filter`. Считают `undefined` новые — `find`, `includes`, спред, `Array.from`

Насколько глубоко работает `Object.freeze`::Только ==верхний уровень==. Вложенные объекты остаются изменяемыми, нужен рекурсивный обход

Почему `typeof null` возвращает `'object'`::Историческая ошибка первой реализации; исправить нельзя без слома совместимости

Почему `instanceof` ненадёжен и чем заменить::Ломается через ==границу realm== (iframe, worker, vm). Для массивов — `Array.isArray`, в общем случае — `Symbol.toStringTag` или утиная типизация

От чего защищает опциональная цепочка::Только от ==`null` и `undefined`==. Работает и для вызова `?.()`, и для индексации `?.[]`

Что делает опция `cause` у Error::Сохраняет исходную ошибку при перевыбрасывании: `new Error('текст', { cause: e })`
