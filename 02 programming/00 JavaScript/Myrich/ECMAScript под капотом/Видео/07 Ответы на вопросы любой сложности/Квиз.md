> [!question] Что вернёт последняя строка?
> ```js
> function Ctor() {}
> const obj = new Ctor();
> console.log(obj.prototype);
> ```
> a) `Ctor.prototype`
> b) `Object.prototype`
> c) `undefined`
> d) `null`
>> [!success]- Answer
>> c) `undefined`
>> Свойство prototype есть у функции, а не у экземпляра. У экземпляра есть внутренний слот прототипа, доступный через Object.getPrototypeOf

> [!question] Оператор `super` находит метод через прототип объекта `this`
>> [!success]- Answer
>> False
>> Он использует слот `HomeObject` метода. Через прототип this при трёхуровневой иерархии возникла бы бесконечная рекурсия

> [!question] В каком слоте метода хранится объект, от прототипа которого `super` начинает поиск?
>> [!success]- Answer
>> HomeObject
>> Устанавливается только для сокращённой записи метода — поэтому в объекте с обычным функциональным выражением super недоступен

> [!question] Что пробрасывает `yield*` помимо значений?
> a) ничего, это сахар для цикла
> b) вызовы `next`, `return` и `throw`
> c) только `throw`
> d) только значение `return`
>> [!success]- Answer
>> b) вызовы `next`, `return` и `throw`
>> Это полноценная передача управления. Значение return вложенного генератора становится значением самого выражения yield*

> [!question] Код после `await null` выполняется синхронно, поскольку `null` не является промисом
>> [!success]- Answer
>> False
>> Продолжение всегда откладывается в микрозадачу. Синхронного продолжения после await не бывает ни для какого значения

> [!question] В каком порядке выведутся строки?
> ```js
> async function a() { console.log('a1'); await b(); console.log('a2'); }
> async function b() { console.log('b1'); }
> console.log('start'); a();
> Promise.resolve().then(() => console.log('micro'));
> console.log('end');
> ```
> a) `start a1 b1 end a2 micro`
> b) `start a1 b1 end micro a2`
> c) `start a1 b1 a2 end micro`
> d) `start end a1 b1 a2 micro`
>> [!success]- Answer
>> a) `start a1 b1 end a2 micro`
>> Продолжение функции a встало в очередь в момент await, то есть до строки с then. Поэтому a2 опережает micro

> [!question] Импортированное имя — это копия значения на момент импорта
>> [!success]- Answer
>> False
>> Это живое индирект-связывание на ячейку исходного модуля, доступное только на чтение. Изменение внутри модуля видно всем импортёрам

> [!question] Что произойдёт при циклической зависимости двух модулей ESM?
> a) ошибка на этапе разрешения зависимостей
> b) один из модулей увидит биндинги партнёра в TDZ
> c) значения окажутся равны `undefined`
> d) цикл будет разорван автоматически
>> [!success]- Answer
>> b) один из модулей увидит биндинги партнёра в TDZ
>> Связывание проходит успешно, но выполняемый первым получит ReferenceError. В CommonJS на этом месте было бы тихое undefined — явная ошибка лучше

> [!question] Символьные ключи обеспечивают настоящую приватность свойств
>> [!success]- Answer
>> False
>> Они не попадают в Object.keys и JSON, но видны через Object.getOwnPropertySymbols и Reflect.ownKeys. Символы дают отсутствие коллизий имён, а не приватность

> [!question] Что вернёт `1 in [1, , 3]`?
>> [!success]- Answer
>> false
>> Дырка — это отсутствие свойства, а не свойство со значением undefined. При этом includes найдёт undefined, а indexOf нет

> [!question] Насколько глубоко действует `Object.freeze`?
> a) на весь граф объектов рекурсивно
> b) только на собственные свойства верхнего уровня
> c) только на перечисляемые свойства
> d) только на массивы
>> [!success]- Answer
>> b) только на собственные свойства верхнего уровня
>> Ссылка становится неизменяемой, но объект по этой ссылке остаётся полноценно изменяемым. Нужен рекурсивный обход

> [!question] Почему `instanceof Array` может вернуть `false` для настоящего массива?
> a) массив создан через литерал
> b) массив пришёл из другого realm
> c) у массива изменили длину
> d) массив заморожен
>> [!success]- Answer
>> b) массив пришёл из другого realm
>> У iframe, воркера и vm-контекста свой набор интринсиков, значит другой Array.prototype. Надёжная проверка — Array.isArray

> [!question] Механизм, вызывающий коллбэк после сборки объекта мусора, называется `___`
>> [!success]- Answer
>> FinalizationRegistry
>> Спецификация не гарантирует вызов коллбэка, поэтому для освобождения критичных ресурсов он не подходит

> [!question] Какой комбинатор нужен, чтобы получить результаты всех промисов, включая отклонённые?
> a) `Promise.all`
> b) `Promise.allSettled`
> c) `Promise.race`
> d) `Promise.any`
>> [!success]- Answer
>> b) `Promise.allSettled`
>> У all есть побочный эффект: при двух отказах вернётся только первая ошибка, а вторая останется необработанной

> [!question] Что произойдёт при досрочном выходе из `for...of` по `break`?
> a) итератор просто перестанет использоваться
> b) будет вызван метод `return()` итератора
> c) будет выброшено исключение
> d) итератор дочитается до конца
>> [!success]- Answer
>> b) будет вызван метод `return()` итератора
>> Для генератора это запускает блок finally. То же происходит при деструктуризации короче последовательности
