> [!question] Что выведет код?
> ```js
> function Ctor() {}
> const obj = new Ctor();
> console.log(typeof obj.prototype, Object.getPrototypeOf(obj) === Ctor.prototype);
> ```
> a) `object true`
> b) `undefined true`
> c) `undefined false`
> d) `function true`
>> [!success]- Answer
>> b) `undefined true`
>> Свойство с таким именем есть у функции, а не у экземпляра. У экземпляра есть внутренний слот прототипа

> [!question] Что выведет код?
> ```js
> const dict = Object.create(null);
> dict.key = 1;
> console.log(typeof dict.toString, 'key' in dict);
> ```
> a) `function true`
> b) `undefined true`
> c) `undefined false`
> d) выбросит `TypeError`
>> [!success]- Answer
>> b) `undefined true`
>> В объект без прототипа не протекают методы. Именно поэтому он правильный выбор для словаря

> [!question] Что выведет код?
> ```js
> const base = { greet() { return 'база'; } };
> const derived = { __proto__: base, greet() { return super.greet() + '+'; } };
> console.log(derived.greet());
> ```
> a) `база+`
> b) `база`
> c) `SyntaxError`
> d) бесконечная рекурсия
>> [!success]- Answer
>> a) `база+`
>> Поиск идёт от прототипа домашнего объекта метода, а не от прототипа получателя. Слот выставляется только сокращённой записи метода

> [!question] Что выведет код?
> ```js
> function* g() {
>   try { yield 1; yield 2; }
>   finally { console.log('cleanup'); }
> }
> const it = g();
> it.next();
> it.return('стоп');
> ```
> a) ничего
> b) `cleanup`
> c) `стоп`
> d) `TypeError`
>> [!success]- Answer
>> b) `cleanup`
>> Метод возобновляет приостановленный контекст в режиме возврата, что запускает блок финализации

> [!question] Что выведет код?
> ```js
> function* inner() { yield 1; return 'итог'; }
> function* outer() { const r = yield* inner(); yield r; }
> console.log([...outer()]);
> ```
> a) `[1, 'итог']`
> b) `[1]`
> c) `['итог']`
> d) `[1, undefined]`
>> [!success]- Answer
>> a) `[1, 'итог']`
>> Значение возврата вложенного генератора становится значением выражения делегирования, а не элементом перебора

> [!question] Что выведет код?
> ```js
> function* dialog() {
>   const name = yield 'имя?';
>   yield 'привет, ' + name;
> }
> const d = dialog();
> console.log(d.next('игнор').value, d.next('Аня').value);
> ```
> a) `имя? привет, Аня`
> b) `имя? привет, игнор`
> c) `привет, игнор` и `undefined`
> d) `undefined привет, Аня`
>> [!success]- Answer
>> a) `имя? привет, Аня`
>> Первый вызов аргумент игнорирует — приостановленного выражения ещё нет. Значение попадает туда, где генератор был приостановлен

> [!question] В каком порядке выведутся строки?
> ```js
> async function a() { console.log('a1'); await b(); console.log('a2'); }
> async function b() { console.log('b1'); }
> console.log('start'); a();
> Promise.resolve().then(() => console.log('micro'));
> console.log('end');
> ```
> a) `start a1 b1 end a2 micro`
> b) `start a1 b1 end micro a2`
> c) `start a1 b1 a2 end micro`
> d) `start end a1 b1 a2 micro`
>> [!success]- Answer
>> a) `start a1 b1 end a2 micro`
>> Продолжение первой функции встало в очередь в момент ожидания, то есть раньше, чем зарегистрировался обработчик промиса

> [!question] Что выведет код?
> ```js
> async function f() { console.log('1'); await null; console.log('3'); }
> f();
> console.log('2');
> ```
> a) `1 2 3`
> b) `1 3 2`
> c) `2 1 3`
> d) `1 2` и ничего больше
>> [!success]- Answer
>> a) `1 2 3`
>> Ожидание не-промиса всё равно откладывает продолжение в микрозадачу. Синхронного продолжения после него не бывает

> [!question] Что выведет код?

>> [!success]- Answer

> [!question] Что выведет код?
> ```js
> const holes = [1, , 3];
> console.log(holes.length, 1 in holes, holes[1]);

>> [!success]- Answer

> [!question] Что выведет код?
> ```js
> const holes = [1, , 3];
> let visited = 0;
> holes.forEach(() => visited++);
> console.log(visited, [...holes].length, holes.includes(undefined), holes.indexOf(undefined));
> ```
> a) `3 3 true -1`
> b) `2 3 true -1`
> c) `2 2 false -1`
> d) `3 3 false 1`
>> [!success]- Answer
>> b) `2 3 true -1`
>> Старые методы дырки пропускают, спред и поиск по совпадению значений считают их неопределёнными, а поиск по строгому равенству — нет

> [!question] Что произойдёт при циклической зависимости двух модулей?
> a) ошибка на этапе разрешения зависимостей
> b) один из модулей увидит биндинги партнёра неинициализированными
> c) значения окажутся неопределёнными
> d) цикл будет разорван автоматически
>> [!success]- Answer
>> b) один из модулей увидит биндинги партнёра неинициализированными
>> Связывание проходит успешно, но выполняемый первым получит ошибку доступа. В старой модульной системе получилось бы тихое неопределённое значение

> [!question] Смена прототипа уже созданного объекта безопасна для производительности
>> [!success]- Answer
>> False
>> Она инвалидирует скрытые классы и кеши обращений — не только для этого объекта, но и для всех мест кода, читавших через него. Прототип задают при создании
