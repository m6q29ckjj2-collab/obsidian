> [!question] Чему равна длина строки?
> ```js
> console.log('a𝒳b'.length);
> ```
> a) 3
> b) 4
> c) 5
> d) 2
>> [!success]- Answer
>> b) 4
>> Символ вне BMP занимает суррогатную пару, то есть две 16-битные единицы. Свойство length считает единицы, а не символы

> [!question] Сколько code unit в семейном эмодзи `'👨‍👩‍👧'`?
>> [!success]- Answer
>> 8
>> Три эмодзи по суррогатной паре плюс два соединителя ZWJ. Code point при этом пять, а графемный кластер один

> [!question] Метод `at()` работает по code point, в отличие от `charAt`
>> [!success]- Answer
>> False
>> Он работает по code unit точно так же. Современный вид метода не добавляет поддержки символов вне BMP

> [!question] Какой механизм в языке идёт по code point, а не по code unit?
> a) `split('')`
> b) `charCodeAt`
> c) итератор строки
> d) индексный доступ
>> [!success]- Answer
>> c) итератор строки
>> Его используют for...of, спред и Array.from. Метод split итератор не использует и разрывает суррогатные пары

> [!question] Что произойдёт с строкой?
> ```js
> console.log('a𝒳b'.split('').reverse().join(''));
> ```
> a) вернётся `'b𝒳a'`
> b) вернётся исходная строка
> c) строка разрушится, пара переставится
> d) выбросит `RangeError`
>> [!success]- Answer
>> c) строка разрушится, пара переставится
>> Половины суррогатной пары меняются местами и перестают быть валидным UTF-16. Корректный вариант — спред с reverse

> [!question] Две визуально идентичные строки могут не быть равны при строгом сравнении
>> [!success]- Answer
>> True
>> Unicode допускает несколько представлений одного текста. Сравнение в спецификации побитовое по code unit, нормализации нет

> [!question] Какие формы нормализации обратимы?
> a) все четыре
> b) только NFC и NFD
> c) только NFKC и NFKD
> d) ни одна
>> [!success]- Answer
>> b) только NFC и NFD
>> Каноническая эквивалентность обратима. Совместимая теряет оформление навсегда: из лигатуры получится fi, обратно уже нет

> [!question] Почему поиск не находит подстроку?
> ```js
> const text = 'élan';  // é декомпозирована
> console.log(text.includes('é'));  // é единым кодом
> ```
> a) `includes` не работает с не-ASCII
> b) строки записаны в разных формах нормализации
> c) нужен флаг регулярного выражения
> d) `includes` сравнивает только по первому символу
>> [!success]- Answer
>> b) строки записаны в разных формах нормализации
>> В тексте лежит база плюс комбинирующий знак, в образце — единый код. Побитово это разные последовательности

> [!question] Диакритику снимают приведением к NFD и удалением категории `___`
>> [!success]- Answer
>> \p{Mark}
>> NFD выносит комбинирующие знаки в отдельные code point, после чего их можно вырезать. Приём не трогает самостоятельные буквы вроде ß

> [!question] Коллекция `Set` схлопнет две записи одного текста в разных формах нормализации
>> [!success]- Answer
>> False
>> SameValueZero сравнивает строки побитово. Именно так в базу попадают два визуально одинаковых логина

> [!question] Чем `String.fromCharCode` отличается от `String.fromCodePoint`?
> a) ничем, это синонимы
> b) первый обрезает аргумент до 16 бит
> c) второй работает только с ASCII
> d) первый принимает только один аргумент
>> [!success]- Answer
>> b) первый обрезает аргумент до 16 бит
>> Поэтому на символах вне BMP он даёт мусор. fromCodePoint сам собирает суррогатную пару

> [!question] Сколько графемных кластеров в строке `'👍🏽'`?
> a) 1
> b) 2
> c) 3
> d) 4
>> [!success]- Answer
>> a) 1
>> При этом code unit четыре, а code point два: базовое эмодзи плюс модификатор тона кожи, оба вне BMP

> [!question] Что вернёт `[...'𝒳'].length`?
>> [!success]- Answer
>> 1
>> Спред использует итератор строки, который идёт по code point и собирает суррогатную пару в один элемент

> [!question] Ограничение поля ввода по `length` надёжно защищает от раздувания текста
>> [!success]- Answer
>> False
>> Один символ с сотнями комбинирующих знаков пройдёт как несколько сотен единиц, а пятьдесят составных эмодзи будут отвергнуты как четыреста. Проверять нужно и графемы, и code unit

> [!question] Какую форму нормализации выбирают для сравнения логинов и имён пакетов?
> a) NFC
> b) NFD
> c) NFKC
> d) нормализация здесь не нужна
>> [!success]- Answer
>> c) NFKC
>> Она сводит визуальные варианты к одному значению. NFC остаётся выбором для хранения и передачи
