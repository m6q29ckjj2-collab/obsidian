> [!question] Что выведет код?
> ```js
> const s = 'a\u{1D4B3}b';
> console.log(s.length, [...s].length);
> ```
> a) `3 3`
> b) `4 3`
> c) `4 4`
> d) `3 4`
>> [!success]- Answer
>> b) `4 3`
>> Символ вне основной плоскости занимает суррогатную пару. Свойство длины считает единицы, спред идёт по символам

> [!question] Что выведет код?
> ```js
> const s = 'a\u{1D4B3}b';
> console.log(s.split('').reverse().join('').length, [...s].reverse().join(''));
> ```
> a) `4` и корректная перевёрнутая строка
> b) `3` и корректная перевёрнутая строка
> c) `4` и битая строка
> d) выбросит исключение
>> [!success]- Answer
>> a) `4` и корректная перевёрнутая строка
>> Длина сохраняется в обоих случаях, но первый вариант переставляет половины суррогатной пары и разрушает символ. Второй идёт по code point

> [!question] Что выведет код?

> b) `1 1 1`

>> [!success]- Answer
>> a) `1 2 2`

> [!question] Соберите code point из суррогатной пары
> ```js
> const hi = 0xD835, lo = 0xDCB3;
> const cp = (hi - 0xD800) * 0x400 + (lo - 0xDC00) + 0x10000;
> console.log(cp.toString(16));
> ```
> a) `d835`
> b) `1d4b3`
> c) `dcb3`
> d) `1f4b3`
>> [!success]- Answer
>> b) `1d4b3`
>> Старший суррогат несёт старшие десять бит смещения, младший — младшие. Плюс базовое смещение

> [!question] Сформулируйте обе основные проблемы типа String
> a) медленная конкатенация и большой расход памяти
> b) единица измерения не совпадает с символом, и у текста нет единственного представления
> c) отсутствие методов поиска и сортировки
> d) невозможность хранить эмодзи
>> [!success]- Answer
>> b) единица измерения не совпадает с символом, и у текста нет единственного представления
>> Обе вытекают прямо из определения типа как последовательности 16-битных единиц

> [!question] Три уровня измерения строки — это code unit, code point и `___`
>> [!success]- Answer
>> графемный кластер
>> Первый даёт свойство длины, второй спред или итератор, третий — сегментатор. Пользователь считает третий

> [!question] Достаточно ли работать по code point, чтобы правильно считать символы?
>> [!success]- Answer
>> False
>> Комбинирующие знаки, модификаторы тона, соединители и селекторы вариантов дают несколько code point на один воспринимаемый символ

> [!question] Какие формы нормализации обратимы?
> a) все четыре
> b) только канонические
> c) только совместимые
> d) ни одна
>> [!success]- Answer
>> b) только канонические
>> Совместимые теряют оформление навсегда: из разложенной лигатуры исходный символ уже не восстановить

> [!question] Спецификация выполняет нормализацию при сравнении строк
>> [!success]- Answer
>> False
>> Сравнение побитовое по единицам. Нормализовать нужно самому, и делать это на границе входа
