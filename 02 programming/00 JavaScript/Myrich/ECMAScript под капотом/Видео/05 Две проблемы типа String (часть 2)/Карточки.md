## Постановка

Сформулируйте обе основные проблемы типа String
?
**1.** Единица измерения (code unit) не совпадает ни с символом Unicode, ни с тем, что пользователь считает символом.
**2.** У одного текста нет единственного представления — визуально одинаковые строки могут состоять из разных последовательностей.

Это баги реализации или следствие определения типа::==Следствие определения==. Язык проектировался, когда Unicode помещался в 16 бит и UCS-2 казался достаточным

---

## Проблема 1: уровни измерения

Три уровня измерения строки и как получить каждый
?
**code unit** — `.length`, `[i]`, `charCodeAt`
**code point** — `[...str]`, `codePointAt`
**графемный кластер** — `Intl.Segmenter`

Какие диапазоны отведены под суррогаты::Старший `U+D800`–`U+DBFF`, младший `U+DC00`–`U+DFFF`

Почему символы вне BMP занимают две единицы::В 16 бит помещается 65 536 позиций, а Unicode содержит более миллиона — остальное кодируется ==парой== code unit

Чем `String.fromCharCode` отличается от `String.fromCodePoint`::`fromCharCode` обрезает аргумент до 16 бит и на символах вне BMP даёт мусор; `fromCodePoint` собирает суррогатную пару

Работает ли `at()` по code point::==Нет==, по code unit — так же, как `charAt`, несмотря на «современность» метода

Какой встроенный механизм идёт по code point::==Итератор строки==. Его используют `for...of`, спред и `Array.from`. `split('')` итератор не использует

Что вернёт `'𝒳'.split('').length` и `Array.from('𝒳').length`::`2` и `1`

Как правильно развернуть строку с символами вне BMP::`[...s].reverse().join('')`. `split('').reverse()` переставляет половины суррогатной пары и ломает строку

---

## Графемные кластеры

Достаточно ли работы по code point для правильного счёта символов::==Нет==. Комбинирующие знаки, модификаторы тона, ZWJ-последовательности, флаги и селекторы вариантов дают несколько code point на один воспринимаемый символ

Сколько code unit и code point в `'👨‍👩‍👧'`::`8` и `5` — три эмодзи по паре плюс два ZWJ

Сколько code unit в `'👍🏽'` и почему::`4` — базовое эмодзи (пара) плюс модификатор тона кожи (тоже пара)

Из чего состоит флаг вроде `'🇺🇦'`::Из двух ==regional indicator==, каждый занимает суррогатную пару: 4 code unit, 2 code point, 1 графема

Что такое селектор варианта начертания::`U+FE0F` после символа — переключает отображение с текстового на эмодзи. `'❤️'` это `U+2764` + `U+FE0F`

Что такое Zalgo-текст и чем он опасен
?
Символ с сотнями комбинирующих знаков: `'а' + '́'.repeat(200)`.
`length` даёт 201, графема одна. Ограничение поля по `length` такой ввод ==пропустит==, а вёрстка разъедется. Проверять нужно оба числа.

## Проблема 2: множественность представлений

Как спецификация сравнивает строки::==Побитово по code unit==, без какой-либо нормализации

Почему `'é' === 'é'` может быть ложным::Одна строка — единый код U+00E9, другая — `e` плюс комбинирующий акут. Разные последовательности, одинаковый вид

Четыре формы нормализации и их эквивалентность
?
**NFC** — каноническая, композиция
**NFD** — каноническая, декомпозиция
**NFKC** — совместимая, композиция
**NFKD** — совместимая, декомпозиция

Чем каноническая эквивалентность отличается от совместимой::Каноническая ==обратима== (из NFD восстановится NFC), совместимая — нет: из `'fi'` лигатуру не вернуть

Что делает NFKC с `'ﬁ'`, `'①'`, `'Ⅻ'`::`'fi'`, `'1'`, `'XII'` — заменяет совместимые формы. NFC их не трогает

Что ломается без нормализации::Поиск (`includes`, `indexOf`), уникальность в `Set`, ключи `Map`, регулярные выражения, сортировка

Почему два визуально одинаковых логина попадают в базу::`Set` и уникальный индекс сравнивают побитово — разные формы записи одного текста считаются разными значениями

## Практика

Где единственно правильное место для нормализации::На ==границе входа==, до любых проверок, сравнений и записи в хранилище

Почему нормализация после проверки — это дыра в безопасности::Строка проходит фильтр в одной форме, а в хранилище попадает в другой — возможно запрещённой

Какую форму выбирать для хранения::==NFC== — компактнее, совместимее, форма по умолчанию в вебе

Какую форму выбирать для сравнения идентификаторов::==NFKC== — сводит совместимые варианты, что важно для логинов, доменов, имён пакетов

Как снять диакритику со строки
?
```js
s.normalize('NFD').replace(/\p{Mark}/gu, '');
```
NFD выносит комбинирующие знаки в отдельные code point, `\p{Mark}` их удаляет.

Почему приём снятия диакритики не трогает `'ß'`::`ß` — ==самостоятельная буква==, а не `s` с диакритическим знаком. Нужны локальные правила через `Intl.Collator`

Чем `Intl.Collator` лучше связки `normalize` + `===`::Нормализует внутри себя ==и== применяет правила языка — решает обе проблемы разом, включая регистр и `ё`/`е`
