### 1. Сформулируйте механизм `this` одним предложением

> [!success]- Ответ
> `this` — не переменная и не параметр, а результат операции `ResolveThisBinding`, которая через `GetThisEnvironment` находит **ближайшую запись окружения со связыванием `this`** и берёт значение оттуда.
>
> Такая запись — Function Environment Record, создаваемая при вызове обычной функции. У стрелочных функций она не создаётся, поэтому поиск продолжается вверх по `[[OuterEnv]]`.
>
> «Пять способов вызова» из популярных изложений — это следствия одного правила, а не пять независимых правил.

### 2. Приведите алгоритм из четырёх вопросов

> [!success]- Ответ
> ```
> 1. Стрелка?               → this из внешней области, дальше не смотрим
> 2. Вызов через new?       → новый объект
> 3. call / apply / bind?   → переданное значение
> 4. Есть база obj.f()?     → obj
>    иначе                  → undefined (strict) / globalThis (sloppy)
> ```
>
> Побеждает первый подошедший пункт. Именно поэтому стрелка игнорирует и `call`, и базу вызова, и `new`.

### 3. Что вернёт каждая строка

```js
const obj = { show() { return this; } };

obj.show();
(obj.show)();
(0, obj.show)();
```

> [!success]- Ответ
> `obj`, `obj`, `undefined` (в строгом режиме).
>
> Скобки вокруг `obj.show` ничего не меняют — ссылка на свойство сохраняется вместе с базой.
>
> А вот оператор **запятая** вычисляет левый операнд, отбрасывает его и возвращает правый **как значение**, а не как ссылку на свойство. База теряется, и вызов становится обычным.
>
> Это не курьёз: минификаторы и транспиляторы используют приём `(0, obj.f)()` намеренно, когда нужно вызвать функцию без базы. В собранном коде он встречается регулярно.

### 4. Объясните разницу режимов

```js
function show() { return this; }
show.call(42);
show.call(null);
```

> [!success]- Ответ
> В **строгом** режиме: `42` и `null` — значения передаются как есть.
>
> В **нестрогом**: объект-обёртка `Number` и `globalThis`.
>
> Операция `OrdinaryCallBindThis` в sloppy mode заменяет `undefined` и `null` глобальным объектом, а примитивы пропускает через `ToObject`. Проверить легко: `typeof show.call(42)` даёт `'number'` в strict и `'object'` в sloppy.

### 5. Почему здесь не нужна директива `'use strict'`

```js
class Counter {
  #count = 0;
  increment() { this.#count++; }
}
const m = new Counter().increment;
m();
```

> [!success]- Ответ
> `TypeError` — и директива действительно не нужна.
>
> Тела классов выполняются в строгом режиме **по определению**, как и код модулей ESM. Поэтому оторванный метод получает `this === undefined`, а не `globalThis`.
>
> Это удачное свойство: ошибка проявляется сразу и явно, вместо тихой порчи глобального объекта, которая случилась бы в нестрогой функции.

### 6. Перечислите три состояния `[[ThisBindingStatus]]`

> [!success]- Ответ
> | Значение | Когда |
> |---|---|
> | `lexical` | стрелочная функция — своего связывания нет |
> | `uninitialized` | производный конструктор до вызова `super()` |
> | `initialized` | обычное состояние |
>
> Переход из `uninitialized` в `initialized` выполняет операция `BindThisValue`, вызываемая из `super()`. До неё обращение к `this` даёт `ReferenceError` — тот же механизм, что у TDZ для `let`.

### 7. Почему эта стрелка не получит объект

```js
const obj = { value: 1, get: () => this.value };
console.log(obj.get());
```

> [!success]- Ответ
> `undefined` (или `TypeError`, если `this` равен `undefined` в модуле).
>
> Стрелка захватывает `this` лексически — из области, где она **создана**. Объектный литерал области видимости не создаёт, поэтому захватывается внешний контекст: `undefined` в модуле ESM, `globalThis` в обычном скрипте.
>
> Стрелка в литерале объекта **никогда** не получит сам объект. Для методов нужна сокращённая запись `get() { ... }`.

### 8. Найдите ошибку и исправьте

```js
class Timer {
  seconds = 0;
  start() {
    setInterval(function () { this.seconds++; }, 1000);
  }
}
```

> [!success]- Ответ
> Обычная функция в коллбэке вызывается **без базы**, поэтому получает собственный `this` — не экземпляр `Timer`.
>
> В браузере `setInterval` вызывает коллбэк с `this`, равным глобальному объекту, и `this.seconds++` тихо создаст `NaN` на нём вместо ошибки.
>
> ```js
> start() {
>   setInterval(() => { this.seconds++; }, 1000); // стрелка берёт this из start
> }
> ```
>
> Это ровно тот случай, ради которого стрелки и вводились.

### 9. Что вернёт код

```js
function f() { return this.tag; }
console.log(f.bind({ tag: 'a' }).bind({ tag: 'b' })());
```

> [!success]- Ответ
> `'a'`.
>
> Связанная функция — экзотический объект со слотами `[[BoundTargetFunction]]` и `[[BoundThis]]`. Второй `bind` оборачивает уже связанную функцию, но её внутреннее связывание перезаписать не может: при вызове внешней обёртки управление доходит до внутренней, которая подставляет свой `[[BoundThis]]`.
>
> Первый `bind` побеждает всегда.

### 10. Что важнее — `new` или `bind`

```js
function Ctor() { this.created = true; }
const Bound = Ctor.bind({ ignored: true });
const inst = new Bound();
console.log(inst.created, inst.ignored);
```

> [!success]- Ответ
> `true undefined`.
>
> `new` важнее. Внутренний метод `[[Construct]]` связанной функции игнорирует слот `[[BoundThis]]` и создаёт новый объект обычным образом, передавая его в целевую функцию.
>
> Это согласуется с алгоритмом из четырёх вопросов: `new` стоит **вторым** пунктом, то есть выше явного указания через `bind`.
