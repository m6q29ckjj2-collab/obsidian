> [!question] Значение получателя вычисляет операция `___`
>> [!success]- Answer
>> ResolveThisBinding
>> Она обращается к поиску ближайшей записи окружения со связыванием. Никакой переменной или скрытого параметра не существует

> [!question] Каков порядок четырёх вопросов для определения получателя?
> a) база вызова, явное указание, конструирование, стрелка
> b) стрелка, конструирование, явное указание, база вызова
> c) конструирование, стрелка, база вызова, явное указание
> d) явное указание, стрелка, база вызова, конструирование
>> [!success]- Answer
>> b) стрелка, конструирование, явное указание, база вызова
>> Побеждает первый подошедший пункт. Именно поэтому стрелка игнорирует и явное указание, и базу

> [!question] Что выведет код?
> ```js
> const obj = { f() { return this; } };
> const key = 'f';
> console.log(obj.f() === obj, obj['f']() === obj, obj[key]() === obj);
> ```
> a) `true true true`
> b) `true false false`
> c) `true true false`
> d) `false false false`
>> [!success]- Answer
>> a) `true true true`
>> Форма записи обращения к свойству не важна: во всех трёх случаях получается ссылка с той же базой. Базу стирает не индексация, а извлечение значения из ссылки

> [!question] Какая из операций НЕ стирает базу вызова?
> a) оператор запятая
> b) присваивание в переменную
> c) обёртывание в скобки
> d) логическое ИЛИ
>> [!success]- Answer
>> c) обёртывание в скобки
>> Остальные три извлекают из ссылки значение. Это единое объяснение всех потерь получателя

> [!question] Что выведет код?
> ```js
> const obj = { f() { return this; } };
> console.log((obj.f || obj.f)() === obj, (true ? obj.f : 0)() === obj);
> ```
> a) `true true`
> b) `false false`
> c) `true false`
> d) `false true`
>> [!success]- Answer
>> b) `false false`
>> Логический и тернарный операторы возвращают значение, а не ссылку на свойство

> [!question] Что вернёт вызов в строгом режиме?
> ```js
> 'use strict';
> function show() { return this; }
> console.log(typeof show.call(42), show.call(null));
> ```
> a) `number null`
> b) `object null`
> c) `number` и глобальный объект
> d) `object` и глобальный объект
>> [!success]- Answer
>> a) `number null`
>> В строгом режиме аргумент передаётся как есть, включая примитивы и пустую ссылку

> [!question] Что вернёт тот же вызов в нестрогом режиме?
> ```js
> function show() { return this; }
> console.log(typeof show.call(42), show.call(null) === globalThis);
> ```
> a) `number false`
> b) `object true`
> c) `number true`
> d) `object false`
>> [!success]- Answer
>> b) `object true`
>> Примитив оборачивается, а пустая ссылка и неопределённое значение заменяются глобальным объектом

> [!question] Глобальный объект какого набора интринсиков подставляется в нестрогом режиме?
> a) текущего
> b) того, которому принадлежит функция
> c) всегда основного окна
> d) это не определено
>> [!success]- Answer
>> b) того, которому принадлежит функция
>> Для функции из встроенного фрейма это будет глобальный объект того фрейма

> [!question] Три значения слота состояния связывания
> a) `initialized`, `uninitialized`, `lexical`
> b) `strict`, `sloppy`, `lexical`
> c) `bound`, `unbound`, `lexical`
> d) `global`, `local`, `lexical`
>> [!success]- Answer
>> a) `initialized`, `uninitialized`, `lexical`
>> Второе — у производного конструктора до вызова родительского, третье — у стрелочных функций

> [!question] Что выведет код?
> ```js
> const obj = { value: 1, arrow: () => this?.value };
> console.log(obj.arrow());
> ```
> a) `1`
> b) `undefined`
> c) сам объект
> d) выбросит `TypeError`
>> [!success]- Answer
>> b) `undefined`
>> Объектный литерал не создаёт области видимости. Стрелка в нём никогда не получит сам объект

> [!question] Что выведет код?
> ```js
> const arrow = () => 'значение';
> const bound = arrow.bind({ tag: 'другой' });
> console.log(typeof bound, bound(), bound.name);
> ```
> a) `function значение bound arrow`
> b) выбросит `TypeError`
> c) `function undefined bound arrow`
> d) `object значение arrow`
>> [!success]- Answer
>> a) `function значение bound arrow`
>> Связывание создаёт новую функцию и даже даёт ей имя с префиксом, но менять внутри нечего: у стрелки нет собственного связывания получателя

> [!question] Что выведет код?
> ```js
> function f() { return this.tag; }
> console.log(f.bind({ tag: 'a' }).bind({ tag: 'b' })());
> ```
> a) `a`
> b) `b`
> c) `undefined`
> d) выбросит `TypeError`
>> [!success]- Answer
>> a) `a`
>> Первое связывание окончательно: повторное оборачивает функцию, но внутреннее значение перезаписать не может

> [!question] Что важнее при вызове связанной функции — конструирование или связывание?
> a) связывание
> b) конструирование
> c) зависит от режима
> d) выбросится исключение
>> [!success]- Answer
>> b) конструирование
>> Внутренний метод конструирования игнорирует связанного получателя. Это согласуется с порядком четырёх вопросов

> [!question] Тела классов и код модулей выполняются в строгом режиме без директивы
>> [!success]- Answer
>> True
>> Поэтому оторванный метод класса получает неопределённое значение, а не глобальный объект, и ошибка проявляется сразу

> [!question] Что выведет код?
> ```js
> class D extends Object {
>   constructor() {
>     let ok = true;
>     try { this; } catch { ok = false; }
>     super();
>     console.log(ok);
>   }
> }
> new D();
> ```
> a) `true`
> b) `false`
> c) выбросит наружу
> d) `undefined`
>> [!success]- Answer
>> b) `false`
>> До вызова родительского конструктора связывание не инициализировано, и обращение бросает — механизм тот же, что у временной мёртвой зоны

> [!question] Где встречается приём с оператором запятая перед вызовом метода?
> a) это ошибка, так не пишут
> b) в коде после минификации и транспиляции
> c) только в учебных примерах
> d) в асинхронном коде
>> [!success]- Answer
>> b) в коде после минификации и транспиляции
>> Так намеренно сбрасывают базу вызова, когда функцию нужно вызвать без получателя

> [!question] Что выведет код?
> ```js
> const obj = { n: 1, m() { return this.n; } };
> const arr = [obj.m];
> console.log(arr[0]());
> ```
> a) `1`
> b) `undefined`
> c) выбросит `TypeError`
> d) сам массив
>> [!success]- Answer
>> b) `undefined`
>> База вызова не потеряна — ею стал сам массив, ведь обращение идёт через индекс. Свойства с таким именем у массива нет, поэтому читается неопределённое значение. Исключения не будет: получатель существует, просто он не тот

> [!question] Стрелочная функция поддаётся явному указанию получателя
>> [!success]- Answer
>> False
>> Своего связывания у неё нет, менять нечего. Методы явного указания существуют и вызываются, но аргумент игнорируют
