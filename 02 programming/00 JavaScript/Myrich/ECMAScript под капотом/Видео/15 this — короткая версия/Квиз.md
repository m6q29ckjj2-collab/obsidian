> [!question] Значение `this` вычисляет операция `___`
>> [!success]- Answer
>> ResolveThisBinding
>> Она обращается к GetThisEnvironment, а тот ищет ближайшую запись окружения со связыванием this. Никакой переменной или скрытого параметра нет

> [!question] Что вернёт вызов?
> ```js
> const obj = { f() { return this; } };
> console.log((0, obj.f)() === obj);
> ```
> a) `true`
> b) `false`
> c) `undefined`
> d) `TypeError`
>> [!success]- Answer
>> b) `false`
>> Оператор запятая возвращает значение, а не ссылку на свойство, поэтому база вызова теряется. Приём намеренно используют минификаторы

> [!question] Скобки вокруг `obj.f` в выражении `(obj.f)()` сбрасывают базу вызова
>> [!success]- Answer
>> False
>> Скобки сохраняют ссылку на свойство целиком. Базу стирает всё, что извлекает из ссылки значение: запятая, присваивание, логические и тернарный операторы

> [!question] Что вернёт `typeof` в строгом режиме?
> ```js
> 'use strict';
> function show() { return this; }
> console.log(typeof show.call(42));
> ```
> a) `'object'`
> b) `'number'`
> c) `'undefined'`
> d) `'function'`
>> [!success]- Answer
>> b) `'number'`
>> В строгом режиме примитив передаётся как есть. В нестрогом он проходит через ToObject и даёт object

> [!question] Тела классов и код модулей ESM выполняются в строгом режиме без отдельной директивы
>> [!success]- Answer
>> True
>> Поэтому оторванный метод класса получает undefined, а не globalThis, и ошибка проявляется сразу вместо тихой порчи глобального объекта

> [!question] Какое значение слота состояния связывания у стрелочной функции?
> a) `initialized`
> b) `uninitialized`
> c) `lexical`
> d) слот отсутствует
>> [!success]- Answer
>> c) `lexical`
>> Из-за этого проверка наличия связывания даёт ложь, и поиск продолжается вверх по цепочке окружений. Всё поведение стрелок — следствие одного этого значения

> [!question] Какой пункт побеждает, если функция стрелочная и вызвана через `call`?
> a) явное указание через `call`
> b) лексический захват
> c) база вызова
> d) поведение не определено
>> [!success]- Answer
>> b) лексический захват
>> Порядок проверки: стрелка, затем new, затем явное указание, затем база вызова. Побеждает первый подошедший пункт

> [!question] Стрелочную функцию можно вызвать через `new`
>> [!success]- Answer
>> False
>> У неё нет внутреннего метода конструирования и нет свойства prototype. Попытка даёт TypeError

> [!question] Что вернёт вызов в нестрогом режиме?
> ```js
> function show() { return this; }
> console.log(show.call(null) === globalThis);
> ```
> a) `true`
> b) `false`
> c) `undefined`
> d) `TypeError`
>> [!success]- Answer
>> a) `true`
>> В нестрогом режиме undefined и null заменяются глобальным объектом. Причём именно того realm, которому принадлежит функция

> [!question] Сколько раз нужно вызвать `bind`, чтобы перенаправить уже связанную функцию на другой объект?
> a) один раз, поверх существующего связывания
> b) два раза подряд
> c) это невозможно, первое связывание окончательно
> d) достаточно изменить свойство связанной функции
>> [!success]- Answer
>> c) это невозможно, первое связывание окончательно
>> Связанная функция — экзотический объект со слотом связанного this, и повторный bind его не перезаписывает
