## 1. Формальное определение

Спецификация определяет тип String так: множество всех конечных упорядоченных последовательностей **нуля или более 16-битных беззнаковых целых значений**. Каждый элемент последовательности называется **code unit**.

Три слова в этом определении несут всю нагрузку темы:

- **последовательность** — не массив, не объект; значение, а не структура
- **16-битных беззнаковых целых** — не символов, не байтов
- **нуля или более** — пустая строка полноправна

> [!abstract] Чего в определении нет
> Ни слова про Unicode, кодировки, символы или валидность. Формально строка — это просто вектор чисел от 0 до 65535. Интерпретация как UTF-16 добавляется отдельно и **не является обязательной**.

Спецификация прямо оговаривает: строки не обязаны быть well-formed UTF-16, и операции над ними не проверяют парность суррогатов. Это осознанное решение — иначе нельзя было бы разрезать строку в произвольном месте.

```js
const lone = '\uD800';           // старший суррогат без пары
console.log(lone.length);        // 1 — совершенно легальная строка
console.log(typeof lone);        // 'string'
console.log(lone.isWellFormed()); // false — но это лишь информация
```

## 2. Строки неизменяемы

Значение типа String изменить нельзя. Все методы возвращают **новую** строку.

```js
const s = 'привет';
s[0] = 'П';           // молча игнорируется в sloppy mode
console.log(s);       // 'привет'

'use strict';
// s[0] = 'П';        // TypeError: Cannot assign to read only property

const upper = s.toUpperCase();
console.log(s, upper); // 'привет' 'ПРИВЕТ' — исходная не тронута
```

Неизменяемость — не оптимизация, а свойство типа. Именно она позволяет движкам безопасно применять rope-структуры и интернирование: раз содержимое не поменяется, его можно разделять между значениями.

## 3. Примитив против объекта-обёртки

Это разные вещи, и различие имеет наблюдаемые последствия.

```js
const primitive = 'текст';
const wrapper   = new String('текст');

console.log(typeof primitive); // 'string'
console.log(typeof wrapper);   // 'object'

console.log(primitive === wrapper);  // false
console.log(primitive == wrapper);   // true — ToPrimitive у объекта

console.log(wrapper.valueOf() === primitive); // true
```

### String exotic object

Объект-обёртка — **экзотический**: у него переопределены внутренние методы `[[GetOwnProperty]]`, `[[DefineOwnProperty]]` и `[[OwnPropertyKeys]]`, чтобы индексы вели себя как собственные свойства.

```js
const w = new String('абв');

console.log(Object.getOwnPropertyNames(w)); // ['0', '1', '2', 'length']
console.log(Object.getOwnPropertyDescriptor(w, '0'));
// { value: 'а', writable: false, enumerable: true, configurable: false }

console.log(Object.getOwnPropertyDescriptor(w, 'length'));
// { value: 3, writable: false, enumerable: false, configurable: false }
```

Внутри объекта лежит слот `[[StringData]]` с самим примитивом. Индексные свойства не хранятся — они вычисляются на лету операцией `StringGetOwnProperty`.

```js
const w2 = new String('абв');
w2.extra = 'можно';        // обычное свойство добавляется
console.log(w2.extra);     // 'можно'
console.log(Object.keys(w2)); // ['0', '1', '2', 'extra']
```

### Что происходит при `'строка'.method()`

У примитива нет свойств. Обращение к ним — операция `GetValue` над ссылкой, где базой служит примитив: спецификация вызывает `ToObject`, получает временную обёртку, читает свойство и обёртку выбрасывает.

```js
const s = 'текст';
s.custom = 'значение';   // обёртка создана, свойство записано, обёртка уничтожена
console.log(s.custom);   // undefined — новая обёртка ничего не знает о старой
```

Движки этот путь оптимизируют и реальный объект обычно не создают, но семантика именно такая. Отсюда же следует, почему `this` внутри метода различается по режимам:

```js
String.prototype.showThis = function () { return typeof this; };
console.log('текст'.showThis());               // 'object' — sloppy, ToObject
String.prototype.showStrict = function () { 'use strict'; return typeof this; };
console.log('текст'.showStrict());             // 'string' — примитив как есть
```

## 4. Свойство `length`

```js
console.log('привет'.length);   // 6
console.log(''.length);         // 0
console.log('𝒳'.length);        // 2 — одна буква, две единицы
```

`length` — это **количество code unit**, а не символов. Свойство неперезаписываемое и неконфигурируемое, поэтому попытки его изменить бесполезны.

Теоретический максимум длины реализация выбирает сама; спецификация лишь требует, чтобы длина была неотрицательным целым числом, представимым как индекс массива.

## 5. Абстрактная операция `ToString`

Преобразование в строку описано отдельными правилами для каждого типа.

| Значение | Результат |
|---|---|
| `undefined` | `'undefined'` |
| `null` | `'null'` |
| `true` / `false` | `'true'` / `'false'` |
| Number | по алгоритму `Number::toString` |
| String | само значение |
| Symbol | **TypeError** |
| BigInt | цифры без суффикса `n` |
| Object | `ToPrimitive` с хинтом `string`, затем снова `ToString` |

```js
console.log(String(undefined));  // 'undefined'
console.log(String(null));       // 'null'
console.log(String(123n));       // '123' — без 'n'
console.log(String([1, [2, 3]])); // '1,2,3' — join рекурсивно

// Symbol — единственный тип, который бросает
try { String(Symbol('s') + ''); } catch (e) { console.log(e.name); } // TypeError
console.log(String(Symbol('s'))); // 'Symbol(s)' — явный вызов разрешён
```

Последняя пара строк — тонкость: `String(symbol)` работает специальным исключением из правила, а неявное преобразование (конкатенация, шаблон) бросает `TypeError`.

### Числа в строку

```js
console.log(String(0.1 + 0.2));      // '0.30000000000000004'
console.log(String(1e21));           // '1e+21' — с 10²¹ переходит в экспоненту
console.log(String(1e20));           // '100000000000000000000'
console.log(String(-0));             // '0' — знак теряется
console.log(String(NaN));            // 'NaN'
console.log((255).toString(16));     // 'ff' — другое основание
```

Алгоритм выбирает **кратчайшее** десятичное представление, которое при обратном чтении даёт то же самое число. Отсюда и `0.30000000000000004`: короче записать нельзя без потери значения.

## 6. Литералы и escape-последовательности

```js
console.log('\u0041');      // 'A' — ровно 4 шестнадцатеричные цифры
console.log('\u{1D4B3}');   // '𝒳' — фигурные скобки, любое число цифр
console.log('\x41');        // 'A' — две цифры
console.log('\101');        // 'A' — восьмеричная, запрещена в strict mode
```

Форма `\u{...}` появилась в ES6 именно потому, что старая записывает только одну 16-битную единицу — символ вне BMP приходилось задавать двумя escape-последовательностями подряд.

```js
console.log('\uD835\uDCB3' === '\u{1D4B3}'); // true — одно и то же
```

### Шаблонные литералы

```js
const name = 'мир';
console.log(`привет, ${name}`);

// многострочность сохраняется буквально
console.log(`первая
вторая`.length); // 15 — перенос это один code unit U+000A

// теговый шаблон получает сырые и обработанные части
const tag = (strings, ...values) => ({ cooked: strings[0], raw: strings.raw[0] });
console.log(tag`a\nb`); // { cooked: 'a\nb' (с переносом), raw: 'a\\nb' }
```

Свойство `raw` даёт текст **до** обработки escape-последовательностей — на этом построены `String.raw` и библиотеки вроде описаний путей и регулярных выражений.

```js
console.log(String.raw`C:\новая\папка`); // 'C:\новая\папка' — \н не съеден
```

## 7. Сравнение строк

```js
console.log('a' === 'a');  // true — посимвольное сравнение code unit
console.log('a' < 'b');    // true
console.log('Z' < 'a');    // true — 0x5A меньше 0x61
console.log('ё' < 'я');    // false — 0x451 больше 0x44F
console.log('10' < '9');   // true — сравниваются строки, не числа
```

Операция `IsLessThan` для двух строк выполняет лексикографическое сравнение **числовых значений code unit**. Никаких языковых правил, регистра или нормализации.

Следствие, важное для UI: стандартная сортировка строк почти всегда неверна для естественного языка.

```js
console.log(['ёж', 'яблоко', 'арбуз'].sort()); // ['арбуз', 'яблоко', 'ёж']
```

Правильный инструмент — `Intl.Collator`, но это уже [[04 String in wild (часть 3)/Отчёт|третья часть]].

## 8. Методы прототипа обобщённые

Большинство методов `String.prototype` начинаются с `RequireObjectCoercible` и `ToString`, а не с проверки типа. Поэтому их можно применять к чему угодно, кроме `null` и `undefined`.

```js
console.log(String.prototype.toUpperCase.call(123));      // '123'
console.log(String.prototype.slice.call([1, 2, 3], 0, 3)); // '1,2'
console.log(String.prototype.charAt.call(true, 0));        // 't'

try { String.prototype.trim.call(null); }
catch (e) { console.log(e.name); } // TypeError — RequireObjectCoercible
```

Практической пользы в этом мало, но знание объясняет, почему методы не падают на странных аргументах и почему проверка типа лежит на вызывающем коде.

## 9. Итог

> [!success] Что забирать
> - String — конечная упорядоченная последовательность **16-битных беззнаковых целых**; в определении нет ни Unicode, ни символов, ни требования валидности
> - Строки **неизменяемы**; это свойство типа, а не оптимизация, и именно оно делает возможными rope и интернирование
> - Примитив и `new String()` — разные вещи: у объекта-обёртки переопределены внутренние методы, а примитив хранится в слоте `[[StringData]]`
> - Индексные свойства обёртки не хранятся, а вычисляются операцией `StringGetOwnProperty`
> - Обращение к свойству примитива идёт через `ToObject` с временной обёрткой — отсюда `typeof this` внутри метода различается по режимам
> - `length` считает code unit и является неперезаписываемым
> - `ToString` бросает `TypeError` только для Symbol, причём явный `String(sym)` разрешён специальным исключением
> - `String(number)` выбирает кратчайшее представление, дающее при обратном чтении то же число
> - `\u{...}` появился ради символов вне BMP; `raw` в теговых шаблонах даёт текст до обработки escape
> - Сравнение строк лексикографическое по числовым кодам — без языковых правил и нормализации
> - Методы прототипа обобщённые: работают с любым значением, кроме `null` и `undefined`
