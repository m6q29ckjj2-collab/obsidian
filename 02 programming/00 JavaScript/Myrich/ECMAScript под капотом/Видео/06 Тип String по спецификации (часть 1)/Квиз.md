### 1. Воспроизведите определение типа String и назовите, чего в нём нет

> [!success]- Ответ
> Множество всех конечных упорядоченных последовательностей **нуля или более 16-битных беззнаковых целых значений**. Элемент последовательности называется code unit.
>
> Чего в определении **нет**: ни слова про Unicode, кодировки, символы или валидность. Формально строка — вектор чисел от 0 до 65535.
>
> Интерпретация как UTF-16 добавляется отдельно и не является обязательной: спецификация прямо разрешает строкам не быть well-formed. Иначе нельзя было бы разрезать строку в произвольном месте.

### 2. Что произойдёт в каждом режиме

```js
const s = 'привет';
s[0] = 'П';
console.log(s);
```

> [!success]- Ответ
> В sloppy mode — присваивание молча игнорируется, выводится `'привет'`. В strict mode — `TypeError: Cannot assign to read only property '0'`.
>
> Строки неизменяемы: это свойство **типа**, а не оптимизация движка. Именно оно позволяет безопасно разделять содержимое между значениями и делает возможными rope-структуры и интернирование.

### 3. Объясните каждый результат

```js
const p = 'текст';
const w = new String('текст');

console.log(typeof p, typeof w);
console.log(p === w);
console.log(p == w);
```

> [!success]- Ответ
> `'string' 'object'`, `false`, `true`.
>
> Примитив и объект-обёртка — разные значения разных типов. Строгое равенство сравнивает типы и потому ложно.
>
> Нестрогое равенство при сравнении примитива с объектом применяет `ToPrimitive` к объекту, получает ту же строку и даёт `true`. Сам примитив лежит в слоте `[[StringData]]` обёртки.

### 4. Что вернут эти вызовы и почему обёртка — экзотический объект

```js
const w = new String('абв');
console.log(Object.getOwnPropertyNames(w));
console.log(Object.getOwnPropertyDescriptor(w, '0'));
console.log(Object.getOwnPropertyDescriptor(w, 'length'));
```

> [!success]- Ответ
> `['0', '1', '2', 'length']`
> `{ value: 'а', writable: false, enumerable: true, configurable: false }`
> `{ value: 3, writable: false, enumerable: false, configurable: false }`
>
> Обёртка экзотична потому, что у неё переопределены `[[GetOwnProperty]]`, `[[DefineOwnProperty]]` и `[[OwnPropertyKeys]]` — индексы ведут себя как собственные свойства.
>
> Физически они **не хранятся**: операция `StringGetOwnProperty` вычисляет их на лету из `[[StringData]]`. Обратите внимание на различие в `enumerable` между индексами и `length`.

### 5. Почему свойство не сохранилось

```js
const s = 'текст';
s.custom = 'значение';
console.log(s.custom);
```

> [!success]- Ответ
> `undefined`.
>
> У примитива нет свойств. При обращении спецификация вызывает `ToObject`, создаёт **временную** обёртку, записывает в неё свойство и тут же её выбрасывает. При чтении создаётся новая обёртка, ничего не знающая о предыдущей.
>
> В strict mode запись вообще бросит `TypeError`. Движки этот путь оптимизируют и реальный объект обычно не материализуют, но семантика именно такая.

### 6. Почему результаты различаются

```js
String.prototype.a = function () { return typeof this; };
String.prototype.b = function () { 'use strict'; return typeof this; };
console.log('текст'.a(), 'текст'.b());
```

> [!success]- Ответ
> `'object' 'string'`.
>
> В нестрогом режиме `OrdinaryCallBindThis` пропускает примитив через `ToObject` и передаёт обёртку. В строгом — передаёт значение как есть.
>
> Отсюда правило для авторов библиотек: методы, работающие со строками, стоит писать в strict mode, иначе `this` неожиданно оказывается объектом.

### 7. Что вернёт каждое преобразование

```js
console.log(String(null), String(undefined), String(123n));
console.log(String(Symbol('s')));
console.log(Symbol('s') + '');
```

> [!success]- Ответ
> `'null' 'undefined' '123'`, затем `'Symbol(s)'`, затем `TypeError`.
>
> BigInt теряет суффикс `n`. Symbol — **единственный** тип, на котором `ToString` бросает исключение.
>
> Тонкость в последних двух строках: явный вызов `String(sym)` разрешён специальным исключением из общего правила, а неявное преобразование через конкатенацию или шаблонный литерал запрещено. Сделано это ради отладки — иначе символ нельзя было бы просто напечатать.

### 8. Объясните вывод

```js
console.log(String(0.1 + 0.2));
console.log(String(1e20), String(1e21));
console.log(String(-0));
```

> [!success]- Ответ
> `'0.30000000000000004'`, `'100000000000000000000'` и `'1e+21'`, `'0'`.
>
> Алгоритм выбирает **кратчайшее** десятичное представление, которое при обратном чтении даёт ровно то же число. Для суммы `0.1 + 0.2` более короткая запись изменила бы значение — поэтому все семнадцать знаков.
>
> Порог перехода к экспоненциальной форме — `1e21`. Знак нуля при преобразовании теряется; отличить `-0` можно только через `Object.is(x, -0)` или `1 / x === -Infinity`.

### 9. Чем различаются эти записи

```js
console.log('\u0041');
console.log('\u{1D4B3}');
console.log('\uD835\uDCB3' === '\u{1D4B3}');
```

> [!success]- Ответ
> `'A'`, `'𝒳'`, `true`.
>
> Форма `\uXXXX` кодирует ровно **одну** 16-битную единицу и принимает ровно четыре шестнадцатеричные цифры. Символ вне BMP приходилось задавать двумя такими escape подряд — по одной на каждый суррогат.
>
> Форма `\u{...}` из ES6 принимает любое число цифр и задаёт code point целиком, самостоятельно разворачиваясь в суррогатную пару. Результат идентичен — это одна и та же строка.

### 10. Что выведет теговый шаблон

```js
const tag = (strings) => [strings[0], strings.raw[0]];
console.log(tag`a\nb`);
console.log(String.raw`C:\новая\папка`);
```

> [!success]- Ответ
> Первый вызов даёт массив из двух элементов: строку с настоящим переносом строки и строку `'a\\nb'` — то есть с буквальными символами обратного слэша и `n`.
>
> Второй выводит `'C:\новая\папка'` без изменений.
>
> Свойство `raw` содержит текст **до** обработки escape-последовательностей. На нём построен `String.raw`, удобный для путей Windows, регулярных выражений и любых строк, где обратный слэш значим.

### 11. Объясните порядок

```js
console.log('Z' < 'a');
console.log('ё' < 'я');
console.log('10' < '9');
console.log(['ёж', 'яблоко', 'арбуз'].sort());
```

> [!success]- Ответ
> `true`, `false`, `true`, `['арбуз', 'яблоко', 'ёж']`.
>
> Операция `IsLessThan` сравнивает строки лексикографически по **числовым значениям code unit**. Никаких языковых правил, регистра или нормализации.
>
> `Z` (`0x5A`) меньше `a` (`0x61`) — все заглавные латинские идут раньше строчных. `ё` (`0x451`) больше `я` (`0x44F`), потому что буква вынесена за основной кириллический блок. `'10' < '9'` истинно, так как посимвольно `'1'` меньше `'9'`.
>
> Вывод: стандартная сортировка строк почти всегда неверна для естественного языка. Правильный инструмент — `Intl.Collator`.

### 12. Почему это работает и где предел

```js
console.log(String.prototype.toUpperCase.call(123));
console.log(String.prototype.charAt.call(true, 0));
String.prototype.trim.call(null);
```

> [!success]- Ответ
> `'123'`, `'t'`, затем `TypeError`.
>
> Большинство методов `String.prototype` начинаются с `RequireObjectCoercible` и `ToString`, а не с проверки типа. Поэтому они принимают любое значение и приводят его к строке: `123` → `'123'`, `true` → `'true'`.
>
> Предел — `null` и `undefined`: на них падает `RequireObjectCoercible`. Практический вывод: методы не защищают от неверного типа, и проверка лежит на вызывающем коде.
