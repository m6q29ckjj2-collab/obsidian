> [!question] Как спецификация определяет тип String?
> a) последовательность символов Unicode
> b) последовательность 16-битных беззнаковых целых
> c) массив байтов в кодировке UTF-8
> d) последовательность code point
>> [!success]- Answer
>> b) последовательность 16-битных беззнаковых целых
>> В определении нет ни слова про Unicode, символы или валидность. Формально это вектор чисел от нуля до 65535

> [!question] Строка обязана быть корректно оформленным UTF-16
>> [!success]- Answer
>> False
>> Спецификация это прямо оговаривает. Иначе строку нельзя было бы разрезать в произвольном месте

> [!question] Что вернут эти два выражения?
> ```js
> console.log(typeof 'текст', typeof new String('текст'));
> ```
> a) `'string' 'string'`
> b) `'string' 'object'`
> c) `'object' 'object'`
> d) `'string' 'function'`
>> [!success]- Answer
>> b) `'string' 'object'`
>> Примитив и объект-обёртка — значения разных типов. Строгое равенство между ними ложно, нестрогое истинно из-за ToPrimitive

> [!question] В каком внутреннем слоте объекта-обёртки лежит сам примитив?
>> [!success]- Answer
>> StringData
>> Индексные свойства обёртки при этом не хранятся, а вычисляются на лету операцией StringGetOwnProperty

> [!question] Индексные свойства объекта-обёртки перечисляемы
>> [!success]- Answer
>> True
>> У них enumerable истинно, а writable и configurable ложны. У свойства length, наоборот, enumerable ложно

> [!question] Почему свойство не сохранилось?
> ```js
> const s = 'текст';
> s.custom = 'значение';
> console.log(s.custom);
> ```
> a) примитивы неизменяемы, запись игнорируется полностью
> b) создаётся временная обёртка, которая тут же выбрасывается
> c) свойство попадает в String.prototype
> d) свойство сохранилось, вывод покажет значение
>> [!success]- Answer
>> b) создаётся временная обёртка, которая тут же выбрасывается
>> Обращение к свойству примитива идёт через ToObject. При чтении создаётся новая обёртка, ничего не знающая о предыдущей

> [!question] Что вернёт `typeof this` внутри метода `String.prototype` в строгом режиме?
> a) `'object'`
> b) `'string'`
> c) `'undefined'`
> d) `'function'`
>> [!success]- Answer
>> b) `'string'`
>> В строгом режиме примитив передаётся как есть. В нестрогом он проходит через ToObject и даёт object — поэтому методы для строк пишут в строгом режиме

> [!question] Какое преобразование Symbol в строку разрешено?
> a) любое, Symbol свободно приводится к строке
> b) только неявное, через конкатенацию
> c) только явный вызов `String(sym)`
> d) никакое, оба варианта бросают
>> [!success]- Answer
>> c) только явный вызов `String(sym)`
>> Разрешён специальным исключением из правила, ради отладки. Неявное преобразование через конкатенацию или шаблон бросает TypeError

> [!question] Что вернёт `String(-0)`?
>> [!success]- Answer
>> 0
>> Знак нуля при преобразовании теряется. Отличить его можно только через Object.is или делением: единица на минус ноль даёт минус бесконечность

> [!question] С какого значения число переходит в экспоненциальную запись?
> a) `1e15`
> b) `1e18`
> c) `1e21`
> d) `Number.MAX_SAFE_INTEGER`
>> [!success]- Answer
>> c) `1e21`
>> Значение 1e20 выводится полной записью, 1e21 — уже как экспонента. Алгоритм всегда выбирает кратчайшее представление, дающее при чтении то же число

> [!question] Запись `'𝒳'` и запись `'\u{1D4B3}'` дают идентичные строки
>> [!success]- Answer
>> True
>> Форма с фигурными скобками сама разворачивается в суррогатную пару. Она появилась в ES6 именно ради символов вне BMP

> [!question] Что вернёт сравнение?
> ```js
> console.log('Z' < 'a');
> ```
> a) `true`
> b) `false`
> c) `undefined`
> d) `TypeError`
>> [!success]- Answer
>> a) `true`
>> Сравнение лексикографическое по числовым кодам. Все заглавные латинские идут раньше строчных, потому что их коды меньше

> [!question] Для каких значений методы `String.prototype` выбрасывают исключение?
> a) для чисел и булевых значений
> b) только для `null` и `undefined`
> c) для всех значений, кроме строк
> d) ни для каких
>> [!success]- Answer
>> b) только для `null` и `undefined`
>> Методы начинаются с RequireObjectCoercible и ToString, поэтому принимают числа, булевы значения и массивы, приводя их к строке

> [!question] Проверку «значение не является null или undefined» выполняет операция `___`
>> [!success]- Answer
>> RequireObjectCoercible
>> С неё начинается большинство методов прототипа. Практический вывод: от неверного типа они не защищают, это забота вызывающего кода

> [!question] Что даёт свойство `raw` в теговом шаблоне?
> a) строку с уже обработанными escape-последовательностями
> b) текст до обработки escape-последовательностей
> c) массив подставленных значений
> d) исходный код всего шаблона
>> [!success]- Answer
>> b) текст до обработки escape-последовательностей
>> На нём построен String.raw, удобный для путей Windows и регулярных выражений, где обратный слэш значим
