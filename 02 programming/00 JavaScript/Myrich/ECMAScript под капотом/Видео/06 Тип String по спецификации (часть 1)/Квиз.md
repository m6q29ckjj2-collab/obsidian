> [!question] Что выведет код?
> ```js
> const p = 'текст', w = new String('текст');
> console.log(typeof p, typeof w, p === w, p == w);
> ```
> a) `string object false true`
> b) `string string true true`
> c) `string object true true`
> d) `string object false false`
>> [!success]- Answer
>> a) `string object false true`
>> Строгое равенство сравнивает типы. Нестрогое приводит объект к примитиву и получает ту же строку

> [!question] Что выведет код?
> ```js
> const w = new String('абв');
> console.log(Object.getOwnPropertyNames(w));
> ```
> a) `['length']`
> b) `['0','1','2']`
> c) `['0','1','2','length']`
> d) `[]`
>> [!success]- Answer
>> c) `['0','1','2','length']`
>> Индексы ведут себя как собственные свойства, хотя физически не хранятся — они вычисляются на лету

> [!question] Что выведет код?

> a) `true true true`
> b) `false true false`

>> [!success]- Answer
>> b) `false true false`

> [!question] Что выведет код?

> a) `значение`

>> [!success]- Answer
>> b) `undefined`

> [!question] Что выведет код?

> a) `Привет`

>> [!success]- Answer
>> b) `привет`

> [!question] Что выведет код?
> ```js
> const s = 'абв';
> s.length = 10;
> console.log(s.length);
> ```
> a) `10`
> b) `3`
> c) `0`
> d) `TypeError`
>> [!success]- Answer
>> b) `3`
>> Свойство длины неперезаписываемо. В обычном скрипте запись молча игнорируется, а в модуле ESM или теле класса бросает исключение — там строгий режим включён по определению

> [!question] Что выведет код в строгом режиме?
> ```js
> 'use strict';
> String.prototype.check = function () { return typeof this; };
> console.log('текст'.check());
> ```
> a) `object`
> b) `string`
> c) `undefined`
> d) `function`
>> [!success]- Answer
>> b) `string`
>> В строгом режиме примитив передаётся как есть. В нестрогом он проходит приведение к объекту и даёт другой результат

>> c) выбросит `TypeError`

> [!question] Что выведет код?

> [!question] Что выведет код?

> ```
> a) `true true true`
> b) `true false true`

> [!question] Как спецификация определяет тип String?
> a) последовательность символов Unicode
> b) последовательность 16-битных беззнаковых целых
> c) массив байтов в кодировке UTF-8
> d) последовательность code point
>> [!success]- Answer
>> b) последовательность 16-битных беззнаковых целых
>> В определении нет ни Unicode, ни символов, ни требования валидности

> [!question] Строка обязана быть корректно оформленным UTF-16
>> [!success]- Answer
>> False
>> Спецификация это прямо оговаривает, иначе строку нельзя было бы разрезать в произвольном месте

> [!question] В каком внутреннем слоте объекта-обёртки лежит сам примитив?
>> [!success]- Answer
>> StringData
>> Индексные свойства при этом не хранятся, а вычисляются операцией StringGetOwnProperty

> [!question] Проверку «значение не является null или undefined» выполняет операция `___`
>> [!success]- Answer
>> RequireObjectCoercible
>> С неё начинается большинство методов прототипа. От неверного типа они не защищают — это забота вызывающего кода
