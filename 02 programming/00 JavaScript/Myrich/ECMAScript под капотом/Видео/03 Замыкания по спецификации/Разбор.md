### 1. Через какие два механизма спецификации реализуется то, что называют замыканием

> [!success]- Ответ
> Термина «замыкание» в ECMA-262 нет. Работают два слота:
>
> 1. **`[[Environment]]`** у функционального объекта — заполняется в `OrdinaryFunctionCreate` текущим окружением на момент создания функции
> 2. **`[[OuterEnv]]`** у записи окружения — указатель на родительскую запись
>
> Разрешение имени (`GetIdentifierReference`) идёт по этой цепочке до первого совпадения. Специального механизма «захвата переменных» в языке нет.

### 2. Что выведет код

```js
function counter() {
  let count = 0;
  return {
    inc: () => ++count,
    get: () => count,
  };
}
const c = counter();
c.inc(); c.inc();
console.log(c.get(), c.count);
```

> [!success]- Ответ
> `2 undefined`
>
> Обе функции разделяют **одну** запись окружения, поэтому изменение через `inc` видно из `get`. Если бы захватывалось значение, счётчик был бы невозможен.
>
> `c.count` равно `undefined`, потому что `count` — переменная в записи окружения, а не свойство возвращённого объекта. На этом и стоит приватность.

### 3. Почему результаты различаются и какая операция за это отвечает

```js
const a = [], b = [];
for (var i = 0; i < 3; i++) a.push(() => i);
for (let j = 0; j < 3; j++) b.push(() => j);
```

> [!success]- Ответ
> `[3, 3, 3]` и `[0, 1, 2]`.
>
> Отвечает операция **`CreatePerIterationEnvironment`**: для цикла с лексическим объявлением спецификация предписывает создавать новую запись окружения перед первой итерацией и затем перед каждым инкрементом, копируя туда текущие значения.
>
> Важно, что дело **не в природе `let`**, а в специальном правиле для цикла. У `var` окружение одно на всю функцию, и все замыкания видят финальное значение.

### 4. Почему здесь `const` не мешает

```js
const fns = [];
for (const v of [1, 2, 3]) fns.push(() => v);
console.log(fns.map(f => f()));
```

> [!success]- Ответ
> `[1, 2, 3]`
>
> В `for...of` новая запись окружения создаётся на каждой итерации **по построению** — переменная не переприсваивается, а создаётся заново. Поэтому `const` допустим, а замыкания получают разные значения.
>
> В классическом `for(;;)` с `const` был бы `TypeError` при инкременте.

### 5. Что произойдёт с 50 МБ и почему

```js
function make() {
  const huge = new Uint8Array(50 * 1024 * 1024);
  const usesHuge  = () => huge.length;
  const usesSmall = () => 42;
  return usesSmall;
}
const f = make();
```

> [!success]- Ответ
> Останутся в памяти, пока жива `f`.
>
> V8 кладёт в Context только захваченные переменные, но **Context один на область видимости**. `usesHuge` затягивает `huge` в общий контекст, а `usesSmall` этот же контекст разделяет.
>
> Не спасает и то, что `usesHuge` наружу не отдана: она существовала в момент создания контекста, и этого достаточно.
>
> Изоляция — вычислить нужное в IIFE, чтобы крупный объект не пережил свою область.

### 6. Как отличить утечку через замыкание от обычной ссылки

> [!success]- Ответ
> DevTools → **Memory** → Heap snapshot, найти крупный объект, открыть **Retainers**. Если в цепочке удержания присутствует `system / Context`, объект держится замыканием.
>
> Обычная ссылка выглядит в цепочке как свойство объекта или элемент массива.
>
> Дополнительный инструмент — **Allocation instrumentation on timeline**: показывает, какие аллокации пережили сборку мусора.

### 7. Почему `with` запрещён в строгом режиме

> [!success]- Ответ
> `with` создаёт **Object Environment Record**, в которой поиск имени превращается в `HasProperty` на объекте — включая всю прототипную цепочку.
>
> Разрешение имён становится динамическим: до выполнения невозможно сказать, обращается идентификатор к локальной переменной или к свойству объекта. Это ломает статический анализ, минификацию и оптимизации движка.

### 8. Что выведет код

```js
var viaVar = 1;
let viaLet = 2;
console.log(globalThis.viaVar, globalThis.viaLet);
console.log(delete globalThis.viaVar);
```

> [!success]- Ответ
> `1 undefined`, затем `false`.
>
> Global Environment Record — **гибрид**. `var` и функциональные декларации уходят в объектную часть и становятся свойствами `globalThis`; `let`, `const` и `class` — в декларативную, снаружи невидимую.
>
> `delete` возвращает `false`, потому что `CreateGlobalVarBinding` создаёт свойство с `[[Configurable]]: false`. Свойство, созданное присваиванием без объявления, удалить можно.

### 9. Будет ли доступна `err` после блока

```js
try { throw new Error('сбой'); }
catch (err) { console.log(err.message); }
console.log(err);
```

> [!success]- Ответ
> `сбой`, затем `ReferenceError: err is not defined`.
>
> Привязка `catch` живёт в собственной Declarative Environment Record, существующей только на время блока.
>
> С ES2019 привязку можно вовсе опустить, если объект ошибки не нужен: `try { ... } catch { ... }`.

### 10. Какой из вариантов приватности предпочтительнее и почему

```js
// A
function createA(initial) {
  let balance = initial;
  return { get: () => balance, add(v) { balance += v; } };
}

// B
class B {
  #balance;
  constructor(initial) { this.#balance = initial; }
  get() { return this.#balance; }
  add(v) { this.#balance += v; }
}
```

> [!success]- Ответ
> Оба дают настоящую приватность, но **B экономнее**.
>
> В варианте A на каждый экземпляр создаётся по новому функциональному объекту для каждого метода — они не переиспользуются. В варианте B методы лежат в `B.prototype` в единственном экземпляре, а приватное поле хранится в слоте объекта.
>
> Вариант A оправдан, когда объектов немного, а фабричная функция удобнее синтаксически.

### 11. Найдите проблему

```js
function memoize(fn) {
  const cache = new Map();
  return (...args) => {
    const key = JSON.stringify(args);
    if (!cache.has(key)) cache.set(key, fn(...args));
    return cache.get(key);
  };
}
```

> [!success]- Ответ
> `Map` в замыкании **не имеет вытеснения** и растёт неограниченно. При большом разнообразии аргументов это прямая утечка памяти, живущая столько же, сколько мемоизированная функция.
>
> Дополнительно: `JSON.stringify` как ключ не различает `undefined` и отсутствующий аргумент, теряет функции и символы, а на циклических структурах бросает исключение.
>
> Решения: лимит размера с вытеснением по LRU, либо `WeakMap` при объектных ключах, либо готовая реализация.

### 12. Что попадёт в контекст и когда возникнет утечка

```js
function attach(element) {
  const bigData = new Array(1e6).fill('данные');
  element.addEventListener('click', () => console.log('клик'));
}
```

> [!success]- Ответ
> В текущем виде `bigData` в контекст **не попадёт** — обработчик её не захватывает, а V8 кладёт в Context только захваченное.
>
> Утечка появится, если в обработчике появится обращение к `bigData` — тогда массив будет жить, пока элемент в DOM и слушатель не снят.
>
> Отдельный сценарий: элемент удалён из DOM, но ссылка на него осталась, а слушатель не снят — тогда недостижимыми не станут ни элемент, ни захваченные обработчиком данные.
