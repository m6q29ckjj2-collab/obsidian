## Механика

Есть ли в спецификации термин «замыкание»::==Нет==. Есть слот `[[Environment]]` у функции и указатель `[[OuterEnv]]` у записи окружения — замыкание получается как следствие

В каком слоте функции хранится захваченное окружение::`[[Environment]]` — заполняется операцией `OrdinaryFunctionCreate` в момент создания функции

Как называется операция разрешения имени::`GetIdentifierReference` — проверить текущую запись, при отсутствии перейти по `[[OuterEnv]]`, при исчерпании бросить `ReferenceError`

Замыкание захватывает значение или окружение::==Запись окружения целиком==. Поэтому видны все последующие изменения переменных

Что выведет код
?
```js
let shared = 'до';
const read = () => shared;
shared = 'после';
console.log(read());
```
`'после'`. Захвачена запись окружения, а не снимок значения

## Виды Environment Record

Перечислите пять видов записи окружения::Declarative, Object, Function, Global, Module

Что хранит Declarative Environment Record::`let`, `const`, `class`, параметры функции, привязку `catch`

Чем Function ER отличается от Declarative::Добавляет слоты `[[ThisValue]]`, `[[NewTarget]]`, `[[FunctionObject]]`, `[[ThisBindingStatus]]`

Что особенного в Module Environment Record::Declarative плюс ==индирект-биндинги== на импортируемые значения

Какую запись создаёт `with`::==Object Environment Record== — поиск имени превращается в `HasProperty` на объекте

Почему `with` запрещён в strict mode::Делает разрешение имён динамическим и убивает статический анализ. Участвует даже прототипная цепочка объекта

---

## Глобальное окружение

Из чего состоит Global Environment Record::==Гибрид== Declarative и Object части

Что попадает в объектную часть глобального окружения::`var` и функциональные декларации — становятся свойствами `globalThis`

Что попадает в декларативную часть::`let`, `const`, `class` — снаружи через `globalThis` не видны

Почему `delete globalThis.someVar` возвращает `false`::`CreateGlobalVarBinding` создаёт свойство с ==`[[Configurable]]: false`==. Свойство от присваивания без объявления удалить можно

## Циклы

Какая операция делает `let` в цикле «правильным»::==`CreatePerIterationEnvironment`== — новая запись окружения перед каждой итерацией с копией текущих значений

Что выведет код
?
```js
const a = [], b = [];
for (var i = 0; i < 3; i++) a.push(() => i);
for (let j = 0; j < 3; j++) b.push(() => j);
console.log(a.map(f => f()), b.map(f => f()));
```
`[3, 3, 3]` и `[0, 1, 2]`

В какой момент создаётся новая запись при `let` в цикле::Перед первой итерацией и затем ==перед каждым инкрементом==, с копированием текущих значений

Как добивались того же эффекта до появления `let`
?
IIFE с передачей копии параметром:
```js
for (var k = 0; k < 3; k++) {
  (function (copy) { arr.push(() => copy); })(k);
}
```

Почему в `for...of` даже с `const` замыкания корректны::Новая запись окружения создаётся на каждой итерации ==по построению== цикла

Создаёт ли обычный блок `{}` запись окружения::Да, при наличии лексических объявлений — через `BlockDeclarationInstantiation`. `var` при этом уходит в VariableEnvironment функции

## Память и утечки

Сколько Context создаёт V8 на область видимости::==Один==, и кладёт туда только те переменные, которые кем-то захвачены

Почему функция может удерживать объект, который не использует
?
Context ==один на область==. Если крупный объект захвачен любой другой функцией той же области, он попадает в общий Context и живёт, пока жива хоть одна функция оттуда.

Что выведет анализ памяти для этого кода
?
```js
function make() {
  const huge = new Uint8Array(50 * 1024 * 1024);
  const usesHuge = () => huge.length;
  const small = () => 42;
  return small;
}
```
50 МБ останутся живы, пока жива возвращённая `small` — `usesHuge` затянула `huge` в общий Context

Как изолировать крупный объект от замыкания
?
Вычислить нужное в IIFE, чтобы объект не пережил свою область:
```js
const size = (() => {
  const huge = new Uint8Array(1e6);
  return huge.length;
})();
```

Как опознать утечку через замыкание в DevTools::Heap snapshot → Retainers. Если в цепочке удержания стоит ==`system / Context`==, объект держит замыкание, а не структура данных

## Паттерны

На чём стоит приватное состояние в функциональном стиле::На захваченной переменной, недоступной снаружи — она не становится свойством возвращаемого объекта

Чем приватные поля класса лучше замыкания для приватности::Не требуют отдельного функционального объекта на каждый метод и каждый экземпляр — экономия памяти

В чём опасность мемоизации через замыкание::`Map` в замыкании ==не имеет вытеснения== и растёт неограниченно. Нужен лимит размера, `WeakMap` или готовый LRU

Как каррирование использует замыкания::Каждый промежуточный вызов создаёт замыкание с накопленными аргументами и возвращает функцию, ожидающую остальные
