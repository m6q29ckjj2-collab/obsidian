> [!question] Что выведет код?
> ```js
> const a = [], b = [];
> for (var i = 0; i < 3; i++) a.push(() => i);
> for (let j = 0; j < 3; j++) b.push(() => j);
> console.log(a.map(f => f()), b.map(f => f()));
> ```
> a) `[0,1,2]` и `[0,1,2]`
> b) `[3,3,3]` и `[0,1,2]`
> c) `[0,1,2]` и `[3,3,3]`
> d) `[3,3,3]` и `[3,3,3]`
>> [!success]- Answer
>> b) `[3,3,3]` и `[0,1,2]`
>> У var окружение одно на функцию, все замыкания видят финальное значение. Для let спецификация создаёт новую запись окружения на каждой итерации

> [!question] Как называется операция, создающая новую запись окружения на каждой итерации цикла с лексическим объявлением?
>> [!success]- Answer
>> CreatePerIterationEnvironment
>> Ключевой момент: дело не в природе let, а в специальном правиле для цикла. Значения копируются в свежую запись перед каждым инкрементом

> [!question] Замыкание запоминает значения переменных на момент своего создания
>> [!success]- Answer
>> False
>> Захватывается запись окружения целиком, поэтому видны все последующие изменения. Без этого свойства были бы невозможны счётчики и приватное состояние

> [!question] Термин «замыкание» определён в тексте ECMA-262
>> [!success]- Answer
>> False
>> Есть слот `Environment` у функционального объекта и указатель `OuterEnv` у записи окружения. Замыкание получается как следствие этих двух механизмов

> [!question] Сколько объектов Context выделяет V8 на одну область видимости?
> a) по одному на каждую захваченную переменную
> b) один на область, только с захваченными переменными
> c) один на функцию, со всеми переменными
> d) ни одного, всё лежит в стеке
>> [!success]- Answer
>> b) один на область, только с захваченными переменными
>> Отсюда неочевидное следствие: функция удерживает всё, что захвачено любой другой функцией той же области

> [!question] Останутся ли 50 МБ в памяти, пока жива `f`?
> ```js
> function make() {
>   const huge = new Uint8Array(50 * 1024 * 1024);
>   const usesHuge  = () => huge.length;
>   const usesSmall = () => 42;
>   return usesSmall;
> }
> const f = make();
> ```
> a) нет, вернули функцию, не использующую `huge`
> b) да, из-за общего Context области
> c) нет, сборщик мусора соберёт сразу
> d) зависит от размера массива
>> [!success]- Answer
>> b) да, из-за общего Context области
>> usesHuge затянула huge в контекст, а usesSmall этот контекст разделяет. Не спасает и то, что usesHuge наружу не отдана

> [!question] Что нужно увидеть в цепочке Retainers heap snapshot, чтобы опознать удержание замыканием?
>> [!success]- Answer
>> system / Context
>> Обычная ссылка выглядит в цепочке как свойство объекта или элемент массива

> [!question] Конструкция `with` запрещена в строгом режиме
>> [!success]- Answer
>> True
>> Она создаёт Object Environment Record, где поиск имени превращается в HasProperty на объекте вместе с прототипной цепочкой. Разрешение имён становится динамическим

> [!question] Как изолировать крупный объект, чтобы он не попал в общий Context области?
> a) объявить его через `var` вместо `const`
> b) обнулить переменную в конце функции
> c) вычислить нужное внутри IIFE, чтобы объект не пережил свою область
> d) обернуть объект в `WeakRef`
>> [!success]- Answer
>> c) вычислить нужное внутри IIFE, чтобы объект не пережил свою область
>> Обнуление не помогает, если объект уже захвачен другой функцией той же области: контекст один, и он держит всё захваченное. Нужно, чтобы объект физически жил в другой области видимости

> [!question] Окружение, захваченное при создании функции, хранится в слоте `___`
>> [!success]- Answer
>> Environment
>> Заполняется операцией OrdinaryFunctionCreate. Разрешение имени идёт оттуда по цепочке `OuterEnv`

> [!question] В цикле `for...of` использование `const` даёт корректные замыкания
>> [!success]- Answer
>> True
>> Новая запись окружения создаётся на каждой итерации по построению цикла — переменная не переприсваивается, а создаётся заново

> [!question] Что вернёт `delete globalThis.someVar` для переменной, объявленной как `var someVar = 1` на верхнем уровне?
> a) `true`, свойство удалится
> b) `false`, свойство останется
> c) `undefined`
> d) `TypeError` в любом режиме
>> [!success]- Answer
>> b) `false`, свойство останется
>> CreateGlobalVarBinding создаёт свойство с configurable false. Свойство, созданное простым присваиванием, удаляется нормально

> [!question] Будет ли доступна переменная привязки `catch` после выхода из блока?
> a) да, она попадает в область функции
> b) нет, у неё своя запись окружения
> c) да, если объявлена через var
> d) только в нестрогом режиме
>> [!success]- Answer
>> b) нет, у неё своя запись окружения
>> Привязка catch живёт в отдельной Declarative Environment Record на время блока. С ES2019 её можно вовсе опустить, если объект ошибки не нужен

> [!question] Какой вид записи окружения хранит слот `ThisValue`?
> a) Declarative
> b) Object
> c) Function
> d) Module
>> [!success]- Answer
>> c) Function
>> Function Environment Record — это Declarative плюс слоты `ThisValue`, `NewTarget`, `FunctionObject` и `ThisBindingStatus`

> [!question] Чем опасна мемоизация через `Map` в замыкании?
> a) Map не умеет хранить объекты
> b) кэш растёт неограниченно, вытеснения нет
> c) замыкание не сохраняет Map между вызовами
> d) ключи теряются при сборке мусора
>> [!success]- Answer
>> b) кэш растёт неограниченно, вытеснения нет
>> При большом разнообразии аргументов это прямая утечка, живущая столько же, сколько мемоизированная функция. Нужен лимит размера, WeakMap или готовый LRU
