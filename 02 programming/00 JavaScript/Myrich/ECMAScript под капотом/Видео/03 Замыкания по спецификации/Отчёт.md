## 1. Термина «замыкание» в спецификации нет

В ECMA-262 не найти определения closure. Есть две механики, из которых замыкание получается как побочный эффект:

1. У функционального объекта есть внутренний слот **`[[Environment]]`**, куда при создании записывается текущее окружение
2. У каждой записи окружения есть указатель **`[[OuterEnv]]`** на родительскую

Функция плюс её `[[Environment]]` — это и есть то, что называют замыканием. Никакого специального механизма «захвата переменных» язык не содержит.

```js
function outer() {
  const captured = 'значение';
  return function inner() { return captured; }; // [[Environment]] = окружение outer
}
```

При вычислении выражения `function inner...` работает операция `OrdinaryFunctionCreate`, которая получает третьим аргументом текущее окружение и кладёт его в слот. Всё.

## 2. Виды Environment Record

| Вид | Что хранит |
|---|---|
| **Declarative** | `let`, `const`, `class`, параметры, привязка `catch` |
| **Object** | биндинги как свойства объекта — глобальный `var` и `with` |
| **Function** | Declarative плюс `[[ThisValue]]`, `[[NewTarget]]`, `[[FunctionObject]]` |
| **Global** | гибрид Declarative и Object |
| **Module** | Declarative плюс индирект-биндинги на импорты |

Разрешение имени — операция `GetIdentifierReference`: проверить текущую запись, при отсутствии перейти по `[[OuterEnv]]`, при исчерпании цепочки бросить `ReferenceError`.

### Object Environment Record и `with`

```js
const scope = { hidden: 'из объекта' };

with (scope) {
  console.log(hidden); // 'из объекта' — Object ER поверх scope
}
```

`with` создаёт Object Environment Record, где поиск имени превращается в `HasProperty` на объекте. Именно поэтому конструкция запрещена в strict mode: она делает разрешение имён динамическим и убивает статический анализ.

```js
// коварство: прототипная цепочка тоже участвует
const obj = Object.create({ toString: () => 'из прототипа' });
with (obj) { console.log(toString()); } // 'из прототипа'
```

### Global Environment Record — гибрид

```js
var viaVar = 1;
let viaLet = 2;
function viaFn() {}
class ViaClass {}

console.log(globalThis.viaVar);   // 1
console.log(globalThis.viaFn);    // функция
console.log(globalThis.viaLet);   // undefined
console.log(globalThis.ViaClass); // undefined
```

Глобальное окружение состоит из двух частей. `var` и функциональные декларации идут в **объектную** часть и становятся свойствами `globalThis`; `let`, `const` и `class` — в **декларативную**, невидимую снаружи.

```js
var notDeletable = 1;
console.log(delete globalThis.notDeletable); // false
```

Свойство создаётся операцией `CreateGlobalVarBinding` с флагом `[[Configurable]]: false`, поэтому удалить его нельзя. Свойство, созданное присваиванием без объявления, — можно.

## 3. Захватывается окружение, а не значение

Это центральный тезис темы. Замыкание держит ссылку на **запись окружения целиком**, поэтому видит все последующие изменения переменных.

```js
function counter() {
  let count = 0;
  return {
    increment: () => ++count,
    decrement: () => --count,
    current:   () => count,
  };
}

const c = counter();
c.increment(); c.increment();
console.log(c.current()); // 2
```

Три функции разделяют **одну** запись окружения — поэтому изменение через одну видно через остальные. Если бы захватывалось значение, счётчик был бы невозможен.

```js
let shared = 'до';
const read = () => shared;
shared = 'после';
console.log(read()); // 'после' — не 'до'
```

## 4. Циклы и per-iteration environment

```js
const byVar = [];
for (var i = 0; i < 3; i++) byVar.push(() => i);
console.log(byVar.map(f => f())); // [3, 3, 3]

const byLet = [];
for (let j = 0; j < 3; j++) byLet.push(() => j);
console.log(byLet.map(f => f())); // [0, 1, 2]
```

Разницу делает не природа `let`, а операция **`CreatePerIterationEnvironment`**, которую спецификация предписывает для цикла с лексическим объявлением:

1. Перед первой итерацией создать запись окружения и скопировать в неё значения
2. Выполнить тело
3. **Перед инкрементом** создать новую запись и скопировать в неё текущие значения
4. Повторить

Поэтому каждое замыкание получает собственную запись со своим снимком значения.

```js
// то же самое вручную, до появления let
const manual = [];
for (var k = 0; k < 3; k++) {
  (function (copy) { manual.push(() => copy); })(k);
}
console.log(manual.map(f => f())); // [0, 1, 2]
```

> [!warning] `for...of` и `for...in` ведут себя иначе
> ```js
> const ofLoop = [];
> for (const v of [1, 2, 3]) ofLoop.push(() => v);
> console.log(ofLoop.map(f => f())); // [1, 2, 3] — даже с const
> ```
> В этих циклах новая запись создаётся на каждой итерации по построению, поэтому `const` допустим и замыкания корректны.

## 5. Блоки тоже создают окружения

```js
{
  let blockScoped = 'внутри';
  var functionScoped = 'протёк';
}
// console.log(blockScoped); // ReferenceError
console.log(functionScoped); // 'протёк'
```

Каждый блок с лексическими объявлениями получает свою Declarative Environment Record через `BlockDeclarationInstantiation`. `var` при этом уходит в VariableEnvironment функции и блоком не ограничивается.

```js
// привязка catch — тоже отдельная запись
try { throw new Error('сбой'); }
catch (err) { console.log(err.message); }
// console.log(err); // ReferenceError
```

```js
// с ES2019 привязку можно опустить, если она не нужна
try { risky(); } catch { console.log('не вышло'); }
```

## 6. Общий контекст и утечки памяти

Практически самая ценная часть темы. V8 не создаёт запись окружения на каждую переменную — он выделяет **один Context на область видимости** и кладёт туда только те переменные, которые кем-то захвачены.

Отсюда неочевидное следствие: функция удерживает всё, что захвачено **любой** функцией той же области.

```js
function makeLeaky() {
  const huge = new Uint8Array(50 * 1024 * 1024); // 50 МБ
  const small = 42;

  const usesHuge  = () => huge.length; // из-за неё huge попадает в Context
  const usesSmall = () => small;

  return usesSmall; // вернули «лёгкую», но Context общий
}

const leak = makeLeaky(); // 50 МБ остаются живы
```

Даже если `usesHuge` наружу не отдана и больше нигде не используется, `huge` уже в контексте, а контекст держится возвращённой функцией.

```js
function makeClean() {
  const small = (() => {
    const huge = new Uint8Array(50 * 1024 * 1024);
    return huge.length;   // huge не переживает свою IIFE
  })();

  return () => small;
}
```

> [!tip] Как найти такую утечку
> DevTools → **Memory** → Heap snapshot. Найдите крупный объект, откройте **Retainers**. Если в цепочке удержания стоит `system / Context`, объект держит замыкание, а не структура данных.
>
> Второй приём — **Allocation instrumentation on timeline**: видно, какие аллокации переживают сборку мусора.

### Классика: обработчики событий

```js
function attach(element) {
  const bigData = new Array(1e6).fill('данные');

  element.addEventListener('click', () => {
    console.log('клик'); // bigData не используется, но...
  });
}
```

Здесь `bigData` в контекст не попадёт — V8 кладёт туда только захваченное. Но стоит добавить `console.log(bigData.length)` в обработчик, и массив будет жить, пока элемент в DOM. А если элемент удалён, но слушатель не снят, недостижимым не станет ни то, ни другое.

## 7. На чём стоят практические паттерны

### Приватное состояние

```js
function createAccount(initial) {
  let balance = initial; // недоступен снаружи

  return {
    deposit(sum) { balance += sum; return this; },
    getBalance() { return balance; },
  };
}

const acc = createAccount(100);
acc.deposit(50);
console.log(acc.getBalance()); // 150
console.log(acc.balance);      // undefined — переменная не является свойством
```

Современная альтернатива — приватные поля класса, и они предпочтительнее: не требуют по функциональному объекту на каждый метод и на каждый экземпляр.

```js
class Account {
  #balance;
  constructor(initial) { this.#balance = initial; }
  deposit(sum) { this.#balance += sum; return this; }
  getBalance() { return this.#balance; }
}
```

### Мемоизация

```js
function memoize(fn) {
  const cache = new Map(); // живёт в замыкании

  return function (...args) {
    const key = JSON.stringify(args);
    if (!cache.has(key)) cache.set(key, fn.apply(this, args));
    return cache.get(key);
  };
}
```

> [!danger] Кэш в замыкании растёт без ограничений
> `Map` внутри `memoize` не имеет вытеснения — при большом разнообразии аргументов это прямая утечка. В production нужен либо лимит размера, либо `WeakMap` с объектными ключами, либо готовая LRU-реализация.

### Каррирование и частичное применение

```js
const curry = fn => function next(...args) {
  return args.length >= fn.length
    ? fn(...args)
    : (...rest) => next(...args, ...rest);
};

const add = curry((a, b, c) => a + b + c);
console.log(add(1)(2)(3)); // 6
console.log(add(1, 2)(3)); // 6
```

Каждый промежуточный вызов создаёт замыкание с накопленными аргументами.

## 8. Итог

> [!success] Что забирать
> - Термина «замыкание» в спецификации нет — есть слот `[[Environment]]` у функции и `[[OuterEnv]]` у записи окружения
> - Пять видов Environment Record; `with` создаёт Object ER и потому запрещён в strict mode
> - Глобальное окружение — гибрид: `var` и функции в объектной части, `let`/`const`/`class` в декларативной
> - Захватывается **запись окружения**, а не значение — на этом стоят счётчики и приватное состояние
> - Поведение `let` в цикле обеспечивает `CreatePerIterationEnvironment`, а не сама природа `let`
> - `for...of` создаёт новую запись на каждой итерации по построению
> - V8 выделяет **один Context на область**; функция удерживает всё, захваченное любой функцией той же области
> - Утечка через замыкание опознаётся в heap snapshot по `system / Context` в цепочке Retainers
