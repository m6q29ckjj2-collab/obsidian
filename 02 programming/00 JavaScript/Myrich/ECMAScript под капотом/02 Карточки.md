## Нотация спецификации

Что означает `?` перед вызовом абстрактной операции в спецификации::Сокращение для `ReturnIfAbrupt` — если операция вернула abrupt completion (`throw`), немедленно пробросить его наружу

Что означает `!` перед вызовом абстрактной операции::Утверждение, что исключение здесь невозможно. Если оно произойдёт — это баг движка или самой спецификации

Из каких полей состоит Completion Record::`[[Type]]` (normal / throw / return / break / continue), `[[Value]]`, `[[Target]]`

Как в спецификации называется то, что в учебниках зовут «hoisting»::Никак. Есть операции инстанцирования: `FunctionDeclarationInstantiation`, `GlobalDeclarationInstantiation`, `BlockDeclarationInstantiation`

Как называется абстрактная операция за «приведением типов»::Их несколько: `ToPrimitive`, `ToNumber`, `ToString`, `ToNumeric`, `ToBoolean`, `ToObject`. Единой операции «приведения» нет

## Контекст исполнения и стек

Какие поля содержит execution context::code evaluation state, Function, Realm, ScriptOrModule, LexicalEnvironment, VariableEnvironment, PrivateEnvironment

Описан ли `RangeError: Maximum call stack size exceeded` в спецификации::==Нет==. Предел глубины стека отдан на усмотрение реализации

Какой движок реализовал proper tail calls::Только ==JavaScriptCore== (Safari). В V8 и SpiderMonkey оптимизация отсутствует, несмотря на наличие в стандарте

Попадают ли коллбэки промисов в стек контекстов исполнения::Нет. Они ставятся в очередь заданий через `HostEnqueuePromiseJob` и выполняются после полного опустошения стека

Что выведет код и почему
?
```js
console.log('1');
setTimeout(() => console.log('4'), 0);
Promise.resolve().then(() => console.log('3'));
console.log('2');
```
`1 2 3 4`. Синхронный код → микрозадачи (промисы) → макрозадачи (таймеры)

## Инстанцирование деклараций

Какое начальное значение получает `var` при инстанцировании::`undefined`

Какое начальное значение получает `function`-декларация::==Готовый функциональный объект== — поэтому её можно вызвать до строки объявления

Какое начальное состояние у `let`, `const` и `class`::*uninitialized* — обращение до инициализации даёт `ReferenceError` (TDZ)

Почему вызов до объявления даёт `TypeError` для `var`-функции, но `ReferenceError` для `let`
?
`TypeError` — биндинг создан и хранит `undefined`, а `undefined` не вызвать.
`ReferenceError` — биндинг создан, но не инициализирован, доступ к нему запрещён.

Единственный случай, когда `typeof` выбрасывает исключение::Обращение к переменной в ==TDZ==. `typeof` необъявленной переменной по-прежнему безопасен и даёт `'undefined'`

Что выведет код в строгом режиме и что без него
?
```js
{ function f() {} }
typeof f;
```
strict — `'undefined'` (строго блочная область).
sloppy — `'function'`, имя протекает в функциональную область по ==Annex B.3.3==

Является ли Annex B обязательным::Формально нормативно-опционален для не-браузерных сред, но в браузерах реализован везде — на практике считать его обязательным

## Environment Records

Перечислите виды Environment Record::Declarative, Object, Function, Global, Module

Чем Function Environment Record отличается от Declarative::Добавляет слоты `[[ThisValue]]`, `[[NewTarget]]`, `[[FunctionObject]]`, `[[ThisBindingStatus]]`

В каком слоте функционального объекта хранится замкнутое окружение::`[[Environment]]` — записывается в момент создания функции

Замыкание захватывает значение переменной или окружение::==Окружение целиком== (Environment Record). Поэтому изменения переменной видны всем замыканиям, разделяющим запись

Какая операция делает `let` в цикле «правильным»::`CreatePerIterationEnvironment` — на каждой итерации создаётся новая запись окружения с копией текущих значений

Что выведет код
?
```js
const a = [], b = [];
for (var i = 0; i < 3; i++) a.push(() => i);
for (let j = 0; j < 3; j++) b.push(() => j);
console.log(a.map(f => f()), b.map(f => f()));
```
`[3, 3, 3]` и `[0, 1, 2]`. У `var` одно окружение на функцию, у `let` — своё на каждую итерацию

Почему замыкание может удерживать объект, который оно не использует
?
Контекст создаётся ==один на область видимости==. Если хотя бы одна функция области захватила крупный объект, он попадает в общий Context и остаётся жив, пока жива любая из функций этой области.

Как в DevTools отличить утечку через замыкание от обычной ссылки::В heap snapshot посмотреть Retainers: у замыкания в цепочке удержания стоит `system / Context`

Почему `var` на верхнем уровне попадает в `globalThis`, а `let` — нет
?
Глобальное окружение — гибрид. `var` и функции идут в ==Object Environment Record== поверх `globalThis`, а `let`/`const`/`class` — в ==Declarative Environment Record==, невидимый снаружи.

Почему нельзя удалить глобальную `var` через `delete`::Свойство создаётся с `[[Configurable]]: false`

## Связывание this

Какая абстрактная операция определяет значение `this`::`ResolveThisBinding`, которая через `GetThisEnvironment` находит ближайший Function Environment Record

Три значения слота `[[ThisBindingStatus]]`::`lexical` (стрелочные функции), `uninitialized` (производный конструктор до `super()`), `initialized`

Что вернёт `this` в обычной функции, вызванной без контекста::strict — ==`undefined`==; sloppy — ==`globalThis`==

Что произойдёт с примитивом, переданным через `call` в нестрогом режиме::Пройдёт через `ToObject` и станет объектом-обёрткой. В строгом режиме останется примитивом

Что выведет код и почему
?
```js
'use strict';
function f() { return this; }
console.log(typeof f.call('текст'));
```
`'string'` — в strict mode `OrdinaryCallBindThis` передаёт примитив как есть. В sloppy было бы `'object'`

Почему оторванный метод класса даёт `TypeError`, а не работает с `globalThis`::Тела классов ==всегда строгие==, поэтому `this` равен `undefined`

Почему обращение к `this` до `super()` даёт `ReferenceError`
?
В производном конструкторе `[[ThisBindingStatus]]` равен `uninitialized`. Слот заполняется операцией `BindThisValue` в момент вызова `super()` — механизм тот же, что у TDZ.

В чём разница между методом класса и полем-стрелкой
?
Метод лежит в ==прототипе== и получает `this` из вызова — теряется при отрыве.
Поле-стрелка создаётся ==заново для каждого экземпляра== и лексически захватывает `this` — переживает отрыв, но стоит памяти.

## Object

Назовите обязательные внутренние методы объекта::`[[GetPrototypeOf]]`, `[[SetPrototypeOf]]`, `[[IsExtensible]]`, `[[PreventExtensions]]`, `[[GetOwnProperty]]`, `[[DefineOwnProperty]]`, `[[HasProperty]]`, `[[Get]]`, `[[Set]]`, `[[Delete]]`, `[[OwnPropertyKeys]]`

Чем ordinary object отличается от exotic::У ordinary все внутренние методы имеют поведение по умолчанию. Exotic переопределяет хотя бы один — массивы, Proxy, `arguments` в sloppy, namespace-объекты модулей

Два вида свойств и их атрибуты
?
**Data property** — `[[Value]]`, `[[Writable]]`, `[[Enumerable]]`, `[[Configurable]]`
**Accessor property** — `[[Get]]`, `[[Set]]`, `[[Enumerable]]`, `[[Configurable]]`

Какие флаги по умолчанию у свойства, созданного через `defineProperty`::Все ==`false`== — в отличие от обычного присваивания, где все `true`

Гарантирован ли порядок ключей объекта::==Да==, операцией `OrdinaryOwnPropertyKeys`

Каков порядок ключей при переборе::1) целочисленные индексы по возрастанию, 2) остальные строки в порядке добавления, 3) символы в порядке добавления

Что вернёт `Reflect.ownKeys({ b: 1, 2: 2, a: 3, 1: 4, '01': 5 })`
?
`['1', '2', 'b', 'a', '01']`
`'01'` не канонический индекс (не совпадает с `ToString(ToNumber('01'))`), поэтому идёт в строковую группу.

Почему Proxy не может соврать про замороженное свойство::Результат ловушки проверяется операцией `ValidateAndApplyPropertyDescriptor`. Для non-configurable non-writable свойства ловушка обязана вернуть исходное значение, иначе `TypeError`

## Преобразования типов

Существует ли в спецификации операция, меняющая тип значения::==Нет==. Значения иммутабельны по типу; абстрактные операции порождают новые значения

Порядок вызова в `OrdinaryToPrimitive` для хинта `string`::`toString` → `valueOf`

Порядок вызова в `OrdinaryToPrimitive` для хинтов `number` и `default`::`valueOf` → `toString`

Какой встроенный тип трактует хинт `default` как `string`::==`Date`==. Поэтому `date + 1` даёт строку, а `date - 1` — число

Опишите алгоритм оператора `+`
?
`ApplyStringOrNumericBinaryOperator`: ==оба== операнда проходят `ToPrimitive` без хинта → если хотя бы один оказался строкой, конкатенация → иначе `ToNumeric` и сложение.

Почему `[] == ![]` даёт `true`
?
`![]` → `ToBoolean([])` это `true` → `false`.
`[] == false` → правый через `ToNumber` даёт `0`.
`[]` через `ToPrimitive` даёт `''`, затем `ToNumber('')` это `0`.
`0 == 0` → `true`.

Почему `null == 0` даёт `false`, хотя `null == undefined` даёт `true`::В `IsLooselyEqual` равенство `null` и `undefined` прописано отдельным шагом, а приведение `null` к числу в алгоритме отсутствует

Почему `1n + 1` бросает `TypeError`, а `1n + '1'` работает::Арифметика требует одинаковой числовой природы обоих операндов. Строковый путь идёт через конкатенацию и ограничения не имеет

Что особенного у `document.all`::Внутренний слот `[[IsHTMLDDA]]`, закреплённый в стандарте ради веб-совместимости: `document.all == null` истинно, `typeof` даёт `'undefined'`, в булевом контексте ложен

## Тип String

Как спецификация определяет тип String::Конечная упорядоченная последовательность ==16-битных беззнаковых целых==. Не символов и не обязательно валидный UTF-16

Три разных «длины» строки
?
**code unit** — `str.length`
**code point** — `[...str].length`
**графемный кластер** — `Intl.Segmenter` с `granularity: 'grapheme'`

Чему равны `'𝒳'.length` и `[...'𝒳'].length`::`2` и `1` — символ вне BMP занимает суррогатную пару

Почему `'é' === 'é'` может быть `false`::Разные нормализационные формы: U+00E9 против `e` + combining acute. Сравнение строк побитовое по code unit, нормализации нет

Как корректно развернуть строку с эмодзи::`[...str].reverse().join('')` — спред идёт по code point. `split('')` разрушает суррогатные пары

Может ли строка содержать непарный суррогат::==Да==. Проверка — `isWellFormed()` (ES2024), починка — `toWellFormed()`

Что произойдёт при `encodeURIComponent('\uD800')`::`URIError: URI malformed` — одиночный суррогат нельзя закодировать в UTF-8

Почему `['я', 'ё', 'а'].sort()` даёт неверный порядок::Сортировка лексикографична по числовым кодам code unit. Для естественного языка нужен `Intl.Collator`

## NaN

Как кодируется NaN в IEEE 754 binary64::Все биты экспоненты равны единице, мантисса ==не равна нулю==

Сколько битовых представлений у NaN::`2 × (2⁵² − 1)` = ==9 007 199 254 740 990== — около девяти квадриллионов

Сколько значений NaN в типе Number по спецификации::==Ровно одно==. Различать представления средствами языка нельзя

Что такое NaN-boxing::Использование свободных битов мантиссы NaN под указатели и теги типов. Применяется в JavaScriptCore и SpiderMonkey

Три алгоритма сравнения и их поведение на NaN и `-0`
?
**IsStrictlyEqual** (`===`) — `NaN !== NaN`, `0 === -0`
**SameValue** (`Object.is`) — `NaN` равен `NaN`, `0` не равен `-0`
**SameValueZero** (`includes`, Set, Map) — `NaN` равен `NaN`, `0` равен `-0`

Почему `[NaN].includes(NaN)` истинно, а `[NaN].indexOf(NaN)` даёт `-1`::`includes` использует `SameValueZero`, `indexOf` — строгое равенство

Разница между `isNaN` и `Number.isNaN`::Глобальный `isNaN` сначала применяет `ToNumber`, поэтому `isNaN('abc')` истинно. `Number.isNaN` проверяет собственно значение NaN

## Assignment Patterns

Чем `BindingPattern` отличается от `AssignmentPattern`::Первый работает при объявлении, второй — при присваивании, через операцию `DestructuringAssignmentEvaluation`. Это разные грамматические конструкции

Почему `({a} = obj)` требует скобок::`{` в начале инструкции разбирается как начало ==блока==, а не объектного литерала

На какое значение срабатывает дефолт в деструктуризации::Только на ==`undefined`==. Ни `null`, ни `0`, ни `''` его не активируют

Что вернёт `const [a = 1] = [null]`::`null` — дефолт срабатывает исключительно на `undefined`

Что выведет код
?
```js
function f(a = b, b = 2) { return [a, b]; }
f();
```
`ReferenceError: Cannot access 'b' before initialization` — параметры инициализируются слева направо, `b` ещё в TDZ

Какой протокол использует деструктуризация массива::==Протокол итератора==: `GetIterator`, `IteratorStep`, и `IteratorClose` при досрочном выходе

Что выведет код
?
```js
function* gen() {
  try { yield 1; yield 2; } finally { console.log('закрыт'); }
}
const [first] = gen();
```
`'закрыт'`, затем `first === 1`. При досрочном выходе из деструктуризации вызывается `IteratorClose`

Почему объектную деструктуризацию можно применить к неитерируемому объекту::Она читает свойства по ключам и итератор не использует — в отличие от массивной

Что происходит с геттерами при объектном rest
?
`CopyDataProperties` ==вызывает== их и кладёт в результат вычисленное значение. Ленивость, прототип и неперечисляемые свойства теряются.

Почему `const { a: { b } } = {}` бросает `TypeError`::Вложенный паттерн — инструкция «зайти внутрь», а не объявление промежуточного имени. Чтение свойства у `undefined` невозможно. Спасает дефолт: `{ a: { b } = {} }`

Зачем в `function f({ x = 1 } = {})` нужен внешний `= {}`::Чтобы функцию можно было вызвать ==вообще без аргумента==. Без него `f()` попытается деструктурировать `undefined` и упадёт
