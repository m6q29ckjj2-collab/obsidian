## 16.1. Интерактивный режим

Существует два варианта интерактивного REPL. Классический базовый интерпретатор поддерживается на всех платформах с минимальными возможностями управления строкой.

Начиная с Python 3.13 по умолчанию используется новая интерактивная оболочка. Она поддерживает цвет, многострочное редактирование, просмотр истории и режим вставки. Чтобы отключить цвет, подробности смотрите в разделе об управлении цветом. Функциональные клавиши дают дополнительные возможности. F1 открывает интерактивный браузер справки `pydoc`. F2 позволяет просматривать историю командной строки без вывода и без приглашений >>> и .... F3 включает «режим вставки», облегчающий вставку больших блоков кода. Нажмите F3 снова, чтобы вернуться к обычному приглашению.

При использовании новой интерактивной оболочки выйти из неё можно, набрав exit или quit. Скобки вызова после этих команд добавлять не требуется.

Если новая интерактивная оболочка не нужна, её можно отключить через переменную окружения `PYTHON_BASIC_REPL`.

### 16.1.1. Обработка ошибок

Когда возникает ошибка, интерпретатор выводит сообщение об ошибке и трассировку стека. В интерактивном режиме затем происходит возврат к основному приглашению; когда ввод поступал из файла, после вывода трассировки стека интерпретатор завершается с ненулевым кодом возврата. (Исключения, обработанные блоком `except` инструкции `try`, в этом контексте ошибками не являются.) Некоторые ошибки безусловно фатальны и вызывают выход с ненулевым кодом; это относится к внутренним несогласованностям и некоторым случаям нехватки памяти. Все сообщения об ошибках записываются в стандартный поток ошибок; обычный вывод выполняемых команд записывается в стандартный вывод.

Ввод символа прерывания (обычно Control-C или Delete) на основном или вторичном приглашении отменяет ввод и возвращает к основному приглашению. [^1] Ввод прерывания во время выполнения команды возбуждает исключение `KeyboardInterrupt`, которое можно обработать инструкцией `try`.

### 16.1.2. Исполняемые скрипты Python

В BSD-подобных системах Unix скрипты Python можно сделать непосредственно исполняемыми, как shell-скрипты, поместив в начало скрипта строку

```text
#!/usr/bin/env python3
```

(в предположении, что интерпретатор находится в `PATH` пользователя) и дав файлу исполняемый режим. `#!` должны быть первыми двумя символами файла. На некоторых платформах эта первая строка должна заканчиваться концом строки в стиле Unix (`'\n'`), а не Windows (`'\r\n'`). Обратите внимание, что символ решётки `'#'` в Python используется для начала комментария.

Скрипту можно дать исполняемый режим, или права, командой **chmod**.

```bash
$ chmod +x myscript.py
```

В системах Windows понятия «исполняемого режима» нет. Установщик Python автоматически связывает файлы `.py` с `python.exe`, так что двойной щелчок по файлу Python запустит его как скрипт. Расширение может быть и `.pyw`; в этом случае окно консоли, которое обычно появляется, подавляется.

### 16.1.3. Файл запуска интерактивного режима

Когда вы используете Python интерактивно, часто удобно, чтобы при каждом запуске интерпретатора выполнялись какие-то стандартные команды. Этого можно добиться, задав переменную окружения `PYTHONSTARTUP` равной имени файла с вашими стартовыми командами. Это похоже на возможность `.profile` в оболочках Unix.

Этот файл читается только в интерактивных сеансах, а не когда Python читает команды из скрипта и не когда в качестве явного источника команд указан `/dev/tty` (что в остальном ведёт себя как интерактивный сеанс). Он выполняется в том же пространстве имён, в котором выполняются интерактивные команды, так что определённые или импортированные в нём объекты можно использовать без уточнения в интерактивном сеансе. В этом файле можно также изменить приглашения `sys.ps1` и `sys.ps2`.

Если вы хотите прочитать дополнительный стартовый файл из текущего каталога, это можно запрограммировать в глобальном стартовом файле кодом вроде `if os.path.isfile('.pythonrc.py'): exec(open('.pythonrc.py').read())`. Если вы хотите использовать стартовый файл в скрипте, это нужно сделать в скрипте явно:

```python
import os
filename = os.environ.get('PYTHONSTARTUP')
if filename and os.path.isfile(filename):
    with open(filename) as fobj:
        startup_file = fobj.read()
    exec(startup_file)
```

### 16.1.4. Модули настройки

Python предоставляет два хука для настройки: sitecustomize и usercustomize. Чтобы увидеть, как это работает, сначала нужно найти расположение вашего пользовательского каталога site-packages. Запустите Python и выполните этот код:

```python
>>> import site
>>> site.getusersitepackages()
'/home/user/.local/lib/python3.x/site-packages'
```

Теперь в этом каталоге можно создать файл `usercustomize.py` и поместить в него всё, что хотите. Он будет влиять на каждый запуск Python, если только тот не запущен с опцией `-s`, отключающей автоматический импорт.

sitecustomize работает так же, но обычно создаётся администратором компьютера в глобальном каталоге site-packages и импортируется перед usercustomize. Подробности — в документации модуля `site`.

[^1]: Этому может помешать проблема с пакетом GNU Readline.
