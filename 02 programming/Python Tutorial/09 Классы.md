# 9. Классы

← [[08 Ошибки и исключения]] · [[00 Оглавление]] · [[10 Краткий обзор стандартной библиотеки]] →

Классы позволяют объединять данные и функциональность. Создание нового класса создаёт новый *тип* объектов, позволяя создавать новые *экземпляры* этого типа. К каждому экземпляру класса можно присоединить атрибуты для поддержания его состояния. У экземпляров класса также могут быть методы (определённые его классом) для изменения его состояния.

По сравнению с другими языками программирования, механизм классов в Python добавляет классы с минимумом нового синтаксиса и семантики. Это смесь механизмов классов из C++ и Modula-3. Классы Python предоставляют все стандартные возможности объектно-ориентированного программирования: механизм наследования классов допускает несколько базовых классов, производный класс может переопределять любые методы своего базового класса или классов, а метод может вызывать метод базового класса с тем же именем. Объекты могут содержать произвольное количество данных любого вида. Как и модули, классы разделяют динамическую природу Python: они создаются во время выполнения и могут быть изменены после создания.

В терминологии C++ обычно члены класса (включая данные) *публичные* (но см. ниже раздел «Приватные переменные»), а все функции-члены *виртуальные*. Как в Modula-3, нет сокращений для обращения к членам объекта из его методов: функция-метод объявляется с явным первым аргументом, представляющим объект, который передаётся неявно при вызове. Как в Smalltalk, сами классы — объекты. Это даёт семантику для импорта и переименования. В отличие от C++ и Modula-3, встроенные типы можно использовать как базовые классы для расширения пользователем. Кроме того, как в C++, большинство встроенных операторов со специальным синтаксисом (арифметические операторы, индексирование и т. д.) можно переопределять для экземпляров классов.

(Из-за отсутствия общепринятой терминологии для разговора о классах я буду время от времени использовать термины Smalltalk и C++. Я бы использовал термины Modula-3, так как её объектно-ориентированная семантика ближе к семантике Python, чем C++, но ожидаю, что мало кто из читателей о ней слышал.)

## 9.1. Несколько слов об именах и объектах

Объекты обладают индивидуальностью, и несколько имён (в нескольких областях видимости) могут быть привязаны к одному и тому же объекту. В других языках это называется алиасингом (aliasing). При первом знакомстве с Python это обычно не ценят, и этим можно спокойно пренебречь при работе с неизменяемыми базовыми типами (числа, строки, кортежи). Однако алиасинг оказывает, возможно, неожиданное влияние на семантику кода Python с изменяемыми объектами, такими как списки, словари и большинство других типов. Обычно это используется на благо программы, так как алиасы в некоторых отношениях ведут себя как указатели. Например, передача объекта обходится дёшево, так как реализация передаёт только указатель; а если функция изменяет объект, переданный как аргумент, вызывающий увидит изменение — это устраняет необходимость в двух разных механизмах передачи аргументов, как в Pascal.

## 9.2. Области видимости и пространства имён Python

Прежде чем знакомить с классами, я должен сначала рассказать кое-что о правилах областей видимости Python. Определения классов проделывают некоторые аккуратные трюки с пространствами имён, и вам нужно знать, как работают области видимости и пространства имён, чтобы полностью понимать происходящее. Кстати, знание этой темы полезно любому продвинутому программисту на Python.

Начнём с определений.

*Пространство имён* (namespace) — это отображение имён на объекты. Большинство пространств имён сейчас реализованы как словари Python, но обычно это никак не заметно (кроме производительности) и может измениться в будущем. Примеры пространств имён: набор встроенных имён (содержащий функции вроде `abs()` и имена встроенных исключений); глобальные имена в модуле; локальные имена при вызове функции. В некотором смысле набор атрибутов объекта тоже образует пространство имён. Важно знать о пространствах имён, что между именами в разных пространствах имён абсолютно нет связи; например, два разных модуля могут оба определять функцию `maximize` без путаницы — пользователи модулей должны указывать перед ней имя модуля.

Кстати, я использую слово *атрибут* для любого имени после точки — например, в выражении `z.real` `real` — атрибут объекта `z`. Строго говоря, ссылки на имена в модулях — это ссылки на атрибуты: в выражении `modname.funcname` `modname` — объект-модуль, а `funcname` — его атрибут. В этом случае между атрибутами модуля и глобальными именами, определёнными в модуле, существует простое соответствие: они используют одно и то же пространство имён! [^1]

Атрибуты могут быть доступны только для чтения или для записи. В последнем случае возможно присваивание атрибутам. Атрибуты модулей доступны для записи: можно написать `modname.the_answer = 42`. Записываемые атрибуты можно также удалять инструкцией `del`. Например, `del modname.the_answer` удалит атрибут `the_answer` из объекта, названного `modname`.

Пространства имён создаются в разные моменты и имеют разное время жизни. Пространство имён со встроенными именами создаётся при запуске интерпретатора Python и никогда не удаляется. Глобальное пространство имён модуля создаётся при чтении определения модуля; обычно пространства имён модулей тоже существуют до завершения интерпретатора. Инструкции, выполняемые вызовом интерпретатора верхнего уровня, прочитанные из файла скрипта или введённые интерактивно, считаются частью модуля с именем `__main__`, поэтому у них есть собственное глобальное пространство имён. (Встроенные имена на самом деле тоже живут в модуле; он называется `builtins`.)

Локальное пространство имён функции создаётся при вызове функции и удаляется, когда функция возвращает управление или возбуждает исключение, не обработанное внутри функции. (На самом деле «забывается» — лучшее описание того, что происходит.) Конечно, каждый рекурсивный вызов имеет собственное локальное пространство имён.

*Область видимости* (scope) — это текстовая область программы на Python, в которой пространство имён напрямую доступно. «Напрямую доступно» здесь означает, что неполная ссылка на имя пытается найти имя в этом пространстве имён.

Хотя области видимости определяются статически, используются они динамически. В любой момент выполнения существуют 3 или 4 вложенные области видимости, пространства имён которых напрямую доступны:

- самая внутренняя область, которая просматривается первой, содержит локальные имена;
- области охватывающих функций, которые просматриваются начиная с ближайшей охватывающей области, содержат нелокальные, но и неглобальные имена;
- предпоследняя область содержит глобальные имена текущего модуля;
- самая внешняя область (просматривается последней) — пространство имён со встроенными именами.

Если имя объявлено глобальным, все ссылки и присваивания направляются прямо в предпоследнюю область, содержащую глобальные имена модуля. Чтобы перепривязать переменные, найденные вне самой внутренней области, можно использовать инструкцию `nonlocal`; если они не объявлены нелокальными, такие переменные доступны только для чтения (попытка записи в такую переменную просто создаст *новую* локальную переменную в самой внутренней области, оставив внешнюю переменную с тем же именем неизменной).

Обычно локальная область ссылается на локальные имена (текстуально) текущей функции. Вне функций локальная область ссылается на то же пространство имён, что и глобальная: пространство имён модуля. Определения классов добавляют в локальную область ещё одно пространство имён.

Важно понимать, что области видимости определяются текстуально: глобальная область функции, определённой в модуле, — это пространство имён этого модуля, независимо от того, откуда и под каким алиасом функция вызывается. С другой стороны, фактический поиск имён выполняется динамически, во время выполнения — однако определение языка развивается в сторону статического разрешения имён во время «компиляции», так что не полагайтесь на динамическое разрешение имён! (Фактически локальные переменные уже определяются статически.)

Особая причуда Python: если не действует инструкция `global` или `nonlocal`, присваивания именам всегда попадают в самую внутреннюю область. Присваивания не копируют данные — они только привязывают имена к объектам. То же верно для удаления: инструкция `del x` удаляет привязку `x` из пространства имён, на которое ссылается локальная область. Фактически все операции, вводящие новые имена, используют локальную область: в частности, инструкции `import` и определения функций привязывают имя модуля или функции в локальной области.

Инструкцию `global` можно использовать, чтобы указать, что определённые переменные живут в глобальной области и должны быть перепривязаны там; инструкция `nonlocal` указывает, что определённые переменные живут в охватывающей области и должны быть перепривязаны там.

### 9.2.1. Пример областей видимости и пространств имён

Вот пример, демонстрирующий, как ссылаться на разные области видимости и пространства имён и как `global` и `nonlocal` влияют на привязку переменных:

```python
def scope_test():
    def do_local():
        spam = "local spam"

    def do_nonlocal():
        nonlocal spam
        spam = "nonlocal spam"

    def do_global():
        global spam
        spam = "global spam"

    spam = "test spam"
    do_local()
    print("After local assignment:", spam)
    do_nonlocal()
    print("After nonlocal assignment:", spam)
    do_global()
    print("After global assignment:", spam)

scope_test()
print("In global scope:", spam)
```

Вывод этого примера:

```text
After local assignment: test spam
After nonlocal assignment: nonlocal spam
After global assignment: nonlocal spam
In global scope: global spam
```

Обратите внимание, что *локальное* присваивание (по умолчанию) не изменило привязку *spam* в *scope_test*. Присваивание `nonlocal` изменило привязку *spam* в *scope_test*, а присваивание `global` изменило привязку на уровне модуля.

Также видно, что до присваивания `global` для *spam* не было предыдущей привязки.

## 9.3. Первый взгляд на классы

Классы вводят немного нового синтаксиса, три новых типа объектов и некоторую новую семантику.

### 9.3.1. Синтаксис определения класса

Простейшая форма определения класса выглядит так:

```python
class ClassName:
    <statement-1>
    .
    .
    .
    <statement-N>
```

Определения классов, как и определения функций (инструкции `def`), должны быть выполнены, прежде чем они произведут какой-либо эффект. (Можно представить, что определение класса помещено в ветку инструкции `if` или внутрь функции.)

На практике инструкции внутри определения класса обычно являются определениями функций, но другие инструкции тоже допустимы и иногда полезны — к этому мы вернёмся позже. Определения функций внутри класса обычно имеют своеобразную форму списка аргументов, продиктованную соглашениями о вызове методов — это тоже объясняется позже.

Когда происходит вход в определение класса, создаётся новое пространство имён, которое используется как локальная область, — поэтому все присваивания локальным переменным попадают в это новое пространство имён. В частности, определения функций привязывают здесь имя новой функции.

Когда определение класса покидается нормально (через конец), создаётся *объект класса*. По сути это обёртка вокруг содержимого пространства имён, созданного определением класса; об объектах классов мы узнаем больше в следующем разделе. Исходная локальная область (действовавшая непосредственно перед входом в определение класса) восстанавливается, и объект класса привязывается здесь к имени класса, указанному в заголовке определения класса (`ClassName` в примере).

### 9.3.2. Объекты классов

Объекты классов поддерживают два вида операций: обращение к атрибутам и создание экземпляров.

*Обращения к атрибутам* используют стандартный синтаксис, применяемый для всех обращений к атрибутам в Python: `obj.name`. Допустимые имена атрибутов — все имена, которые были в пространстве имён класса при создании объекта класса. Так что, если определение класса выглядело так:

```python
class MyClass:
    """A simple example class"""
    i = 12345

    def f(self):
        return 'hello world'
```

то `MyClass.i` и `MyClass.f` — допустимые обращения к атрибутам, возвращающие целое число и объект-функцию соответственно. Атрибутам класса можно присваивать значения, так что значение `MyClass.i` можно менять присваиванием. `__doc__` — тоже допустимый атрибут, возвращающий строку документации класса: `"A simple example class"`.

*Создание экземпляра* класса использует функциональную запись. Представьте, что объект класса — функция без параметров, возвращающая новый экземпляр класса. Например (для класса выше):

```python
x = MyClass()
```

создаёт новый *экземпляр* класса и присваивает этот объект локальной переменной `x`.

Операция создания экземпляра («вызов» объекта класса) создаёт пустой объект. Многим классам хочется создавать объекты с экземплярами, настроенными на определённое начальное состояние. Поэтому класс может определять специальный метод с именем `__init__()`, например:

```python
def __init__(self):
    self.data = []
```

Когда класс определяет метод `__init__()`, создание экземпляра класса автоматически вызывает `__init__()` для вновь созданного экземпляра. Поэтому в этом примере новый, инициализированный экземпляр можно получить так:

```python
x = MyClass()
```

Конечно, для большей гибкости у метода `__init__()` могут быть аргументы. В этом случае аргументы, переданные оператору создания экземпляра класса, передаются в `__init__()`. Например,

```python
>>> class Complex:
...     def __init__(self, realpart, imagpart):
...         self.r = realpart
...         self.i = imagpart
...
>>> x = Complex(3.0, -4.5)
>>> x.r, x.i
(3.0, -4.5)
```

### 9.3.3. Объекты-экземпляры

Что теперь можно делать с объектами-экземплярами? Единственные операции, которые понимают объекты-экземпляры, — обращения к атрибутам. Есть два вида допустимых имён атрибутов: атрибуты данных и методы.

*Атрибуты данных* соответствуют «переменным экземпляра» в Smalltalk и «членам-данным» в C++. Атрибуты данных не нужно объявлять; как и локальные переменные, они появляются, когда им впервые присваивается значение. Например, если `x` — экземпляр `MyClass`, созданный выше, следующий фрагмент кода выведет значение `16`, не оставив следа:

```python
x.counter = 1
while x.counter < 10:
    x.counter = x.counter * 2
print(x.counter)
del x.counter
```

Другой вид обращения к атрибуту экземпляра — *метод*. Метод — это функция, которая «принадлежит» объекту.

Допустимые имена методов объекта-экземпляра зависят от его класса. По определению все атрибуты класса, являющиеся объектами-функциями, определяют соответствующие методы его экземпляров. Так что в нашем примере `x.f` — допустимая ссылка на метод, поскольку `MyClass.f` — функция, а `x.i` — нет, поскольку `MyClass.i` — не функция. Но `x.f` — это не то же самое, что `MyClass.f`: это *объект-метод*, а не объект-функция.

### 9.3.4. Объекты-методы

Обычно метод вызывают сразу после привязки:

```python
x.f()
```

Если `x = MyClass()`, как выше, это вернёт строку `'hello world'`. Однако вызывать метод сразу необязательно: `x.f` — объект-метод, его можно сохранить и вызвать позже. Например:

```python
xf = x.f
while True:
    print(xf())
```

будет выводить `hello world` до скончания времён.

Что именно происходит при вызове метода? Вы могли заметить, что выше `x.f()` вызывалась без аргумента, хотя в определении функции `f()` аргумент был указан. Что случилось с аргументом? Конечно, Python возбуждает исключение, когда функция, требующая аргумент, вызывается без него, — даже если аргумент на самом деле не используется…

Вы, возможно, уже догадались об ответе: особенность методов в том, что объект-экземпляр передаётся как первый аргумент функции. В нашем примере вызов `x.f()` в точности эквивалентен `MyClass.f(x)`. В общем случае вызов метода со списком из *n* аргументов эквивалентен вызову соответствующей функции со списком аргументов, созданным вставкой объекта-экземпляра метода перед первым аргументом.

В общем случае методы работают так. Когда происходит обращение к не-данным атрибуту экземпляра, просматривается класс экземпляра. Если имя обозначает допустимый атрибут класса, являющийся объектом-функцией, ссылки на объект-экземпляр и объект-функцию упаковываются в объект-метод. Когда объект-метод вызывается со списком аргументов, из объекта-экземпляра и списка аргументов строится новый список аргументов, и объект-функция вызывается с этим новым списком.

### 9.3.5. Переменные класса и переменные экземпляра

Вообще говоря, переменные экземпляра предназначены для данных, уникальных для каждого экземпляра, а переменные класса — для атрибутов и методов, общих для всех экземпляров класса:

```python
class Dog:

    kind = 'canine'         # class variable shared by all instances

    def __init__(self, name):
        self.name = name    # instance variable unique to each instance

>>> d = Dog('Fido')
>>> e = Dog('Buddy')
>>> d.kind                  # shared by all dogs
'canine'
>>> e.kind                  # shared by all dogs
'canine'
>>> d.name                  # unique to d
'Fido'
>>> e.name                  # unique to e
'Buddy'
```

Как обсуждалось в разделе [[#9.1. Несколько слов об именах и объектах]], общие данные могут иметь, возможно, неожиданные эффекты при использовании изменяемых объектов, таких как списки и словари. Например, список *tricks* в следующем коде не следует делать переменной класса, потому что один-единственный список будет общим для всех экземпляров *Dog*:

```python
class Dog:

    tricks = []             # mistaken use of a class variable

    def __init__(self, name):
        self.name = name

    def add_trick(self, trick):
        self.tricks.append(trick)

>>> d = Dog('Fido')
>>> e = Dog('Buddy')
>>> d.add_trick('roll over')
>>> e.add_trick('play dead')
>>> d.tricks                # unexpectedly shared by all dogs
['roll over', 'play dead']
```

Правильный дизайн класса должен использовать вместо этого переменную экземпляра:

```python
class Dog:

    def __init__(self, name):
        self.name = name
        self.tricks = []    # creates a new empty list for each dog

    def add_trick(self, trick):
        self.tricks.append(trick)

>>> d = Dog('Fido')
>>> e = Dog('Buddy')
>>> d.add_trick('roll over')
>>> e.add_trick('play dead')
>>> d.tricks
['roll over']
>>> e.tricks
['play dead']
```

## 9.4. Разрозненные замечания

Если одно и то же имя атрибута встречается и в экземпляре, и в классе, при поиске атрибута приоритет отдаётся экземпляру:

```python
>>> class Warehouse:
...    purpose = 'storage'
...    region = 'west'
...
>>> w1 = Warehouse()
>>> print(w1.purpose, w1.region)
storage west
>>> w2 = Warehouse()
>>> w2.region = 'east'
>>> print(w2.purpose, w2.region)
storage east
```

На атрибуты данных могут ссылаться как методы, так и обычные пользователи («клиенты») объекта. Другими словами, классы непригодны для реализации чистых абстрактных типов данных. На самом деле в Python ничто не позволяет принудительно скрывать данные — всё основано на соглашениях. (С другой стороны, реализация Python, написанная на C, может полностью скрывать детали реализации и при необходимости контролировать доступ к объекту; это могут использовать расширения Python, написанные на C.)

Клиенты должны использовать атрибуты данных с осторожностью — клиенты могут нарушить инварианты, поддерживаемые методами, затоптав их атрибуты данных. Обратите внимание, что клиенты могут добавлять к объекту-экземпляру собственные атрибуты данных, не влияя на корректность методов, если избегать конфликтов имён — и здесь соглашение об именовании может избавить от многих головных болей.

Для обращения к атрибутам данных (или другим методам!) изнутри методов нет сокращений. Мне кажется, это на самом деле повышает читаемость методов: при беглом просмотре метода нет шанса перепутать локальные переменные и переменные экземпляра.

Часто первый аргумент метода называют `self`. Это не более чем соглашение: имя `self` не имеет для Python абсолютно никакого особого значения. Однако учтите, что, не следуя соглашению, ваш код может быть менее читаемым для других программистов на Python, и возможна также программа-*обозреватель классов*, опирающаяся на такое соглашение.

Любой объект-функция, являющийся атрибутом класса, определяет метод для экземпляров этого класса. Необязательно, чтобы определение функции текстуально находилось внутри определения класса: присваивание объекта-функции локальной переменной в классе тоже подходит. Например:

```python
# Function defined outside the class
def f1(self, x, y):
    return min(x, x+y)

class C:
    f = f1

    def g(self):
        return 'hello world'

    h = g
```

Теперь `f`, `g` и `h` — атрибуты класса `C`, ссылающиеся на объекты-функции, а следовательно, все они методы экземпляров `C`, причём `h` в точности эквивалентен `g`. Обратите внимание, что такая практика обычно лишь сбивает с толку читателя программы.

Методы могут вызывать другие методы, используя атрибуты-методы аргумента `self`:

```python
class Bag:
    def __init__(self):
        self.data = []

    def add(self, x):
        self.data.append(x)

    def addtwice(self, x):
        self.add(x)
        self.add(x)
```

Методы могут ссылаться на глобальные имена так же, как обычные функции. Глобальная область, связанная с методом, — модуль, содержащий его определение. (Класс никогда не используется как глобальная область.) Хотя хороший повод использовать глобальные данные в методе встречается редко, у глобальной области есть много законных применений: например, функции и модули, импортированные в глобальную область, могут использоваться методами, как и функции и классы, определённые в ней. Обычно класс, содержащий метод, сам определён в этой глобальной области, а в следующем разделе мы найдём несколько веских причин, по которым методу может понадобиться ссылаться на собственный класс.

Каждое значение — объект, а потому имеет *класс* (также называемый его *типом*). Он хранится как `object.__class__`.

## 9.5. Наследование

Конечно, возможность языка не заслуживала бы названия «класс», если бы не поддерживала наследование. Синтаксис определения производного класса выглядит так:

```python
class DerivedClassName(BaseClassName):
    <statement-1>
    .
    .
    .
    <statement-N>
```

Имя `BaseClassName` должно быть определено в пространстве имён, доступном из области, содержащей определение производного класса. Вместо имени базового класса допустимы и другие произвольные выражения. Это может быть полезно, например, когда базовый класс определён в другом модуле:

```python
class DerivedClassName(modname.BaseClassName):
```

Выполнение определения производного класса происходит так же, как для базового класса. При построении объекта класса базовый класс запоминается. Это используется для разрешения ссылок на атрибуты: если запрошенный атрибут не найден в классе, поиск продолжается в базовом классе. Это правило применяется рекурсивно, если сам базовый класс является производным от какого-то другого класса.

В создании экземпляров производных классов нет ничего особенного: `DerivedClassName()` создаёт новый экземпляр класса. Ссылки на методы разрешаются так: ищется соответствующий атрибут класса, при необходимости спускаясь вниз по цепочке базовых классов, и ссылка на метод допустима, если в результате получен объект-функция.

Производные классы могут переопределять методы своих базовых классов. Поскольку у методов нет особых привилегий при вызове других методов того же объекта, метод базового класса, вызывающий другой метод, определённый в том же базовом классе, может в итоге вызвать метод производного класса, который его переопределяет. (Для программистов на C++: все методы в Python фактически `virtual`.)

Переопределяющий метод в производном классе может на самом деле захотеть расширить, а не просто заменить метод базового класса с тем же именем. Есть простой способ вызвать метод базового класса напрямую: просто вызовите `BaseClassName.methodname(self, arguments)`. Иногда это полезно и клиентам. (Обратите внимание, что это работает, только если базовый класс доступен как `BaseClassName` в глобальной области.)

В Python есть две встроенные функции, работающие с наследованием:

- Используйте `isinstance()` для проверки типа экземпляра: `isinstance(obj, int)` будет `True`, только если `obj.__class__` — `int` или некоторый класс, производный от `int`.
- Используйте `issubclass()` для проверки наследования классов: `issubclass(bool, int)` — `True`, так как `bool` — подкласс `int`. Однако `issubclass(float, int)` — `False`, так как `float` не подкласс `int`.

### 9.5.1. Множественное наследование

Python поддерживает и форму множественного наследования. Определение класса с несколькими базовыми классами выглядит так:

```python
class DerivedClassName(Base1, Base2, Base3):
    <statement-1>
    .
    .
    .
    <statement-N>
```

В большинстве случаев, в простейших ситуациях, поиск атрибутов, унаследованных от родительского класса, можно представлять как поиск в глубину, слева направо, без повторного поиска в одном и том же классе при пересечении в иерархии. Таким образом, если атрибут не найден в `DerivedClassName`, он ищется в `Base1`, затем (рекурсивно) в базовых классах `Base1`, а если там не найден — в `Base2`, и так далее.

На самом деле всё немного сложнее; порядок разрешения методов меняется динамически для поддержки кооперативных вызовов `super()`. В некоторых других языках с множественным наследованием этот подход известен как call-next-method и мощнее, чем вызов super в языках с одиночным наследованием.

Динамическое упорядочивание необходимо, потому что все случаи множественного наследования демонстрируют одно или несколько ромбовидных отношений (когда хотя бы к одному из родительских классов можно обратиться несколькими путями из самого нижнего класса). Например, все классы наследуют от `object`, так что любой случай множественного наследования предоставляет больше одного пути к `object`. Чтобы не обращаться к базовым классам более одного раза, динамический алгоритм линеаризует порядок поиска так, чтобы сохранить порядок слева направо, заданный в каждом классе, вызывать каждый родительский класс только один раз и быть монотонным (то есть класс можно унаследовать, не влияя на порядок старшинства его родителей). В совокупности эти свойства позволяют проектировать надёжные и расширяемые классы с множественным наследованием. Подробнее см. «The Python 2.3 Method Resolution Order».

В некоторых случаях множественное наследование не допускается; подробности — в разделе о множественном наследовании.

## 9.6. Приватные переменные

«Приватных» переменных экземпляра, к которым нельзя получить доступ иначе как изнутри объекта, в Python не существует. Однако есть соглашение, которому следует большинство кода на Python: имя с префиксом в виде подчёркивания (например, `_spam`) следует считать непубличной частью API (будь то функция, метод или член-данные). Его следует считать деталью реализации, которая может быть изменена без предупреждения.

Поскольку есть обоснованный сценарий использования закрытых членов класса (а именно, избежание конфликтов имён с именами, определёнными подклассами), существует ограниченная поддержка такого механизма, называемого *искажением имён* (name mangling). Любой идентификатор вида `__spam` (как минимум два ведущих подчёркивания, не более одного завершающего) текстуально заменяется на `_classname__spam`, где `classname` — имя текущего класса с отброшенными ведущими подчёркиваниями. Это искажение выполняется независимо от синтаксической позиции идентификатора, если он находится внутри определения класса.

> [!note] См. также
> Спецификацию искажения приватных имён — подробности и особые случаи.

Искажение имён помогает подклассам переопределять методы, не нарушая вызовы методов внутри класса. Например:

```python
class Mapping:
    def __init__(self, iterable):
        self.items_list = []
        self.__update(iterable)

    def update(self, iterable):
        for item in iterable:
            self.items_list.append(item)

    __update = update   # private copy of original update() method

class MappingSubclass(Mapping):

    def update(self, keys, values):
        # provides new signature for update()
        # but does not break __init__()
        for item in zip(keys, values):
            self.items_list.append(item)
```

Пример выше работал бы, даже если бы `MappingSubclass` вводил идентификатор `__update`, поскольку он заменяется на `_Mapping__update` в классе `Mapping` и на `_MappingSubclass__update` в классе `MappingSubclass` соответственно.

Обратите внимание, что правила искажения в основном предназначены для предотвращения случайностей; всё же можно получить доступ к переменной, считающейся приватной, или изменить её. Это может быть даже полезно в особых обстоятельствах, например в отладчике.

Заметьте, что код, переданный в `exec()` или `eval()`, не считает имя класса вызывающего кода текущим классом; это похоже на эффект инструкции `global`, действие которой так же ограничено кодом, компилируемым в байт-код вместе. То же ограничение применяется к `getattr()`, `setattr()` и `delattr()`, а также при прямом обращении к `__dict__`.

## 9.7. Всякая всячина

Иногда полезен тип данных, похожий на «запись» (record) Pascal или «структуру» (struct) C, объединяющий несколько именованных элементов данных. Идиоматичный подход для этого — использовать `dataclasses`:

```python
from dataclasses import dataclass

@dataclass
class Employee:
    name: str
    dept: str
    salary: int
```

```python
>>> john = Employee('john', 'computer lab', 1000)
>>> john.dept
'computer lab'
>>> john.salary
1000
```

Фрагменту кода на Python, ожидающему определённый абстрактный тип данных, часто можно передать класс, эмулирующий методы этого типа данных. Например, если у вас есть функция, форматирующая данные из файлового объекта, вы можете определить класс с методами `read()` и `readline()`, получающими данные из строкового буфера, и передать его как аргумент.

У объектов-методов экземпляров тоже есть атрибуты: `m.__self__` — объект-экземпляр с методом `m()`, а `m.__func__` — объект-функция, соответствующий методу.

## 9.8. Итераторы

К этому моменту вы, вероятно, заметили, что по большинству объектов-контейнеров можно выполнять цикл инструкцией `for`:

```python
for element in [1, 2, 3]:
    print(element)
for element in (1, 2, 3):
    print(element)
for key in {'one':1, 'two':2}:
    print(key)
for char in "123":
    print(char)
for line in open("myfile.txt"):
    print(line, end='')
```

Такой стиль доступа ясен, краток и удобен. Использование итераторов пронизывает и объединяет Python. За кулисами инструкция `for` вызывает `iter()` для объекта-контейнера. Функция возвращает объект-итератор, определяющий метод `__next__()`, который обращается к элементам контейнера по одному. Когда элементов больше нет, `__next__()` возбуждает исключение `StopIteration`, которое сообщает циклу `for` о завершении. Метод `__next__()` можно вызвать с помощью встроенной функции `next()`; этот пример показывает, как всё работает:

```python
>>> s = 'abc'
>>> it = iter(s)
>>> it
<str_iterator object at 0x10c90e650>
>>> next(it)
'a'
>>> next(it)
'b'
>>> next(it)
'c'
>>> next(it)
Traceback (most recent call last):
  File "<stdin>", line 1, in <module>
    next(it)
StopIteration
```

Увидев механику протокола итераторов, легко добавить поведение итератора вашим классам. Определите метод `__iter__()`, возвращающий объект с методом `__next__()`. Если класс определяет `__next__()`, то `__iter__()` может просто возвращать `self`:

```python
class Reverse:
    """Iterator for looping over a sequence backwards."""
    def __init__(self, data):
        self.data = data
        self.index = len(data)

    def __iter__(self):
        return self

    def __next__(self):
        if self.index == 0:
            raise StopIteration
        self.index = self.index - 1
        return self.data[self.index]
```

```python
>>> rev = Reverse('spam')
>>> iter(rev)
<__main__.Reverse object at 0x00A1DB50>
>>> for char in rev:
...     print(char)
...
m
a
p
s
```

## 9.9. Генераторы

Генераторы — простой и мощный инструмент для создания итераторов. Они пишутся как обычные функции, но используют инструкцию `yield`, когда хотят вернуть данные. Каждый раз, когда для генератора вызывается `next()`, он возобновляет работу с того места, где остановился (он помнит все значения данных и то, какая инструкция была выполнена последней). Пример показывает, что генераторы могут создаваться до смешного просто:

```python
def reverse(data):
    for index in range(len(data)-1, -1, -1):
        yield data[index]
```

```python
>>> for char in reverse('golf'):
...     print(char)
...
f
l
o
g
```

Всё, что можно сделать с помощью генераторов, можно сделать и с помощью итераторов на основе классов, как описано в предыдущем разделе. Генераторы так компактны потому, что методы `__iter__()` и `__next__()` создаются автоматически.

Другая ключевая особенность в том, что локальные переменные и состояние выполнения автоматически сохраняются между вызовами. Это сделало функцию проще для написания и гораздо понятнее, чем подход с переменными экземпляра вроде `self.index` и `self.data`.

Помимо автоматического создания методов и сохранения состояния программы, когда генераторы завершаются, они автоматически возбуждают `StopIteration`. В сочетании эти возможности позволяют создавать итераторы с не большими усилиями, чем написание обычной функции.

## 9.10. Генераторные выражения

Некоторые простые генераторы можно кратко записать как выражения с синтаксисом, похожим на списковые включения, но с круглыми скобками вместо квадратных. Эти выражения предназначены для ситуаций, когда генератор сразу используется охватывающей функцией. Генераторные выражения компактнее, но менее универсальны, чем полные определения генераторов, и обычно более экономны по памяти, чем эквивалентные списковые включения.

Примеры:

```python
>>> sum(i*i for i in range(10))                 # sum of squares
285

>>> xvec = [10, 20, 30]
>>> yvec = [7, 5, 3]
>>> sum(x*y for x,y in zip(xvec, yvec))         # dot product
260

>>> unique_words = set(word for line in page  for word in line.split())

>>> valedictorian = max((student.gpa, student.name) for student in graduates)

>>> data = 'golf'
>>> list(data[i] for i in range(len(data)-1, -1, -1))
['f', 'l', 'o', 'g']

>>> x = [[1,2,3], [], [4, 5]]
>>> g = (*i for i in x)
>>> list(g)
[1, 2, 3, 4, 5]
```

В большинстве случаев генераторные выражения должны быть заключены в круглые скобки. Однако в особом случае, когда оно передаётся как единственный аргумент функции (как в примерах выше с `sum`, `set`, `max` и `list`), генераторное выражение не нужно заключать в дополнительную пару скобок. То есть следующие два фрагмента кода семантически эквивалентны:

```python
>>> f(x for x in y)
>>> f((x for x in y))
```

как и следующие:

```python
>>> f(*x for x in y)
>>> f((*x for x in y))
```

[^1]: За исключением одного. У объектов-модулей есть секретный атрибут только для чтения `__dict__`, возвращающий словарь, используемый для реализации пространства имён модуля; имя `__dict__` — атрибут, но не глобальное имя. Очевидно, его использование нарушает абстракцию реализации пространства имён, и им следует пользоваться только в таких вещах, как посмертные отладчики.
