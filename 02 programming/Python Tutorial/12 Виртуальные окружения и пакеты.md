# 12. Виртуальные окружения и пакеты

← [[11 Краткий обзор стандартной библиотеки — часть II]] · [[00 Оглавление]] · [[13 Что дальше]] →

## 12.1. Введение

Приложения на Python часто используют пакеты и модули, не входящие в стандартную библиотеку. Приложениям иногда нужна конкретная версия библиотеки, потому что приложению может требоваться исправление определённой ошибки, либо приложение может быть написано с использованием устаревшей версии интерфейса библиотеки.

Это значит, что одна установка Python может не удовлетворять требованиям каждого приложения. Если приложению A нужна версия 1.0 определённого модуля, а приложению B нужна версия 2.0, то требования конфликтуют, и установка любой из версий, 1.0 или 2.0, оставит одно из приложений неработоспособным.

Решение этой проблемы — создать виртуальное окружение: самодостаточное дерево каталогов, содержащее установку Python определённой версии плюс некоторое количество дополнительных пакетов.

Тогда разные приложения могут использовать разные виртуальные окружения. Чтобы разрешить приведённый выше пример конфликтующих требований, у приложения A может быть своё виртуальное окружение с установленной версией 1.0, а у приложения B — другое виртуальное окружение с версией 2.0. Если приложению B потребуется обновить библиотеку до версии 3.0, это не повлияет на окружение приложения A.

## 12.2. Создание виртуальных окружений

Модуль, используемый для создания виртуальных окружений и управления ими, называется `venv`. `venv` установит ту версию Python, из которой была запущена команда (как сообщает опция `--version`). Например, выполнение команды с `python3.12` установит версию 3.12.

Чтобы создать виртуальное окружение, выберите каталог, в котором хотите его разместить, и запустите модуль `venv` как скрипт с путём к каталогу:

```bash
python -m venv tutorial-env
```

Это создаст каталог `tutorial-env`, если он не существует, а также создаст внутри него каталоги с копией интерпретатора Python и различными вспомогательными файлами.

Обычное расположение каталога для виртуального окружения — `.venv`. Это имя обычно скрывает каталог в вашей оболочке, так что он не мешается, и при этом имя объясняет, зачем каталог существует. Оно также предотвращает конфликт с файлами определений переменных окружения `.env`, которые поддерживают некоторые инструменты.

Создав виртуальное окружение, его можно активировать.

В Windows выполните:

```bat
tutorial-env\Scripts\activate
```

В Unix или MacOS выполните:

```bash
source tutorial-env/bin/activate
```

(Этот скрипт написан для оболочки bash. Если вы используете оболочки **csh** или **fish**, вместо него есть альтернативные скрипты `activate.csh` и `activate.fish`.)

Активация виртуального окружения изменит приглашение вашей оболочки, показывая, какое виртуальное окружение вы используете, и изменит окружение так, что запуск `python` даст вам именно эту версию и установку Python. Например:

```text
$ source ~/envs/tutorial-env/bin/activate
(tutorial-env) $ python
Python 3.5.1 (default, May  6 2016, 10:59:36)
  ...
>>> import sys
>>> sys.path
['', '/usr/local/lib/python35.zip', ...,
'~/envs/tutorial-env/lib/python3.5/site-packages']
>>>
```

Обратите внимание, что активированное виртуальное окружение никак не изменяет переменную `PYTHONPATH`. Это может привести к неожиданным результатам, если путь содержит ссылки на код, несовместимый с версией Python, которую использует виртуальное окружение. Лучшая практика — выполнить `unset PYTHONPATH` в bash или эквивалент для используемой вами оболочки.

Чтобы деактивировать виртуальное окружение, введите в терминале:

```bash
deactivate
```

## 12.3. Управление пакетами с помощью pip

Устанавливать, обновлять и удалять пакеты можно программой **pip**. По умолчанию `pip` устанавливает пакеты из [Python Package Index](https://pypi.org). Просмотреть Python Package Index можно, зайдя на него в веб-браузере.

У `pip` есть ряд подкоманд: «install», «uninstall», «freeze» и т. д. (Полную документацию по `pip` смотрите в руководстве «Установка модулей Python».)

Установить последнюю версию пакета можно, указав имя пакета:

```text
(tutorial-env) $ python -m pip install novas
Collecting novas
  Downloading novas-3.1.1.3.tar.gz (136kB)
Installing collected packages: novas
  Running setup.py install for novas
Successfully installed novas-3.1.1.3
```

Можно также установить конкретную версию пакета, указав имя пакета, затем `==` и номер версии:

```text
(tutorial-env) $ python -m pip install requests==2.6.0
Collecting requests==2.6.0
  Using cached requests-2.6.0-py2.py3-none-any.whl
Installing collected packages: requests
Successfully installed requests-2.6.0
```

Если выполнить эту команду повторно, `pip` заметит, что запрошенная версия уже установлена, и ничего не сделает. Можно указать другой номер версии, чтобы получить её, или выполнить `python -m pip install --upgrade`, чтобы обновить пакет до последней версии:

```text
(tutorial-env) $ python -m pip install --upgrade requests
Collecting requests
Installing collected packages: requests
  Found existing installation: requests 2.6.0
    Uninstalling requests-2.6.0:
      Successfully uninstalled requests-2.6.0
Successfully installed requests-2.7.0
```

`python -m pip uninstall` с одним или несколькими именами пакетов удалит пакеты из виртуального окружения.

`python -m pip show` покажет информацию о конкретном пакете:

```text
(tutorial-env) $ python -m pip show requests
---
Metadata-Version: 2.0
Name: requests
Version: 2.7.0
Summary: Python HTTP for Humans.
Home-page: http://python-requests.org
Author: Kenneth Reitz
Author-email: me@kennethreitz.com
License: Apache 2.0
Location: /Users/akuchling/envs/tutorial-env/lib/python3.4/site-packages
Requires:
```

`python -m pip list` покажет все пакеты, установленные в виртуальном окружении:

```text
(tutorial-env) $ python -m pip list
novas (3.1.1.3)
numpy (1.9.2)
pip (7.0.3)
requests (2.7.0)
setuptools (16.0)
```

`python -m pip freeze` выдаст похожий список установленных пакетов, но вывод будет в формате, который ожидает `python -m pip install`. Распространённое соглашение — помещать этот список в файл `requirements.txt`:

```text
(tutorial-env) $ python -m pip freeze > requirements.txt
(tutorial-env) $ cat requirements.txt
novas==3.1.1.3
numpy==1.9.2
requests==2.7.0
```

Файл `requirements.txt` затем можно закоммитить в систему контроля версий и поставлять как часть приложения. Пользователи смогут установить все необходимые пакеты с помощью `install -r`:

```text
(tutorial-env) $ python -m pip install -r requirements.txt
Collecting novas==3.1.1.3 (from -r requirements.txt (line 1))
  ...
Collecting numpy==1.9.2 (from -r requirements.txt (line 2))
  ...
Collecting requests==2.7.0 (from -r requirements.txt (line 3))
  ...
Installing collected packages: novas, numpy, requests
  Running setup.py install for novas
Successfully installed novas-3.1.1.3 numpy-1.9.2 requests-2.7.0
```

У `pip` гораздо больше опций. Полную документацию по `pip` смотрите в руководстве «Установка модулей Python». Когда вы напишете пакет и захотите сделать его доступным в Python Package Index, обратитесь к [руководству пользователя по упаковке Python](https://packaging.python.org/en/latest/tutorials/packaging-projects/).
