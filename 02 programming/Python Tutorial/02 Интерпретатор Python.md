# 2. Использование интерпретатора Python

## 2.1. Запуск интерпретатора

Интерпретатор Python обычно устанавливается как `/usr/local/bin/python3.15` на тех машинах, где он доступен. Если добавить `/usr/local/bin` в путь поиска вашей Unix-оболочки, его можно запустить командой:

```bash
python3.15
```

в оболочке. [^1] Поскольку каталог установки интерпретатора выбирается при установке, возможны и другие места; уточните у местного гуру Python или системного администратора. (Например, популярное альтернативное расположение — `/usr/local/python`.)

На Windows-машинах, где Python установлен из Microsoft Store, доступна команда `python3.15`. Если установлен лаунчер py.exe, можно использовать команду `py`. Другие способы запуска Python описаны в разделе про менеджер установки Python.

Ввод символа конца файла (Control-D в Unix, Control-Z в Windows) на основном приглашении завершает интерпретатор с нулевым кодом возврата. Если это не работает, выйти можно командой `quit()`.

Возможности редактирования строки в интерпретаторе включают интерактивное редактирование, подстановку из истории и автодополнение кода в большинстве систем. Быстрее всего проверить, поддерживается ли редактирование командной строки, так: введите слово на приглашении Python и нажмите стрелку влево (или Control-b). Если курсор двигается, редактирование есть; краткое описание клавиш смотрите в приложении «Интерактивное редактирование ввода и подстановка из истории» (глава 14). Если ничего не происходит или появляется последовательность вроде `^[[D` или `^B`, редактирования командной строки нет, и стереть символы в текущей строке можно только клавишей backspace.

Интерпретатор работает примерно как оболочка Unix: если его вызвать со стандартным вводом, подключённым к tty-устройству, он читает и выполняет команды интерактивно; если вызвать с именем файла в аргументе или с файлом на стандартном вводе, он читает и выполняет *скрипт* из этого файла.

Второй способ запуска — `python -c command [arg] ...`: он выполняет инструкции из *command*, аналогично опции `-c` оболочки. Поскольку инструкции Python часто содержат пробелы и другие символы, специальные для оболочки, обычно рекомендуется заключать *command* целиком в кавычки.

Некоторые модули Python полезны и как скрипты. Их можно вызывать командой `python -m module [arg] ...`, которая выполняет исходный файл модуля *module*, как если бы вы написали его полный путь в командной строке.

Когда используется файл скрипта, иногда полезно запустить скрипт, а потом остаться в интерактивном режиме. Это делается указанием `-i` перед скриптом.

Все опции командной строки описаны в разделе «Командная строка и окружение».

### 2.1.1. Передача аргументов

Когда интерпретатору известны имя скрипта и дополнительные аргументы после него, они преобразуются в список строк и присваиваются переменной `argv` модуля `sys`. Получить этот список можно, выполнив `import sys`. Длина списка не меньше единицы; если скрипт и аргументы не заданы, `sys.argv[0]` — пустая строка. Если имя скрипта задано как `'-'` (то есть стандартный ввод), `sys.argv[0]` равен `'-'`. При использовании `-c` *command* `sys.argv[0]` равен `'-c'`. При использовании `-m` *module* `sys.argv[0]` равен полному имени найденного модуля. Опции, найденные после `-c` *command* или `-m` *module*, не обрабатываются самим интерпретатором, а остаются в `sys.argv` для обработки командой или модулем.

### 2.1.2. Интерактивный режим

Когда команды читаются с tty, говорят, что интерпретатор находится в *интерактивном режиме*. В этом режиме он запрашивает следующую команду с помощью *основного приглашения*, обычно это три знака «больше» (`>>>`); для строк продолжения используется *вторичное приглашение*, по умолчанию три точки (`...`). Перед первым приглашением интерпретатор выводит приветствие с номером версии и уведомлением об авторских правах:

```text
$ python3.15
Python 3.15 (default, May 7 2025, 15:46:04)
[GCC 10.2.0] on linux
Type "help", "copyright", "credits" or "license" for more information.
>>>
```

Строки продолжения нужны при вводе многострочных конструкций. Например, посмотрите на инструкцию `if`:

```python
>>> the_world_is_flat = True
>>> if the_world_is_flat:
...     print("Be careful not to fall off!")
...
Be careful not to fall off!
```

Подробнее об интерактивном режиме — в разделе «Интерактивный режим».

## 2.2. Интерпретатор и его окружение

### 2.2.1. Кодировка исходного кода

По умолчанию исходные файлы Python считаются закодированными в UTF-8. В этой кодировке в строковых литералах, идентификаторах и комментариях можно одновременно использовать символы большинства языков мира, хотя стандартная библиотека использует для идентификаторов только ASCII — этому соглашению должен следовать любой переносимый код. Чтобы все эти символы отображались правильно, редактор должен распознавать файл как UTF-8 и использовать шрифт, поддерживающий все символы файла.

Чтобы объявить кодировку, отличную от умолчательной, в *первую* строку файла нужно добавить специальный комментарий. Синтаксис такой:

```python
# -*- coding: encoding -*-
```

где *encoding* — одна из допустимых кодировок (`codecs`), поддерживаемых Python.

Например, чтобы объявить, что используется кодировка Windows-1252, первой строкой исходного файла должна быть:

```python
# -*- coding: cp1252 -*-
```

Единственное исключение из правила «первой строки» — случай, когда исходный код начинается со строки «shebang» UNIX. Тогда объявление кодировки нужно добавить второй строкой файла. Например:

```python
#!/usr/bin/env python3
# -*- coding: cp1252 -*-
```

[^1]: В Unix интерпретатор Python 3.x по умолчанию устанавливается не с исполняемым файлом `python`, чтобы он не конфликтовал с одновременно установленным исполняемым файлом Python 2.x.
