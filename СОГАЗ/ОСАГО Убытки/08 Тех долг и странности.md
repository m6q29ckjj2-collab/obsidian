## Вероятные баги

| | Где | Что |
|---|---|---|
| 🔴 | `OsagoLossesResultantScreen.tsx` | `const { osago_losses_property_damage: osagoLossesPropertyDamage, osago_losses_property_damage: osagoLossesHealtDamage }` — карточка здоровья управляется флагом **имущества**. Флаг `osago_losses_health_damage` запрашивается, но не используется |
| 🔴 | `OsagoLossesVehicleDamageScreen.tsx`, `OsagoLossesPropertyDamageScreen.tsx` | `.unwrap().catch(showRequestError)` на основном PATCH гасит ошибку, и цепочка `selected → signType → files → goBack` выполняется дальше. Пользователь видит хаб, хотя шаг не сохранился |
| 🔴 | 5 экранов-форм (`onPressCloseStep`) | `if (!isDirty) navigation.goBack()` без `return`, после чего вызывается `onPressOutFlow()` |
| 🔴 | `OsagoLossesRouterBottomSheet.tsx` | `useBackHandler` всегда перехватывает Android back на хабе: `goBack` без подтверждения, даже когда шторка закрыта |
| 🟠 | Resultant ↔ BankDetails / SelfInspectionDamage | Свитчи «имущество» и «здоровье» живут только в Redux (`applicationSelectedOverride`) и **не PATCH-атся**. На бэке флаги только включаются |
| 🟠 | `OsagoLossesAddVehicleFormScreen.tsx` | PATCH `stepVehicleDamage` с урезанным `damagedVehicle` затирает собственника, водителя, способ возмещения и `policyNumber` |
| 🟠 | `OsagoLossesRouterBottomSheet.tsx` | «Начать заново»: сначала `DELETE`, потом `POST`. При ошибке `POST` черновика нет совсем |
| 🟠 | `useOsagoLossesDraftResolver` | Новый черновик создаётся на каждом открытии без `draftId`, пустые черновики копятся |
| 🟠 | `osagoLossesSlice/types.ts` → `BankDetailsStepType` | Тип чтения (`BankDetails`, `Beneficiary`, `bic`, `settlementAccount`) не совпадает с тем, что пишем (`bankDetails`, `beneficiary`, `bik`, `accountNumber`) |
| 🟠 | `OsagoLossesHealthDamageScreen.tsx` | `applicantRelation = injuryDetails` при смерти. Также нет обновления `signType` (в отличие от Vehicle и Property) |
| 🔴 | CheckProfile, HealthDamage, AddVehicleForm, файлы в Incident и DocumentSign | Мутации без `.unwrap()`: ошибки PATCH **полностью глотаются**, навигация идёт дальше, как при успехе. См. [[06 Ошибки и edge-кейсы]] |
| 🟠 | `OsagoLossesDocumentSignScreen.tsx` | `userId = profile?.id ?? 0` |
| 🟠 | `createNewPolicyFromVehicle.ts` | `product: 'еОСАГО'`, а фильтр ищет `'е-ОСАГО'`. Скорее всего намеренно, но неочевидно |

## Структура и гигиена

- **Два файла API с одинаковым именем экспорта** `osagoLossesApi`: `osagoLossesSlice/osagoLossesApi.ts` (основной) и `slice/osagoLossesApi.ts` (только геокодер). Плюс две папки для «слайса»: `osagoLossesSlice/` (API и типы) и `slice/` (Redux store и геокодер). Стоит слить в одну.
- **Экраны больше лимита в 300 строк:** VehicleDamage 784, IncidentData 709, BankDetails 652 («экран п…ц, надо реФАКчить»), HealthDamage 523, SecondParticipant 447, DocumentSign 439, CheckProfile 419, PropertyDamage 400, Resultant 394.
- Хук `useGetHealthDamageUploadFileLists` импортируется в VehicleDamage из файла `useGetVehicleDamageUploadFileLists`, то есть имя не совпадает с файлом.
- Имя файла с кириллической «о»: `components/vehicleDamageScreen/DoсumentCardList.tsx`.
- Опечатки в именах и строках: `mialeageView` (ключ API!), `pathOsagoLossesApplicantSignType`, `osagoLossesHealtDamage`, `heathDamageCertificates`, `Posession`, «Госусключ», событие `…next_page_page_…`.
- Повторяющийся TODO «попытки избавиться от useEffect ни к чему не привели» в 5 компонентах форм.
- `OsagoLossesAttachedFileCard` дублирует `AttachedFile` (TODO).
- `signType` вычисляется одинаково в двух местах (`isLegalEntity ? 'ukep' : oid ? 'goskey' : 'pep'`). Стоит вынести в util.
- Флаг `isVehicleApplicationSelected` по умолчанию `true` на хабе (`?? true`), но после CheckProfile он всегда `false`, так что дефолт срабатывает только для старых черновиков.
