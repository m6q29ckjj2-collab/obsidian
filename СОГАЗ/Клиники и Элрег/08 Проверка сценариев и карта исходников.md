# Проверка сценариев и карта исходников

[[СОГАЗ/Клиники и Элрег/00 Обзор|К оглавлению]]

## Чек-лист

Эти сценарии предложены для проверки. Подготовка документации не означает, что они пройдены на стенде.

- [ ] Один пациент, один полис — выбор автоматический, можно записаться.
- [ ] Один пациент, несколько полисов — выбранный полис используется в auth, каталоге и фильтрах.
- [ ] Несколько пациентов — можно выбрать основного и ребёнка.
- [ ] У основного пациента полиса нет, у ребёнка есть — сценарий завершается загрузкой выбора.
- [ ] Доступных полисов нет — понятное сообщение и выход.
- [ ] Вход из полиса сохраняет нужный полис.
- [ ] `bookingMode=map` — каталог работает без Medonline auth.
- [ ] Путь через клинику и путь через специальность приводят к корректному расписанию.
- [ ] Разные адреса одной клиники используют правильные medonlineId.
- [ ] Смена дня, врача и клиники не оставляет выбранный чужой слот.
- [ ] Конкурентная запись в занятый слот даёт понятную ошибку и свежие слоты.
- [ ] Ошибка сети/таймаут после подтверждения не провоцирует незаметный дубль.
- [ ] Запись после успеха появляется в правильном профиле ленты.
- [ ] Перенос меняет существующую запись и показывает актуальное время.
- [ ] Отмена убирает/обновляет событие правильного пациента.
- [ ] Напоминания читаются и сохраняются.
- [ ] Истёкшая авторизация позволяет восстановить сценарий.
- [ ] Возврат назад и повторный вход не показывают данные другого полиса.
- [ ] Пустые регионы, пустые клиники и ошибка фильтров имеют понятное состояние.
- [ ] Недоступные виды помощи, будущая дата и франшиза соответствуют согласованным правилам.
- [ ] Часовой пояс проверен для устройства и клиники в разных регионах.
- [ ] Завершённый приём позволяет добавить файлы заключения и затем открыть их.
- [ ] Web/PWA, полная нативка и оболочка проверены отдельно в нужной среде.

## Аналитика

В `useClinicHandlers` найдены события с `flow=main_page`, `product=dms`, `page=appointment`. Выбор клиники использует `block=offline`, `event=click_button`, `event_identifier=n`. Переход к цифровой клинике использует `block=online`, `event=click_widget`, `event_identifier=digital_clinic`. Плитка Здоровья отдельно вызывает `reportDmsTileClick`.

Это найденные точки входа аналитики в описанном сценарии. Полная схема событий сервисов и отчётность на сервере по исходникам фронтенда не определяются.

## Как актуализировать заметки

После изменения API проверить URL, query/body, трансформацию ответа, условие skip, источник пациента/полиса и инвалидацию тегов. После изменения навигации проверить обе регистрации экрана. После изменения Элрега сверять создание с отображением, переносом и отменой в Telemed.
