# Карточки таймлайна и логика шевронов

Назад: [[00 Обзор]] · Дальше: [[02 Баги и план правок]]

## Структура `BaseAppointmentCard`

```
┌ root (radius 12, padding 16/12, bg primar) ─────────────┐
│ header:  [🕒 dateBadge]                [categoryBadge]  │
│ titleRow (TouchableOpacity) : title ........ [ШЕВРОН T] │
│ doctorBlock (TouchableOpacity, activeOpacity 0.5)       │
│   ├ OMS:   «Телефон для звонка» + номер  (шеврона нет)  │
│   ├ не OMS и не analysis:                               │
│   │    аватар · специальность / ФИО  ........ [ШЕВРОН D]│
│   └ clinic (если есть): 📍 название / адрес / телефоны   │
│ actionsContainer (если actions.length):                 │
│   Divider                                               │
│   [иконка] label ................... [ШЕВРОН A] (×N)    │
│ extraContentSlot                                        │
│   Current: Отменить / Подключиться / «врач свяжется»    │
│            eventMessage ............ [ШЕВРОН M]         │
│   Past:    eventMessage (текст)                         │
└─────────────────────────────────────────────────────────┘
```

Четыре независимых места, где рисуется шеврон, у каждого свое условие:

| № | Где | Условие (код) |
|---|---|---|
| **T** | справа от заголовка | `(!isAnalysis \|\| type==='self_added_analyses') && !NO_CHEVRON_TYPES.includes(type) && !!onPressAppointment` |
| **D** | справа от блока врача | `!!onPressAppointment && (isOms \|\| opinion \|\| !!doctorName \|\| !!clinic) && !isAnalysis && !NO_CHEVRON_TYPES.includes(type)` **и** при этом блок рисуется только если `!isOms` |
| **A** | справа в каждой строке action | `!appointmentInProgress` |
| **M** | справа от `eventMessage` (только `CurrentAppointmentCard`) | `isAnalysis` |

`NO_CHEVRON_TYPES = vaccine_record, injury_record, disease_record, surgery_record`.

Все T, D, M и тап по карточке ведут в **один и тот же** `onPressAppointment`; у A свои обработчики.

## Что делает `onPressAppointment`

### Запланировано (`renderCurrentEventCard`)
Обработчик есть **всегда** (никакой проверки кликабельности):
- `isAnalysis` → `handleAnalysesDetailsPress` (`AnalysisDetailsScreen`; для не-`self_added` без `analysisProviderSlug` — **молча ничего не делает**)
- иначе → `AppointmentDetailsScreen` (для `oms_consultation` с доп. параметрами `oms*`)

### Прошедшие (`renderPastEventCard`)
Обработчик есть, только если `isClickable`:

```
isMISConsultation = type==='mis_appointment' && category==='consultations'
isConclusionEvent = medcardType==='conclusions'
hasClickAction    = consultationType==='online' || type==='offline_appointment'
                    || isAnalysis || isMISConsultation || isConclusionEvent
isMedcardNoDetails = category==='medcard' && !medcardType
isClickable = hasClickAction && !isMedcardNoDetails
```

Обработчик — **цепочка независимых `if`** (не `else if`):
| Условие | Экран |
|---|---|
| `consultationType==='online'` | `CompletedAppointmentDetailsScreen` (id = `appointmentId`) |
| `offline_appointment` или MIS-консультация | `CompletedOfflineAppointmentDetailsScreen` |
| `isAnalysis` | `AnalysisDetailsScreen` |
| `isConclusionEvent` | просмотр заключения (`Linking` на PDF или `ConclusionDetailsScreen`) |

## Матрица: какие шевроны рисуются сейчас

Обозначения: ✓ шеврон есть, ✗ нет, `*` зависит от условия справа. «Тап» — реагирует ли карточка на нажатие.

### Запланировано
| Тип события | Тап | T | D | M | Комментарий |
|---|---|---|---|---|---|
| `appointment`, `ta_appointment`, `transcription_*`, `mis_consultation`, `legal/financial_consultation` | да | ✓ | ✓ `*` врач или клиника | — | при «Подбираем специалиста» D нет, T есть |
| `opinion` | да | ✓ | ✓ всегда | — | |
| `oms_consultation` | да | ✓ | ✗ (ветка OMS шеврон не рисует) | — | условие D для OMS мертвое |
| `offline_appointment`, `mis_appointment` | да | ✓ | ✓ `*` врач или клиника | — | |
| любой analysis-тип (`lab_*`, `external_lab_*`, `set_lab_choice`, …) | да | ✗ | ✗ | ✓ `*` есть `eventMessage` | без сообщения шевронов нет вообще, но заголовок кликается |
| `self_added_analyses` | да | ✓ | ✗ | ✓ `*` | |
| `cancel_lab_order_*` | да | ✗ | ✗ | ✓ `*` | |

### Прошедшие
| Тип события | Тап | T | D | A | Комментарий |
|---|---|---|---|---|---|
| online: `appointment`, `ta_appointment`, `opinion`, `transcription_online`, `oms/legal/financial/mis_consultation` | да | ✓ | ✓ `*` врач / клиника / `opinion` | `*` | **двойной шеврон T + D** |
| `offline_appointment` | да | ✓ | ✓ `*` | `*` | двойной |
| `mis_appointment` + `consultations` | да | ✓ | ✓ `*` | `*` | двойной |
| `mis_appointment` + другая категория | нет | ✗ | ✗ | `*` | |
| заключения: `medcardType==='conclusions'` (`mis_prescription` и др.) | да | ✓ | ✓ `*` | ✓ «Просмотр заключения» | |
| `self_added_analyses` | да | ✓ | ✗ | — | единственный analysis с T |
| остальные analysis-типы (`lab_results_ready`, …) | да | ✗ | ✗ | — | **кликабельно без единого шеврона** |
| `self_added_appointment` | нет | ✗ | ✗ | ✓ «Просмотр заключения» | |
| диагностика (`instrumental_diagnostics_result`, `general_diagnostics`, category `researches`) | нет | ✗ | ✗ | `*` | не кликабельна |
| `vaccine/injury/disease/surgery_record` | нет | ✗ | ✗ | — | `NO_CHEVRON_TYPES` дублирует `isMedcardNoDetails` |
| `transcription_offline`, `checkup_*` в past | нет | ✗ | ✗ | `*` | `consultationType` = `null` или `checkup`, `hasClickAction=false` |

> [!warning] Столбец «Тап» для past рассчитан по коду, а не проверен на устройстве. Реальные `type`/`category`, которые приходят из API, стоит свериться на примерах.

### Action-строки (A)
| Action | Где формируется | Условие |
|---|---|---|
| Видео/Аудио/Чат (подключиться) | `renderCurrentEventCard` | `isConsultationActiveNow \|\| canJoinConsultationNow` |
| Просмотр заключения | `renderPastEventCard` | `prescriptionUrl \|\| self_added_appointment \|\| resultId \|\| isMISConsultation` |
| Добавить заключение | `renderPastEventCard` | `offline_appointment && !resultId && !prescriptionUrl` |
| Оценить врача | `renderPastEventCard` | `surveyUrl && (offline_appointment \|\| MIS-консультация)` |
| Оценить клинику | `renderPastEventCard` | `clinicSurveyUrl && (offline_appointment \|\| MIS-консультация)` |

Во время идущей консультации (`appointmentInProgress`) у action-строки шеврона нет, и кнопка отключена, а подключиться предлагается отдельной `Button` ниже. Получается два способа подключиться: строка action (disabled) и кнопка.

## Целевая логика (предложение к обсуждению)

> [!tip] Вопросы к дизайну/продукту, ответы определят правки
> 1. **Один шеврон на одну тап-зону.** Сейчас T и D дублируются при одном и том же обработчике. Оставить только T (справа от заголовка) или только D?
> 2. **Analysis-карточки в past**: нужен шеврон (T или M), раз они кликаются? Или сделать некликабельными?
> 3. **Планируемые без деталей** (анализы без `analysisProviderSlug`): прятать шеврон или показывать с заглушкой?
> 4. **Единый цвет шеврона**: сейчас T/D/M — `brand.primary.ink`, A — `textInput.bottom.default`. Это намеренно?

Предлагаемый подход: вынести расчет в одну чистую функцию, например `getAppointmentCardTapTarget(appointment, hasPress)` → `'title' | 'none'`, и из нее же определять и `onPress`, и шеврон, чтобы условия `isClickable` и `showChevron` не расходились. Плюс единый `switch` по типу вместо четырех разрозненных булевых выражений.
